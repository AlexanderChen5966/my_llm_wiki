AI 同事不是「換個親切名字的 AI Agent」，而是架構上的升級——差別就像雇用一位多才多藝的自由工作者，和打造一支協同運作的團隊。

## T（核心論點）

- **AI Agent**：單一模型 + 序列式執行 + 一個執行緒 → 適合聚焦、單領域任務
- **AI 同事**：多個專門 Agent + 平行執行 + 編排器 → 適合複雜、跨部門工作流程

總完成時間差異：
- AI Agent：所有步驟時間的**總和**
- AI 同事：接近最長子任務所需時間（其他子任務平行跑）

## B（適用場景）

**選 AI Agent：**
- 工作集中在單一領域（純程式撰寫或純寫作）
- 任務彼此獨立，不跨越多個工具
- 需要快速輕量，不想承擔設定成本
- 單人使用，自動化需求簡單

**選 AI 同事：**
- 工作流程跨越多個工具、資料來源、輸出形式
- 同一流程需要研究 + 分析 + 創作 + 格式化
- 需要平行執行滿足時間限制
- 資料隱私/本地部署是必要條件
- 需要透明可視的工作流程監控

## R（完整內容）

### 七大面向比較

| 面向 | AI Agent | AI 同事 |
|------|---------|--------|
| 架構 | 單一 Agent、序列式 | 多 Agent、平行式 |
| 任務處理 | 一次一條執行緒 | 編排後的平行工作流 |
| 專業分工 | 通才 | 各領域專家 |
| 介面 | 聊天 / CLI | 桌面原生工作流程 UI |
| 模型支援 | 通常單一供應商 | 模型無關，可自由搭配 |
| 部署方式 | 僅雲端 | 先本地部署，支援自架 |
| 定價 | 每位使用者訂閱制 | 免費（開源）+ 推理成本 |

### 實際案例：競爭分析

**用 AI Agent：**
- 提示研究競對 A → 等待 → 提示研究競對 B → 等待 → 整理試算表 → 寫摘要
- 每步依序，你負責管理交接
- 總主動參與度：高

**用 AI 同事：**
- 一次描述：「研究五家競對，整理比較試算表，撰寫一頁摘要」
- Browser Agent 同時研究全部五家，Document Agent 即時整理，Writing Agent 同步撰寫
- 總主動參與度：極低，總耗時：≈ 最長子任務

### 演進路徑

聊天機器人（對話/無狀態）→ 副駕 Copilot（嵌入單一應用）→ Agent（自主/有工具）→ **AI 同事（協同/多 Agent）**

每一步加入前一個典範沒有的能力。Agent 是 AI 同事的基礎模組；問題是這些 Agent 各自獨立工作，還是協作——對於複雜真實世界任務，協作幾乎總是更好。

### 開源選項

Eigent（Apache 2.0）：完整開源的多 Agent AI 同事平台，本地部署，資料不經過供應商。

## C（關鍵行動）

- [ ] 評估自己的工作流程：有多少步驟可以平行？有多少工具需要跨接？
- [ ] 如果「一直在管理交接、拼接輸出、替 AI 當專案經理」→ 已超出單一 Agent 範式
