哥倫比亞大學博士生 Koukyosyumei 重新實作 40 篇 multi-agent LLM 論文後歸納：幾乎所有方法都能用「**迴圈結構 + 提示設計 + 集約規則**」三要素解釋，多數核心演算法約 100 行內就能實作。個別方法不是完全不同的演算法，而是少數基本模式用不同方式組合而成。

## T（核心論點）

多代理方法的表面差異被論文各自的術語放大了，抽掉包裝後只剩三個可參數化的維度：

1. **迴圈結構（怎麼重複處理）**：如何反覆執行
2. **提示設計（給每個 agent 什麼指令）**：角色與任務邊界
3. **集約規則（怎麼整合多個輸出）**：把多份候選收斂成一個結論

把這三者參數化，就能涵蓋相當大範圍的 multi-agent 研究。**集約規則往往只有 10 行，卻是論文新意的核心**。

## B（適用場景）

**適用：**
- 理解、比較、選型不同 multi-agent 方法（辨認它其實是哪種基本模式）
- 自己動手實作多代理系統，避免被論文術語綁架
- 判斷一篇 multi-agent 論文的真正貢獻在哪一層

**不適用 / 注意：**
- 目的是理解機制，不是複現論文 benchmark 分數
- 樣本獨立性（見下）在共享上下文框架中容易被無意破壞，需刻意設計隔離

## R（三要素展開 + 8 種系統類型）

### 容易被忽略的獨立性要求

Self-Consistency、CodeT、CoVe 等方法隱含前提是「多個樣本彼此看不到對方輸出」。在所有 agent 共享同一對話上下文的框架中，這種獨立性會被悄悄破壞——一旦某樣本能參照其他樣本，就不再是獨立生成的多代理系統。解法：讓每個 agent 在隔離沙盒工作，只在被允許時才通訊。

### 改善迴圈大同小異

Self-Refine / Reflexion / CRITIC / Self-Debug / Constitutional AI 結構幾乎相同：
1. 生成初始成果 → 2. 取得回饋 → 3. 用回饋改善 → 4. 視需要重複

差別只在**回饋來源**（批評 agent / 自我反思 / 工具執行結果 / 重讀程式碼 / 明文化憲法）。把回饋當一級物件參數化，這些方法可實作成同一個函式。

### 集約規則（約 10 行，本質所在）

多數決 / 依信心加權投票 / 多評分者平均 / 計算同意票 / 一對一比較勝場數。

### 辯論的本質是「讓誰看見什麼」的通訊拓樸

- 匯流排型（人人看見所有發言）/ 星型（經中央 agent 傳遞）/ 環型（僅相鄰通訊）/ 樹型（階層傳遞）
- 加上停止條件與投票規則，就能表達大部分辯論方法的設計空間

### 40 篇歸為 8 種系統類型

1. 改善迴圈　2. 多樣本生成與投票　3. 辯論　4. 多評審判定
5. 多輸出融合　6. 先探索再確定最終方案　7. 分階段管線（軟體開發/長文生成）　8. 動態團隊編成與管理

## C（關鍵行動）

- [ ] 看到新 multi-agent 方法時，先問：迴圈結構、提示設計、集約規則各是什麼
- [ ] 設計多代理系統時，明確決定樣本要不要獨立，並用沙盒隔離落實
- [ ] 把「回饋來源」抽成參數，改善迴圈就不必為每種方法重寫
- [ ] 辯論型系統先畫通訊拓樸（誰看得到誰），再加停止與投票規則
