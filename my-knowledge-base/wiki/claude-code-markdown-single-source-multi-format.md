## T（核心論點）

教材最怕「三份檔案、三個版本」——Word 改了、簡報忘了改、網頁又是舊的。解法：**內容只寫一次，寫在 Markdown 裡，其他格式全部從它生**。同一份 md 可以走 pandoc 轉 Word、python-pptx 轉簡報、Claude 直接生 HTML——**一次寫、三處用，改來源，三種格式重生一次就同步**。這不只是格式轉換，Claude Code 更大的價值在「把結構化內容變成多種格式」——教材、簡報、文件、講義正好全是這種活。

## B（適用場景）

**適用：** 需要同一份內容以多種格式交付（紙本講義+投影簡報+線上網頁）；教學教材製作；需要多套視覺風格但內容不變的簡報

**不適用 / 注意：**
- 不是全自動：pandoc 的 Word 表格框線要補、python-pptx 精細版面偶爾要手動收尾、HTML 互動要調——**前面 80% 骨架與內容 AI 一次到位，最後 20% 仍需人工**
- 若只需要「Markdown → 投影片」的標準需求，**Marp 這類現成框架更省事**；本文的價值在「完全客製」風格，框架內建主題給不了

## R（四個層次）

### 一、為什麼 Markdown 是「單一真相來源」

| 特性 | 對「跟 AI 協作」的好處 |
|---|---|
| **純文字** | Claude 讀它、改它都順，調一段落不必碰排版 |
| **好版控** | `git diff` 一眼看到「這版改了哪句」，不像 Word/PPTX 是二進位黑盒 |
| **一源多格式** | 同一份 md，pandoc 轉 Word、python-pptx 轉簡報、Claude 直接生 HTML |

### 二、一份 md，三種產出

| 格式 | 技術 | 用途 |
|---|---|---|
| **Word 講義** | pandoc（包成 skill，一句話轉，自動修表格框線）| 學員印紙本，跟著操作不用盯投影幕 |
| **PPTX 簡報** | **python-pptx**（Claude 讀 md 章節結構，一頁頁組出 .pptx——標題/條列/重點框照排）| 上課直接開 PowerPoint/Keynote 投 |
| **HTML 網頁/簡報** | 🔑 **連轉都不用，直接請 Claude Code 生**——自帶 CSS、能鍵盤翻頁 | 丟進瀏覽器就能放；自學學員一個連結就看得到 |

```bash
pandoc 01_照片教學.md -o word/01_照片教學.docx --from markdown --to docx
```

### 三、不只內容，還有教學鷹架

AI 幫的不只是「把字打出來」，還有**教學設計本身**：

- **一句話重點**：每段開頭 `💡` 濃縮成一句，先抓核心再看細節
- **⚠️ 警告框**：像「iCloud 一邊刪兩邊都刪」這種一踩就出事的地雷獨立標出
- **emoji 當路標**：降低純文字對新手的壓迫感
- **📷 截圖預留位**：該補圖的地方先留記號，內容定稿後統一補

甚至能產**講師教學指南**（課程分幾節、每節幾小時、節奏設計）：
```
講解示範(10–15分) → 跟著操作(5–10分) → 獨立練習(5–10分) → 提問確認(3–5分)
```
> 這已經不只是「幫你打字」，是**幫你把一堂課的骨架搭出來**——你把「教什麼、教給誰」講清楚，它把鷹架搭好，你再填血肉、微調節奏。

### 四、🔑 同內容、多套皮膚——四種簡報風格只換 CSS

四份 HTML 的**版面結構完全一樣**，差別只在最上面那組 CSS 變數：

```css
/* 風格A 親切：暖奶油底 + 橘 */
:root { --bg: #FFF8F0; --ink: #3A2E26; --c1: #FF9F68; }
/* 風格C 深色：深夜底 + 青 */
:root { --bg: #0e0f13; --ink: #f2f3f5; --accent: #4fd1c5; }
```

四種風格：**親切教學風**（給長輩看最舒服）、**蘋果簡約風**（大量留白）、**深色質感風**（適合投影幕演講）、**三步驟流程風**（拆成 1→2→3）。

> 內容一字沒改，四種風格一鍵切換——這種「同內容多套皮膚」手工做要重排四遍，交給 AI 就是換組 `:root` 的功夫。

## C（關鍵行動）

- [ ] 任何要多格式交付的內容，先寫成單一 Markdown 來源，別開多個檔案分別排版
- [ ] Word 講義走 pandoc（包成 skill 一句話轉），PPTX 走 python-pptx，HTML 直接請 Claude 生
- [ ] 教材類內容主動要求 AI 加教學鷹架（一句話重點、警告框、emoji 路標）
- [ ] 需要多視覺風格時，只維護 CSS 變數層，不要重排版面結構
- [ ] 標準投影片需求優先用 Marp 等現成框架；只有需要完全客製風格才手刻
