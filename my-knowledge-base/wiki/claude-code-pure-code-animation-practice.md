## T（核心論點）

🔑 **純程式碼動畫的底層是：每一格畫面都是時間的純函數 `draw(t)`**——同一個 t 永遠畫出同一格（不用 `Math.random`、不讀現在時間；有狀態的模擬要先算好或存快照）。做到這點，才能逐格渲染、多個瀏覽器平行算、單獨抽某一秒出來檢查或修改。成品品質的差距，主要來自三個工作習慣：**① 讓模型看自己的樣片**（渲染截圖總表與連續格膠卷，自己挑毛病再改）；**② 先寫共用骨架與場景規格書，再把場景分給子代理，最後分面向審查**；**③ 另外找一個沒看過素材的 AI 驗收**，看它能不能說出影片在講什麼。渲染層用 HyperFrames／Remotion，或自己寫 puppeteer／Playwright 逐格截圖＋FFmpeg，都有人實測做出成品（兩說並列，見 [[claude-codex-video-toolchain-selection]]）。

## B（背景）

**適用（rar.design 作者觀點）：**
- 生成藝術、技術型動態、品牌系統；風格化 2D、像素、幾何、程式化 3D、物理模擬
- 需要精準、可一直改參數的案子：改一個顏色、拉長兩秒只要改一行重新渲染，不必整支重抽

**不適用／注意：**
- 寫實人物表演、實拍質感：影片生成模型比較直接（作者觀點）
- 需要實拍素材或大量手繪的商業案：After Effects 比較順手（作者觀點）
- 有人聲的歌要另外準備；模型能合成配樂與音效（作者觀點）
- 🔴 **倖存者偏差**：首週作品都是作者滿意才貼出來的，失敗版本沒人貼（作者自己提醒）
- 🔑 **品味沒辦法外包**：模型看得出卡頓、跑版、字太小，但「這個橘配這個藍好不好看」「這一拍該不該更狠」要由你給標準（rar.design 作者實測心得）

## R（關鍵細節）

### 1. 底層原理：把時間寫成函數

- After Effects 是關鍵影格之間內插；純程式碼動畫反過來，只有一個 `draw(t)`，丟進任何時間點就畫出那一格（rar.design）
- 因為每格只跟時間有關：同一格可重畫無數次、結果一樣；可以開多個瀏覽器同時渲染不同格；也可以在一格內「多拍幾次」做真正的動態模糊（rar.design 以 1/120 秒快門取 5 個瞬間疊合）
- 🔑 **節拍表（SCORE）**：先請 Claude 寫一份「譜」（哪拍有大鼓、拍手、breakdown），畫面與聲音讀同一份，字母落地、變形、轉場天生對拍（rar.design 作者實測）
- 可重現規則（rar.design 限制段）：隨機改用固定種子亂數；反應擴散、物理這類有狀態模擬，要先整段算好存起來，或定期存快照、往回跳時從快照重算

**同一條規則的五個出處（彼此一致）：**

| 出處 | 寫法 | 層級 |
|---|---|---|
| rar.design〈12 種效果〉 | 每一格都是時間的純函數（不能用 `Math.random`） | 作者實測 |
| rar.design〈首週動畫〉轉述 P(doom) 動畫指南 | 每個鏡頭只能由時間決定，不准隨機數，也不准讓前一格影響下一格；九個章節平行算圖、渲染順序是亂的，所以必須這樣 | 轉述原作者 |
| 數位時代 | 做成「可指定任一秒」的畫面 | 作者實測 |
| rain.tips（Remotion） | 只由 `useCurrentFrame`／`interpolate`／`spring` 驅動，禁 CSS transition、`Math.random`、目前日期 | 作者範本 |
| HyperFrames README | deterministic MP4 | ✅ 官方（Team Lead 2026-10-19 核對） |

可以直接貼進 brief 的一句（rar.design 作者建議）：「所有動態都由時間 t 決定，同一個 t 永遠畫出同一格；需要隨機感，就用固定種子的亂數。」

### 3. 習慣一：讓模型看自己的樣片

- **做法**（rar.design 作者實測）：先請 Claude 寫一個渲染小工具——輸入場景名稱與時間點，輸出那幾格的截圖並拼成**縮圖總表**；挑 **8～10 個關鍵時間點**，動作細節再加一條**連續 12 格的膠卷**。Opus 5.5 看得懂圖片，會自己打開總表挑毛病（鏡頭停了 0.1 秒、橘配藍變成洋紅、字被 IG 按鈕蓋住），回頭改程式再渲染；**每個場景至少三輪**，直到它自己也挑不出問題
- 作者提到 Anthropic 官方短片〈Building verification loops in Claude Code〉講的就是這件事（原文只附縮圖、沒附連結），並附官方 best-practices「give Claude a way to verify its work」連結（見 frontmatter）
- 首週案例（經 rar.design 轉述）：Chris Riley 的玻璃馬賽克，agent 渲染後逐格看，列出改了什麼（金魚貼金牆糊成一團 → 改銅橘玻璃加藍描邊），也老實列出兩個沒解決的問題；Vox〈small print〉配樂合成完回頭逐秒檢查再修一輪
- 反例（轉述 BitsMinds，**單題單次**）：三個模型做同樣三道動畫題、**不准開瀏覽器看自己的成品**；Opus 5.5 交流道那題輸在一條線——每條匝道出入口都被白色路緣線畫過去，這種錯只有看圖才抓得到
- prompt 結尾可加（rar.design 作者建議）：「渲染完每秒截一格檢查，列出你改了什麼、還剩哪些問題。」這份回報就是你的驗收清單
- 對照 [[karpathy-opus5-lotr-3d-case]]：Karpathy 的實驗暴露「模型看不到自己的作品」，只能靠不同時間點截圖反推、非常費力；本條的縮圖總表＋膠卷，是把這個缺口**主動做成工具**

### 4. 習慣二：先寫骨架與規格，再分工、再分面向審查

- **共用骨架**（rar.design 作者實測）：畫布尺寸、節拍、配色、字體、轉場、後製；再寫一份**場景規格書**，規定每個場景要交什麼、安全區在哪、效能上限多少
- **子代理分工**：一個子代理負責一段效果，各自寫、各自渲染、各自看圖修改
- **分面向審查**：全部完成後，再派一組審查代理，每個只看一面——IG 安全區與手機可讀性、逐格找瑕疵、聲畫對拍、文案與數據；前後幾輪挑出幾十個問題，多數是作者自己看片不會發現的（例如轉場比拍點早 5 格）
- 首週案例 P(doom) MV（156.6 秒，經 rar.design 轉述）：第二版開工前，Opus 5.5 先寫一份分鏡表（每句歌詞對上秒數、畫面、轉場）與一份給子代理的動畫指南，全片拆成九章節、各一個檔案平行畫，最後無頭瀏覽器逐格算圖再用 FFmpeg 合成；原始碼在 github.com/JohnHeibel/PDoomVideo
- 數位時代的順序（作者實測）：**先要分鏡表** → 確認內容後輸出開頭／中間／結尾 **3 張關鍵畫面** → 做一段 **2 秒動態測試**確認速度與節奏 → 才做完整影片
- 🔑 設計師最該學的是順序：先要分鏡表與美術設定，看過、改過再開工——**改文件只要幾秒，渲染完再改要重跑幾十分鐘**（rar.design 作者觀點）

### 5. 習慣三：另找一個沒看過素材的 AI 驗收（數位時代作者觀點）

- 影片做完，把成品丟給另一個**沒看過官網**的 AI，問：「這支影片在講什麼？」答案和你想傳達的不同，就代表影片還沒把訊息說清楚
- 驗收條件範例：產品必須在 3 秒內出現、文字大到手機看得清楚、影片必須有字幕

### 6. 實例一：rar.design 30 秒 IG Reels、12 種效果（設計師 Riven，作者實測）

**起點**：在 Claude Code 打一句「做一支 15 秒的動態設計作品集，秀出你有多會做動態，全力以赴」，幾輪來回後變成以下規格。（與益盛 iChurch 40 秒的 showreel 型一句話提示詞同一型，見 [[hyperframes-heygen-html-to-video]]。）

| 項目 | 數值 |
|---|---|
| 規格 | 30 秒、1080×1920（9:16）、60fps、1,800 格 |
| 內容 | 開場問句＋12 種效果（各約一小節）＋快剪回顧 |
| 節拍 | 128 BPM，一拍 0.46875 秒，16 小節＝30 秒 |
| 規模 | 約 28 萬字元原始碼；**0 個**影片、圖片、音效素材 |
| 工具鏈 | Canvas 2D＋WebGL2（GLSL）；puppeteer-core 控制本機 Chrome；**六個無頭 Chrome 平行**；每格 5 次取樣動態模糊；後製光暈、色差、底片顆粒；ffmpeg-static 輸出 MP4；Web Audio（OfflineAudioContext）合成配樂 |
| 渲染時間 | M3 Max 筆電、六個 Chrome，含啟動約 5 分鐘 |
| 效能預算 | 單次 draw 約 60 ms；含 5 次取樣與後製，一格約 400 ms 以內 |

- ⚠️ 數字（28 萬字元、5 分鐘、±6 ms）來自單一作者、未公開完整原始碼，無法查核；作者說「沒開任何剪輯軟體」，但經過幾輪來回與多輪子代理審查，**實際投入時間與 token 未公開**
- 軟體需求：Claude Code、Node.js、Chrome；puppeteer-core、ffmpeg-static、matter.js 等套件可以請 Claude 在專案裡自己裝（作者觀點）

**作者的第一句骨架指令**（節錄原文，可直接改用）：

```text
幫我建立一個用程式碼做動態影片的專案：1080×1920、60 fps、30 秒、128 BPM。
每一格都要是時間的純函數（不能用 Math.random），用 Canvas 2D 和 WebGL2 畫，
用 puppeteer 控制本機的 Chrome 逐格渲染，每格做 5 次取樣的動態模糊，
最後用 ffmpeg-static 輸出 MP4。另外寫一個預覽工具，可以指定時間點輸出截圖總表，
每次改完都先渲染總表給自己看過再告訴我。
```

**12 種效果與關鍵技法**（作者實測；只列技法，程式碼見原文）：

| # | 效果 | 關鍵技法 |
|---|---|---|
| 01 | 彈跳球（時間感） | 先定落地拍點，再用 h = g·Δ²/8 反推高度；高斯脈衝壓扁、沿速度方向等面積拉伸 |
| 02 | 可變字體 | Canvas 不能用 font-variation-settings → 同一 woff2 註冊 64 個 FontFace（AW62～AW125），每個用 stretch 鎖一個寬度 |
| 03 | 形狀變形 | 256 根等角輻條的半徑陣列，變形就是兩條陣列內插（不做錨點對應） |
| 04 | 黏土 3D | SDF raymarching；反推焦距讓 3D 球與上一段 2D 圓 match cut |
| 05 | 包浩斯網格 | stagger、mulberry32 固定種子配色 |
| 06 | 流動線條 | 3D Perlin noise 山脊線 |
| 07 | 液態玻璃 | 2D SDF metaballs、7 波長 Cauchy 色散 |
| 08 | 光線步進 | domain repetition、16 波長薄膜干涉 |
| 09 | 二十萬粒子 | 無狀態粒子：位置＝f(id, t) |
| 10 | 反應擴散 | Gray–Scott；步數寫成時間的純函式，每 2048 步存快照 |
| 11 | 著色器風格化 | G-buffer 延遲風格化，同一物件換五種印刷術 |
| 12 | 剛體物理 | matter.js 以固定 1/240 秒步長先算完存軌跡，渲染只查表內插；校準迴圈讓落地壓在拍點 ±6 ms 內 |

**可遷移的坑**（作者實測）：
- 硬切進來的鏡頭，**第一格就要能讀**：進場動畫的時鐘先走 0.15 秒（pre-roll），跟拍子綁定的元素仍用真實時鐘
- 轉場終點可以刻意放在小節線之後，讓畫面在切點前一格才吃滿，避免提早黑幕
- 彈簧過衝會破壞 match cut：交棒前最後一小段強制鎖回目標形狀
- stagger 的延遲是往後加的，收合起點要**從下一個 downbeat 倒推**
- 補色輪廓光只放在暗部，否則受光面會混出洋紅色
- 打點準不準要逐幀看 downbeat 前後的 still，不能只看曲線圖
- 重複晶格的鏡頭每幀最多移動 0.4 格，否則看起來在閃（像倒轉的車輪）
- IG 會重新壓縮：細碎閃點會被壓成色塊 → 塵埃改成柔邊大光點、降低動態顆粒；**平台壓縮也要當成畫面的一部分來設計**
- 畫面上的 HUD 數字要和 shader 共用同一組常數，避免「字看起來專業、數學是假的」

**IG Reels 規格**（作者實測）：輸出 1080×1920；上方約 250px、下方約 420px 會被介面蓋住；右下按鈕欄約 x 940 以右；響度約 −14 LUFS；另外自訂封面，個人頁格狀縮圖只顯示中間 3:4。

**授權**（作者實測）：畫面是自己程式算的，但字體與函式庫是別人的——本片用的 Archivo、Noto Sans TC、JetBrains Mono、Instrument Serif 是 SIL OFL，matter.js 是 MIT；換別的字體或函式庫，商用前要再確認。

### 7. 實例二：數位時代 24 秒宣傳片、六步驟（韋惟珊，作者實測）

> 作者為自家產品做宣傳片；本條**只收方法**。從開始討論到第一版約 30 分鐘、成品約 24 秒。⚠️ 圖卡內容只擷取到標題，細節可能缺漏；token、方案、使用介面都沒交代。

1. **程式碼算畫面**：用網頁技術寫出「每一秒、每一格該出現什麼」，自動截圖，再合成影片；需要能在電腦上直接執行程式的環境
2. **先拆參考片**：找一支喜歡的影片丟給 Claude（選 Opus 5.5），問：「拆解這支影片的視覺風格、節奏、轉場與鏡頭語言，不要照抄內容。根據這些特色，建議我的影片腳本和分鏡可以怎麼設計。」
3. **備齊素材**：文案、圖片、Logo、icon、字體、產品截圖放進同一個資料夾；提示詞寫明尺寸、對象、目標、CTA，並指定「HTML＋CSS＋JavaScript 寫動畫，做成可指定任一秒的畫面，用 Playwright 截圖，再用 ffmpeg 合成 MP4，要有配樂，動態跟音樂節奏要配合；缺 Playwright 或 ffmpeg 先告訴我並幫我安裝」
4. **讓它讀官網規劃故事**：官網資訊夠完整時，直接給網址請它解讀內容、抓圖片、規劃影片
5. **先看分鏡、3 張關鍵畫面、2 秒測試片**（見第 4 節），也可以下導演式指令（例如指定某一格放慢幾倍推進）
6. **另找 AI 驗收**（見第 5 節）

### 8. 實例三：益盛四支品牌動畫（HyperFrames）

詳見 [[hyperframes-heygen-html-to-video]] 第 8 節。和本條相關的兩點：
- **兩種提示詞寫法都做得出來**：一段英文 showreel 型提示詞（無分鏡、無素材）vs 詳細中文分鏡＋角色圖＋截圖
- 總 token 大多是快取讀取，輸出 token 只佔一小部分

### 9. prompt 三種寫法與 brief 範本（rar.design〈首週動畫〉，作者觀點，案例經轉述）

| 寫法 | 例子 | 何時用 |
|---|---|---|
| 短版：題材、長度、風格，其他交給它 | Michael Guo 沙畫美國史：兩分鐘、美國 250 年歷史、要生動有品味並配合適的音樂音效 | 要故事感；大家有共同記憶的題材 |
| 長版：畫面規格一條一條鎖死 | Majid Manzarpour 像素巫師五段 prompt（畫面規格／角色／動作／場景／驗收），例如「姿勢參數平滑地算，但每一格都量化回像素格，讀起來像每秒 8～12 張」 | 要特定畫風 |
| 世界觀規則：只給一條物理設定 | Dan Fein 玻璃馬賽克：磁磚從沒黏牢，可以掀起、翻面、飛走再扣回；Chris Riley 原封不動丟進去跑出 80 秒的片 | 想要沒見過的動態語言 |

描述動作時用熟悉的動畫詞彙：緩動、預備動作、擠壓伸展、一拍二（作者觀點）。

**可直接改的 brief 範本**（rar.design 原文，方括號換成你的內容）：

```text
做一支［秒數］秒、［比例］的動畫，輸出成單一 HTML 檔，只用 Canvas 2D 和原生 JavaScript，不用任何圖檔、字型或音檔。
畫面：［畫風，例如手繪線條加紙張質感］，全片只用［色票］這幾個顏色。
角色與動作：［角色描述］。動作分成［待機、預備、主動作、收尾］幾個狀態，狀態之間用緩動，換表情不要硬切。
時間規則：所有動態都由時間 t 決定，同一個 t 永遠畫出同一格；需要隨機感，就用固定種子的亂數。
驗收：渲染完每秒截一格檢查，列出你改了什麼、還剩哪些問題，確認沒問題再交件。
```

要輸出影片，就在 Claude Code 跑，最後加一句「用 HyperFrames 渲染成 MP4」（作者建議；安裝見 [[hyperframes-heygen-html-to-video]]）。

### 10. 介面選擇（rar.design 作者觀點）

| 介面 | 適合 | 首週例子 |
|---|---|---|
| Claude 網頁版 | 單檔 HTML 小動畫、互動展示、想直接丟連結給人看 | 安提基特拉遊戲（直接發成 artifact） |
| **Claude Code**（有講明介面的作品多半在這裡） | 要輸出 MP4、要它看樣片自己修、要跑一兩個小時、要開子代理 | P(doom) MV、沙畫美國史、BitsMinds 測試 |
| Claude Design | UI 動效、行銷短動態、在畫布上邊看邊調 | **首週熱門作品裡一支都沒有** |

- 多數作者沒講用哪個介面；有講明的，Claude Code 佔多數（作者觀察，倖存者偏差）
- 產品路線對照：Claude Motion 是另一條「由 Claude 代管程式」的路，見 [[claude-motion-beta-2026-10]]；Claude Design 的定位見 [[claude-design-tool]]

### 11. 首週案例精選（原作者自報，經 rar.design 轉述）

> 只挑有可查連結或可遷移意義的幾例。觀看數、成本、時間多為原作者自報。Dan Fein、Edwin Arbus 是 **Anthropic 員工**，作品有利益相關。

- **P(doom) MV**：156.6 秒，Claude Code，九章節子代理平行，p5.js 水彩筆刷逐格繪製；原始碼 github.com/JohnHeibel/PDoomVideo
  - ⚠️ 2026-10-19：repo 擁有者**兩說並列、都沒核對**——github.com/JohnHeibel/PDoomVideo（rar.design；數位時代〈10 種風格〉的資料來源段）vs github.com/mexicat/pdoom-video（同一篇數位時代的正文連結，正文卻寫「GitHub 用戶 JohnHeibel 公開」）。athemeroy README 另列 JohnHeibel 的 ClaudeAnimationBase（p5.js＋p5.brush，與本片筆刷相符），傾向前者，但仍未一手核對（見 [[opus-5-5-video-case-libraries]]）

- **Stefan Vaskevich 湖畔城堡**：透過 **Blender 官方 MCP**，程序化建模＋渲染 10 秒鏡頭，35 分鐘、19.96 萬輸出 token、換算 API 約 13.3 美元；同題 GPT-6 Astra 28 分鐘、約 14.5 美元（**單題單次**）
  - ⚠️ 2026-10-19：這裡的「Blender 官方 MCP」和 aiposthub〈Blender MCP 教學〉說的 **MCP for Blender（原 blender-mcp，ahujasid）**——該文明寫「第三方專案，並非 Blender 官方」——**可能不是同一個東西，也可能是轉述時的誤稱，沒有核對**；引用時請區分（工具細節見 [[claude-codex-video-toolchain-selection]] 第 9 節附註）
- **Michael Guo 沙畫美國史**：兩分鐘，一段短 prompt；用 Pro 方案五小時額度約三成（訂閱，非 API）；配樂是 Python 產生 MIDI，再用 FluidSynth 配免費音色庫出聲
- **Majid Manzarpour 像素巫師**：約 30 分鐘、額度幾乎沒動
- **BitsMinds 三模型測試**（**單題單次、不准看自己成品**）：Opus 5.5 三題 59／63／77 分鐘，交流道題想了 57 分鐘、寫檔一分半；總分 Opus 5.5 10 分對 Astra 8 分。遊樂園題的觀察值得記：Astra 的旋轉木馬畫最細卻沒在轉，Opus 5.5 畫得較粗但整台機器真的在轉——🔑 **評估動畫要看動起來對不對，只比截圖會看走眼**
- 推理強度：最高強度很慢、時間大多花在動筆前；作者建議**從中等強度開始**，畫面邏輯複雜又沒辦法讓它看畫面時才往上調（作者觀點）

## C（連結與應用）
