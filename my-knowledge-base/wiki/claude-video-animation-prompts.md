五篇都在處理同一件事：**「做得有質感一點」沒有指定任何動作**，AI 只能每次猜一個。本條目合併五篇（raw-pipeline 路徑 ②，各篇 40／30／36／24／18，合計 148），整理三種把動畫要求講清楚的做法：**給動作一個名字**（Motion Prompt）、**先寫狀態再談動作**（LottieFiles Motion Design Skill）、**先比方向、再做、留可修改的專案**（Huashu-motion、Moritz 發布片需求）。

> ⚠️ **來源性質**：🔴 **五篇都是 aiposthub／Philo**，單一站點、單一作者，互為延伸閱讀，**互引不構成佐證**。五篇都**沒有附站方實測**：Motion Prompt 篇是回 GitHub 倉庫的查證整理；兩份需求範本（發布片、表單）明言「本站依公開方法改寫、非原作者逐字 prompt、未做成片實測」；Huashu-motion 與 Moritz 的示範影片都標「非本站實測」。數字（144 個名稱、470 顆星、120–180 毫秒等）都是作者查詢當日的轉述，**本庫未回官方倉庫核對**。

## T（核心論點）

> **動畫要求講不清楚，卡住的不是想像力，而是不知道那個動作叫什麼、它服務哪個狀態、整支片要往哪個方向。** 所以要依序補上三樣東西：**名字**（讓「有質感」變成「#005 遮罩揭示，0.6 秒」）、**狀態**（動作只在真實狀態改變時出現）、**方向**（先比幾張關鍵影格再投入製作）。

三個支撐點：

1. 🔑 **名字代表一組明確動作**：Motion Prompt 每個名稱背後有規格（哪個元素幾秒到幾秒、什麼緩動、移動多少像素），代理搬到別的專案時節奏不會跑掉；團隊也能用「請用 #005」溝通，而不是各自理解「有質感」
2. 🔑 **功能性動效先從狀態開始，不從特效開始**：按鈕要先寫出閒置／處理中／成功／錯誤四種狀態，動畫才有角色；🔴 **不要拿動畫長度假裝等待時間**——資料沒送完就不能播成功
3. 🔑 **選擇要發生在投入完整製作之前**：先看三張不同構圖的關鍵影格、先做最難的鏡頭，再完成其他場景；成片要留在可點選、可局部修改的專案裡

## B（適用場景）

**適用：**
- 常需要跟 AI 或同事描述動畫、鏡頭、介面效果的設計師、剪輯師、前端開發者、PM
- 表單、按鈕等需要狀態回饋的產品介面（LottieFiles 篇以送出按鈕為第一個練習）
- 已有官網、Logo、明確賣點的軟體產品，要做 24～30 秒發布片

**不適用 / 注意：**
- 想要整套完成品模板的人：Motion Prompt 官方明說**目錄只涵蓋個別動作**，影片要說什麼、怎麼排、每個場景多長，要自己和代理決定
- 只用中文工作的人：Motion Prompt 官方名稱只有英文與日文；繁中（台灣用語）、簡中、西文都是社群 PR，作者查詢時**尚未合併**
- 🔴 安裝 Skill ≠ 網站已有動畫：LottieFiles 的 Skill 是文字規則，Lottie 動畫檔是可播放的資產，Creator MCP 又是另一層工具連線——三者不同
- 示範片的品質、製作速度是作者那一次的結果，不代表任意提示詞都能做到

## R（操作步驟）

### 1. 給動作一個名字：Motion Prompt（大滝昇平，MIT）

- **是什麼**：日本創作者大滝昇平（Shohei Ohtaki）開源的動效名稱庫；每個條目有編號、名稱、一行意思、提問範例、會動的示範，以及可讓 AI 重建的規格與程式碼。編號固定，官方承諾公開後不重新編號、不改已發布名稱
- **六個主題包、各 24 個，共 144 個**（轉述官方 README 與 FORMAT 文件）：

| 主題包 | 編號 | 內容 |
|---|---|---|
| motion | 001–024 | 動態圖形動作（彈出、錯開、遮罩揭示） |
| camera | 025–048 | 鏡頭運動與轉場 |
| ui | 049–072 | 介面元件名稱 |
| lp | 073–096 | 登陸頁與網頁特效 |
| photo | 097–120 | 照片風格、燈光、畫風 |
| motion2 | 121–144 | 動態圖形第二批（10-19 才加入） |

- ⚠️ **數字更正**：X 上 Voxyz 的介紹貼文（分享者，非作者）寫「五個主題、120 個」，作者 10-19 加了第六包後已是 144 個；貼文只提 Claude Code，官方說 Codex 與其他讀技能的代理也適用。引用數字要以倉庫當天狀態為準並註明日期
- **三種用法**（依自動化程度）：
  1. **不安裝**：在展示站找到動作，把名稱放進指令，再補秒數、強度與要動的東西。README 範例：「用從下方出現的遮罩揭示帶入標題，0.6 秒，每行比前一行稍晚」「緩慢向前推近她的臉，移動鏡頭，不要變焦」。⚠️ 官方**沒有提供前後效果對照數據**
  2. **安裝技能**（Node.js 18+）：`npx skills add showheyohtaki/motion-prompt`，或直接把一句安裝指令貼給 Claude Code。說「打開 motion-prompt 資料庫」開展示頁，選樣本（可加一行備註如「用在開場標題」）→ 按「傳給 AI」→ 回 AI 說「把這支影片的開頭照這樣修改」；或直接說「用 #012 和 #045」。支援 Remotion、CSS、Canvas 等
  3. **做自己的版本**：`make-your-own` 資料夾有提示詞，可翻成其他語言或做自己領域的名稱庫（燈光、音效、烹飪、建築都行）——這也是官方給中文使用者的建議作法
- **規格怎麼保住節奏**：每個條目是 Canvas 2D 函式，**只由時間決定**（不讀系統時鐘、繪製時不用隨機數），循環交界要無縫——與 [[claude-code-pure-code-animation-practice]] 的 `draw(t)` 同一原則。例：#005 遮罩揭示一次 2.35 秒、循環 4.7 秒；分隔線 0.1–0.5 秒從中間長出，上方文字 0.35–1.0 秒從 120px 下方升起、五次方緩出。規定**規格數字都取自程式碼、不能自己編**，要寫到「不看示範也能重建」
- **代理施工步驟**（技能規則）：讀專案（Canvas／Remotion／AE／CSS、尺寸、影格率、場景計時、字型顏色）→ 逐場景列出需要的**一個**動作（要人一起決定）→ `get` 取規格與程式碼、`kit` 取該包共用常數與函式（缺了跑不起來）→ **時長、延遲、緩動、過衝量、距離角度維持原樣，文字顏色標誌圖片換成你的** → 「把這段換成 #005」時只換動作、不動場景長度 → 多元素時每個進場落在節拍上、一次只讓一件事在動、整支用同一種緩動 → 實際播放或渲染檢查 → 回覆列出用了哪些編號、放哪個場景、改了什麼、哪些無法驗證
- 🔑 **防編造規則**：移植的程式碼必須是**當次用 `get`／`kit` 印出來的**，不能憑名稱自己寫一份再說是目錄裡的元素
- **不是每包都該搬成程式**：photo 包是寫進圖像模型提示詞的字眼，技能規則寫明不要移植進產品；給 Veo、Seedance、Sora 等影片模型時只用名稱與規格寫成句子，**結果只會接近、不會完全相同**
- **網路與安全**（README 轉述）：腳本只對展示站 api 資料夾發讀取請求，連不上改用 GitHub 原始檔，不上傳專案內容；「傳給 AI」是本機只聽 127.0.0.1 的暫時接收器，需隨機權杖；目錄快取 6 小時；沙盒沒網路時以代碼 3 結束。官方要求代理安裝時不改原有設定檔或其他技能——仍建議裝完自己確認
- **授權**：MIT，官方寫明程式碼、影片、圖片都可商用；用到元素程式碼時要**保留第一行**（「Motion Prompt #編號、MIT License、版權人與網址」）。🔴 展示站嵌入的他人 X 貼文不在 MIT 範圍；另參考了 Seokwoooo 的 Lucian UX/UI Prompt（第三方聲明附對方 MIT 文字）
- **限制**：示範是 539×208 卡片尺寸，不是 4K 素材，要依專案尺寸與影格率調整；倉庫 10-14 才建立、無正式發行版（10-20 查詢約 470 顆星）
- 作者建議的小驗收：挑三個專案真的會用的動作 → 在小專案把一個換進現有影片，確認節奏沒跑掉 → 檢查第一行授權是否保留

### 2. 先寫狀態再談動作：LottieFiles Motion Design Skill

- **三層要分清**：Motion Design Skill（`npx skills add LottieFiles/motion-design-skill`）是**教代理怎麼安排動作的文字規則**；Lottie 動畫檔是可播放資產；Lottie Creator MCP 是讓代理操作 Creator 的工具連線。官方 Creator MCP 文件也說 Skill 提供方法、不取代 MCP。本篇的表單需求可交給既有網頁開發流程，不一定要用 Creator，也不需要 LottieFiles 帳號（用 Creator MCP 才要）
- **送出按鈕四狀態**（作者整理）：

| 狀態 | 使用者想知道 | 畫面應說明 |
|---|---|---|
| 尚未送出 | 我可以做什麼 | 清楚的動作名稱 |
| 處理中 | 有收到我的操作嗎 | 正在處理，避免重複操作 |
| 成功 | 完成了嗎 | 完成結果與下一步 |
| 錯誤 | 哪裡有問題 | 可理解的原因與重試方式 |

- **時間參考**（官方 timing-easing-tables，經轉述）：按鈕與切換控制 **120–180 毫秒**；錯誤震動 **300–400 毫秒**。⚠️ 這是該專案的設計建議，不是每個產品必須遵循的標準
- 🔴 **動畫不能脫離真實結果**：只播放打勾動畫、卻沒接到實際成功結果，會讓人誤以為預約已成立；資料還沒送完就維持處理中，已完成也不要硬讓人看完整段動畫
- 不是每個元素都要位移：錯誤訊息已出現在欄位下方時，改邊框與文字可能就夠，不必讓輸入框彈跳
- **需求範本要點**（作者自編，非實測）：先讀送出與錯誤流程、說明四狀態如何切換 → 列**保留項**（送出邏輯、驗證規則、欄位內容、成功失敗判定；不加網路請求、不改後端）→ 每個狀態的要求（處理中維持按鈕寬度；錯誤保留已填內容）→ 設計方向（安定簡潔、避免大幅縮放與持續彈跳）→ **先說明每段動作的目的、時間、觸發條件再實作** → 支援手機與系統「減少動態」偏好 → 列出修改檔案與人工檢查步驟。若重複送出是流程本身造成，要先說明原因，**不能靠動畫掩蓋**
- **修稿換成具體要求**：「太晃」→「保留成功訊息，只移除旋轉，縮小變化幅度」；錯誤後整張表單跳動 →「保留原位置，提示放在對應欄位，錯誤文字出現時不推走送出按鈕」
- **減少動態偏好**：取消大幅滑入、視差、循環動作，保留簡單狀態變化；**減少動態不代表拿掉成功或錯誤資訊**（沒有動畫也要有可讀文字）
- **驗收要故意讓流程失敗**：處理時間拉長（沒提前顯示成功）／鍵盤操作（焦點可見）／發生錯誤（已填內容保留）／切手機寬度（不互相遮住）／開減少動態（結果資訊仍在）

### 3. 先比方向、再做、留可修改專案：Huashu-motion 與 Moritz 發布片

- **Huashu-motion**（花叔，開源 Skill，裝進 Claude Code 或 Codex）：先看產品 → 提出**三個方向、各一張實際渲染的關鍵影格**（字體、色彩、構圖先選定）→ 選定後寫場景節奏表 → **先做最難的鏡頭**（如介面縮放、產品拆解）→ 完成其他場景 → 成片留在可**按 C 點選畫面留言**修改的專案（留言帶時間點與場景資訊交給代理，「開頭標題太擠」變成有位置的任務）
  - 本機需求（官方列出）：Node 22+、Chrome 類瀏覽器、FFmpeg
  - 原作者公開紀錄裡有針對**音樂在片尾突然中斷**的修改——畫面輸出順利，聲音仍要單獨確認
  - 程式碼授權 ≠ 示範片裡的角色、品牌、音樂權利
- **Moritz Kremb 發布片**：原作者公開了初始需求，並回覆使用 **HyperFrames**（不必從影片外觀猜工具）。需求重點：選可辨識產品、用真實素材、呈現功能與好處。🔴 **介面圖是真的，操作仍可能被演錯**（一個按鈕直接跳到產品做不到的結果）——每個鏡頭都要有依據：

| 畫面 | 應提供的依據 |
|---|---|
| 使用前 | 觀眾遇到的具體問題 |
| 操作中 | 真實按鈕與正確步驟 |
| 使用後 | 可以驗證的結果 |
| 品牌收尾 | 正確 Logo 與下一步 |

- **兩份需求單的共同骨架**（aiposthub 依公開做法改寫，**非原作者逐字、未做成片實測**）：指定產品與資料來源（研究範圍可控）→ 觀眾看完只需記住**一項價值** → 產品功能只採用我提供的說明 → 外部素材附來源、不把示意介面當真實功能 → 先交場景表（每個鏡頭要證明哪件事）→ 文字完整出現後留閱讀時間 → 先給短段預覽 → 交付 **MP4＋可修改專案**（HyperFrames 專案或可點選留言的專案）
- **驗收**：找**沒看過產品的人**試看，請他說出「產品幫誰做了什麼」（熟悉產品的人會自己補中間步驟）；再核對介面文字與功能結果，這些對了才去微調動態速度。檢查可編輯性：改一個標題、一個數字、一段停留時間——**只能整支重做，就還沒發揮可編輯的價值**
- 公開素材被代理找到 ≠ 可自由重用：要記錄原始頁面與權利

### 4. Hairline（線條動畫技能）

工具本體（等角線條、跟著指標反應、`/hairline-create`、輸出單一 HTML、MIT）已收在 [[claude-codex-video-toolchain-selection]] 第 5 節，此處不重寫。本篇只補與本條主軸相關的兩點（作者觀點）：請助手先提**少量方向再選一款細化**，避免一次生成大量難以比較的版本；需求要寫用途、畫面比例、輸出形態（單一檔案／元件／可整合程式）與**不可改變的條件**（保留標題位置、不加文字、適合深色背景）。內建 27 種圖形是程式庫清單，不是生成能力的測試分數。

## 原始摘要

- **Motion Prompt 篇（40）**：144 個動效名稱庫的內容、三種用法、只由時間決定的規格設計、代理施工步驟、網路請求、MIT 授權與第一行保留、社群中文 PR 未合併、只涵蓋單一動作的限制；並更正分享貼文的 120／五包舊數字
- **LottieFiles 篇（30）**：以送出按鈕為例，Skill／動畫檔／Creator MCP 三層區分、四狀態表、官方時間參考、表單需求範本、修稿具體化、減少動態與故意失敗的驗收表
- **Moritz 篇（36）**：讓 Claude 選產品、找真實素材做 SaaS 發布片；原作者公開初始需求並回覆用 HyperFrames；真實素材也要搭配真實操作的鏡頭依據表、改寫需求單、陌生人試看驗收
- **Huashu-motion 篇（24）**：三方向關鍵影格、先驗最難鏡頭、按 C 點選留言修改、產品資料夾準備、需求單、聲音單獨驗收
- **Hairline 篇（18）**：工具本體已在 [[claude-codex-video-toolchain-selection]]；本條只取「少量方向再細化」「寫明輸出形態與不可改條件」
