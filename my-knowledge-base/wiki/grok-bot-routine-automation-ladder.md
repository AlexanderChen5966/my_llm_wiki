以《數位時代》的 Grok Bot Routine 教學（2026-09-18，主來源）為骨架，併入同站 Grok Bot 新手教學（2026-09-18 更新版）的「職務章程三要素」。雖然範例綁在 Grok Bot，但「先做對、再固化、最後排程」與「排程五要素」可以直接套用到 Claude Code／Cowork 排程任務、ChatGPT 排程等任何雲端排程 Agent。

## T（核心論點）

> 自動化要依「**職位 → 做對一次 → 固化 Skill → 排程**」的順序往上走，不能倒過來。排程只決定「何時跑」，不會讓 Bot 變聰明；第 1 步沒磨好，錯誤會每天準時出現。所以每個 Routine 都必須寫清**五要素**：何時跑（含時區）／資料從哪來／要交出什麼／哪些事要先問你／失敗或讀不到時怎麼辦。指令裡還要把「**失敗**」（要說明原因）和「**空結果**」（回「本次未找到」，不湊數）分開寫。

## B（適用場景）

**適用：**
- 任何雲端排程 Agent 的例行任務設定（Grok Bot Routine、Claude Code／Cowork 排程、ChatGPT 排程任務）
- 流程固定、每天內容不同的重複工作（新聞晨報、競品巡檢、稿單整理）
- 要讓 Agent 在無人看管下執行，因此必須先畫清權限紅線的情境

**不適用 / 注意：**
- 流程還沒手動跑順的任務：這時直接排程，只會把錯誤固定下來重複發生
- 本條目依據的是單一平台官方教學的媒體轉述，沒有實測數據；平台數值（上限、保留筆數）以官方文件現況為準
- 主來源「Bot／Skill／Routine 差異」小節底下原本應有一張比較表，但剪藏時遺失，本條目**不補寫**該表內容
- 新手教學原文把 CLAUDE.md／AGENTS.md 誤植為「Claude.me／Agent.me」（AI 初稿痕跡），本條目不照抄；該文的平台支援說法也前後不一（重點段寫初發「macOS 桌面版與 iOS」，第 1 步與 FAQ 才加上 Windows，沒寫 Windows 何時上線），細節見 [[grok-bot-cloud-agent-product-overview]] 的補充資料

## R（操作步驟）

### ① 階梯 0：先把 Bot 當「職位」寫職務章程（新手教學）

sairahul1 的說法是「提示詞是一次請託，Bot 是一個職位」。章程要寫清三件事：

| 要素 | 內容 |
|---|---|
| **職責範圍** | 負責哪一塊、每天或每週該產出什麼、成果放到哪裡 |
| **執行標準** | 格式、長度、語氣，以及你不要的東西（例：沒把握的數字標「待查證」，不要自己補） |
| **不能做的事** | 花錢、對外發送、碰到法律或合約字眼，一律停下來問 |

第三項最關鍵：「**什麼都要問的 Bot 太老實，什麼都不問的 Bot 太危險**」。

🔑 章程裡寫「每個工作日早上執行」**不等於已經建立排程**。要在指定時間自動開跑，還要另外建 Routine（銜接下方階梯 3）。

### ② 階梯 1–3：做對一次 → 存成 Skill → 建 Routine（Routine 教學）

1. **手動執行一次**：在負責的 Bot 對話直接貼任務，觀察三件事：來源是否為官方或主流媒體、有沒有混進過期資料、格式好不好讀。不滿意就在同一段對話補一句修正，再跑一次
2. **存成 Skill**：結果穩定後，請 Bot 把流程存成 Skill。官方建議 Skill 要寫到**能獨立執行**：需要哪些權限、怎麼驗證結果、哪些事要先問人（桌面版在輸入框打「/」叫出）
3. **建 Routine**：用對話或 Routines 面板設定；頻率可選每小時／每天／週一至五／每週／每月；觸發條件除了固定時間，也可以是事件（例如某個 Slack 頻道出現特定關鍵字）

### ③ 排程五要素與「失敗 vs 空結果」

| 要素 | 範例指令中的寫法 |
|---|---|
| 何時跑（含時區） | 每週一至週五台灣時間早上 8 點開始執行 |
| 資料從哪來 | 用「AI 新聞晨報」Skill 搜尋過去 24 小時 |
| 要交出什麼 | 整理成 5 則晨報，直接貼在這個對話裡 |
| 哪些事要先問你 | 不要寄信、不要發到 Slack |
| 失敗或讀不到時怎麼辦 | 見下方兩種情況分開寫 |

- **失敗**（搜尋失敗、來源讀不到）→ 說明原因，**不可**回覆「沒有新聞」
- **空結果**（搜尋成功但沒有合適的消息）→ 回覆「本次未找到符合條件的新聞」，**不湊數**

兩者如果混在一起，「沒東西」就分不出是真的沒有，還是其實壞掉了。

### ④ 運作邊界

- **時區**：取設定裡的 Timezone 欄位（預設跟著電腦），不是它讀取的網站或 Slack 的時區；建好後要核對下一次執行時間
- **假日**：「週一至五」不會避開台灣國定假日，需要時手動暫停
- **時間語意**：8 點是**開始**時間，不是完成時間
- **執行位置**：在 Bot 自己的雲端電腦上跑，筆電關機照跑
- **手機 App**：只能暫停／恢復排程
- **容量**：每個 Bot 最多 50 個 Routine；執行紀錄**只保留最近 20 次**，重要產出要在指令中指定另存（例如 Notion）
- **刪除**：刪 Routine 立即生效、不可復原；刪掉 Bot 會連帶刪除它所有的 Routine

### ⑤ 沒有執行時的六項排查

1. Routine 是否仍為啟用狀態
2. 排程時間與 Timezone 是否正確
3. 負責執行的 Bot 是否仍存在
4. 任務需要的 Plugin 是否仍保持登入
5. 雲端電腦能否正常存取資料來源
6. 帳號用量或存取權限是否遭暫停

也可以打開執行紀錄看最近一次失敗的原因。**改完設定先跑一次 Test run**，再等下一次正式排程。

## C（關鍵行動）

- [ ] 挑一個**已經手動跑順**的任務（沒跑順的先回到階梯 1）
- [ ] 寫出五要素，特別是「哪些事先問你」與「失敗時怎麼辦」
- [ ] 在指令中把「失敗」與「空結果」分開寫，並禁止湊數
- [ ] 核對 Timezone 與下一次執行時間，接著跑一次 Test run
- [ ] 觀察前 20 次執行紀錄（超過就被覆蓋），重要產出指定另存位置

## 原始摘要

- **主來源（Routine 教學，2026-09-18）**：以「平日早上 8 點自動 AI 新聞晨報」示範三步驟。依官方文件，Routine 的定義是「把一個工作流程指派給一個 Bot，並告訴它何時執行」。文章的核心提醒是「Routine 解決的是『這件事我不想每天重新交代』，它不會讓 Bot 變聰明，只是把你已經確認做得對的事固定下來重複做」。內容包括五要素、時區／假日／開始時間三個常見誤解、50／20 的容量限制、刪除不可復原，以及六項排查清單。
- **併入部分（新手教學，2026-09-18 更新版，原文首發約 2026-08）**：只取第 4 步「職務章程與權限界線」。三要素加上「太老實 vs 太危險」，以及「章程寫了每工作日執行，不等於已建排程」的提醒，後者也是兩篇文章互相引用的交會點。該文的定價、平台支援與幕僚長模式屬於產品層與多 Bot 編制，歸 [[grok-bot-cloud-agent-product-overview]]，不放在這裡。
