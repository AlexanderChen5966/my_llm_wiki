## T（核心論點）

Devin 可以在**雲端 macOS VM** 裡用 Xcode 建置、透過 Computer Use 操作 **iOS Simulator**，走過折疊 App 的展開／半折／關閉狀態切換並錄影交付。但這是**模擬器證據**：沒有 USB 實機、VM 效能不代表實機、錄影經過剪輯——影片能證明「這段介面流程被操作過」，**不能當實機測試、不能當耗時紀錄、也不能取代測試套件與 CI**。真正讓代理產出可用證據的，是把測試寫成「**起點 → 切換動作 → 應保留的結果**」。

## B（適用場景）

**適用：**
- 需要反覆重現介面狀態切換流程（折疊、前後景、輸入中切換）的行動 App 團隊
- 想用影片＋測試紀錄改善代理交接品質，再決定是否擴大自動化

**不適用 / 注意：**
- 🔴 **無 USB 連實體裝置**：不能把這份證據寫成實機測試；耗電、溫度、動畫效能要另接實機驗證
- 🔴 **錄影經剪輯**（加提示、縮短閒置、調整節奏）：**不能用片長算執行耗時**；要量效率另記開始／結束時間與人工介入
- 影片處理可能因程式崩潰或逾時失敗；要求保留原始執行結果
- 工作階段睡眠會保存磁碟，但**執行中程式不延續**（模擬器、開發服務需重啟），隔天接續先確認環境再錄影
- 部分組織需窗口開通 macOS VM；示範的模擬裝置名稱未必在每個工作階段都有
- TestFlight 上傳有文件但需帳戶、簽署與 App Store Connect 設定；**上傳 ≠ 上架**

## R（操作步驟）

1. **確認環境**：帳戶／組織是否已開 macOS VM；記錄 Xcode、Simulator 實際版本（官方 VM 預裝 Xcode、iOS Simulator、Homebrew）；把啟動方式寫進專案環境設定，重開工作階段可重用
2. **寫測試案例**（以使用者正在做的工作出發，而非只按螢幕尺寸分類）：

| 項目 | 寫進任務的內容 |
| --- | --- |
| 起始環境 | 指定程式版本與可用模擬器 |
| 使用者工作 | 例：填寫尚未送出的表單／相機倒數中 |
| 切換動作 | 例：輸入後展開，再折回較小畫面 |
| 預期結果 | 已輸入內容保留、按鈕可用（行為由產品先定義，代理不替團隊決定） |
| 交付證據 | 操作影片、測試結果、失敗步驟 |

3. **先交一條主流程**，確認建置／啟動／錄影都能跑，再補關鍵分支（倒數中關閉、輸入中切換、回到前景）；交代不應改動的範圍
4. **影片對到同一份程式版本**：影片說明留測試版本、裝置狀態、主要步驟、切換發生位置（倒數前關閉 vs 倒數中關閉是不同案例）；之後再改就依影響範圍決定是否重跑
5. **畫面成功之外核對資料**：表單重開後資料是否存在、照片是否真的保存；搭配測試紀錄或結果檔
6. **失敗回報**：從哪一步開始、預期什麼、實際發生什麼；錄影失敗與 App 當掉分開處理
7. 完整覆蓋仍走既有測試套件＋CI；涉及硬體與效能的判斷接實機驗證

## C（關鍵行動）

- [ ] 交辦代理做模擬器測試時，每個案例都寫「起點／切換動作／應保留結果」
- [ ] 審查影片時確認對應的程式版本；不拿片長估耗時
- [ ] 交付文件中明標「模擬器證據」，實機與效能另列待驗項目
