作者用 Claude Code + GitHub 建立「個人使用說明書」持續三個月後的最大發現：**最有效的不是 Skills/MCP 等自動化工具，而是「為了交給 AI 而被迫把自己寫成文字」的過程本身**。五軸時態分類法解決了 AI 諮詢時「初次見面問題」，設計原則是依目的分離靜態與動態資訊。

## T（核心論點）

**人生管理的瓶頸不是 AI 不夠強，而是輸入端的「自己」太模糊。** 向 AI 諮詢職涯或決策，每次都得從頭解釋「我是誰」，不是因為 AI 記憶力差，而是因為多數人的價值觀、目標、習慣從未被真正語言化。把自己寫成機器可讀的使用說明書，最大的收穫不是自動化，而是**自我理解的副產品**。

## B（適用場景）

- 想讓 AI 諮詢更深入（不只是每次從頭解釋「我是誰」）
- 一再立目標又忘記的人
- 想把 Claude Code Skills + MCP 應用在個人生活管理的工程師

## R（完整內容）

### 五軸時態分類法

用**時態**而非主題來分類，解決 AI 讀取時「不知道該重點看哪裡」的問題：

| 軸 | 目錄 | 內容 | 時態 |
|---|------|------|------|
| 1 | `00_self` | 自己這個人（價值觀、性格、健康、金錢、經歷）| 靜態 |
| 2 | `01_direction` | 前進方向（人生目標、年度目標、里程碑）| 未來 |
| 3 | `02_work` | 進行中的工作 | 進行中 |
| 4 | `03_journal` | 日常紀錄與回顧 | 過去〜現在 |
| 5 | `04_knowledge` | 從外部吸收的知識（書籍、思想）| 累積 |

**設計原則：**
- AI 做**諮詢**時讀：靜態的 self + direction
- AI 做**回顧**時讀：時間序列的 journal
- 混在一起 → AI 不知道該重點看哪裡

### 運作規則（CLAUDE.md）

把操作規則寫在單一 `CLAUDE.md`，AI 每次都讀：
- 「金錢或健康等敏感資訊不要擅自修改」
- 「新目標要先從年度目標開始做」
- 人類很難一直守約，但規則明文化後 AI 會忠實照做

### 自製 Skills（生活斜線命令）

```bash
/life-advice  # 讀入所有 MD，依脈絡給建議
/new-task     # 以年度目標為起點開出新 Issue
/monthly-review  # 回顧當月紀錄，整理結果
/daily-sync   # 每天零散紀錄，每月反映到各分類
```

最有感的是 `/monthly-review`：把「月底回顧目標」這件人類最不擅長的事，做到半自動運轉。

### MCP 整合

透過 MCP 把行事曆和任務管理工具連到 Claude：
- 一個對話介面整合多個 App 的資訊
- 「看一下下週行程，對照目標，提議空檔利用方式」

### 三個核心洞察

**1. 言語化的強迫力（最重要）**  
以為「自由最重要」，但真要寫的時候卡住了：「自由，是從什麼的自由？」這個卡住就是自我理解。**為了交給 AI 而寫，最後卻被最原始的書寫拯救了。**

**2. 目標由人掌握，AI 負責實行**  
不能把「人生該怎麼活」也丟給 AI——否則表面上是在最佳化自己的人生，實際上卻被最佳化成「某個人的平均值」。讀地圖可以交給 AI，但要去哪裡還是得自己決定。

**3. 自己是最難破解的遊戲**  
只有把價值觀、習慣、判斷基準這些「規格」寫出來，才算真正能把自己當成一個可攻略的對象。

### 四階段入門路徑

| 等級 | 行動 | 所需時間 |
|------|------|---------|
| Lv1 | 備忘錄寫下「價值觀/今年想做的事/最近煩惱」，直接貼給 AI | 今天 5 分鐘 |
| Lv2 | 把檔案分成「自己・目標・記錄」三類 | 週末 1 小時 |
| Lv3 | 放上 Git，用 diff 比較半年前的自己 | 週末半天 |
| Lv4 | Claude Code Skills + MCP 自動化 | 幾天 |

**最可惜的：一開始就衝 Lv4 然後挫折。** Lv1 本身就已經很有效。
