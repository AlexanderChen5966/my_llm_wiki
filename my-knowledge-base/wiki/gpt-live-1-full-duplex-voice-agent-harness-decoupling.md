## T（核心論點）

> **語音 Agent 的關鍵設計不是找一個模型同時扛語音生成與複雜推理，而是把兩者解耦：
> 前端用便宜快速的語音層維持「邊聽邊說」的自然節奏，後端才按需委派給更強（更貴、更慢）的推理模型。**

GPT-Live-1 於 2026-09-10 正式開放 API（先前僅存在於 ChatGPT 內部消費端）。核心技術是原生
**全雙工（Full-Duplex）**：模型推送音訊輸出的同時，麥克風收音神經網路仍持續活躍，不需等待
播放完畢就能感知使用者的插話與停頓，端到端延遲壓到 **150～250 毫秒**。

🔑 **模型太小則笨、模型太大則貴且延遲高**的兩難，OpenAI 的解法是 **Agent Harness 解耦架構**：
GPT-Live-1 專職前端語音互動，複雜推理與工具調用委派給後端自選模型（GPT-6 Astra、GPT-5.5，
或企業自建框架）。

## B（適用場景）

**適用：**
- 建置電話客服、語言教學 Agent、車載助理等需要「自然打斷、邊聽邊說」的即時語音場景
- 已有一套文字 Agent／Tool 生態，想加一層語音介面而不重寫後端推理邏輯
- 評估語音 AI 導入的成本效益（本篇附完整成本試算模型）

**不適用 / 注意：**
- 這是新發布產品的官方/媒體深度解析，非獨立第三方長期評測，落地案例（Speak/Yelp/Hatch）數據
  來自官方揭露，導入前建議自行小規模驗證
- ⚠️ 語音專用 System Prompt 與文字 Chat Completion 的提示詞寫法不同（見下方），直接沿用文字
  Prompt 效果會打折扣

## R（架構與工程細節）

### 1. 三代語音架構對比

| 評估維度 | 第一代：拼裝管線 Cascade | 第二代：GPT-4o Realtime | 第三代：GPT-Live-1 解耦全雙工 |
| --- | --- | --- | --- |
| 底層架構 | Whisper(STT) + LLM + TTS | 單一端到端模型 | 前端語音層 + 後端自選 Harness |
| 端到端延遲 | 1,500～3,000ms | 300～600ms | **150～250ms** |
| 雙工模式 | 半雙工（對講機式） | 偽全雙工（依賴外部 VAD） | **原生全雙工** |
| 思考停頓容忍 | 極差 | 普通 | **極佳**（Speak 實測打斷率降 80%） |
| 口語反饋 Backchannel | 不支援 | 支援有限 | **原生支援** |
| 複雜業務推理 | 依賴單次 Prompt | 單一模型難兼顧 | **解耦委派後端專門處理** |

### 2. Agent Harness 是什麼

「Harness（執行框架）」指包覆模型外部的系統工程基礎設施：管理對話狀態機、維護 Session
上下文、攔截即時事件、協調 Tool Calling、在多個專業模型間動態路由。GPT-Live-1 的解耦帶來
兩個優勢：① 後端思考時前端可用口語安撫填補等待，消除「恐怖沉默死寂」；② 開發者可讓便宜的
GPT-Live-1 全程監聽，只在真正需要深度推理時才按 Token 呼叫更貴模型。

### 3. 智慧停頓容忍：Speak 實測打斷率降 80%

語言學習場景中，外語學習者開口思考常需 0.5～1.5 秒；傳統 VAD 會立刻判定「沉默＝發言結束」
而搶話。GPT-Live-1 透過聲調起伏、尾音未完成狀態與上下文語義判斷「話講完」與「只是在思考」，
Speak 導入後非預期打斷率降低近 80%。

### 4. 成本試算：每分鐘 0.05 美元

前端語音層定價 $0.05/分鐘（約 NT$1.6）。企業客服試算（每通 4 分鐘、含 2 次資料查詢）：
語音層 NT$6.40 + 後端推理 NT$0.96 + VoIP NT$1.92 ＝ **單通約 NT$9.28**，對比美國真人客服
NT$140～250、台灣在地客服 NT$45～75，成本降幅約 80～90%。

### 5. 開發者實戰三要點

- **語音專用 System Prompt**：避免 Markdown／條列符號，明確要求口語化短句與等待時的即時填詞
  （例：查詢時先說「讓我看一下後台庫存喔」）
- **調控 Silence Timeout**：快速應答場景（點餐/地址確認）設短（400ms）；深度諮詢/語言教學
  場景放寬（1000～1500ms）
- **狀態機需監聽兩個關鍵事件**：`session.interrupted`（使用者插話時立即淡出並清空音訊緩衝，
  避免回音／雙重聲音）、`task.delegated`（後端推理超過 2.5 秒未回應時，觸發第二段安撫句）

### 6. 落地案例

- **Speak**：語言學習，非預期打斷率降近 80%
- **Yelp Host**：嘈雜餐廳訂位電話，全雙工記憶鏈能處理顧客隨時推翻上一句（四人改三人、
  六點改六點半）而不需機械式重複確認
- **Hatch**：居家維修派工，2 分鐘內完成報價與預約，帶來 35%+ 業務增長

## C（關鍵行動）

- [ ] 若正在設計語音 Agent，優先評估「前端語音層＋後端推理委派」架構，而非用單一端到端模型硬扛所有工作
- [ ] 語音 System Prompt 另外撰寫，移除 Markdown／條列符號，加入等待時的口語填詞指引
- [ ] 依場景差異化設定 Silence Timeout（快速應答 vs 深度諮詢）
- [ ] 實作狀態機時務必處理 `session.interrupted` 的音訊淡出與緩衝清空，避免回音
- [ ] 若評估導入客服/語音場景，用本篇成本試算模型（分鐘計價+後端 Token+VoIP）先估算 ROI

## 原始摘要

OpenAI 於 2026-09-10 將 GPT-Live-1 全雙工語音模型開放 API，取代傳統 STT+LLM+TTS 半雙工架構
（延遲 1.5-3 秒）。核心創新為「前端極速語音層＋後端 Agent Harness 思考委派」解耦架構，
前端定價每分鐘 0.05 美元，Speak 實測非預期打斷率降低近 80%，Yelp、Hatch 已落地應用於嘈雜
餐廳訂位與居家維修派工場景。文中提供三代語音架構完整對比表、企業客服成本精算，以及語音
System Prompt 撰寫、Silence Timeout 調控與 Event Loop 狀態機設計的開發者實戰建議。
