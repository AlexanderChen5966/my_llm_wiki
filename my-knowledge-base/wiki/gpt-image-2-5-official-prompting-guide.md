## T（核心論點）

> **GPT Image 2.5 的提示詞效果好壞，取決於「資訊密度是否對應需求複雜度」，而非篇幅長短。**
> 修圖類提示詞的核心方法論可濃縮成一句話：**Change X, Preserve Y**——同時明確說出「要改什麼」
> 與「必須保留什麼」，否則模型可能連沒被要求的部分（臉孔、姿勢、背景、構圖）一起重新生成。

生圖類提示詞的核心是**先定義最終成品類型**，再依需求複雜度拆成場景/主體/風格/文字/限制；
簡單修改（如「移除手中的花，其他不要動」）反而不需要冗長描述——**需求越具體，AI 越知道
哪裡可以發揮；限制越清楚，也越不會在沒被要求的地方自行加工。**

## B（適用場景）

**適用：**
- 需要精準控制修圖範圍（換衣服、去背、局部替換）而不希望人物/背景/構圖被連帶改動
- 多張參考圖片合成，需要讓 AI 正確理解每張圖各自的用途（人物/服裝/背景/風格參考）
- 需要穩定生成同一角色的連續插畫、廣告看板多輪迭代等「多輪編輯」場景
- API 端需要理解 Flare/Sunburst 兩模型定位與品質/解析度參數選型

**不適用 / 注意：**
- ⚠️ **「跟上一張一樣」不夠可靠**：多輪編輯中即使已說過「same character」，重要特徵（服裝顏色、
  五官比例、配色）仍建議在後續每一輪重新明確寫出，否則容易隨編輯次數偏移
- 🔴 **透明背景≠棋盤格圖案**：棋盤格只是軟體顯示透明區域的預覽方式，若要求 AI 在畫面中「加入
  棋盤格」會產生錯誤結果，正確做法是要求輸出 Alpha 透明通道
- 本條目是提示詞寫作方法論骨架，不是逐條照抄即可用的完整範例庫——完整 130 組範例查
  [[chatgpt-image-prompts-130]]，模型世代差異查 [[chatgpt-images-2-5-sketch-and-api-models]]

## R（八大原則與 Change/Preserve 結構）

### 1. 八大原則（bnext-92209 版本命名）

1. **先定義最終成品類型**：與其說「畫一張圖」，明確指出商品照片/廣告/流程圖/簡報；需求複雜時
   拆成場景/主體/細節/限制區塊
2. **格式沒有標準答案**：短句、段落、類 JSON、標籤式寫法皆可，重點是資訊是否容易閱讀與修改
3. **描述真正看得見的細節**：與其寫「電影感」，不如具體指定材質/光線/顏色/畫面媒介（例：
   photorealistic、35mm 底片質感、霓虹燈光源），相機焦段/鏡頭參數也可加入輔助模型理解「視覺效果」
4. **人物動作要具體**：拆成景別/身體姿勢/視線方向/手部動作/與周圍物件的互動，比「自然一點」
   更容易得到預期結果
5. **需要正確文字就用引號指定**：把必須出現的文字放進引號，描述位置/字體/排版，並可要求
   「只出現一次」「不要有其他文字」
6. **修改內容和保留內容分開寫**（即 Change/Preserve，見下）
7. **多張參考圖片要分配角色**：圖片 1 提供人物、圖片 2 提供服裝、圖片 3 提供背景，避免一次
   丟大量圖片任由 AI 自行揣測用途
8. **一次改一件事**：先看上一張生成結果，再針對一項條件修改；重要特徵即使先前說過，後續編輯
   仍應再次強調

### 2. Change X, Preserve Y（wingzero-4060 版本命名法）

同一件事的另一種組織方式——修改既有圖片時同時說清楚「什麼要改」與「什麼不能改」：

> 「只更換人物服裝，保持人物身份、臉部特徵、身體比例、姿勢、表情、髮型、背景、攝影角度與
> 構圖不變。」

比只寫「把衣服換成黑色洋裝」精確得多，能充分利用 Precision Editing 與 Subject Preservation
能力。官方換衣服範例的完整保留清單：**臉部、五官、膚色、身形、姿勢、表情、髮型、身體比例**
皆需逐一列出，即使已說「same character」仍建議重要特徵再寫一次。

### 3. 生成型 vs 修改型的萬用結構

**生成型**：
```
製作一張【成品類型】。
主體：【人物／商品／物件】
場景與構圖：【位置、動作、鏡位、畫面安排】
風格：【媒介、光線、材質、色彩、攝影或插畫風格】
文字：「【必須完整呈現的文字】」
限制：
・不要【不需要的內容】
・必須保留【重要條件】
```

**修改型**：
```
只修改：【真正要改的東西】
保留：【人物身份／五官／姿勢／構圖／背景／光線／商品形狀】
不要：【AI 可能自行增加或修改的內容】
```

wingzero-4060 版本另給出更細的階段拆法：**Scene（場景）→ Subject（主體）→ Details（細節）
→ Constraints（限制）**，適合複雜圖片；濃縮到一句可記成
**目標→場景→主體→構圖→動作→視覺風格→參考圖片用途→修改內容→必須保持的元素→禁止事項**。

### 4. 多參考圖片標示語法

不要只寫「參考這些圖片」，明確標示每張圖的角色：

```
Image 1：人物身份參考
Image 2：服裝參考
Image 3：攝影風格參考
Image 4：背景參考
```

再說明如何組合（例：把 Image 2 的狗放到 Image 1 的女性旁邊，同時保持 Image 1 原本的背景/
構圖/光線）。

### 5. Sketch → 寫實三技巧

草圖轉寫實照片時，把「轉換風格」與「保留結構」分開寫：**完整保留原本的畫面配置、比例與
透視關係**；根據草圖原意選擇合理材質與光線；不加入新元素或文字。否則 AI 可能把草圖當靈感
來源重新設計整個場景，而非單純寫實化。

### 6. 簡單修改不必寫長，複雜修改才需要結構化

- 刪除單一物件：「移除男子手中的花，不要修改其他任何內容」即可
- 換衣服/募資簡報/賀卡這類需要精確控制的複雜任務，才需要完整列出限制與保留清單
- 判準是**需求的資訊密度**，不是刻意堆疊形容詞看起來很會下 Prompt

### 7. 多輪編輯：一次只改一件事

流程：**生成 → 查看結果 → 修改一件事情 → 再查看 → 繼續修改**，而非每次重新產生整張圖或
一次要求改十幾個地方。範例：第一輪做黃昏公路廣告看板 → 第二輪只說「把場景改成下雪的冬季
夜晚」（不重新描述整張看板）。好處是若結果走鐘，容易定位是哪個新指令造成的。

### 8. API 品質與解析度參數（wingzero-4060 補充，bnext-92209 未涵蓋）

品質設定：`auto` / `low` / `medium` / `high` / `xhigh` / `max`；輸出尺寸除常見
1024×1024/1536×1024/1024×1536 外，支援更高解析度（2048×2048、2048×1152、3840×2160、
2160×3840）。官方建議先測試較低品質是否已符合需求，而非一律使用最高品質，藉此降低生成
時間與成本——與 [[chatgpt-images-2-5-sketch-and-api-models]] 記載的 Flare（速度優先）/
Sunburst（品質優先）模型分工原則一致。

## C（關鍵行動）

- [ ] 修圖類任務一律用 Change/Preserve 結構下指令，不要只描述要改的部分
- [ ] 多張參考圖片時，明確標示每張圖的角色（人物/服裝/背景/風格），不要只說「參考這些圖片」
- [ ] 多輪編輯時每次只改一個條件，重要特徵（服裝顏色/五官比例）在每一輪都重新明確寫出
- [ ] 透明背景需求要求輸出 Alpha 通道，不要要求「加入棋盤格」
- [ ] API 選型先從較低品質/Flare 測試，確認效果不足再升到 xhigh/Sunburst，降低生成成本
- [ ] 簡單修改（移除單一物件）保持指令簡短，不要為了看起來專業硬堆形容詞
