2026-08-25～26 三則官方公告合併整理。三者其實回答同一個問題：**Cowork 從「每次交辦都是一張白紙」變成有記憶、能操作網頁、能自己按時跑的執行環境。**

## T（核心論點）

三項更新各自的關鍵取捨，都不在功能本身，而在**邊界**：

| 更新 | 功能 | 🔴 真正該先知道的邊界 |
|---|---|---|
| 記憶互通 | Chat 與 Cowork 共用同一套記憶 | **只適用雲端執行的 Cowork 任務；本機 session 不使用這套記憶** ⚠️ |
| 內建瀏覽器 | Claude 用專屬瀏覽器導航、點擊、輸入 | Prompt Injection 風險**降低但未消除**，官方建議初期僅用於受信任網站 |
| 排程任務 | 遠端按時執行，電腦關機照跑 | **一旦任務需要本機檔案，它就只在本機執行**——「電腦關著也會跑」隨即失效 |

> ⚠️ 2026-10-08 更新：10/6 起 Pro／Max 新任務一律雲端執行，「需要本機檔案就只在本機跑」這個**機制**已經改成 Desktop 橋接、要用時才複製單檔上雲；但 Desktop 關閉就碰不到本機檔案，所以「要遠端常駐就別依賴本機檔案」這個**取捨仍然成立**。已在本機執行的舊排程留在原電腦完成。見 [[claude-cowork-merged-into-chat-2026-09]] 補充段。

## B（適用場景）

**適用：** 評估要不要把例行工作交給 Cowork 排程；判斷記憶功能對跨 session 交辦的實際幫助；需要操作沒有 API 的內部系統或供應商後台。

**不適用 / 注意：**
- ⚠️ 三項都是**付費方案**功能，且 Team／Enterprise 另有管理員開關。
- ⚠️ 內建瀏覽器只存在於**桌面應用程式**；網頁與手機版沒有直接搭載（但桌面版保持開啟並連線時可遠端下指令）。

## R（三項更新的實際內容）

> ⚠️ **2026-09-16 已改版**：Cowork 獨立分頁已併入一般對話 Chat（詳見 [[claude-cowork-merged-into-chat-2026-09]]），
> 本節「記憶互通」原本區分「雲端執行的 Cowork 任務」與「本機 session」的前提，是建立在 Cowork 為獨立可指定的
> 執行環境之上；新架構下由 Claude 自行判斷該用哪種能力，這套雲端/本機的觸發區分需要重新確認是否仍成立，
> 排程任務與內建瀏覽器的入口位置也可能一併受影響。
>
> ⚠️ 2026-10-08：新任務全部上雲後，「雲端任務／本機 session」這個區分對新任務已經不適用；舊的本機任務是否使用共用記憶，來源沒有說明。

### 一、記憶互通（8/25）

- **打通**：聊天裡累積數月的專案脈絡（本季優先順序、各專案進度），交辦給 Cowork 的那一刻就已經在了；Cowork 執行過程產生的資訊也會**回流到聊天**
- **寫入時機改變**：從「對話結束後做摘要」改成**對話進行中即時累積**（提到專案期限改到九月，下一次對話就已經知道，不需要特別說「記住這件事」）
- 🔑 **記憶不是黑盒子**：所有內容以「主題」（Topics）為單位列在設定裡，**每一則都是一個檔案，可以打開讀、直接改、或刪掉**。官方說這些檔案都很短，而且**改一次全面生效**（例如把公司舊名稱在檔案裡更正，之後每次對話都用新的）
- **隱私**：健康、種族、族裔、宗教、政治立場、性別認同等敏感主題**預設不寫入**。若開啟「將敏感主題納入記憶」，有三個限制：每次存下都會通知／**只從開啟那刻往後記、不回溯補存**／隨時可關
- 🔴 **即使開啟也絕不儲存**：敏感識別碼（社會安全碼、政府核發身分證號）、犯罪紀錄、移民身分，以及任何違反使用政策的內容——遇到這些 Claude 會主動告知無法寫入
- **開放範圍**：Free／Pro／Max 的網頁、桌面、行動版預設開啟；敏感主題儲存預設關閉；Team／Enterprise 由管理員決定

### 二、內建瀏覽器（8/26）

- **獨立運行**：與日常瀏覽器完全獨立，**無法讀取你的分頁、書籤或密碼**
- **逐站轉移登入狀態**：macOS 可從 Chrome／Edge／Firefox 轉移；**Windows 與 Linux 僅支援自 Firefox 匯入**
- 🔴 **預設排除銀行、電子郵件及 SSO 等敏感網站**，除非使用者主動設定授權
- **典型場景**：為報告蒐集研究資料、登入供應商後台下載當月發票、**操作尚未具備 API 串接功能的內部系統**
- 🔑 **與 Claude in Chrome 的分工**：內建瀏覽器適合把**整個網頁任務「外包」**（AI 背景執行，使用者去做別的事）；Claude in Chrome 專注處理**當前開啟的網頁**，利用你已登入的帳號協助更新 CRM、清理收件匣、修改文件。已安裝外掛者維持以 Claude in Chrome 為預設，可在 `Settings → Cowork → Preferred browser` 切換
- **Prompt Injection**：沿用 Claude in Chrome 的安全標準，透過**交叉比對「Claude 的實際動作」與「使用者的原始指令」**進行審查。官方坦言可大幅降低但無法完全杜絕
- 支援 macOS／Windows／Linux（Linux 標為 Beta）

### 三、排程任務（Scheduled tasks）

**與每天自己貼一次 prompt 的差別**不是省下貼上那幾秒，而是任務的**存在形式**變了：貼的 prompt 是一次性對話，講完就沒了；排程任務是 Claude 把 prompt 存成任務指令按頻率反覆執行。每次執行是**獨立的 Cowork session**，能力與一般任務完全相同（含連接器、技能、已安裝外掛）。

**建立方式二選一**：
- `Scheduled → New task → Create with Claude`：Claude 用選擇題問你，湊齊資訊後列出預計的任務名稱／頻率／要做的事再確認（適合還不確定自己要什麼的人）
- `Set up manually`：六個欄位——任務名稱、提示詞、**核可模式**、執行頻率、選填的模型與**工作資料夾**。頻率五選項：每小時／每天／每週／僅平日／手動

**五種官方典型用法**（共通點都是「輸入來源固定、輸出格式固定」）：每日簡報（摘要過去 24 小時 Slack／郵件／行事曆）、每週報告、定期研究（追蹤主題／競爭對手／產業新聞）、檔案整理、團隊更新（從專案管理工具產生站立會議摘要）。

🔴 **最容易讀漏的一段**——主說明寫「排程任務搭配你的連接器與存放在 Claude 帳號裡的檔案運作，**不能綁定你電腦上的資料夾**」；但手動設定的「工作資料夾」欄位底下註明「**若排程任務需要本機檔案或應用程式，它就只會在本機執行**」。兩句合起來：

> 🔑 **一旦你把本機檔案拉進任務，「電腦關著也會跑」這個最大賣點就不成立了。要保住遠端常駐，資料得先搬進 Claude 帳號或走連接器——這是設定前的取捨，不是跑失敗才回頭發現。**
>
> 「排程任務真正要你決定的不是跑幾點，而是**這件事的資料放在哪裡**。」

**前提**：限 Pro／Max／Team／Enterprise 四種付費方案；Cowork 本身在桌面版供付費方案使用，網頁與手機版對 Pro／Max／Team 仍是 beta，Enterprise 需擁有者啟用。

## C（關鍵行動）

- [ ] 建排程任務前先決定**資料放哪裡**——要遠端常駐就不能碰本機檔案
- [ ] 挑第一個排程任務時選「每週至少重複三次、輸出格式固定」的工作；**含糊的任務換來含糊的日報**
- [ ] 指令裡明確寫「找不到內容的區塊寫『無』，不要略過」這類格式約束
- [ ] 打算依賴記憶互通前，確認任務是**雲端執行**（本機 session 不吃這套記憶）
- [ ] 去記憶設定把 Topics 逐則看一遍——它們是短檔案，可讀可改可刪
- [ ] 內建瀏覽器初期只在受信任網站使用；不要為了方便去授權銀行／郵件／SSO
