一位工程師為 AI 代理人建立團隊共享外部記憶層的實驗報告。難得之處在於**它花了同等篇幅講「這個原型絕對沒證明什麼」**，並在過程中推翻了自己最初的成本假設。

## T（核心論點）

大多數 AI 記憶實作都是同一種模式的變體：存起來、取回、注入提示詞，然後把結果稱作記憶。

> 「這其實和在公寓裡到處貼便利貼，然後決定『公寓現在會記得事情』沒有太大差別。」

🔑 **記憶根本不該屬於模型本身，而應該屬於模型周圍的系統。**

> 模型應該可以在明天消失，但歷史仍然保留。Claude 今天寫下的內容，GPT 明天應該能讀；本地模型下週應該能質疑它。

而做得越久，作者越懷疑真正有趣的問題不是記憶本身，**而是「遺忘的經濟學」**。

## B（適用場景）

**適用：** 設計跨 session／跨工具／跨模型的記憶層；判斷一條資訊該進 RAG 還是進記憶；為記憶層設計信任與過時機制；重新設計「記憶有沒有用」的評估指標。

**不適用 / 注意：**
- 🔴 **作者明確聲明：可運作 ≠ 有用。**「一個可運作的記憶 API，只能證明代理人可以取回先前狀態。真正重要的主張是：因為有了那個狀態，代理人是否能做出更好的工作。」
- 🔴 **記憶層可能變成一台高效率地把昨天的錯誤灌進今天會話的機器**——這與 [[memharness-memory-reconstruction]] 的實測結論（加記憶反而變差）獨立地指向同一件事。
- ⚠️ 原型的檢索仍然「刻意做得很原始」（讓模型依索引描述自行決定取什麼），作者自認**檢索的精確率與召回率必須成為評估的一部分**，目前尚未做到。
- ⚠️ 最關鍵的失敗模式**需要時間才會出現**（矛盾累積、兩個代理人描述不同、錯誤假設撐久到讓五條後續記憶依賴它），而「沒有一個可信的 benchmark 開關叫做 `--simulate-six-months-of-organizational-chaos`」。

## R（操作步驟）

### 一、RAG 與記憶的分野

| | RAG | 記憶 |
|---|---|---|
| 取回什麼 | **已經存在某處**的資訊：文件、程式碼、工單、政策、資料庫紀錄 | **由流程本身產生**的資訊 |
| 具體內容 | — | 為什麼選 A 不選 B、為什麼 C 失敗、為什麼要容忍 D、E 之後改變了什麼、哪個假設只是暫時的、團隊犯錯後學到什麼 |

🔑 **「模型懂的程式語言比我這輩子都學不完，它不知道的是我上週二在專案裡到底發生了什麼。」** 這些資訊不可能合理地存在於模型權重裡——它不是通用知識，是**工作過程中產生的狀態**。

> 很多時候，它們正是**本該變成文件、卻從來沒有變成文件**的資訊。於是新的 AI 會話必須靠從頭重新發現這些缺失的歷史來付出代價。

### 二、架構：邊界比管線重要

實作刻意做得很無聊——團隊共用的小型 HTTP 記憶中心，記憶是**帶結構化中繼資料的純 Markdown 檔**，分一般知識與專案特定知識，每個會話透過自己的 MCP 伺服器存取。工具介面極小：列出有哪些、抓取相關的、寫入新的。

> **重點不在 MCP 的管線，而在邊界：模型不是記憶庫，客戶端不是記憶庫，MCP 伺服器也不是記憶庫。記憶獨立存在於它們之外。**

🔑 **記憶檢索經濟：索引很便宜，細節會吃上下文。**
- 會話開始時只給一個小型索引，讓它知道有哪些記憶可用
- **完整內容只有在代理人明確要求時才進入上下文**

反例：把整個公司的歷史直接吼進每一次提示詞裡——

> **「那不是記憶，那是包裝精美的上下文污染。」**

⚠️ 但這背後藏著一個醜陋的假設：**代理人必須抓到正確的記憶。** 一個存在但從未被取用的記憶，功能上等同於被遺忘；而抓進不相關的記憶，只是多了幾步的上下文污染。

### 三、🔴 沒有來源的記憶，只是拿退休金的幻覺

一旦代理人可以寫入持久化記憶，下一個問題立刻出現：**為什麼下一個代理人要相信前一個代理人寫的內容？**

想像一條記憶寫著「這個元件一定要用 Redis」。那是團隊明確的決策、根據當前程式碼推論的結果、暫時的權宜之計，還是某個自信但錯誤的結論剛好撐過了那一輪會話？

> 🔴 **沒有來源的持久化記憶非常危險，因為錯誤資訊不會隨著對話消失。它會在你的基礎設施裡退休，並在無限未來中持續誤導後續代理人。**

解法是**信任分級**：

| 狀態 | 實際語義 | 證據力 |
|---|---|---|
| 未審核 | 「Agent X 在時間 Y 說這件事是真的」 | 弱——要影響重要決策，應先拿程式碼、規劃或使用者資訊檢查 |
| 已審核 | 人類確認過的權威 | 強 |

🔑 **記憶是一份報告，而不是一條指令。**
🔑 **AI 修改已審核記憶，審核狀態就消失**——「模型不能在不發出任何聲響的情況下改寫已核准的歷史，還繼續保有核准徽章。」

而審核機制本身有個明顯陷阱：**如果每條記憶都需要人類核准，那只是把文件瓶頸換到另一層**，完全破壞了寫入端經濟學。所以：

> 🔑 **審核不能是寫入路徑，必須是一種升級機制。** 代理人應能以低信任成本廉價地建立記憶；只有其中較少、真正成為穩定專案指引的那一部分，才消耗人類審核。
> **人類負責整理權威，而不是手動撰寫歷史痕跡。**

### 四、過時：年齡影響信心，不影響存在

大多數 AI 記憶示範看起來很棒，因為它們只持續十五分鐘。同一套系統放著跑六個月，**一條記憶可以完美地被取回，卻同時已經完全是錯的**。

作法：追蹤記憶年齡、把老舊記憶標成過時、若記憶在描述程式碼則明確提醒代理人與目前實作比對。**但刻意不自動刪除舊記憶**——

> 🔑 **年齡不等於真相。** 四年前的架構決策仍可能解釋為什麼系統有一半長成現在這樣；今天早上才建立的記憶可能已經完全是胡說八道。
> **年齡應該影響的是信心，而不是是否存在。**

🔑 這讓設計脫離常見的快取思維：**快取問「某個值還能不能重複使用」；記憶問一個更難的問題——「我現在應該相信它多少？」**

### 五、🔴 探索稅：作者推翻自己的成本假設

原本的假設是「有記憶的程式碼代理人應該能少用 token，因為不必每次重新摸索整個儲存庫」。想清楚之後，這個理論壞掉了：

> 一個具備記憶的會話**實際上可能會用更多 token**——先拿索引、再抓記憶、解讀來源、驗證過時說法，之後可能還是得檢查相同的原始碼。

但 API 花費也許不是該看經濟效益的地方：

> 每個新的程式碼代理人進入儲存庫時，某種程度上都帶著**專業失憶**。它搜尋程式碼、重建架構、發現慣例、嘗試某件事、發現為什麼行不通；隔天另一個會話又重演一個更小版本的同樣考古行動。
>
> 🔑 **真正昂貴的不是探索的 token，是人類又要再解釋一次**：這個回應格式不能改、那個遷移我們已經試過、這個服務因為客戶端限制所以行為不同、對我知道這看起來不對、不，拜託不要再重構它了。
>
> 🔴 **組織一直在為了重新發現自己早就花錢發現過的資訊而持續付費。這就是探索稅。**

**因此評估指標要換**——同儲存庫、同模型、同任務，開啟／關閉記憶中心兩種條件下比較：

- token 使用量（作者預測**大致持平甚至稍差**）
- 達成可接受結果所需的**實際時間**
- **人類修正的次數**
- **重複走錯路的次數**
- **代理人違反已知團隊決策的頻率**

> 🔑 結論隨之改變：最強的賣點不是「AI 會話變便宜了」，而是**「AI 會話不再反覆重審已經定案的決策」**。即使 API 帳單幾乎沒變，記憶系統在經濟上仍然有價值——**工程師一小時的成本遠高於讓模型多讀一千個 token**。

### 六、為什麼純文字是最重要的無聊決策

記憶是純文字：不是模型專屬的隱藏狀態、不是只在某個嵌入空間裡才有意義的向量、不是某種專有的「持久化認知表示」。

> Claude 可以建立一條記憶，GPT 可以讀它，本地模型可以不同意它，尚未存在的模型也可以繼承同一段專案歷史。
>
> ⚠️ 這**不代表模型可以互換**——不同模型會用不同方式解讀同一條記憶，看見不同事物、犯不同錯誤。權重仍然非常重要。**但歷史不會再因為模型更換而消失。**

🔑 由此形成的分離：**模型變成可替換的運算資源，記憶成為持久的組織狀態。**

### 七、也許這根本不是 AI 記憶問題

> 軟體團隊會忘記決策當初為何做出、方法為什麼失敗、以及哪個看起來很蠢的實作之所以存在，是因為更乾淨的版本之前就炸過一次。六個月後，某個人會「修正」它，然後在 production 裡重新發現同一個問題。

過去二十年一直在賣這個問題的解方：Wiki、Confluence、ADR、內部入口網站。它們都遇到同樣的經濟問題——**寫文件的人先付出成本，未來某個人才享受好處**。

🔑 AI 代理人也許能改變這點，因為**代理人在工作發生時就已經在場**：它看過檔案、失敗的方法、修正動作、決策改變的原因，所以產出一條精簡記憶的**邊際成本幾乎是零**。

> 真正的可能性不是「AI 會讀文件」，而是**AI 在做事的副產品中就能產生歷史痕跡**，而不是要求人類事後補文件。如果成立，代理人就改變了許多知識管理系統失敗的**寫入端經濟學**。
> ⚠️ 但這句話裡的「如果」很重，作者聲明還沒有證明它。

## C（關鍵行動）

- [ ] 判斷一條資訊該進 RAG 還是記憶：問它是「已經存在某處」還是「由流程產生」——決策理由、失敗原因、暫時假設都屬後者
- [ ] 記憶層先設計**索引／細節兩段式載入**，別讓完整歷史進每次提示詞
- [ ] 每條記憶都要帶作者、時間、來源與**信任狀態**；未審核記憶當「某 Agent 說過」而非事實
- [ ] 審核設計成**升級機制**而非寫入門檻，否則只是換一層文件瓶頸
- [ ] 舊記憶標過時但**不自動刪**——讓年齡影響信心，不影響存在
- [ ] 評估記憶價值時**不要只看 token**：加上人類修正次數、重複走錯路次數、違反既有決策的頻率
- [ ] 記憶用純文字存，換模型時歷史要能留下
