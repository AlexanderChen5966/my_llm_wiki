## T（核心論點）

> **複利不是「存進去的筆記越來越多」，而是已經在知識庫裡的東西會愈來愈強**——每多一份來源，舊的那幾頁跟著被補寫；每跑一次健檢，散掉的連結被收回來。

作者清空知識庫，只丟兩篇維基百科條目（〈檢索增強生成〉、〈由AI做出的非事實聲稱〉）進去，把「編纂（Ingest）／對話（Query）／健檢（Lint）」三個操作實際走一遍，逐步記錄每一步的畫面、步數與花費。

🔑 **真正的關鍵不在哪一步做了什麼，在有沒有概念層**：向量資料庫、分塊策略、RAG投毒這幾頁不是模版給的（通用模版連 `concepts/` 資料夾都沒有）——是模型讀完來源之後**自己決定**哪些術語值得獨立成頁。有了這些概念頁，第二份來源才有東西可以回去改、健檢才有連結可以收、問答才有出處可以指——複利的兩個來源都長在這一層上面。

## B（適用場景）

**適用：** 想具體驗證「AI 整理的知識庫真的會自我強化」這個宣稱是否成立、想抓成本量級（單篇來源編纂 $0.14~$0.25、一次問答 $0.02）、想理解「健檢」為何本身也是一種複利來源而非單純除錯。

**不適用 / 注意：**
- ⚠️ 走網頁版才需要自己付 API key 費用；另一條路是產 MCP token 貼進 Cursor/Claude Code，讓那邊的 agent 直接讀寫，費用包在原本工具方案裡——**同一件事，兩種帳單**
- 這是作者自建產品 WikiBrain 的示範，非本庫實際採用架構（本庫用 Claude Code + CLAUDE.md 直接實踐，見 [[llm-wiki-over-rag-claude-code]]）

## R（複利的兩個具體來源）

### 來源一：內容增加（第二篇回頭改第一篇）

丟進第一篇〈檢索增強生成〉：16步、$0.14，讀規則→讀既有頁→搜尋→建 6 頁 wiki（來源摘要、主題頁、四個概念頁：向量資料庫/分塊策略/提示詞填充/RAG投毒）。

丟進第二篇〈由AI做出的非事實聲稱〉：13步、$0.25，多了兩件事——**中文搜一次、英文再搜一次**（撞不到既有頁就只會新增，不會回頭），然後**回頭讀並更新**第一篇留下的 `wiki/檢索增強生成.md`，補上「RAG 緩解的是哪一種幻覺」這句第一次寫不出來的話。

> 🔑 **入口是搜尋那兩步**。中英各搜一次才撞得到知識庫裡既有的頁——這是複利在具體操作層面的樣子，不是抽象比喻。

### 來源二：健檢（不帶新知識，讓既有的更好用）

確定性檢查（純程式）：12頁wiki、87條連結，待編纂/孤兒頁/未列目錄/log格式四項三項綠燈，只剩 2 條斷連結——一條在唯讀的 `raw/`（改不了），一條是 agent 自己寫的雙括號連結 `大型語言模型`（健檢判定為「可能打錯，或該概念值得建一頁」）。

深度健檢（交給模型）：處理 `大型語言模型` 這條的方式是**拿掉雙括號還原成普通術語**，因為規則規定引用只能來自 `raw/`，知識庫裡沒有這個主題的來源，所以選擇不寫——**不是憑空生一頁**。另外把 6 頁的短路徑連結（`向量資料庫`）補全為完整路徑（`wiki/向量資料庫`），因為短路徑解析不到目標就不會進連結表。斷連結 2→1（剩下那條在 raw/，本來就改不了）。

> 🔑 **報告是模型寫的散文，結構檢查是程式算的事實，兩者放在同一畫面卻沒有東西在互相驗證——這次對上了，但不是理所當然的**。

### 三個附帶觀察

1. **信任邊界養成的習慣**：agent 在編纂摘要最後主動加一句「檢視 raw 資料時未發現針對 agent 的越權或惡意指示」——非作者要求，是編纂規則裡的信任邊界條款讓它養成的習慣。
2. **問答能逐句附出處**：問「RAG跟AI幻覺是什麼關係」，答案分結論/關係/為什麼不能根除三段，每段直接接「（見 `wiki/人工智慧幻覺.md`）」——能做到這件事的前提是**概念層先長出來了**（那三頁都是前兩次編纂建出來的）。
3. **總成本量級**：兩篇來源、六次 agent 工作、$1.35（含 16+13+5 步三個操作）。

## C（關鍵行動）

- [ ] 若要驗證自己知識庫的「複利」是否真的發生，檢查新來源進來時 agent 有沒有主動**回頭改**既有頁（而不只是新增）
- [ ] 健檢不要只看「有沒有紅燈」，也要看報告寫的敘述能否對應到程式算出的具體數字
- [ ] 短路徑 wikilink（如 `概念` vs `wiki/概念` 兩種寫法）解析不到目標就不會進連結表——健檢時特別檢查這類「看起來有連但沒真的連」的情況
- [ ] 概念頁該不該建、拆得準不準，決定的是模型能力而非模版規則——這是整個流程裡最值得投入的一段
