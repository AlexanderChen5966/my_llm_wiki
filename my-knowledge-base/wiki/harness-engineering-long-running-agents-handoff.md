這篇把 [[harness-engineering]] 拉到「長任務跨輪次」的角度：Harness 不只是 Guides × Sensors，還包括**啟動環境、狀態保存、交接與驗收**，決定下一輪能從哪裡接續。與 [[claude-code-session-handoff]]（交接檔五段骨架）互補：後者講「檔案怎麼寫」，本篇講「整條流程怎麼設計、怎麼驗收」。

## T（核心論點）

長任務失敗多半不是模型不夠強，而是**對話紀錄、實際檔案與外部系統的狀態不同步**，下一輪只能重新猜進度，或把「看起來完整」誤判成「已完成」。解法是讓每一輪都留下**可回查的依據**：目前成果、證據位置、下一步、待人決定的事。

- Harness 負責把「接收資訊 → 選工具 → 執行 → 看結果」接成流程，並安排狀態保存、錯誤處理與停止條件。
- 與 Context Engineering 的分工：後者安排模型每一步讀到什麼；Harness 還要把工具執行、狀態保存與驗收接起來，讓資訊在工作中持續更新。設計時先問「下一輪開始需要知道什麼？由哪個步驟保存？」
- 草稿／已查證／已驗收是三種不同狀態，下一步各不相同；單一「完成」標記會讓後續跳過必要檢查。

## B（適用場景）
**適用：** 跨多輪對話、跨人或跨工具的任務（研究報告、需求文件、軟體維護）；需要稽核或獨立驗收的交付；經常「做到一半要重新解釋」的工作。
**不適用 / 注意：**
- 一次性短任務不需要整套流程；單一代理搭配任務清單與交接資料就夠，有獨立驗收或平行需求時再評估多代理與協調成本。
- 🔴 本篇為二手整理：Anthropic 兩篇研究的描述、Session／Checkpoint 官方文件（作者標 11 月 5 日查詢）皆未對一手核對；表格範例（訪談→產品需求文件）是**作者原創示範**，不是官方案例。
- 作者自述「Anthropic 案例提供設計方向，實際採用仍要配合自己的工具與工作條件」。

## R（操作步驟）
1. **第一輪先建可驗收的成果清單**（共同起點）：交付規格（讀者與深度）、來源清單（版本與位置）、成果清單（寫到可檢查，例如「每項需求有來源、情境、待決處」而非「需求表完成」）、驗收規則（引述可回查、未決項標記）。
2. **交代工作環境**：資料位置、編輯工具、成果保存位置；程式任務再加啟動方式與必要設定；工具依賴登入或外部服務時寫明可用條件，服務失效時先做不受影響的部分並記下受阻事項。初始化控制規模，只建必要資料，遇缺口再補。
3. **每輪先確認現況再推進一項**：讀目標與進度 → 檢查既有成果是否仍可用 → 只挑一項範圍清楚的工作 → 完成、檢查、保存。
4. **交接表**留五欄：本輪成果／證據位置／實際狀態／下一步／需要決定的事。避免「進度良好」「大致完成」這類無法驅動下一步的描述。
5. **中斷後先讀現況再比對成果清單**：已存在且通過檢查的保留，只缺部分就標出缺口補上，不直接重跑（避免重複內容），並記下為何重試。
6. **製作與驗收分開**：驗收者依成果與規格判斷（可為同事、測試工具或另一個代理）；回饋要指出位置、問題、驗收方式（例：「某需求缺來源 → 補原文位置或移到未決清單」）；修改後只重驗受影響與連動部分。作者轉述 Anthropic 2026-03 研究：獨立評估本身仍需清楚標準、評分方式要校準。
7. **先做一次中斷與接續試跑**：完成部分內容後停下，讓新一輪只憑保存的資料接手；看能否找到成果、是否誤判完成、是否重複處理。卡在找檔案就改入口，判斷錯誤就把驗收證據寫清楚。

### 現有工具能保存什麼（作者 11/5 查詢，未核對）
| 工具 | 保存範圍 | 限制 |
|------|----------|------|
| Claude Agent SDK session | 對話紀錄的保存與續接／分支 | 只涵蓋對話脈絡 |
| Claude Code checkpoint | 一定範圍的檔案與對話狀態，供回復或摘要 | 主要追蹤本輪經檔案編輯工具納入的檔案；其他檔案與外部系統變動要另外管理 |

選工具前先列出「這項工作會改動哪些地方」，再確認各處如何回查與恢復。

### 常見問答（作者回答摘要）
- 壓縮對話 vs 重開一輪：看保存的狀態夠不夠、接手後能否通過同樣驗收。
- 有續接功能還要進度文件嗎：跨工具、跨人或需稽核時，仍建議另存成果與證據位置。
- 文件工作適用嗎：有多階段、來源版本或固定完成條件的都可先用簡單交接表試跑。

## C（關鍵行動）
- [ ] 挑一個範圍清楚的長任務，建立「交付規格＋成果清單＋驗收規則」三件套
- [ ] 把現有交接檔補上「證據位置」與「需要決定的事」兩欄（對照 [[claude-code-session-handoff]] 的五段骨架）
- [ ] 做一次中斷試跑：新對話只讀交接資料，檢查是否誤判完成、重複處理
- [ ] 需要獨立驗收時，先寫驗收標準再決定由人、測試或另一個代理執行
