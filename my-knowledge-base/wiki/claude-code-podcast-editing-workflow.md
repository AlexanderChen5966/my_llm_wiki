## T（核心論點）

Podcast 剪輯真正花時間的不是「輸出」，而是在冗長音檔裡反覆尋找贅字、重錄與離題段落。Claude Code 不是傳統音訊剪輯軟體，而是能讀取專案檔案、理解文字內容、執行固定工作流程的助理——做法是先把音訊轉成帶時間碼的逐字稿，再讓 Claude Code 分類找出可疑片段、產生剪輯建議清單，最後交由人工確認才執行。**核心設計原則是「先提出建議，再等待核准」，而非全自動剪輯**：Claude Code 定位為「初剪助理」，降噪、混音、內容取捨與最終核准仍須由人完成。

## B（適用場景）

**適用：** 有 Podcast/訪談錄音需要初剪，希望用 AI 加速找出贅字/重錄/離題片段；多人訪談需要同步處理多軌音檔；已熟悉 Claude Code 基本操作、想延伸到創意工作流程。

**不適用 / 注意：** Claude Code 不能直接降噪、混音、EQ、壓縮或響度調整，這些仍需專門音訊工具；「離題」判斷非固定規則，AI 只適合標記可疑段落並說明理由，最終取捨仍需製作人依節目調性決定；未公開訪談若含個資、合約或未發布商業資訊，交給 AI 或轉錄服務前應先確認資料處理方式與受訪者同意範圍；第一次操作不應讓工具直接覆蓋原始錄音。

## R（操作步驟）

**建議流程分四階段：**
1. 整理原始錄音、分軌、逐字稿與片頭片尾素材
2. 讓 Claude Code 從逐字稿找出可能需要處理的片段（疑似贅字、重錄、離題）
3. 先產生剪輯建議清單，由人確認後才執行
4. 輸出初剪版本，從頭到尾完整試聽

**適合交給 Claude Code 的工作 vs 仍要由人決定：**

| 適合交給 Claude Code | 仍要由人決定 |
|---|---|
| 整理逐字稿與時間碼 | 哪些故事值得保留 |
| 找出疑似重錄、贅字與離題段落 | 停頓和語氣是否影響節目節奏 |
| 產生交給製作人審核的剪輯清單 | 最終版本能不能公開 |
| 依固定規則處理重複工作 | 完整試聽與成品核准 |

**多人訪談注意事項：** 主持人和來賓的音軌必須同步處理，若其中一條音軌少了幾秒，後面整集都可能對不起來——雙軌輸出後務必確認沒有錯位。

**「先建議、後核准」的必要性：** 如果一開始就讓 AI 直接修改原始錄音，只要時間碼偏移或逐字稿辨識錯誤，就可能剪掉完整句子；因此每一步剪輯建議都應先列清單，等人工確認才真正執行。

## C（關鍵行動）

- [ ] 第一次操作時，先把原始錄音複製一份工作副本，不讓 Claude Code 直接覆蓋原始檔
- [ ] 讓 Claude Code 產出的剪輯建議清單先過人工確認，再執行實際剪輯操作
- [ ] 多軌錄音先確認各軌時間碼對齊，避免雙軌輸出後產生錯位
- [ ] 涉及個資、合約或未發布商業資訊的訪談內容，交給 AI 或轉錄服務前先確認資料處理方式與受訪者同意範圍
- [ ] 降噪、EQ、混音、響度調整仍交給專門音訊工具，不要期待 Claude Code 完成這部分

## 原始摘要

文章說明如何用 Claude Code 協助 Podcast 初剪：先將音訊轉成帶時間碼逐字稿，再由 Claude Code 分類找出贅字、重錄與疑似離題片段，產生剪輯建議清單交由人工確認後才執行，而非全自動剪輯。強調降噪、混音、內容取捨與最終核准仍須由人完成，Claude Code 定位為「初剪助理」而非取代製作人。
