Agent OS 不是多建幾個 Agent，也不是讓一個萬能 AI 接管所有事——它是一套個人工作控制層：從真實目標開始，把任務拆成「工位」，給每個工位分配上下文和驗收標準，讓核查者獨立於生產者，高風險動作停在「待確認」，經驗沉澱成可複用資產。以「消化上百篇稍後讀」為實例示範。

## T（核心論點）

**分工不是為了顯得高級，而是為了隔離上下文、隔離責任、隔離風險。** 把一件事整包丟給一個 AI 從頭做到尾很危險：寫筆記的 Agent 若同時負責核查，會順著自己的錯誤圓下去；負責提煉的若同時能刪除，會把誤判直接落地。這不是 AI 笨，是組織結構錯了。

## B（適用場景）

任何要交給 AI 的重複性多步驟任務（整理稍後讀、寫 Newsletter、消化會議記錄、整理競品資料）；需要防止 AI「一鍵執行卻悄悄改壞資料」的場景。

## R（四道工位 + 實測案例）

**基礎四工位**：
1. **抓取工位**：正文交給成熟工具存好（Readwise/Obsidian Web Clipper），AI 只做已存內容的標題/分類讀入，**不硬編分類**（沒正文就老實說沒有）
2. **提煉工位**：把每頁提成要點，判斷值不值得留
3. **核查工位**：把提煉結果拿回**原文**逐條比對，鐵律——**不能讓寫筆記的工位自己查自己**（盲區一樣，等於自己審自己的卷子）
4. **確認工位**：彙總前三道結果成待辦清單，每條給建議（刪/歸檔/保留/深讀），**只出建議、不自動落地**，人一條條拍板

**真實踩坑案例**：提煉工位只看標題/摘要不讀正文，把一份「穩步增長 8%」的行業報告寫成「爆發式增長、同比翻倍」，還把這頁從「該學習」誤判為「可歸檔」——核查工位比對原文後標成「可疑」，換到另一個 AI 工具重跑一次核查（共用同一份設定，不用重配）獨立得出相同結論。**若省略核查、一鍵跑到底：真資料被丟掉，假數字被當真，而且不會發現。**

**工位定義四要素**：角色／責任／上下文（只能依據給定原文，不能靠記憶）／驗收標準。核查工位範例：對得上原文標「已核實+出處」，對不上標「可疑/原文無依據」。

**個人開始搭建的六步**：① 寫清楚目標（非「幫我整理」而是「整理成待確認提案，由我決定」）② 畫出工位（輸入/提煉/核查/確認是最基礎四段）③ 每工位寫清角色/任務/上下文/驗收標準 ④ 補上禁止動作（「不能做什麼」常比「要做什麼」更重要）⑤ 定義交接產物（每步輸出檔案/表格，系統才可恢復可替換）⑥ 加確認邊界（所有刪除/歸檔/發布/發信/改記憶的動作停在待確認）

## C（關鍵行動）

- [ ] 任何委派給 AI 的多步驟任務，先畫工位再選工具
- [ ] 核查工位永遠是另一個獨立上下文，且必須給它真實原文而非摘要
- [ ] 高風險動作（刪除/歸檔/發布/改長期記憶）一律停在「待確認」，AI 只給建議不自動落地
- [ ] 模型是租來的，上下文（怎麼分工/怎麼驗收/怎麼決定落地）是自己的資產
