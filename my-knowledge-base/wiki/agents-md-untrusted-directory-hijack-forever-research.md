Forever Security 於 2026-10-22 公開研究：客戶電腦 Downloads 資料夾裡的惡意 AGENTS.md，曾誘導程式代理嘗試安裝惡意套件，被安全產品攔下。研究者之後在隔離環境重建 Codex 攻擊鏈，並另外設計 Claude Code 的端點轉向測試。

⚠️ **時效與可信度**：單一二手來源（aiposthub 轉述原研究），事件日 2026-10-22；Codex／Claude Code 的信任關卡與 AGENTS.md 讀取規則隨版本變動，本條目為 2026-11-03 查閱的狀態，未附版本號（來源亦未附）。

## T（核心論點）

**把「能讀」和「能授權」分開**：工作目錄與其中的指令文件（AGENTS.md／CLAUDE.md）是需要先檢查的**不可信輸入**。純文字不會自己執行，但當讀它的代理能改檔案、呼叫終端機與連線時，文字就能影響這些能力怎麼被用。風險不在某個關鍵字，而在「來源」與「權限」被混在一起——文件可以提供專案資訊，不代表作者取得改動代理自身設定的資格。

## B（適用場景）

**適用：**
- 設計「讓代理整理下載內容、處理來源不明資料夾」的流程時，作為威脅模型的真實案例
- 檢視團隊對代理的批准關卡、沙箱、全域設定（如 `~/.codex/config.toml`）管理規範時
- 向同事說明「為什麼 AGENTS.md 讀取規則放寬後，工作目錄要當不可信輸入」

**不適用／注意（務必分清三種證據等級）：**
- 🔴 **真實事件只有一件**：被安全產品攔下的惡意套件安裝嘗試，指令來自 Downloads 內的 AGENTS.md。**檔案如何進入 Downloads 未確認**；惡意程式在執行前就被阻擋，不能寫成「客戶電腦被接管」或「客戶 Claude 權杖被盜」。
- 🟡 **受控測試（非真實受害）**：Codex 攻擊鏈、Claude Code 端點轉向與權杖取得，都是研究者在隔離環境重建／另行設計的。以受控網頁展示下載方式，只證明「傳遞路徑可行」，不補上真實事件缺的證據，也不等於「瀏覽者開網頁就會中招」。
- ⚠️ **數字一律是研究者自報、無完整樣本數與版本，勿外推**：Codex 測試超過九成完成攻擊路徑；Claude Code 約一半跟進流程、同一 session 內執行約五分之一。**這些不是受害率，也不是兩個產品的安全排名**。
- ⚠️ **遙測數字是使用分布不是受害率**：自家遙測約半數客戶曾在 Downloads 內啟動代理、約四分之一代理 session 開啟真實瀏覽器。「全球半數開發者做過」與「半數使用者受害」都超出原資料。
- 「作者認為不能靠單一修補」是研究者分析，不是 OpenAI／Anthropic 的正式承諾。

## R（事件與測試的還原）

### 1. 真實事件（Forever 在客戶電腦上看到的）
安全產品發現代理正要安裝已知惡意套件，往前追查才發現指令來自 Downloads 的 AGENTS.md（非專案相依套件或正常程式庫設定）。調查重點因此不是「使用者有沒有主動執行下載程式」，而是**文件怎麼被提升成操作依據、操作是否越出使用者原本要整理檔案的範圍**。

### 2. 為什麼這份文字能影響代理
- 據 OpenAI 文件（轉述）：Codex 找到專案根目錄時會從根讀到當前目錄；**找不到專案根目錄時只讀當前目錄的 AGENTS.md**。在專案裡工作與直接在 Downloads 啟動，輸入環境不同。
- Codex 有信任關卡，不會對任意未受信任目錄的 AGENTS.md 照單全收；但「把 Downloads 當工作區」會讓這個前提變得值得注意。
- 研究者的觀察：短而直接的安裝要求較易遭拒，**長篇工程規範包住的「例行準備」較易被接受**。

### 3. Codex 測試路徑（受控）
1. 文件包裝成「例行工具設定」，要求寫入全域設定 `~/.codex/config.toml`，註冊一個 MCP 工具伺服器
2. 伺服器在 session 開始時載入，改設定不一定立即影響原連線，所以文件再要求**開子 session「驗證設定已就緒」**，使設定生效
3. 文件甚至勸代理停用原有保護來完成驗證——來源不明規範在要求擴大自己的執行能力
4. 因為是**全域設定**，影響不隨離開 Downloads 消失，之後在其他正當專案開工也可能載入同一項目

### 4. Claude Code 測試路徑（受控）
以 CLAUDE.md 偽裝成「內部模型閘道說明」，誘使代理把專案模型端點改到研究者控制的伺服器，再觀察登入權杖與工具回應。
- TLS 憑證正常：**問題是目的地被換，不是加密被破解**；說「權杖明文傳輸」並不精確
- 端點被換後，攻擊者能以模型服務形式回傳工具要求，客戶端會把它當模型回應的一部分
- 研究者表示因此取得測試用權杖並驗證能以該身分呼叫服務（測試環境）

### 5. 防範（來源列出的做法）
- 保留批准關卡與沙箱；對要求「繞過」它們的文件保持警覺（這與單靠模型辨認語氣是否可疑是兩種不同防線）
- 來源不明檔案先當資料檢查，再放進**獨立工作目錄**；搬過去的檔案仍要檢查，搬家不等於安全
- 發現不明工具註冊或模型端點，交管理者核對設定來源、變更時間與實際使用
- 若權杖可能外流，需撤銷並輪替；**刪掉指令檔不會讓已外流的有效權杖失效**
- 檢查要分階段：文件存在、設定已改、程序已執行是不同層，處理方式不同

## C（關鍵行動）

- [ ] 整理來源不明檔案時，不在 Downloads 直接啟動代理；先放獨立目錄、先檢查有無自己沒加入的 AGENTS.md／CLAUDE.md
- [ ] 檢查代理全域設定（工具伺服器註冊、模型端點）有無不明項目，並確認批准關卡與沙箱仍開啟
- [ ] 對外轉述本事件時固定三句：真實＝被攔下的安裝嘗試；其餘為受控測試；數字為自報、勿外推
