## T（核心論點）

> **記憶管「長期穩定」，交接管「當下這一攤」。兩件事，兩種工具。**

`CLAUDE.md`（你寫的規矩）與自動記憶（它自己記的筆記）都不適合放「這次做到哪、剛剛決定了什麼」——因為那種東西**會過期**。寫進「每次對話都自動載入」的常駐檔，只會讓 Claude 每次都讀一份過時資訊。

三種「換」不要搞混：

| 你想做的事 | 用什麼 |
|---|---|
| 換一個**全新對話**，舊的不要了 | `/clear` |
| 讓它記住**長期的規矩／偏好** | `CLAUDE.md`、自動記憶 |
| 把**當下這攤進度**搬到下一塊白板 | **交接檔** |

搞混的下場很具體：把「這次做到哪」寫進 `CLAUDE.md`，它變成一份每次都被讀一遍的過期筆記；反過來把「這個專案一律用 yarn」只留在交接檔裡，下次開新任務又得重講。

## B（適用場景）

**適用：**
- 對話太長開始變慢、感覺它「有點忘了前面」，想開乾淨白板時
- 要把進度傳給同事、或餵給另一個 agent
- 想精準控制「帶哪幾件事過去」，而不是賭 `/compact` 會不會留

**不適用 / 注意：**
- ⚠️ **內建的先用，不夠再手動**：同一個對話想接著跑 → `/compact` 就好，別一開始就把流程搞複雜
  > 🔑 **但「什麼時候」按仍歸 [[claude-code-7-usage-mistakes]]（2026-09-03 調和）**：本篇回答的是**工具選擇**（同對話續跑用 `/compact`，不必動用 handoff 檔），該篇回答的是**時機**——🔴 **實作到一半不要 compact**（壓縮會把「接下來要做什麼」摘要吃掉，重開後疊上半套實作而不自覺），只在**工作分界點（提交後）**按；長任務先把計畫寫進 `PLAN.md`。
  > 兩篇不衝突：**時機歸該篇、工具選擇歸本篇。**
- 🎯 **交接檔是一次性快照，不是 `CLAUDE.md`**——任務做完就可以丟掉，別把它變成常駐檔

## R（操作步驟）

### 一、先認識三個內建工具及其極限

| 指令 | 作用 | 丟掉什麼 |
|---|---|---|
| **`/compact`** | 把整段對話換成結構化摘要（需求與意圖、關鍵技術概念、看過改過哪些檔、遇到什麼錯誤怎麼修、待辦、目前進度），騰出白板空間**在同一個對話**繼續 | 逐字的工具輸出、中間推理過程、先前讀過的原始程式碼細節 |
| **`/rewind`**（或按兩下 `Esc`） | 回到之前某時間點的**對話與程式碼狀態**，也可從某則訊息重新摘要 | — |
| **`/resume`** | 從清單挑一個之前的 session 接著做 | — |

> 💡 白板快滿時 Claude Code 會**自己**壓縮（auto-compaction），不是只有手動 `/compact` 才會發生。所以有時你覺得「它怎麼好像忘了前面的細節」——很可能就是剛剛自動壓縮過了。

**這三招的共同限制**：
1. **壓縮留什麼是「它」決定的**——你沒辦法精準指定「A、B、C 這三件事一定要留」
2. **跨不出這台機器、這個專案**——沒辦法傳給同事或另一個 agent
3. **有時你就是想要一塊乾淨白板**——只想帶結論過去；壓縮是把舊的濃縮，不是重新開始

### 二、可直接複製的指令

換對話前：
```markdown
我們等一下要換一個新對話繼續。
幫我產生一份交接檔 handoff.md，寫清楚:
1. 這個任務的目標
2. 目前已經完成什麼、改了哪些檔
3. 剛剛做的關鍵決定，以及為什麼這樣決定
4. 還沒做的下一步
5. 有哪些地方不要碰、有什麼雷
```

新對話開場一句：
```markdown
先讀 handoff.md，然後接著上一棒繼續做。
```

### 三、🔑 五段骨架與它的判斷標準

- **① 目標** — 這個任務要達成什麼，一兩句話
- **② 已完成** — 做到哪一步、動過哪些檔
- **③ 關鍵決定 + 為什麼** — **最重要、也最容易斷片的一項**。「我們選了 A 方案，因為 B 方案在這個情境會卡住」——這句沒留下來，下一棒很可能又繞回去試 B
- **④ 下一步** — 接手的第一件事該做什麼
- **⑤ 別碰 / 注意** — 哪些檔不要動、踩過什麼雷

判斷標準只有一條：

> **想像你明天失憶了坐回這台電腦，你會希望桌上那張紙寫什麼？**

### 四、交接檔比 `/compact` 多的三個好處

**你控制內容**（點名要寫哪幾件事）／**它是一個檔案**（可貼給下一個對話、傳給同事、丟給另一個 agent、存進 git，跨得出這台機器）／**人也讀得懂**（不用翻對話記錄）。

### 五、（進階）同一招也能交接給另一個 agent

一個 agent 專心做調研，產出交接檔；另一個 agent 讀那份檔接手實作。兩者沒有共用記憶、沒有共用白板——**那份交接檔就是它們唯一的接口**。

> 這就是多 agent 協作最樸素的雛形：不是什麼玄妙的架構，就是「上一棒寫一張紙條，下一棒讀它接手」。作者建議先把「換對話用交接檔」練熟就夠了。

### 六、作者後來的調整：`.md` → `.html`

純文字 `.md` 打開一片黑白，重點跟雜訊長得一樣，常要讀第二遍才抓得到；`.html` 可以放大重點、標色、排成表格，掃一眼就知道現在在哪。做網頁時更明顯——可以直接叫它畫一個簡單的 wireframe，用畫面對需求比打一百字描述精準。

## C（關鍵行動）

- [ ] 先分清楚「記憶」與「交接」：穩定的規矩 → `CLAUDE.md`／自動記憶；當下的進度 → 交接檔
- [ ] 交接檔的價值在**「為什麼」和「下一步」**——只寫「我做了什麼」用處有限
- [ ] 內建的先用：同對話繼續跑用 `/compact`；要乾淨白板 + 只帶結論、或要傳給別人才用交接檔
- [ ] 任務結束就丟掉交接檔，別讓它變成常駐檔
- [ ] 🔬 可試：把交接檔換成 `.html`，看掃讀速度有沒有差

## 原始摘要

「讓資訊跨對話傳下去」共三種工具，各管一段、不要互相取代：**你寫的規矩**（`CLAUDE.md`，專案長期慣例，要常駐）／**它記的筆記**（自動記憶，讓它自己長）／**你交接的快照**（交接檔，用完就丟）。系列規劃 20 篇，下一篇 G6 講「用 HTML 跟 Claude 溝通」。
