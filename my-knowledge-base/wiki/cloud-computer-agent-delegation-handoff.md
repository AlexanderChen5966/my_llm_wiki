兩個同期的「雲端 AI 電腦」案例：**Pine Computer**（2026-10 封閉測試，給開發者用 API 把任務交給雲端電腦，含瀏覽器、檔案、命令列）與 **Perplexity Computer 電商工作流**（2026-11-03，一個代理串起 Shopify、Meta 廣告、Klaviyo）。兩篇都是 aiposthub 二手整理；評測與成效數字都是官方口徑。

## T（核心論點）

> **雲端電腦讓代理能跨網站做完一整段操作，但能不能交出去，取決於任務單有沒有寫清楚三件事：成果長什麼樣、哪些動作留給人決定、卡住時交回什麼。**

三個支撐點：

1. **「進度分數」≠「完成率」**：Pine 在 SaaS-Bench v1.1（106 項任務）檢查點得分 78.3%，整件任務完成率只有 27.4%。拿前者當成功率，會低估人工補完的工作量
2. **每個需要授權的動作都要分開確認**：登入、送出詢價、付款是三種結果。同意登入不代表同意送出，付款欄位出現時要回到人確認
3. **成效要以「一件通過人工確認的成果」計算**：模型費、基礎設施、第三方服務、重跑次數、接手時間都要算進去；官方案例的倍數不能直接套用到自己身上

## B（適用場景）

**適用：**
- 定期要跨多個網站蒐集、比對、整理的工作（供應商報價、競品廣告、價格變動）
- 已有商店、廣告、郵件工具，想讓一個代理接手「研究 → 素材 → 投放 → 回報」之間的搬運
- 開發者想把「代理在雲端做事、人在需要時接手」接進自己的產品

**不適用 / 注意：**
- 🔴 雲端執行會改變資料流向：客戶名單、內部檔案能不能交給服務，要先確認再定測試範圍；官方說的隔離、限定存取、加密是架構說明，不能取代自己的帳號與資料管理
- 驗收標準寫不清楚的工作，先把工作本身整理好，再談交給代理
- Pine 仍在封閉測試，自帶模型與金鑰還是「即將提供」；Perplexity 各串接的方案、價格與地區沒有完整列出

## R（操作步驟）

### 1. 寫一份能接手的任務單（Pine 範例改寫）

把「幫我找最好的廠商」改成可驗收的交付：

> 調查指定三家供應商的公開名片印刷頁，整理尺寸、紙材、最低數量、公開交期、價格條件與來源網址。找不到的欄位標示頁面未提供。只讀資料，不送出表單、不付款；需要登入或遇到存取限制時，停止並回報目前進度。

- **「最好」要先換成比較條件**：最快、最便宜還是最符合紙材要求，模型無法替你取捨
- **每一列都要附查詢條件**：價格附上規格（數量、單雙面、紙材）；交期附上起算條件（「確認稿件後起算」不能寫成保證到貨日）；附上查詢日期
- **沒有的資料照實寫**：例如「頁面未提供指定日期承諾」，不要補推測值
- 第一次測試先挑一頁有標準答案的網站，把「資料抽取錯誤」和「跨網站操作錯誤」分開觀察

### 2. 設計交接點

| 情境 | 做法 |
|---|---|
| 要登入 | Pine 發出回呼，人接管串流畫面自己輸入密碼。交接訊息要寫清楚停在哪裡，例如「已整理兩家公開報價，第三家要登入看會員價，目前未送出詢價」 |
| 登入後 | 範圍限定在讀取價格與交期；要不要寄詢價、加入訂單，等比較表完成後由人決定 |
| 出現收件或付款欄位 | 回到人工確認，針對當下的具體資料確認，不能沿用先前的登入同意 |
| 卡住（要驗證、資料不存在、網站故障） | 停止訊息要包含原因、最後完成的步驟、已取得的資料；已完成的部分照樣交付，未完成的標成未完成 |
| 恢復 | 先核對網站與登入狀態是否不變，再補缺的欄位；整段重跑可能拿到不同價格或重複操作 |

🔑 **指定一位接手負責人**：大家都以為別人會處理通知，代理正確停下來也沒用。

### 3. 多管道活動：一份需求貫穿各管道（Perplexity 電商）

官方流程分七類工作：競品研究 → 資料分析 → 靜態廣告 → 影片廣告（延伸已有成效的 UGC）→ 媒體購買（大量上傳、命名規則、每日依效率目標調預算）→ Shopify 登陸頁 → Klaviyo 郵件流程。

- **需求先寫清楚**：目標商品、對象、完成條件、活動期間、預算總額、每次回報要呈現的數據
- **廣告與頁面要對應同一個承諾**：廣告主打的組合或使用情境，進到商店要找得到
- **一個版本只改一項**：主角、文案、優惠同時改，就分不出是哪一項影響了表現；命名規則決定報表認不認得出版本
- 研究、創意、執行三段的產出分開驗收：研究要附資訊來源，創意要對應品牌與商品，執行要回報實際使用的頁面、素材與預算
- 用跨裝置的審核與批准回到實際成果確認，不要只看一句「已完成」；共享 Projects 保留歷史，接手的同事才知道前一版為什麼改

### 4. 怎麼讀官方數字

| 數字 | 口徑 | 不能推出 |
|---|---|---|
| Pine 每件任務 1.02 美元 | 只算模型用量；基礎設施另計，消費產品零售口徑是 3.60 美元；各系統的執行預算不同 | 你能省下的比例 |
| Get Maine Lobster：3 萬美元 Meta 廣告，收入 3.5 倍、ROAS +63%（對照代理商活動） | 單一客戶案例；同頁另有「Meta 收入約 3 倍」的說法，兩者口徑未說明 | 兩個倍數合併計算；套用到自己的品牌；淨利（還要扣商品成本、折扣、履約） |
| True Classic：Klaviyo 重建 19 條流程 | 客戶描述的交付範圍與時間感受 | 營收影響 |

### 5. 小批驗收

1. 準備 5 份不同規格的需求，含資料齊全、價格缺漏、需要登入三種情境
2. 逐份檢查：來源打得開、規格一致、缺漏有照實標示、遇到登入確實停在交接點、沒有越過送出界線
3. 請沒參與設定的同事抽一列，從來源找回相同規格與交期；再依停止訊息接手一次，記下花了多少時間
4. 保留被刪掉的錯誤欄位與修正原因，同樣的錯誤再出現時可以直接處理
5. 試點報告只寫本批的通過數與限制（例如「公開頁可完成，會員頁仍需人工」），用來決定下一輪範圍；三家網站做得到，不代表其他網站也做得到

## C（關鍵行動）

- [ ] 第一個雲端代理任務只做「只讀＋產出有來源的表格」，登入、送出、付款都列成人工步驟
- [ ] 任務單固定寫四項：欄位、來源、停止條件、接手人
- [ ] 看評測時分開記「檢查點分數」和「整件完成率」，預算用「每件合格成果的總成本」估
- [ ] 做多管道活動時，每個素材版本只改一個變因，命名規則先定好

## 原始摘要

**Pine Computer**：雲端 AI 電腦（瀏覽器＋檔案＋命令列），透過 API 交付任務；系統主動傳遞畫面變化，減少模型反覆確認環境；登入時發回呼，讓人接管串流畫面；SaaS-Bench v1.1 檢查點 78.3%、完成率 27.4%；每任務 1.02 美元只算模型費；目前封閉測試。站方用供應商比較表示範任務單、交接訊息、停止訊息與小批驗收。

**Perplexity Computer 電商**：一個代理串起競品研究、分析、廣告素材、媒體購買、Shopify 登陸頁、Klaviyo 郵件；龍蝦品牌案例收入 3.5 倍、ROAS +63%，但沒有可重建的期間與分組；建議從一項進行中的活動、一段明確的工作開始。

**合併判斷（2026-11-19）**：[[grok-bot-cloud-agent-product-overview]] 是單一產品的架構介紹，[[codex-computer-use-modes]] 談本機操作權限分級；兩者都沒有涵蓋「跨網站任務單＋交接點＋合格成果成本」這組做法。兩篇各 27 分、合計 54，依路徑 ② 合併新建。
