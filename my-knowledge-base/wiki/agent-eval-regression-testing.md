同作者、同一門課（《Agent Eval 實戰》六格工作包：用例／成功標準／評分方式／**重複執行**／放行決定／**回歸**）的兩篇導讀，本條目合併第四格與第六格。兩篇都是作者錄課前的**小範圍試做**，作者自己強調結論只適用於那幾次執行。

## T（核心論點）

> **「四次都通過，也只說明這四次，不能說成它可靠。」**

Eval 說白了就是**事先定好什麼算做成，再拿結果去對**。兩個最容易省略、卻最常出事的格子：

1. **重複執行（pass^k）**：單次成功率 80% 的任務，連做五次「至少對一次」是 99.97%（pass@k），「五次全對」只有 0.8⁵＝**32.8%**（pass^k）。要它每週都做對，看的是後者。只跑一次，看不到說明的第二種讀法。
2. **回歸（改前／改後）**：改提示詞、改 Skill、換模型之後，用**同一份凍結的輸入、同一張檢查表**重跑，看原本做到的事還在不在。🔴 **同一份規則換一個模型，結果就變了**——Opus 5.5 三次五行全找到，Claude Sonnet 5 六次裡有五次把「沒跑過的 12 項測試」寫成「實測」。

## B（適用場景）

**適用：**
- 調通一條打算反覆使用的提示詞／Skill 之後，確認它不只是「這次剛好對」
- 新模型發布、想把日常任務切過去之前
- 精簡或改寫 Skill（例如剝離私人依賴做分享版）後，確認底線沒丟
- 修好一個問題後，確認沒把原本對的地方改壞

**不適用 / 注意：**
- ⚠️ 兩篇的實驗規模都很小：會議記錄篇只有兩份**虛構**材料、四次正式執行、一個模型；換模型篇是 3 次 vs 6 次。只能當「方法示範」，不能當「模型優劣」的證據
- ⚠️ 不需要寫程式或搭評測平台；但也因此只能抓到「檢查表寫到的那幾格」，表外的差異要靠「和其他幾次哪裡不一樣」欄位人工記
- 🔴 官方說「建議審計舊指令」（GPT-6 Astra 發布時 OpenAI 的建議）**不等於舊規則已經壞了**——作者實測舊版與精簡分享版在三個場景都守住底線，真正造成差異的是換模型

## R（操作步驟）

### 一、重複執行（第四格）

1. **寫兩三條「拿什麼證明做完了」**：打開結果看一眼就能判斷對錯，不寫「整理得清楚」這類形容詞
2. **說明定稿後一個字不改，原樣再跑兩次**：同一份材料、每次開新對話、輸出存成檔案，**只看檔案，不看 AI 在對話框裡的自我總結**
3. **換一份沒參與修改的新材料跑一次**：改說明時一直盯著原材料，說明很容易剛好只適配它
4. **每次都用同樣的條件對，記一行**：

| 第幾次 | 用哪份材料 | 條件 1 | 條件 2 | 和其他幾次哪裡不一樣 |
|---|---|---|---|---|
| 1 | 材料一（定稿版結果） | | | 基準 |
| 2 | 材料一，原樣再跑 | | | |
| 3 | 材料一，原樣再跑 | | | |
| 4 | 材料二，未參與修改 | | | |

5. **改過說明，就把所有條件從頭再對一遍**

**實例（會議記錄→待辦清單）**：
- 首跑全過；原樣重跑三次，有兩次把會上明說「以後再議」的小程式排進待辦第 7 條——說明沒寫「沒定的事怎麼處理」，模型在兩種讀法之間來回換，而原本的完成條件也攔不住
- 補上「會上沒定下來的事不列進清單」後，重跑一次全過；🔴 再多跑兩次，其中一次把「已定由陳雨負責、只缺日期」的客戶訪談移出表格——新約束沒區分「事情沒定」與「事情定了、只缺負責人或日期」
- 定稿說明把兩者分開寫，四次正式執行全過；但新材料把「改期」放在表外說明、舊材料則單列成待辦——條件都過，若下游要求改期必須進表，就是**驗收條件漏了一條**

### 二、換模型／改規則的回歸（第六格）

1. **先寫檢查表，再動規則或模型**：從規則中挑 3～5 樣絕不能丟的東西。作者工作日誌 Skill 的五行：為什麼只改下載入口／被推翻的原判斷／檔名是刻意不改／**12 項測試是歷史報告還是本次重跑**／Excel 真機尚未驗證
2. **每格只允許三種填法**：找到了（抄 AI 輸出原句）／未找到／寫錯了（抄那句錯的原句）
3. **表底寫明工具、模型、參數設定**
4. **一次只改一個對象**：改規則就固定工具、模型與可控設定；測換模型就規則一字不改
5. **先用現有模型跑「改前」欄當基線（baseline）**；若改前就已「未找到／寫錯了」，記「基線未過」，不算到後續改動頭上
6. **新對話、相同輸入跑「改後」欄**
7. **改前找到、改後丟了**：
   - 改的是規則 → 立刻還原那句再跑一次，看能不能回來
   - 只換了模型 → 先別把任務切過去，把丟掉的那一行與模型名記進表底，往後每次換模型都拿它複查
8. **兩欄都全找到**：結論只寫「在這份材料、這一次執行上，沒有發現丟東西」，不放大

## C（關鍵行動）
- [ ] 挑一條最近調通、會反覆用的提示詞或 Skill，原樣再跑兩次＋換一份新材料跑一次，填四行記錄表
- [ ] 為最常用的 Skill（例如 handoff／工作日誌類）寫一張 3～5 行的回歸檢查表，**特別放一行「驗證狀態是否區分歷史結果與本次實測」**
- [ ] 下次換預設模型（或升級 Claude Code 主模型）前，先用舊模型跑一次基線存檔，再換
- [ ] 檢查表底固定記錄：工具、模型、推理強度

## 原始摘要

**週刊 049（重複執行）**：作者以虛構會議記錄試做「整理成待辦清單」，說明為「每條寫清做什麼、負責人、截止日期；原材料沒給的標『未提供』，不補猜」，兩條完成條件為「定下來的事都有一條、缺欄寫未提供」與「人名日期金額都能在原文找到出處」。首跑全過，但原樣重跑三次冒出「以後再議」的事被列進待辦；修好後再多跑又發現已定的訪談被移出表格。兩處問題都是只跑一次看不到的。最終定稿後四次執行全過，但作者只下「只說明這四次」的結論，並列出未覆蓋範圍（虛構材料、四次、單一模型）。pass@k／pass^k 定義引自 Anthropic 工程文章。

**PRO 專刊（回歸）**：起因是 GPT-6 Astra 發布時 OpenAI 建議審計舊指令，作者把自用工作日誌 Skill 剝離私人自動化做成分享版。凍結輸入與判斷標準後，同模型、同推理強度下舊版與分享版在三個場景各跑一次（共六次，不挑不重跑），兩版都守住底線（不借用無關會話 ID、不捏造沒跑的測試、不因缺元資料拒絕保存、不把排查中的問題說成已解決）。但換模型後，輸入為「修 CSV 中文亂碼、只准改瀏覽器下載入口、共用序列化模組不能動」的虛構對話，附帶一份 12 項測試全過的**歷史**工具結果：Opus 5.5 三次都標明「來源是會話記錄附帶的歷史工具結果，本次寫日誌時沒有重新執行」，Sonnet 5 六次中五次寫成「實測」（其中同一份規則三次裡兩次）。作者強調後果在交接：一句未核驗的「實測通過」寫進交接文件，下游就會當成已發生的事實。

## 補充資料

**2026-11-19 補充（來源：AI 郵報 Philo〈Google ADK2.14.0 穩定化執行介面：多次評測、工具比對與升級限制怎麼看？〉https://www.aiposthub.com/google-adk-python-214-multi-run-evaluation-upgrade/ ，2026-11-09；依官方 release 與 eval_config 文件整理）**

- **框架層的「重複執行」實作**：Google ADK 2.14.0（2026-11-07）CLI 評測可指定**重跑次數**與**並行數**（兩者不能互代：並行只縮等待，不增觀察次數）；重跑>1 時每輪從測例初始狀態開新會話，固定的 session ID 會被忽略。⚠️ 入口預設不同：CLI 預設跑 1 次、程式測試用的 AgentEvaluator 預設 2 次且不讀同一份設定
- 🔑 **合併規則決定評測在回答什麼**（官方示例，非實測）：三次相似度 0.875／0.182／0.875、門檻 0.6——**平均 0.644 通過；看最差一次 0.182 不通過；要求通過率≥90% 只有 67% 不通過**。同一組資料三種讀法三種結論，呼應本條目「pass@k vs pass^k」
- 平均的單位也影響權重：逐回合平均 vs 先算每輪再等權；通過率可針對單一指標或「整題全指標同時達成」
- **當機不進通過率分母，但預設容許當機 0 次**；刻意容許一次時，「3 過＋1 當機」算出 3/3＝100%，報告要同時保留當機次數
- 工具參數比對（ToolArgsMatcher，仍為實驗介面）可逐欄位設精確／忽略大小寫／數字容差／語意判斷，部分欄位對仍可整體判不符；語意比對要另一個模型裁判＝額外成本，預設文字重疊指標分不出「燈已開／燈已關」
- 對本條目的啟示：檢查表除了「跑幾次」，還要**寫明合併規則（平均／最差／通過率）與當機怎麼算**
