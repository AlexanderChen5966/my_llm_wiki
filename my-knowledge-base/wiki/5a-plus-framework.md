5A+ 是 MAPS 框架中 S（Systems）層的具體實踐方法論，提供從想法評估到規模化運營的完整循環。六個階段（AIM → ACQUIRE → ATTEMPT → ADJUST → APPLY → PLUS）搭配量化決策門檻，確保每個 AI 資產化專案都能數據驅動、小步快跑，避免過度準備或追求完美的常見陷阱。

## T（核心論點）

5A+ 的核心設計理念是「讓資產化成為一個可量化、可重複的流程」：
- 每個階段都有明確的入場條件和退出標準
- 用資產化價值評分（頻率 × 耗時 × 複雜度係數）決定是否值得做
- MVP 優先、時間盒管理，避免完美主義導致永遠無法落地
- Plus 階段的持續運營機制讓知識真正沉澱，而不是做完就忘

**與其他框架的關係**：
- **5A+ 是 MAPS 中 S（Systems）的展開**：M 影響 AIM 評估，A 在 ATTEMPT/ADJUST，P 在 ATTEMPT 設計 Prompt，S 就是整個 5A+ 本身
- **與 SCQA 的關係**：每個 A 階段都可以用 SCQA 結構來表達成果和決策
- **與 TBRC 的關係**：TBRC 用來組織每個 A 階段的文件內容

## B（適用場景）
**適用：**
- 評估是否值得把某個重複任務做成 Skill/工作流
- 新 Skill 從構思到上線的完整開發過程
- 需要在團隊中推廣某個 AI 工具或方法

**不適用：**
- 一次性任務（直接執行不需要走完整流程）
- 資產化價值評分 < 20 分的低頻簡單任務

## R（六階段操作框架）

### 快速參考卡
```
A1 (AIM)     → 評估價值，定義目標  （資產化價值 ≥ 50 分才繼續）
A2 (ACQUIRE) → 快速學習，準備資源  （80/20 原則，< 1 天完成）
A3 (ATTEMPT) → 創建 MVP，快速驗證  （時間盒 < 1 週，至少 3 個測試用例）
A4 (ADJUST)  → 數據驅動，迭代優化  （三維評估：功能性 50%、效率性 30%、可用性 20%）
A5 (APPLY)   → 擴展場景，團隊共享  （文件 + 試點 + 推廣三步驟）
+  (PLUS)    → 持續運營，知識沉澱  （週/月/季回顧機制）
```

### A1（AIM）— 資產化價值評估公式
```
資產化價值 = 頻率評分（1-10）× 耗時評分（1-10）× 複雜度係數（1.0-3.0）

決策標準：
≥ 150 分 → 最高優先級，立即開始
100-149 分 → 高優先級，本週啟動
50-99 分→ 中優先級，排入計劃
20-49 分 → 低優先級，資源充裕時考慮
< 20 分 → 不建議資產化
```

### A3（ATTEMPT）— MVS（Minimum Viable Skill）設計原則
1. 只做核心功能，暫時忽略完整錯誤處理、性能優化、邊界情況
2. 時間盒限制：簡單任務 2-4 小時、中等任務 1-2 天、複雜任務不超過 1 週
3. 至少 3 個測試用例（正常、邊界、異常情況）

### A4（ADJUST）— 三維評估模型
| 維度 | 權重 | 關鍵指標 |
|------|------|---------|
| 功能性（是否能用） | 50% | 觸發準確率 ≥ 90%、執行成功率 ≥ 95%、完全正確率 ≥ 80% |
| 效率性（是否值得） | 30% | 節省時間 ≥ 70%、ROI ≥ 5 |
| 可用性（是否好用） | 20% | 首次使用 < 10 分鐘、步驟 ≤ 3 個 |

**評級：** 9-10 優秀可推廣 / 7-8 良好可使用 / 5-6 需改進 / < 5 重大調整

### 各階段常見陷阱
- A1：目標過於宏大 / 沒有量化標準 / 忽視資源限制
- A2：過度準備 / 收集癖（收藏卻不看）/ 跳過基礎
- A3：MVP 不夠 M / 沒有時間盒 / 測試不充分
- A4：追求完美（7 分就可以用）/ 憑感覺優化 / 沒有版本規劃
- A5：過早推廣 / 文件不足 / 缺乏支持渠道
- Plus：沒有定期回顧 / 知識沒有沉澱

## C（關鍵行動）
- [ ] 下次開始新任務前，先用「資產化價值公式」評分——低於 50 分直接執行，不走完整流程
- [ ] A3 設計 MVS 時，把完整功能清單列出後，90% 都標記為「v2.0」，只留核心的 1-2 個功能先跑
- [ ] 每次完成一個階段後，在 outputs/ 記錄評估結果和下一步決策
