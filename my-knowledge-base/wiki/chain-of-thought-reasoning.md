LLM 預設傾向「直覺式」一步到位輸出答案，遇到多步驟邏輯或數學問題時容易跳步出錯。Chain-of-Thought（CoT）透過要求模型顯式輸出中間推理步驟，把「黑箱直覺」轉成「可檢視、可除錯」的推理鏈，是 Agent 可靠性的基礎技術之一。

## T（核心論點）

CoT 的核心是讓模型在給出最終答案前，先逐步寫出推理過程，藉此提升複雜任務的正確率並讓錯誤可被定位。延伸技術 Tree-of-Thought（ToT）讓模型在多個推理分支間搜尋與比較，ReAct 則把推理與工具呼叫（Action）交錯進行，三者構成由淺到深的推理方法演進。

## B（適用場景）

**適用：**
- 數學計算、邏輯推導、多步驟規劃等容易「跳步出錯」的任務
- 需要除錯模型錯誤推理路徑的場景（CoT 讓中間步驟可被檢視）
- 配合工具呼叫的 Agent 任務（ReAct 模式）

**不適用：**
- 簡單事實查詢或單步任務，要求 CoT 反而增加無意義的 token 成本與延遲
- 對延遲高度敏感的即時應用

## R（三種推理方法與提示技巧）

### 三種推理方法

| 方法 | 核心機制 | 特點 |
|------|---------|------|
| Chain-of-Thought（CoT） | 線性逐步推理 | 簡單有效，但只能沿單一路徑推進 |
| Tree-of-Thought（ToT） | 多分支推理樹，搜尋並比較不同路徑 | 能回溯與比較，成本較高 |
| ReAct | 推理（Reason）與行動（Act）交錯 | 結合工具呼叫，適合 Agent 任務 |

### CoT Prompting 技巧

| 技巧 | 做法 |
|------|------|
| Zero-shot CoT | 直接加一句「請逐步思考」（Let's think step by step）|
| One-shot CoT | 提供一個含完整推理步驟的範例 |
| Few-shot CoT | 提供多個不同情境的推理範例，提升泛化能力 |

### 兩個示範

1. **數學應用題**：直接問答模型容易算錯進位或漏看條件；加上「請逐步列出計算過程」後，模型會先列出已知條件、再分步運算，正確率明顯提升，且錯誤步驟可被人工定位修正。
2. **邏輯推理題**（如年齡/順序推斷）：未使用 CoT 時模型容易跳過中間關係直接猜測；使用 CoT 後模型逐一列出已知關係式並推導，得出正確結論。

### 與幻覺緩解技術的關係

CoT 本身不能完全消除幻覺（模型仍可能在某個推理步驟編造錯誤前提），需搭配 RAG（檢索增強生成，提供外部事實依據）或 Tool Use（呼叫計算器/搜尋等工具驗證中間結果）才能進一步降低幻覺率，三者是互補而非替代關係。

## C（關鍵行動）

- [ ] 多步驟邏輯/數學任務優先嘗試 Zero-shot CoT（加一句「請逐步思考」），成本最低且效果顯著
- [ ] 若任務有明確固定模式，改用 Few-shot CoT 提供範例，比單純要求模型思考更穩定
- [ ] 涉及外部事實或計算正確性要求高的任務，CoT 需搭配 RAG 或 Tool Use，不能單靠推理鏈消除幻覺
- [ ] 簡單事實查詢不要套用 CoT，避免不必要的 token 與延遲成本
