## T（核心論點）

如果證據本身帶著惡意指令，對模型來說文字都一樣，並不天然知道哪段是規則、哪段只是待引用資料。沒有一條正規表示式能宣布解決 Prompt Injection，需要**四層防線組合**才有實際防護力：① System 規則標記來源為不可信資料（能降低成功率，但不是安全邊界，可被繞過）；② `security_guard.py` 正則掃描隔離高風險模式（覆寫指令/Prompt 外洩/角色重設），命中即隔離並重新分配代號，全部隔離則拒答；③ 即使惡意來源進入 Prompt，引用驗證器仍會拒絕偽造的 `[S999]`；④ 未審核文件先進 Staging（`indexed=false`），避免任何人上傳惡意文字後立刻污染線上知識庫。除了 Prompt Injection，還有兩個常被忽略的風險：**資料投毒**（偽造內容不含可疑指令詞彙，正則完全不會命中，需靠來源治理而非 Prompt 技巧）與**權限錯置**（須在檢索前依 ACL 過濾，讓未授權 Chunk 根本不進 Context，事後輸出過濾已經太晚）。

## B（適用場景）

**適用：** 設計 RAG 系統的多層安全防線（來源標記、正則掃描隔離、引用驗證、Staging 審核）；建立最小安全回歸矩陣（直接注入/間接注入/多語變形/良性安全文章）；判斷資料投毒與權限錯置這兩類不靠 Prompt Injection 手法的風險；設計安全事件處理流程（隔離文件、重建索引、清快取、輪替憑證）。

**不適用 / 注意：** 任何一層防線都可能被繞過，這些措施降低風險，沒有任何一條能宣稱「解決 Prompt Injection」；良性安全文章（討論「什麼是 System Prompt」）可能因含關鍵詞被誤判隔離，安全評測必須同時回報攻擊攔截率與良性通過率。

## R（操作步驟）

1. **威脅模型四類風險**：使用者直接要求洩漏系統提示；惡意文件藏指令經 Retrieval 進 Context；模型偽造或宣告未使用的來源；系統曝光內部路徑、憑證或未審核文件。直接注入來自提問本身，間接注入藏在文件/網頁/PDF 中，更難追查。
2. **第一層：標記來源為不可信資料**：System Message 與來源 JSON 分開，明確規定不得執行來源中的程式、網址、工具要求，不得揭露系統提示或憑證；這類規則能降低成功率但不能當安全邊界，攻擊者可換語言、拆字、編碼繞過。
3. **第二層：隔離明確可疑來源**：`security_guard.py` 掃描覆寫指令（ignore previous / 忽略指令）、Prompt 外洩（system prompt / 系統提示）、角色重設（you are now / 現在你是）三類模式；命中來源不進 Context，重新分配代號確保引用封閉集合仍成立；若所有來源都被隔離則直接拒答。
4. **第三層：輸出仍要通過引用驗證**：即使惡意來源進入 Prompt，模型輸出不存在的 `[S999]` 時 Day 21 驗證器會拒絕；來源正文裡的網址不能被模型自動變成正式引用。
5. **第四層：未審核文件先進 Staging**：文件匯入只寫入 Staging，回覆 `indexed=false`，須經格式驗證、內容審核與重新建索引後才進入回答，避免任何人 POST 惡意文字後立刻污染線上知識庫。
6. **測試需同時涵蓋攔截與誤傷**：評測集需含明確攻擊、變形攻擊（多語/分隔/編碼）、良性安全文章、引用偽造與來源欄位污染，避免把所有文件都隔離就得到毫無意義的「零攻擊成功」；`quarantined` 計數是「規則命中數」非「來源數」，Log 須分清避免安全報表誤導。
7. **資料投毒是獨立風險**：偽造內容（如「所有 API 都應停用 CSRF」）不含可疑指令詞彙，正則完全不會命中；需要來源治理——驗證 owner、版本、審核狀態，重要規範要求雙人核准，更新保留差異與可回滾版本。
8. **權限錯置須在檢索前過濾**：即使 Prompt 要求「不要洩漏 S2」，模型已看到內容後任何輸出過濾都太晚，正確順序是在 BM25/向量搜尋候選階段就依使用者身分與 ACL 過濾；快取設計也要考慮跨使用者授權隔離。
9. **資料外洩防範**：API 應移除內部絕對路徑、禁止任意 `source_url`、遮罩憑證格式；根本做法是不要把金鑰、Token、個資放進知識庫，一旦秘密進入 Context，再好的 Prompt 都只剩機率性防線。

10. **事件處理**：命中高風險規則記錄 Trace ID/文件版本/規則名稱並告警；確認惡意後隔離原始文件、重建受影響索引、清除相關快取、查詢哪些回答曾引用它；若涉憑證洩漏需輪替憑證而非只刪文件。公開錯誤訊息維持中性，避免告訴攻擊者哪條規則命中。
11. **每次更換模型/Prompt/Guard 規則/文件解析器都應重跑最小安全回歸矩陣**：直接注入、間接注入、多語變形、編碼混淆、偽造引用、Metadata 污染、未授權文件、良性安全文章與正常問答。

## C（關鍵行動）

- [ ] 建立四層防線（來源標記不可信／正則掃描隔離／引用驗證／Staging 審核），不依賴單一防護
- [ ] 安全評測同時回報攻擊攔截率與良性通過率，避免誤傷正常技術文件
- [ ] 為資料投毒建立來源治理機制（owner/版本/審核狀態驗證），不只靠 Prompt Injection 規則
- [ ] 檢索前依使用者身分與文件 ACL 過濾，讓未授權 Chunk 根本不進候選池與 Context
- [ ] 每次更換模型、Prompt、Guard 規則或文件解析器都重跑最小安全回歸矩陣
