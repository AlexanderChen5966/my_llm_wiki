## T（核心論點）

給 Agent 加記憶系統，ALFWorld 成績從 **76.4% 掉到 70.1%**——加了記憶反而更差。MemHarness 論文（上海人工智慧實驗室 × 浙大 × 復旦）指出問題不在記憶本身，而在 agent 是**死背（reproductive）還是重構（reconstructive）**：把過去成功軌跡原封不動餵回去，環境已變、舊經驗變噪音。解法是**用之前先根據當下狀態重構那段記憶**——保留適用的、丟掉不適用的、必要時整段拒絕。一個 Qwen2.5-7B 加上這機制做到 **85.2%，贏 Gemini-2.5-Pro 23.1 個百分點**。

## B（適用場景）

**適用：** 設計 agent 記憶系統；評估是否該引入 Mem0/Zep 類向量記憶框架；理解「經驗多」與「有智慧」的工程差異

**不適用 / 注意：**
- 這是**單一論文的 benchmark 結果**（ALFWorld / WebShop 兩個環境），跨到真實生產場景的外部效度未驗證
- MemHarness 需要 **GRPO 端到端訓練**才能長出重構能力，不是一個可以直接掛上現有 agent 的外掛模組——這是實務採用的最大門檻

## R（機制與數據）

### 🔴 為什麼「靜態記憶回放」會扯後腿——兩層原因

1. **環境已經變了**：過去成功的行動序列是在特定狀態下產生的，搬到不同狀態就變成錯誤指引（就像上個專案 monolith 成功、下個專案環境不同卻硬套）
2. 🔑 **成功經驗的「權威感」更危險**：失敗的經驗你會懷疑它，**成功的經驗你會信任它——agent 也是**。原封不動拿到的成功軌跡會壓過 agent 對當下環境的判斷。**越成功的記憶，越容易讓 agent 放棄獨立思考**

> 論文的認知科學引用：**Human remembering is reconstructive rather than reproductive.**
> 你回想昨天的會議，浮現的不是逐字稿，而是根據「現在需要什麼」重新組裝的版本。
> ⚠️ **現有 agent 記憶系統（Mem0、Zep、各種向量 memory 框架）幾乎都在做 reproductive 的事**：存下來、檢索出來、原封不動送進 context。

### 三階段推論管線

| 階段 | 做什麼 |
|---|---|
| **一、取回（Retrieval）** | 用 BGE-M3 embedding 做 cosine similarity，拉出最相關的 3 條過去經驗（含當時的觀察狀態 ＋ 行動序列）|
| **二、重構（Reconstruction）** | 🔑 關鍵步驟。**同一個 policy model 扮演「批判者」**：把記憶與當前狀態並排比較，生成「重構後的指引」；差太遠則直接輸出 `<EMPTY>`＝「這段記憶沒用，丟掉」|
| **三、行動生成** | 根據**重構後的指引**（不是原始記憶）決定下一步 |

**關鍵設計**：三步都由同一個 7B 模型完成——**沒有額外 critic 模型、沒有 reward model、沒有人工標註的重構範例**。用 GRPO 端到端訓練，只靠任務成敗當獎勵（成功 +10、失敗 0、加 0.1 權重格式獎勵）。

### 為什麼重構有效——三個設計選擇

1. **讓模型看到「原始狀態 vs 當前狀態」的對比**：記憶不只存行動序列，還存當時的 source state。消融證明：拿掉 source state，85.2% → **80.0%**
2. **允許整段拒絕**（`<EMPTY>`）：這個逃生口防止負遷移，不適用的記憶不會被硬塞進決策
3. **沒有人教它「怎麼重構才對」**：純靠 RL 獎勵端到端學出來——**他們沒有定義「好的重構長什麼樣」，而是讓結果倒推：能幫你完成任務的重構就是好重構**

### 主實驗數據

| 方法 | 模型規模 | ALFWorld | WebShop |
|---|---|---|---|
| Gemini-2.5-Pro | 大型 | ~62% | ~36% |
| Qwen2.5-7B + GRPO（純 RL，無記憶）| 7B | 76.4% | 66.1% |
| **Mem0 + GRPO** | 7B | **52.0%** | – |
| **SimpleMem + GRPO** | 7B | **54.5%** | – |
| **MemHarness** | **7B** | **85.2%** | **75.6%** |

🔴 **最該注意的是中間兩行**：Mem0 與 SimpleMem 是業界常見記憶框架，加上去比純 RL baseline **還差**（52.0% vs 76.4%）。**這不是框架實作問題，是「靜態記憶回放」整個範式的問題。**

### 🔑 消融實驗——整篇論文最重要的一行

| 設定 | ALFWorld |
|---|---|
| 純 GRPO（無記憶）| 76.4% |
| RL + 原始記憶直接注入 | 70.1% |
| MemHarness 去掉重構模組 | 79.6% |
| MemHarness 完整版 | 85.2% |
| **MemHarness 訓練，但測試時不給記憶** | **83.0%** |

最後一行：**用記憶重構做訓練、測試時完全不給記憶，仍有 83.0%，比純 RL 高 6.6pp**。

> 這意味著**重構記憶的訓練過程順便提升了模型本身的推理能力**——就像工程師長期練習「把舊方案改寫成適合新環境的方案」，即使手邊沒有舊方案，解題能力也因這種訓練而提升。論文稱之為「重構目標內在增強推理能力」。

## 對應到人的經驗：replay 與 reconstruct 的差別

原文把三個機制對應到人生經驗的運用，即「經驗多」與「有智慧」的差別：

- **記得當時的脈絡，不是只記得結論**：資深的人不只記得「我做了 X 然後成功了」，還記得「當時客戶很急、預算只有一半、團隊才三個人，所以才這樣做」
- **懂得說「這次不一樣」**：最厲害的不是經驗最多的人，是知道什麼時候該放下經驗從零思考的人——**這需要承認「我以前對的東西現在可能不對」，比承認失敗還難**
- **智慧不是教出來的，是試出來的**：MemHarness 的 RL 訓練就是在模擬「嘗試、看結果、調整」

> 有些人活了 40 年每次都在 replay（我以前這樣成功所以現在也這樣），有些人每次都在 reconstruct（我以前這樣成功，但現在情況不同，哪些部分還能用）——**經歷一樣多，智慧差很多**。

## C（關鍵行動）

- [ ] 🔴 導入任何記憶框架前先做「有記憶 vs 無記憶」對照——**靜態回放可能讓表現低於 baseline**
- [ ] 記憶不要只存「做了什麼」，**一定要連當時的環境狀態一起存**（拿掉 source state 掉 5.2pp）
- [ ] 給記憶系統一個「整段拒絕」的逃生口，別讓不適用的記憶被硬塞進決策
- [ ] 對「成功經驗」比對「失敗經驗」更謹慎——權威感會壓過對當下的判斷
- [ ] 評估既有向量記憶方案（Mem0/Zep）時，確認它是 reproductive 還是有重構層
