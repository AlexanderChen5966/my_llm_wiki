## T（核心論點）

> **「關鍵字和向量哪個好」是個錯誤的問題；正確的問題是「誰的主場在哪裡」——而要回答這個問題，
> 評測集本身必須先誠實，不能拿一份偏袒某一方的考卷宣布勝負。**

BM25 在舊評測集 v1（12 題）已經是滿分，比賽還沒開始就結束了，因為 v1 十二題以術語型問題為主，
那是關鍵字的主場。真正有意義的對決，要先把秤校準：新增涵蓋跨語言、口語改寫、同義詞困境的題型，
讓評測集代表真實使用者會問的各種問法，而不是偏向某一方的展示題。

## B（適用場景）

**適用：** 需要在導入 Hybrid Search／Reranker 之前，先量化 Keyword Search（BM25）與
Vector Search（語意搜尋）各自的失敗模式與適用主場；建立 oracle 聯集分析，判斷「融合是否值得做」；
設計評測集迭代與版本化流程（v1 → v2）。

**不適用 / 注意：** 看到成績之後才回頭放寬標籤／調整標註，是在讓秤遷就成績，與調參過擬合是同一種病
——標註模糊地帶應記錄下來交由後續仲裁，而不是直接改標籤讓數字變漂亮；oracle 聯集是分析用的假想
完美裁判，不是可部署的方法，不能拿來當實際檢索系統的成績。

## R（操作步驟）

1. **校準評測集版本**：發現舊評測集偏向某一方時，明確新增涵蓋其弱點的題型（本例新增跨語言、
   口語改寫、同義詞困境三種，共 4 題，v1 的 12 題 → v2 的 16 題），並誠實記錄新題型的洩題性質
   （哪些題目已經被看過表現）
2. **逐題記錄「首個正解名次」而非只看 Hit@K 二元判定**：`rank_of_first_relevant()` 對每一題
   取完整排名中第一個相關文件出現的名次，能看出差距的形狀，不只是命中與否
3. **建立逐題對決表**：把 BM25 與 semantic 的名次並排列出，觀察區塊反轉現象——術語主場（v1 區）
   兩者接近打平，口語/跨語言主場（v2 區）語意搜尋壓倒性勝出，BM25 甚至對英文題整份排名交白卷
4. **計算 oracle 聯集**：假設任一方法答對就算對，得出融合的理論天花板（本例 Hit@1 15/16），並比較
   兩方法的失敗集合是否重疊——重疊越少，融合的潛在油水越大
5. **解剖共同失敗題**：對兩個方法都答錯的題目（本例 q18）做逐名深挖，區分「方法真的弱」與
   「標註本身有模糊地帶」，並將判斷過程與紀律留下記錄（不因看到成績回頭改標籤）
6. **記錄速度成本差異**：不只比準確率，也量測查詢延遲（本例 BM25 0.2ms vs semantic 31ms，差
   150 倍），作為後續高流量場景角色分配的依據

## C（關鍵行動）

- [ ] 導入 Hybrid/Reranker 前，先用 oracle 聯集分析驗證融合是否有實質油水，避免無效工程
- [ ] 評測集迭代時明確記錄新題型解決了哪個舊版本的偏頗，並標注洩題題目
- [ ] 建立「看到成績不可回頭放寬標籤」的評測紀律，把模糊地帶記錄成待仲裁項目而非直接改標籤
- [ ] 同時記錄準確率與查詢延遲，兩者一起影響架構選型

## 原始摘要

「讓 LLM 不只會回答，還會查證：打造 Agentic RAG 智慧知識助理」系列 Day 15，把評測集校準為 v2
（12 題 → 16 題，新增跨語言、口語改寫、同義詞困境三種題型），讓 BM25 與語意搜尋逐題對決：
semantic 14/16 首度超過 BM25 12/16，但這是考卷變完整而非方法變強；oracle 聯集指出融合天花板為
Hit@1 15/16，且兩方法失敗集合幾乎不相交，成為下一篇 Hybrid Search 的立案依據。BM25 平均查詢僅
0.2ms，semantic 需 31ms，速度差 150 倍。共同失敗題 q18 的解剖同時暴露語意分數壓縮、標註模糊地帶、
以及「不因看到成績而改標籤」的評測紀律三件事。
