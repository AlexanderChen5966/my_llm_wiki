從圖書館借閱紀錄（822 筆、703 本童書）出發，一個下午用 Claude 做出小小讀者閱讀成就儀表板，並揪出孩子 2 歲後閱讀類型斷掉的缺口，附完整可複用工作流。

## T（核心論點）

輸入資料明確時（結構化 CSV），需求可以直接用聊的交給 Claude 討論再動手；但拿紀錄來做什麼、如何解讀、給出什麼引導建議，屬於人類的判斷範疇——AI 負責整理資料、建議分析角度、寫程式腳本執行任務，人類負責提出真正想解決的問題與挑剔品質。品質不是一次到位，而是透過反覆挑剔擴充需求逐步逼出來的。

## B（適用場景）

**適用：** 有結構化個人資料（借閱紀錄、消費紀錄、健康數據等）想做成可視化儀表板洞察成長/使用軌跡的場景；可遷移到其他個人資料儀表板專案。
**不適用 / 注意：** 額外查詢（如作者資訊、延伸書單）需要搜尋外部資料，建議明確要求 AI 採用「最省 token 的做法」（寫程式腳本執行搜尋而非模型直接大量生成）。

## R（操作步驟）

1. **輸入資料+討論需求**：把 CSV 匯出的借閱紀錄丟給 Claude，明確說明想做什麼（依年份呈現看過幾本、偏好類型、最愛書籍），並請它先提想法討論完再動手
2. **人類決定分析角度**：AI 建議分齡成長軌跡、系列書偵測；人類補充作者偏好整理、推薦未讀書單等需求，並要求用「最省 token」方式（寫程式腳本搜尋市圖資料而非模型憑空生成）
3. **反覆挑剔擴充需求**：對照「閱讀起步走」分齡書籍建議評估發展適齡度、寫給家長的引導建議、書單改中文書名為主、增加得獎書單比對
4. **觀察並提出缺口**：Claude 根據紀錄提出具體觀察（如「敘事理解可能超齡，但中文兒歌韻文兩歲後幾乎歸零」），並給出可執行的補強建議
5. **建資料夾+寫更新指南**：完成後要求「把相關資料都收進一個資料夾，並寫一份更新指南，之後放新資料進去，你照指南做就能更新」，讓專案可持續複用而非一次性產出

## C（關鍵行動）

- [ ] 需要額外搜尋外部資料時，明確要求 AI 用程式腳本執行而非模型直接大量生成，節省 token
- [ ] 完成主要產出後，務必請 AI 建資料夾＋寫更新指南，讓專案能持續複用
- [ ] 品質靠反覆挑剔逼出來——第一版產出後主動追加 2-3 個具體新需求（分齡評估/中文書單/得獎書單比對）
