SpaceXAI（Grok Bot 團隊）設計師 John Bai 用兩張 Figma 截圖＋一句語音指令，透過自建機器人「Figma Bro」遠端交件——人在健身房，設計照樣做完。這不是 Figma 功能介紹，是一套**任何 agent 都能搬過去用的「下指令方法論」**：截圖只負責標範圍與樣式，精確數值一律交給 MCP 直接讀原檔。

## T（核心論點）

> **截圖定「範圍與樣式」，MCP 讀原檔決定「精確數值」**——這是截圖比純文字指令好用的關鍵原因。

機器人讀不懂「放在剛才那個位置」，卻看得懂一張已經對好位置的圖。把固定不變的排版規矩（畫板怎麼排、間距多少、遇歧義先問）寫死進機器人系統指令本身，而不是每次臨時交代，才是真正省下的時間。

## B（適用場景）

**適用：**
- 任何需要對 agent 下「視覺型」指令、又不想每次重講規格的場景（不限 Figma，網頁/文件/簡報皆可套用同邏輯）
- 想設計自己的「下指令系統指令」，把一次性交代變成一勞永逸的規則
- 需要在離開電腦的情境下（通勤、健身房）仍能推進設計交件

**不適用 / 注意：**
- 前提是機器人已能透過 MCP 讀到 Figma 原檔既有的畫板或元件；空白畫布上無「樣式參照」可循時效果會打折
- 文中操作細節基於 podcast 口述整理，非官方教學逐字稿，指令範本為依內容重建版本

## R（六步工作法）

1. **接上 MCP，先把規矩講死**：建立與 Figma 的 MCP 連線後，把排版規矩（畫板橫向並排、間距 50/100px、不清楚先問）寫進機器人系統指令本身，不要每次現場交代
2. **兩張截圖定範圍**：一張是「已完成的樣式參照」，一張是「待處理的目標範圍」，讓機器人照樣式套用到未完成部分——截圖角色分工是這套方法的核心
3. **先做一個樣板，再套用其餘**：親手做好一個版本當樣板，交給機器人比照套用到其餘頁面，省去逐頁重複操作
4. **語音改稿，一次只改一項**：整體放大 → 邊角改圓 → 依回饋調顏色，分開下指令，方便追蹤是哪句指令造成哪個變化，出錯不必整批重做
5. **原型先做成能點的東西，不必先過 PM**：「垃圾桶開發法」——假設丟掉成本極低，就不必為了一個還不確定的點子先去說服產品經理
6. **出錯後要求機器人記住修正**：形成累積式學習，愈用愈貼近使用者習慣

系統指令範本（依內容重建，非原始模板）：

```
固定規矩（每次都遵守，不必再問）：
1. 產出的畫板一律橫向並排，不要上下堆疊。
2. 畫板之間間隔 50 像素；畫板尺寸較大時間隔 100 像素。
3. 精確的位置、尺寸與間距以 Figma 原檔既有的畫板或元件為準，截圖只用來指出樣式與範圍。
4. 一次產出全部版本，完成後列一張表說明各版本做了什麼。
5. 任何一點不清楚，先問我，不要自己猜。
```

同集另一位設計師 Peng Zheng 把同一邏輯用在無 CMS、無 Figma 的個人網站與生活雜務（打卡定位、影像處理、庫存/行事曆自動化），證明這套「截圖＋語音」方法論可遷移到任何工具鏈。

## C（關鍵行動）

- [ ] 把重複下達的規矩（排版、間距、遇歧義先問）寫進機器人系統指令，不要每次臨時交代
- [ ] 改稿一次只提一項要求，方便追蹤因果、降低整批重做風險
- [ ] 出錯後明確要求機器人「記住這次修正」，累積成長期習慣

## 原始摘要

《數位時代》報導 Claire Vo 主持的 podcast《How I AI》2026-09-14 集，SpaceXAI 設計師 John Bai 與同事 Peng Zheng 展示各自的 agent 工作流。核心是把「截圖定範圍樣式、MCP 讀原檔定精確數值」的分工，與「規矩寫進系統指令」的做法，組成一套可離開電腦仍持續交件的設計工作法。
