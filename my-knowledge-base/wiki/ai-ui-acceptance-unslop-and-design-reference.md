## T（核心論點）

> **AI 做的介面「一眼假」，問題不在模型做不出來，而在你只給了「做得好看」——參考與驗收都要拆成可檢查的項目：要借用什麼、元件叫什麼或行為是什麼、每個狀態該發生什麼、改名後還成不成立。**

四個可操作的抓手：

1. **去模板感用清單，不用形容詞**：unslop 把改法拆成九項（間距、顏色、圖示、文案、字體、版面、細節、視覺、動態），最後做 🔑 **換名測試**——把產品名換成別家的，畫面還說得通，就是模板
2. **說出元件名字，或把行為寫清楚**：實驗中只說「跳出視窗」3 分、指名元件或白話寫行為都是 4 分——**名字不是唯一辦法，精確才是**
3. **寫出毫秒、像素與曲線**，不要寫「順一點」
4. **截圖只是一個時間點**：參考對齊視覺之後，要用狀態表（展開／收合／選中／過長／載入／失敗）與「做了什麼之後應該發生什麼」補齊互動

## B（適用場景）

**適用：**
- 用 Claude Code／Codex 等 agent 做前端原型、儀表板、落地頁，想避開紫色漸層、emoji 圖示、驚嘆號文案這類模板感
- 寫給 AI 的 UI 需求單、AGENTS.md／CLAUDE.md 的介面規則
- 看到「某模型會設計了」的展示影片時，判斷能不能當證據、怎麼轉成自己的需求清單

**不適用 / 注意：**
- 🔴 **減字會刪掉必要資訊**：加「少寫次要說明」指令後，五份設定頁**全部**刪掉不可復原提醒，只有三份在確認框保留後果——規則要明寫保留錯誤原因、權限、費用、不可逆後果
- 🔴 **元件展示 ≠ 能用**：畫面上有某元件，不代表接得上資料、處理得了失敗
- unslop 是 CC BY 4.0（可商用、要署名）；生成主視覺另接付費圖像服務（會先問）；作者另賣設計服務。transitions.dev 免費版可商用但不能轉包成競品，另有付費方案
- 🔴 unslop 影片與 SKILL.md 不完全一致：影片把產品名 EmberAI 改成 Ember，SKILL.md 卻寫明不改產品名；影片 10/27 發、repo 10/29 才建
- 安裝任何第三方 skill 前先讀它的 SKILL.md 與腳本（aiposthub 建議）

## R（操作步驟）

### 1. unslop：九項依序做，一項做完整個畫面再做下一項

安裝（README）：`git clone https://github.com/heydamir/unslop` 後 `cp -r unslop/skills/unslop ~/.claude/skills/`；用法 `/unslop this dashboard`、`/unslop the hero of <網址>`（Codex 用 `$unslop`）；README 稱支援 Claude Code、Codex、Google Antigravity，處理 Next.js／React／Vue／Svelte／Tailwind／純 HTML，只有網址或只有截圖也行（截圖先重建成靜態 HTML）。

流程：先看畫面（能跑就截圖）→ 依 `references/signs.md` 審查列出每個徵兆 → 決定改多少（徵兆少就只改那幾項、沿用品牌；沒問題就說沒有）→ 🔑 **寫五行方向（產品、性格、世界、重點時刻、招牌細節）後停下來等你回答**；性格不能寫 clean、modern、sleek、minimal、premium 這類形容所有模板的字 → 依序做九項 → 跑檢查表 → 回報。

| 項目 | 檢查重點（aiposthub 意譯 SKILL.md） |
|---|---|
| 1 間距 | 全用 4 的倍數；同類同尺寸；群組內 < 群組間；導覽列每列 32–36、列距 2–4；側欄 16、卡片 20–24、頁邊 24–32 |
| 2 顏色 | 一組帶色調的中性色階；文字三層；**只一個強調色且少用**，強調色上字對比 4.5:1；拿掉色相漸層、漸層文字、彩色光暈與陰影、霓虹邊框；邊線用文字色 6–10% 透明度 |
| 3 圖示 | emoji 全換成同一套線條圖示（沒有就用 lucide）、16 或 18px、線寬 1.5；沒資訊量的圖示拿掉；類別色用小色點 |
| 4 文案 | 標題說「為誰做什麼」；不用驚嘆號、不用「Welcome back 👋」；標籤要短；變化寫跟什麼比（+12% vs last month）；不用 supercharge／seamless／unlock／magic；查不到的宣稱（10,000+ teams、10x faster）拿掉；範例資料要像真的；PRO、New ✨ 徽章非必要就拿掉 |
| 5 字體 | 介面一組字體最多再配一個；字重 400／500（偶爾 600）；句首大寫、不用全大寫加寬字距；數字 tabular-nums；不用斜體強調 |
| 6 版面 | 保留原區塊與順序；app 維持真實比例（側欄 240–280）；落地頁首屏一個主要動作 |
| 7 細節 | 圓角成套（內＝外－內距，≥4；控制項 8–10、卡片 12–16、面板 14–20）；快捷鍵做成小按鍵框；計數用安靜小字；圖表放在安靜格線上、一張圖一個強調色；focus 框鍵盤看得到 |
| 8 視覺 | 拿掉填版面的裝飾（色球、星雲、發光格線、全像腦袋）；首屏視覺要說明產品的某件真事 |
| 9 動態 | 拿掉沒理由的循環動畫（非即時狀態的 pulse／ping、飄浮、視差）；不用 `transition-all`、彈簧、hover 放大；只轉 color／background／border／opacity／transform；**整個畫面一條曲線、少數幾個時長** |
| 換名測試 | 換成別家產品名還說得通 → 在文案、視覺、**招牌細節**（只有這產品會有、一致使用的小細節，例：監控工具的即時狀態點）上推更明確 |

五條「不要做」：不改產品名；不改產品是什麼與區塊順序；**不用新裝飾取代舊裝飾、不拿一種流行換另一種**（玻璃、顆粒、霓虹、bento 格）；不發明功能、宣稱或資料；不要每個產品都套同一外觀。

### 2. 元件：叫得出名字，或把四件事寫清楚

中文「彈窗」在 Component Gallery 至少對到四種（aiposthub 整理的對照）：

| 元件 | 定義（Gallery，意譯） |
|---|---|
| Modal（Dialog） | 疊在內容上，**要先處理它才能回到下面** |
| Popover | 從某元素彈出、**點擊觸發**、可放可互動元素 |
| Tooltip | 滑過觸發、只顯示說明 |
| Toast（Snackbar） | 像推播通知的提醒，不擋操作 |

**實驗**（2026-11-08，Opus 5.5、claude.ai 無痕新對話、團隊待辦單頁四功能、三種寫法各 3 次、Playwright 540×960 操作判分）：A「跳出視窗」中位數 3、B 指名元件 4、C 白話寫行為 4。唯一差別在「點頭像」：**A 三次都做成全頁遮罩的置中對話窗**，B／C 六次都是頭像旁的小面板。🔴 預訂門檻是 B 要比 A 多 2 分才算證明，**實際只差 1 分、未達門檻**；A 版的 CSS 類別也叫 tooltip／toast／dialog——模型本來就懂這些名字，只是沒被告知要哪一個。

寫法：知道名字就寫名字；不知道就寫清楚 **疊在哪、用什麼觸發（點或滑過）、要不要先處理才能回去、會不會擋其他操作**。

**元件清單實驗**（Fable 5.2 篇，另組 Opus 5.5、拆帳 App 元件展示頁各 5 份，29 種標準評分）：沒給名稱清單中位數 **12／29**，給 31 條名稱清單 **27／29**。🔴 B 組本來就拿到更多具體需求，不代表模型學會新能力，也**不是 Fable 5.2 vs Opus 5.5 的比較**；判準（Dialog 要有標題與確認／取消、Accordion 至少三列）放寬會改變分數。

### 3. 動態：寫出毫秒、像素、曲線

transitions.dev 免費版 CSS 數值（2026-11-09 讀取，**官方範例值、非業界標準**）：

| 轉場 | 動作 | 開／關（ms） |
|---|---|---|
| Modal | scale 0.96＋透明 → 100%＋淡入 | 250／150 |
| Dropdown | 97% → 100%，可設展開原點 | 250／150 |
| Toast | 下方 16px、模糊 2px、97% → 定位清晰淡入 | 350／250 |

規律：**開比關慢**；三組同一條曲線 `cubic-bezier(0.22, 1, 0.36, 1)`；都附 `prefers-reduced-motion` 關轉場。給 AI 的寫法範例（aiposthub 自組）：「彈窗開啟從 96% 放大並淡入 250 毫秒、關閉 150 毫秒；通知從下方升 16 像素加 2 像素模糊，開 350、關 250；曲線 cubic-bezier(0.22, 1, 0.36, 1)；系統開啟減少動態時關掉轉場。」🔴 只做了並排展示，**沒測使用者偏好**——給數字的目的是可重現、可調，不是證明更好看。更多動作的時長與緩動查表見 [[motion-reference-easing-dictionary]]。

### 4. 文案：AGENTS.md 一句規則＋刪改表

Zihua 貼文的原句：`Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.` aiposthub 建議再補一段自家限制（範例，非逐字翻譯）：

> 介面文案使用使用者熟悉的名稱。刪除不幫助操作的介紹、口號與重複提示，保留完成任務必須知道的錯誤原因、修改方式、權限及費用。每個按鈕說明按下後會發生的事。

測試（2026-11-08，Opus 5.5，設定頁與產品介紹頁各有無指令 × 5 次；🔴 **指令加在提示詞前，未測 agent 實際讀 AGENTS.md**；字數＝中文字＋英文單字×2）：設定頁中位數 130 → 52、介紹頁 553 → 245。副作用見 B 段（不可復原提醒被刪）。設定頁以操作為主、介紹頁要講清產品與條件——**不能用同一個字數目標管兩種頁**。

驗收：請 AI 同時交**刪改表**（原句、保留／刪除理由、對應情境）；用三情境走一次（第一次進來、輸入錯誤、完成操作）；按鈕與成功訊息用同一個動作名稱（「儲存設定」→「已儲存」）。

### 5. 設計參考：先說要借什麼，再補狀態

- 寫明要借用哪一部分（字體層級、側欄密度、展開方式），不要只說「做得像這張」——否則 AI 分不出必要內容與範例品牌的裝飾
- 參考影片要留出處；看到「某模型做的」先找原作與作者說明，再決定能不能當能力證據（Dom 的「Fable 5.2 真的會設計」是作者自述、無可重跑提示詞）
- 影片看得出方向與速度，看不出**觸發條件**（同樣的卡片放大可能是點擊、滑過或捲動）→ 補一句：「點卡片後圖片在 600 毫秒內展開成詳情頁，按返回反向收回原卡片，動畫途中可取消」（時間為示範值）
- 比較提示方式時固定內容、尺寸、通過條件；**先對照幾何位置與操作，再評美感**

狀態表（以側欄為例）：

| 狀態 | 需求要補的內容 |
|---|---|
| 展開與收合 | 寬度、文字是否隱藏、焦點留在哪 |
| 選中項目 | 怎麼表示目前位置 |
| 長標題與很多項目 | 換行、省略或捲動規則 |
| 載入與失敗 | 等待提示、重試入口、保留哪些內容 |

元件互動驗收（正常／等待／失敗）：

| 元件 | 畫面之外要檢查 |
|---|---|
| 金額輸入 | 空值、小數、負數、上限 |
| 檔案上傳 | 失敗能否重試、進度是否對應真實傳輸 |
| 確認對話框 | 取消是否保留資料、鍵盤焦點 |
| 倒數計時 | 歸零後狀態、重新整理是否改變結果 |

AI 說完成後先測：最主要操作 → 空資料 → 長文字 → 取消流程。

## C（關鍵行動）

- [ ] 下一個 AI 做的頁面：先列「要出現哪些元件」清單（叫不出名字就寫四件事：疊在哪／怎麼觸發／要不要先處理／擋不擋操作）
- [ ] 驗收時對畫面跑一次 unslop 九項清單＋換名測試；只改審出的項目、不拿新流行換舊流行
- [ ] 動效需求一律寫毫秒、像素、曲線與 reduced-motion
- [ ] 若在 AGENTS.md／CLAUDE.md 加減字規則，同時寫明「保留錯誤原因、權限、費用、不可逆後果」，並要求交刪改表
- [ ] 用截圖或影片當參考時，旁邊列出要借的部分＋觸發＋狀態＋通過條件，做成一張工作單照著驗
