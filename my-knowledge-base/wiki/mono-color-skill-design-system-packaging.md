## T（核心論點）

> **Mono Color Skill 最值得看的不是單色海報好不好看，而是它示範了如何把設計師腦中的隱性判斷，
> 改寫成可重複、可檢查、可版本管理的 AI 工作流程。** 設計師 Yan Liu 公開在 GitHub 的開源 AI 設計
> Skill（MIT License），把單色／受控雙色海報設計的判斷邏輯（配色分工、留白節奏、字體角色、
> 印刷質感、評測案例）整理成 `SKILL.md`，讓 AI 能重複讀取並產出一致風格的視覺成果，而非每次
> 重新描述 Prompt。這是知識資產化（MAPS/Skills）範疇的方法論示範：把「這張圖不對」的直覺，
> 拆成色票、留白、字體角色、禁止事項與驗收條件，讓個人經驗變成可交接的系統。

真正的差異不是字數——把一大串 Prompt 存起來，仍可能只是「更長的單次指令」；Skill 的價值在於
把設計決策**分層管理**，讓人知道哪一份檔案負責色彩、哪一份負責構圖，修改後也能用評測案例檢查
有沒有破壞原本規則。

## B（適用場景）

**適用：**
- 需要長期維持品牌視覺一致性的設計師、內容團隊、小型公司（電子報、podcast 封面、活動海報等
  高頻重複輸出場景）
- 想把「隱性設計判斷」轉成可版本管理、可測試、可交接的系統，而非停留在個人經驗
- 評估是否要為自己的知識庫或工作流建立第一版可版控 Claude Skill，需要具體 MVP 步驟參考

**不適用 / 注意：**
- 偶爾做一張圖時，直接寫 Prompt 可能更快；長期維護一套 Skill 系統有前期成本
- 規則完整不代表每次生成都一樣，最終圖片仍受模型/版本/隨機性影響，需用自己的真實案例重複
  測試（一次通過率、修改輪數），不能只看官方精選範例
- 第三方 Skill 可能包含高權限指令（讀檔案、執行 scripts、呼叫外部工具），安裝前應比照審查
  軟體的標準檢查 `SKILL.md`、`scripts/`、外部連線與寫入行為
- 授權分層：程式碼／Skill 指令採 MIT License 可自由使用修改，但 `examples/` 範例圖片受
  Visual Asset License 限制，未經作者書面許可不得商用

## R（把美感拆成可執行規則的具體做法）

1. **先把每次需求整理成固定配方**：不直接把主題丟給圖片模型，而是先判斷主體、用途、文字、
   圖片角色、畫面比例、配色、構圖、字體層級與印刷處理，整理成固定配方；未指定需求時有預設值
   （如直式 3:4、中性白底、受控雙色），避免 AI 每次為了「有創意」任意更換版面
2. **顏色是分工，不是裝飾**：預設最多兩個墨版，主墨版佔印刷區域約 70%～85%，輔墨版約
   15%～30% 且須有明確任務（如只負責日期或一個幾何標記），阻止 AI 隨機加色
3. **留白負責節奏**：紙張留白維持畫面 25%～55%，用於控制閱讀順序；同時保留一個刻意的
   「打破點」（偏移裁切、放大單字、旋轉標籤），避免版面過度安全
4. **字體按功能分角色**：依內容功能分工（安靜敘事用文學襯線字、文化活動用 Grotesk、公共資訊
   用窄體字、補一句話用手寫字），而非一律套用「粗體大標題＋小字說明」
5. **印刷質感預設克制**：現行版本預設「當代編輯設計＋受控雙色」，不預設復古做舊；網點漂移、
   套色偏移、乾邊等做舊質感需使用者明確要求才啟用
6. **用評測案例守住規則**：專案含評測案例、資料格式與 GitHub Actions 自動檢查，機器負責攔截
   可量化錯誤（規則衝突、配色 ID 不存在），設計師負責判斷資訊層級與整體品質
7. **建立自有 Skill 的 MVP 五步驟**：① 只選一種輸出尺寸 ② 寫 5-10 條不可違反規則
   ③ 參考資料分檔存放（色票/字體/Logo/版型/文案各自存放，不全塞進 SKILL.md）
   ④ 準備 5 個真實測試案例（正常需求、長標題、沒有照片、人物照片、衝突指令）
   ⑤ 保留人工決策點（正式商用前人工複核文案、圖片權利、品牌一致性）

## C（關鍵行動）

- [ ] 若團隊每週重複寫相似 Prompt，優先盤點「每天都在重複的決策」，做成第一版 Skill 而非
      再寫一份萬用神 Prompt
- [ ] 安裝第三方 Skill 前，先讀 `SKILL.md`/`scripts/`，鎖定版本，在沒有敏感資料的獨立專案測試
- [ ] 建立設計/內容類 Skill 時比照本篇 MVP 五步驟：單一輸出尺寸、5-10 條硬規則、參考資料分檔、
      5 個真實測試案例、保留人工複核點
- [ ] 引用開源 Skill 專案的範例素材前，先確認程式碼授權（MIT）與素材授權（Visual Asset License
      等）是否分離，避免誤用示範圖片商用
