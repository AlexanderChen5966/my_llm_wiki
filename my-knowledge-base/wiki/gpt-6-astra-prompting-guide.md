> **世代關係**：本條目是 **GPT-6 Astra** 的官方提示詞指南；前一代 **GPT-5.6 Sol** 的官方指南見
> [[gpt-5-6-prompting-4-elements-framework]]（目標／背景／輸出／邊界四要素、「別微管理強模型」）。
> 兩者**不衝突可並存**：四要素是提示詞的骨架，本篇是針對 Astra 特定行為傾向的校正貼片。

## T（核心論點）

> **這一代的提示詞不是在「教模型怎麼做」，而是在「校正它的預設習慣」。**

OpenAI 點出 Astra 的五項行為傾向，每一項給一段可直接寫進系統提示或設定檔的提示詞：

| 預設行為 | 症狀 | 校正方向 |
|---|---|---|
| **主動性與跟進** | 長任務連貫性比前代好；但指令模糊時**更可能回頭詢問而非自行假設**，無人值守任務會因此中斷 | 授權自行完成全程，劃出可逆／不可逆界線 |
| **指令遵從與技能檔** | 對 `SKILL.md`、`AGENTS.md` **更敏感**；檔案不清楚或互相衝突會讓它提早暫停或偏離意圖 | 明訂效力順序＋要求指認影響來源 |
| **寫作風格** | 預設偏好列表、表格與 Markdown；可能跨對話重複使用固定句式 | 明確指定較少格式化的輸出方式 |
| **子代理分工** | 委派子代理的頻率**低於**工作流程所需 | 訂出平行化門檻 |
| **測試與驗證** | 認定完成前傾向完整驗證，小改動的測試範圍可能超出需要 | 給三條件判準控制驗證規模 |

⚠️ **這些模板調整的是行為傾向，而非能力上限。** 模型停下詢問有時是因為指令確實缺少關鍵資訊；把授權提示詞開到最大，它可能帶著錯誤假設一路執行，**後續修正成本反而更高**。授權的前提是任務描述本身已經足夠完整。

## B（適用場景）

**適用：**
- 從 GPT-5.x 遷移到 Astra，發現它變得「更愛問」「格式化過度」「測試跑太多」
- 有多份 `SKILL.md` / `AGENTS.md` 的環境，模型行為變得難以歸因
- 需要無人值守跑完整段任務的 agent 流程

**不適用 / 注意：**
- 第四節（子代理分工）**只適用於具備多代理架構的環境**，單一對話可跳過
- ⚠️ 這些提示詞**不會取代**平台安全、工具權限或系統層級限制，也不凌駕於其上
- ⚠️ **模板之間會互相牽制**：當「不要詢問、直接完成」與技能檔中「逐步確認」的規則同時存在時，效力順序那一段就不能省略
- 官方範例都是英文，來源已改寫為中文模板；導入前建議用自己的典型任務測過

## R（五組校正提示詞）

### 一、讓模型少問多做

**授權自行完成全程**——關鍵在最後一句劃出的界線：

> 請從指令與先前對話中推斷使用者的意圖與任務範圍，以行動為預設值，把使用者想完成的任務推進到結束……必要時可自行建立隔離的 worktree 或 checkout、解決合併衝突、執行唯讀操作或開立草稿 PR，**除非該動作明顯具破壞性或不可逆**。

🔑 **這比只寫「請自主完成」清楚得多，模型知道哪裡可以放手、哪裡該停下。**

**🔴 中文語感陷阱**：中文的請求常以問句呈現。「**可以幫我改一下嗎**」在語感上是要求執行，模型若把它理解成**能力確認**，可能只回「可以，我會這樣做」便停止。

> 當使用者的訊息帶有請求行動的語氣，例如「可以幫我……」、「我想要……」、「幫我看看……」，一律視為執行指令，直接開始工作。不要停在確認自己做得到、提出計畫或詢問是否繼續。也不要為了節省時間或步驟，交出僅部分完成的結果。

**規定確認的時機**——先把已授權且能讓成果變具體的部分做完，再提問：

> 在向使用者提出確認問題之前，先完成脈絡中已獲授權、且能讓提案變得具體可審的工作。**使用者應該是在審核一個成品，而不是一個構想。** 部署變更、寫入外部系統、合併 PR 或發布網站之前，先把前置工作全部做完，讓使用者的核准成為最後一個動作。可逆操作、唯讀查詢、檢查與修正，或先前已授權的事項，不需要再次徵求同意。**不要因為假設性的風險，就自行加入使用者沒有要求的警語、免責聲明、審核流程或安全合規檢查清單。**

（最後一句與 [[ai-agent-forbidden-tasks-agents-md]] 的明禁清單呼應）

### 二、使用者指令高於技能檔

> 使用者的指令優先於技能檔中的指引。若使用者的明確指令與技能檔內容衝突，以使用者指令為準。

**並要求模型指認影響來源**（多技能檔環境特別實用）：

> 若某個技能檔導致你請求許可、暫停、留下未完成的工作，或偏離使用者意圖，請列出並連結你實際讀取的 `SKILL.md` 檔案，引用該條指示原文，並說明它如何適用。**同時區分哪些是技能檔的明確要求，哪些是你自己的解讀。**

例：使用者要求直接覆蓋原檔，模型卻每次都先問要不要備份——加入這段後，它能指出是哪一份 `SKILL.md` 的哪條「先確認」規則造成停頓，以及那是明確要求還是自己的推論。

### 三、規定寫作風格（三段不同用途）

- **一般敘述**（報告、說明文件）：以段落為主，每段發展一個主要論點；只有資訊確實平行、具先後順序或需並列比較時才用列表；**避免巢狀列表**；主要論點放開頭，用字平實、主動語態
- **技術說明**（工程文件、教學稿）：白話優先於術語，技術細節只在有助說明時出現，**依使用者透露的背景深淺調整專有名詞密度**
- **去罐頭文**（對外文案）：避免「總而言之」「簡單來說」「值得注意的是」「深入探討」「賦能」；**不要補述你不會做什麼**；🔑 **明禁「不是 X，而是 Y」這類對比句式——那會引入使用者從未提及的替代方案**；不要自創複合名詞標籤或制式轉折語

### 四、判斷什麼時候拆任務給子代理

> 只要有機會透過委派任務給其他代理來平行處理工作，且這麼做能節省時間或提升品質，就應該使用協作工具進行分工，**無論你目前是主代理或子代理**。

另加可讀性要求（代理間訊息與最終回覆都可能由人閱讀）：**確保內容易讀，在文字與數字之間保留正確的空格**。

### 五、控制驗證的規模（三條件判準）

要不要跳過測試，看三件事**是否同時成立**：① 這次改動可以還原 ② 影響範圍很小 ③ 寫出來的測試只是把程式碼邏輯再講一次。三個都符合就不必另外寫測試；其他情況照測，但**只跑跟這次改動有關的部分，通過之後就停手**。

> 對於可逆、影響範圍小、且測試內容只是複述實作邏輯的變更，不需要另外撰寫測試。若決定以測試驗證，請確保測試對驗證實作本身有意義。執行與本次變更相關的測試並完成必要檢查，通過之後，除非出現新的變更、失敗或未解決的疑慮，否則不要擴大或重複測試，直接繼續推進任務。

## C（關鍵行動）

- [ ] 遷移到 Astra 前，**先稽核** `AGENTS.md`、`SKILL.md` 等指令檔，清掉過時、模糊、互相衝突的要求（Astra 對這些檔案更敏感）
- [ ] 在系統提示加入「使用者指令優先於技能檔」——多技能檔環境不可省
- [ ] 中文環境務必加「可以幫我……＝執行指令」那段，否則會被讀成能力確認
- [ ] 推理強度設定：原本用 `none` / `minimal` 的應用改從 `low` 測起

## 補充資料

### 三項與提示詞相關的設定

- **推理強度**：🔴 **Astra 不支援 `none`**。原本用 `none` 或 `minimal` 的應用，官方建議先從 `low` 測起並比較結果；其餘維持原本等效強度後逐一對照
- **對話中途調整推理深度**：`configuration_update` 輸入項目可在長對話中為困難工作拉高推理強度、為例行追問調低，**而不必改寫原始提示詞前綴，因此有助保留快取**。設定持續生效直到下一個 `configuration_update` 覆蓋。官方建議用於標準、單代理請求
- **從 GPT-5.x 遷移**：比提示詞本身更該優先做的，是稽核模型可讀取的 `AGENTS.md`、技能檔與其他指令檔

### 第三家媒體轉述的三項增量（2026-09-15 併入）

來源：https://www.aiposthub.com/gpt-6-astra-skills-agents-md-prompt-guide/ （aiposthub，同一份 OpenAI 官方指南的第三次轉述，核心規則與上述兩條目重疊約 70–80%，僅下列 3 點具增量價值）

- **「任何／所有／相關／一般」等過廣字眼是 Skill 描述警訊的具體判準語彙**：Skill 描述若出現這類詞彙，通常代表觸發條件寫得太寬，容易讓 Agent 在只碰到同領域名詞、卻沒進入該專門流程時也被誤觸發。理想描述要同時包含「做什麼」與「何時使用」兩個要素。
- **「5 步整理法」稽核流程**（可作既有補充資料的操作清單版本）：
  1. 盤點會自動生效的指令（Skills、`AGENTS.md`、系統 Prompt、常用任務範本，找出重複與過時內容）
  2. 縮小每個 Skill 的觸發條件（描述需同時回答「做什麼」與「何時使用」）
  3. 把長 Skill 拆成「入口＋分流」（`SKILL.md` 只保留共同原則與選路邏輯，背景資料/腳本/範本移到 `references/`／`scripts/`／`assets/`）
  4. 保留真正重要的決策邊界（正式環境寫入、刪除資料、公開發布、付款、權限調整等仍需明確確認條件）
  5. 用三類任務做回歸測試（一個小修正、一個標準功能、一個高風險操作，比較調整前後是否選對 Skill、讀對文件、在正確位置停下）
- **「每次更換主要模型都應重新驗證 Skills 與專案指令」提醒**：這不是一次性設定，而是模型升級週期的一部分——換模型後應用一組代表性任務重新測試，精簡後的版本若出現漏讀重要文件、跳過必要檢查或誤判授權，才把對應規則加回去，且要綁定清楚的觸發條件。

來源：https://www.kocpc.com.tw/archives/668795 （電腦王阿達，同一份 OpenAI 官方指南的第四次轉述，核心規則與上述條目重疊 70-80%，僅下列 2 點具增量價值）

## 補充資料：GPT-6 家族三層定位與價格（2026-09-29 併入，非提示詞主題）

來源：https://rar.design/posts/gpt-6-sol-luna-guide （設計師 Riven，2026-09-23；OpenAI 於美國時間 2026-09-22 發表 GPT-6 Sol／Luna）。本條目的 T 是提示詞校正，此段屬模型選型資訊；因本庫目前只有這一條 GPT-6 家族條目，暫掛於此。

### 🔴 世代混淆提醒：GPT-6 Sol ≠ GPT-5.6 Sol

- **GPT-5.6**：Sol／Terra／Luna 三級，**Sol 是旗艦**（本庫 [[chatgpt-chat-work-codex-comparison]]、[[codex-desktop-2026-onboarding-guide]] 記載的分級即此代）
- **GPT-6**：Astra／Sol／Luna，**旗艦是 Astra，Sol 由旗艦下降一格**；本次公告**未提 Terra**
- 名稱沿用但定位變了——凡引用「Sol」「Luna」都要標明世代

### 定位與價格（OpenAI 官方，經作者整理）

| | Astra | Sol | Luna |
|---|---|---|---|
| 定位 | 最強，要最好的結果 | 複雜 coding、專業工作、agent 工作流 | 大量、目標明確的任務 |
| API 價格（每百萬 token 入／出） | $10／$50 | $2／$10 | $0.10／$0.50 |
| 快取讀取 | $1.00 | $0.20 | $0.01 |
| 推理強度 | low～max | none～max（預設 medium） | none～max（預設 medium） |

⚠️（2026-10-08 補）DevDay 2026 的 OpenAI Decisions API 原文只寫「Luna」，未說明是 GPT-6 Luna 或專用變體、未公布價格——本段 $0.10／$0.50 **不可套用**到 Decisions API。→ [[decision-model-ecosystem]]

- **快取讀取只收一折**；中途改推理強度或開關工具**不會使快取失效**
- **單次輸入 >272K tokens**：整筆輸入與快取讀取 **2 倍**、輸出 **1.5 倍**——長 context 任務要把這個門檻算進每任務成本
- API 名 `gpt-6-sol`／`gpt-6-luna`；context 1,050,000 tokens、單次輸出上限 128K
- 與 GPT-5.6 促銷價比較：Sol $4/$20 → $2/$10、Luna $0.20/$1.20 → $0.10/$0.50
- 開放範圍：ChatGPT Work 與 Codex（Plus／Pro／Business／Enterprise／Edu），一般聊天尚未上線；Free／Go 僅桌面版 App 可用 Luna（截至 2026-09-23）
