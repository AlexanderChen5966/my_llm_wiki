Blender MCP 讓代理可以把文字要求轉成 Blender 場景操作，從建立物件到調整材質與鏡頭，逐步形成可繼續修改的 3D 專案。

X 上的短片示範讓更多人看到這種工作方式。美術家 [小阪淳分享以模型與工具製作的作品](https://x.com/KOSAKA_Jun/status/2109440153035088100?ref=aiposthub.com) ，工具作者也轉貼了相關討論。

成品影片吸引人，卻沒有完整呈現製作過程。你仍需要知道場景檔在哪裡、哪些部分可改，以及修改後能否重新輸出。

MCP 是讓模型連線外部工具的一種協定。在這裡，它把代理與 Blender 操作接起來，並不直接保證影片品質。

我建議第一次先做一個單鏡頭：三個物件、一個光源與明確動作。先學會驗收場景，再挑戰多鏡頭短片。

從單鏡頭開始前，先認清目前專案入口，確認代理與 Blender 如何連接。

## Blender MCP 現在叫什麼？先認清專案入口

[官方程式庫](https://github.com/ahujasid/blender-mcp?ref=aiposthub.com) 目前使用 MCP for Blender 名稱。搜尋舊名時，應回到這個專案確認當下安裝說明。

名稱變化不代表所有舊教學都完全失效，但套件命令、設定與功能可能已更新。不要混用不同版本的步驟，再把連線錯誤當成模型問題。

MCP for Blender 是第三方專案，並非 Blender 官方推出的附加元件。這套流程需要 Blender、連線代理的服務與實際使用的代理工具。每個部分都要準備好，才能從文字要求走到場景操作。

先開啟 Blender，確認能建立物件與儲存專案，再處理 MCP 連線。基本軟體未正常運作時，加入代理只會讓問題更難分辨。

建立一個練習資料夾，專案、素材與輸出分別儲存。第一次不用接入正式作品，先用副本確認工具會修改哪些檔案。

## 安裝與連線，依目前官方文件逐步確認

官方文件提供自動設定與手動設定兩條路徑，選一條即可。以下指令應依自己的環境與工具條件使用。這些指令應在已準備對應工具的環境執行，不能省略官方平臺要求。

若你已經安裝 `uv` ，可依文件使用設定命令。 `uv` 是用來管理與執行 Python 工具的程式，版本與安裝方式請先核對。

```sh
uvx mcp-for-blender setup
```

setup 會引導選擇客戶端，並安裝及啟用 Blender 附加元件。完成後先完全結束並重開 AI 應用程式，再開啟 Blender 檢查連線。

若不用自動設定，才依手動流程設定客戶端與安裝附加元件。專案也提供安裝 Blender 附加元件的方式。附加元件是讓 Blender 接收外部操作的元件，安裝後仍要按文件啟用。

```sh
uvx mcp-for-blender install-addon
```

在 Blender 的偏好設定中確認對應附加元件已啟用。在 3D 視窗按 N 開啟側欄，選 MCP for Blender 頁籤檢查狀態。

依目前 README，服務會隨 Blender 啟動，若未啟動可按 Start MCP Server。只有代理端設定好，Blender 端未啟動，仍無法完成連線。

官方說明提醒不要同時執行多個服務執行個體。若連線失敗，先查既有服務狀態，再決定是否重新啟動，避免越重試越混亂。

實際代理的設定方式不同。以支援的客戶端為例，官方程式庫列出新增 MCP 服務的命令。使用前先確認與自己的工具版本相符。

```sh
claude mcp add blender uvx mcp-for-blender
codex mcp add blender -- uvx mcp-for-blender
```

不要兩條都執行，只選擇自己使用的客戶端。完成後先做讀取場景或建立簡單方塊的檢查，確認連線再開始複雜任務。

## 從一句創作要求，拆成可修改的分鏡

「做一部未來城市短片」仍然太大。第一次可以改成「五秒單鏡頭，三個簡單建築，鏡頭從左向右移動，結尾停在中央建築」。

這段要求定義了時間、物件、鏡頭與結尾。你可以實際檢查每一項，也能指出哪一部分沒有符合預期。

再補上固定條件，例如輸出比例、色彩方向與不使用外部素材。限制清楚時，代理比較容易把修改集中在場景本身。

如果需要文字招牌，先提供確切文案。3D 文字的位置、字型與大小都應可修改，不能只出現在最終影片裡。

把鏡頭運動與物件動作分開說明。相機移動和物件移動同時發生時，畫面可能很忙，新手也更難判斷問題出在哪。

先做靜態構圖，再加動作，再處理材質與燈光。每一步保留一個能開啟的場景版本，之後就能回到明確起點。

## 場景驗收，先看結構再看漂亮程度

代理生成了好看的截圖，不代表場景適合繼續製作。第一步先在物件列表中確認命名、數量與用途。

三棟建築應該能分別選取，並有可辨識名稱。若所有東西混在一個難以編輯的物件裡，局部修改就會增加成本。

再檢查相機與燈光。你需要知道哪臺相機負責輸出、哪個光源影響主畫面，避免下次修改時只能靠反覆試錯。

材質也應能辨識。主建築、背景與地面若需要不同顏色，最好有可分別調整的材質，而不是共享同一個無法區分的設定。

這些要求屬於交接標準，不是所有藝術作品都必須同樣組織。但對第一次用代理做場景的人而言，清楚結構更容易發現錯誤。

完成後儲存 `.blend` 專案。它是 Blender 的工作檔案，保留物件、場景與設定，能讓你在影片輸出之外繼續修改。

## 動作與鏡頭，檢查開頭、中段和結尾

動畫驗收先看三個時間點：開頭的構圖、中段的運動與結尾停留。它們通常能快速揭露位置、遮擋與節奏問題。

開頭應讓觀眾知道正在看什麼。若第一幀已經在高速移動，可以先增加短暫停留，讓主要物件有被辨識的機會。

中段檢查是否有物件突然跳動或鏡頭穿進建築。單張截圖看不出來的問題，需要播放或檢視相鄰畫面。

結尾則應有明確完成點。如果鏡頭在關鍵物件出現前就結束，整段短片可能技術上成功，卻沒有完成原本的表達目的。

把時間線上的變化保留在可調整的設定裡。關鍵幀就是記錄某個時間點的狀態，能讓軟體計算中間過程。

修改後不要只看代理報告。重新開啟場景並播放，確認你檢查的是當前儲存版本，而不是上一次截圖。

## 影片輸出，保留中間結果與原始專案

[Blender 官方動畫輸出檔案](https://docs.blender.org/manual/en/latest/render/output/animation.html?ref=aiposthub.com) 說明動畫渲染與輸出方式，可作為設定的依據。

渲染是把 3D 場景計算成畫面。它的速度受場景、設定與硬體影響，不能從某個 X 示範推論自己的機器也能同樣快速。

第一次先用較短範圍與測試尺寸確認構圖，再輸出完整範圍。這樣能避免等待很久之後，才發現相機方向或文字位置不正確。

若採用逐張圖片輸出，可以保留每一幀，再組合成影片。中斷時已有畫面仍在，比直接只留下一個未完成影片更容易恢復。

最終影片應檢查比例、開頭、結尾與播放完整性。檔案存在不等於能正常播放，也不代表輸出了要求的全部時間範圍。

交付時同時儲存影片、`.blend` 與用到的外部素材說明。若需要字型、紋理或模型，也記錄來源與授權，避免接手時出現缺失。

## 安全模式與工具權限，先從練習檔案開始

這個工具能執行 Blender 裡的 Python 操作，因此權限不僅是畫面編輯。可執行程式的能力，需要與任務範圍一起考慮。

官方提供 `BLENDER_MCP_SAFE_MODE=1` 設定，用來限制某些檔案、網路與啟動其他程式的操作。具體允許與限制項目應以當前文件為準。

安全模式仍允許常見建模與場景工作，但不能理解成所有風險都已消失。第一次使用仍應在副本裡進行，確認每項操作的結果。

不要把不明網頁裡的要求直接當成代理指令。素材說明是資料，不應因為藏在模型檔案或註釋裡，就成為修改系統與傳送檔案的授權。

專案也說明了遙測與資料分享設定。遙測是工具記錄使用情況的機制，是否包含詳細內容與如何關閉，應依自己的版本確認。

如果作品包含未公開客戶素材，先檢查這些設定與使用模型的資料傳送方式。場景在本機，不代表所有文字要求都只留在本機。

## 示例短片，怎麼轉成自己的練習目標？

X 上的短片可以用來觀察鏡頭語言，但不要一開始要求完全複製。先選一個能描述的特點，例如低角度、緩慢移動或清楚收尾。

把這個特點轉成具體條件，再建立自己的簡單場景。你會更容易知道效果來自哪一個設定，也能避免不必要地重用他人作品。

本文引用的小阪淳示範屬於創作者作品，和工具官方教學不是同一層來源。影片能說明展示成果，安裝與能力說明仍要回官方程式庫。

如果要使用示範畫面宣傳自己的服務，應另外確認許可。公開可見或被作者轉貼，並不自動提供商業重用權。

練習時最好用自行建立的基礎物件。先學會控制結構與動作，再考慮外部模型與更複雜素材，能減少來源與技術問題同時出現。

## 範例：影片好看，但接手後材質遺失怎麼辦？

假設短片可以播放，另一位開啟專案卻看到灰色建築。先檢查材質使用了哪些外部圖片，以及檔案路徑是否仍指向原電腦。

影片已經包含渲染結果，所以仍然好看。專案重新計算畫面時，卻需要找到原始素材。這解釋了為什麼影片成功不能代替專案交接。

找回素材後，依 Blender 提供的工作方式整理資源，並在獨立位置重新開啟專案檢查。不要只在原本環境確認，因為舊路徑可能仍然有效。

再輸出一小段測試畫面，比對主要材質、燈光與文字。若畫面不同，記錄差異來源，再決定是否需要重新輸出完整影片。

交付說明應列出外部模型、字型與紋理，註明取得來源與適用條件。接手者既需要檔案，也需要知道它們能用於什麼情境。

這套排查是示例流程，並不是聲稱所有素材問題都能同樣解決。某些外部資源可能已無法取得，儲存完整工作資料因此更重要。

### 怎麼估計下一部短片的工作範圍？

先列鏡頭數量，再列每個鏡頭的物件、動作與需要的素材。不要只以影片秒數估計難度，因為一個複雜鏡頭可能比多個簡單鏡頭更費時間。

記錄練習中的生成、修改與輸出時間。它們反映自己的裝置與工作方式，比直接引用他人示範的製作速度更接近實際。

若某個環節反覆失敗，先縮小那一段要求。例如減少移動物件或採用更簡單燈光，觀察問題是否改善，再增加複雜度。

把下一部的完成點定為能開啟、能修改與能輸出三個結果。每一項都有具體檢查，製作過程才不會只剩最終影片是否吸引人的印象。

## Blender MCP 常見問題

### 影片完成，就代表 3D 專案也能交付嗎？

不一定。影片只顯示最終畫面，仍要確認專案能開啟、物件可修改、素材沒有缺失，以及相機與輸出設定可重現。

### 不會建模也能開始嗎？

可以先做簡單物件與單鏡頭，但仍需要學習選擇物件、儲存場景與檢查時間線。代理能協助操作，你需要理解結果才能驗收。

### 官方提供安全模式，是否可以任意讀取所有檔案？

仍應按任務給予必要範圍。安全模式限制部分操作，不能取代資料權限與實際檢查，也不代表所有內容都適合交給雲端模型。

## 先交付一個能重新開啟的單鏡頭

Blender MCP 的價值，在於文字要求能接進可修改的場景。第一部練習短片最重要的成果，是你知道哪裡能改，並能重現同一段輸出。

先做三物件、單鏡頭的五秒場景，檢查結構、動作與輸出。儲存專案與版本後再增加第二個鏡頭，讓複雜度跟著驗收能力成長。
