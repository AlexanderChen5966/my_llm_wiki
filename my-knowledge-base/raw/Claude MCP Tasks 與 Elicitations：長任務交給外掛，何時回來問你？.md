Claude MCP Tasks 要解決的，是研究做到一半還在等待時，你不知道工作究竟有沒有繼續的問題。因為外掛可能花很久整理資料，對話視窗的安靜，很容易被誤認成失敗。

Claude 開發者官方帳號在 2026 年 10 月 23 日宣布，Claude 加入 MCP Tasks 與 Elicitations 支援，讓外掛可以接下深度研究等長工作，完成後再回報。

MCP 是讓 AI 與外部工具溝通的協定。這次新增的機制，把「工作交出去之後怎麼追蹤」及「缺少條件時怎麼問你」放進工具之間的對話。

這對經常用外掛查資料的人有用，因為原本一次呼叫必須等到最後，現在可以用明確狀態辨認進度。但這也需要你使用的客戶端與外掛都實作相應能力。

如果只是請 AI 改一句文案，差異可能不大。當工作要跨多個資料來源、需要追加研究範圍時，可追蹤與可補問，才開始影響整個流程是否順利。

要理解這次更新，可以先想像你把一份研究交給同事：交辦成功、對方正在做，以及成果已驗收，是不同階段。

## Claude MCP Tasks 如何讓長工作變得可追蹤？

Tasks 為花比較久的工具工作保留一個可以查詢的身分，讓呼叫端不必把整段等待都塞進同一次回覆。依 [MCP Tasks 規範](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/tasks?ref=aiposthub.com) ，任務會有狀態，也可以在結果可用後取得內容。

你可以把它理解成寄件單號。拿到單號代表系統知道是哪一件包裹，但包裹抵達哪裡，仍要看後續紀錄。同樣地，工具接受任務後，使用者還要分清執行中與完成。

### 工作狀態代表什麼？

規範列出的狀態包括工作中、需要輸入、完成、失敗與取消。這些名稱把等待拆開，所以遇到卡住的工作，可以先確認是在跑、在等資料，還是已經停止。

例如你要求整理一個領域的研究，外掛可能先完成搜尋，接著發現「近年」的期間不夠明確。如果任務進入需要輸入的狀態，這時候應該補上日期條件，再決定後續處理方式。

但進度狀態並不等於每一個研究步驟都已公開。工具提供多少細節，仍取決於它的實作。因此使用者看到工作中時，可以期待有可追蹤的狀態，不能直接推定會得到完整的內部思考紀錄。

完成也只表示這次協定要求的工作已經產生結果。若工具回來的是一份含缺漏的報告，客戶端可能已成功取回內容，但你的研究目的仍沒有達成，還是得檢查來源與範圍。

這個差別會影響重試。因為當工具已做完、只是回傳出了問題，再送一次完全相同的工作，可能重複消耗資源。先讀任務身分與狀態，有助於判斷應該接續取回結果，還是重新執行。

### 為什麼不能把取消當成立刻清空一切？

取消是向工作端提出停止要求，但已經發生的動作不會因此自動倒轉。例如研究外掛已讀取一批資料，取消後並不能假設所有暫存、費用或外部變更都被復原。

對需要寫入其他服務的外掛，這點尤其重要。如果工作中途已建立文件，應該讓工具清楚回報目前產物，再決定是否保留，否則使用者會把取消誤解為整件事從未發生。

Tasks 提供追蹤的骨架，實際產品還得把這些狀態翻成容易理解的介面。使用者需要的答案很直接：做到哪裡、還欠什麼，以及接下來可以做什麼。

## Elicitations 如何補問，又讓使用者保有決定權？

Elicitations 讓工具在需要條件時，透過客戶端向你索取資訊。依 [MCP 補問規範](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation?ref=aiposthub.com) ，它可以使用表單，也可以引導到外部頁面完成適合在網站處理的步驟。

這補上長工作常見的缺口。因為你一開始交代的要求未必完整，讓工具在遇到分歧時問一個具體問題，通常比替你猜完所有條件更容易修正。

以研究為例，外掛可以詢問報告的讀者是工程師還是主管。兩種答案會改變用詞與深度，所以這是值得補問的決定。若只是字體大小等不影響內容的細節，工具則可以先用合理預設完成。

### 表單適合問哪些資訊？

表單適合讓你提供可整理的條件，例如選擇報告期間、輸出語言或結果數量。因為問題有明確欄位，使用者可以看見送出的是什麼，工具也比較容易檢查資料是否齊全。

但這種方便有範圍。規範禁止透過表單補問密碼、API 金鑰、存取權杖與付款憑證等機密，因為這些內容一旦經過對話與中介系統，就增加外洩的可能。

API 是讓程式串接服務的介面，而金鑰往往代表呼叫服務的權限。若外掛需要登入另一個平台，應該使用符合規範的外部流程，讓你在可信任的目的地完成操作。

一般補問也應提供拒絕或取消的選擇。因為需要額外資訊不代表你有義務交出更多資料，使用者應能衡量提供這項資訊是否符合最初的工作目的。

### 外部頁面與聊天視窗有什麼差別？

網址模式會把敏感操作移到對話之外。例如外部服務要你授權帳號，客戶端可以先說明目的地與用途，再讓你決定是否前往，而不用把第三方憑證貼進聊天。

規範也要求妥善處理網址，避免在連結裡夾帶個資或憑證。因為網址可能被瀏覽器紀錄、日誌或轉貼保存，所以即使是一次性的補問，也不能把連結當成隱密保管箱。

這裡有兩層不同的連線關係。客戶端先連上 MCP 服務，服務另外可能需要連上第三方平台。後者的授權，不能被寫成前者已經取得所有權限。

因此「工具會回來問我」的價值，在於把需要人做決定的地方清楚呈現。問題應該讓你理解接下來會發生什麼，接著才由你提供資訊或拒絕。

## 開發者要怎麼把追蹤與補問接起來？

開發者應先確認呼叫端與服務端支援哪些能力，再設計長工作。因為 Tasks 在 2025 年 11 月 25 日版規範中仍標為實驗性功能，協定存在與所有客戶端都能使用，是兩個不同的條件。

Claude 這次的產品公告，代表官方開始支援相關機制。至於特定外掛能否運作，還得看外掛實作及實際連線。也不能拿 Claude Code 的文件，直接推定 Claude 網頁版所有畫面都長一樣。

如果團隊先前已做一般工具呼叫，可以挑一個耗時、結果容易驗證的工作改造。例如固定來源的文件整理，比跨平台又包含寫入的完整工作，更容易釐清問題發生在哪一段。

### 任務身分與使用者身分都要對得上

規範特別提醒任務存取控制，因為能查任務身分的人，不應因此讀到其他人的結果。即使工作只是研究，結果仍可能包含企業內部資料，所以每次查狀態與取回內容，都要綁定正確的授權背景。

保留任務多久也需要說清楚。因為工具端不必無限保存所有任務，使用者過了很久再來取結果，可能遇到過期。因此介面應提供可理解的回應，避免把「結果已清除」誤報成「從未開始」。

補問則要知道答案屬於哪個人、哪個任務。如果同時有多個研究工作，使用者回答一個期間，不能被錯套到另一份報告，否則兩份結果都可能表面成功、內容卻偏離要求。

這也是測試不能只看正常路徑的原因。開發者要試用戶拒絕補問、工作失敗、任務到期，以及取得結果時暫時斷線，才能知道使用者是否還有明確的恢復方式。

## 一般使用者怎麼試第一個長任務？

先選一個資料範圍明確、完成標準可描述的工作。因為你要驗證的是外掛能否交付可追蹤的結果，若一開始就要求「把整個市場研究完」，很難區分工具故障與要求本身太模糊。

例如可以指定官方網站、日期區間與一份有來源連結的摘要。接到回覆後，先看工作是否有可辨認的狀態，再檢查來源能否打開，以及每個重要結論是否有支持資料。

遇到補問時，可以先判斷答案會不會改變結果。若問題涉及帳號權限或外部寫入，則應看懂用途再決定。如果外掛問的資訊與任務無關，也可以拒絕並縮小範圍。

### 怎麼避免同一件事重做？

工作等了一段時間時，先查原任務是否還在進行。因為長等待本來就是這次機制想處理的情況，連續重新送出同一要求，反而可能讓多份工作一起跑，增加辨認結果的負擔。

如果工具回報失敗，則看它有沒有說明已完成的部分。整理資料完成一半與完全沒有開始，適合的補救方式不同。有現成產物時，接續處理通常比整份重來更容易保留脈絡。

成果回來後，最好選一兩條核心事實反查。因為長任務機制改善的是交辦與回報，資料品質仍取決於來源、工具與整理方法，狀態變成完成不能取代內容查核。

### 把失敗畫面也納入第一次測試

長任務最容易讓人困惑的地方，通常出現在正常流程之外。例如你離開對話後再回來，工作可能已經完成。此時應該取回原結果，避免把重新整理頁面誤當成重新執行的指令。

另一種情況是外掛已取得答案，但傳回客戶端時連線中斷。因為執行與傳輸分屬不同階段，清楚保留任務身分，才能協助工具判斷應該補傳內容，還是重新調用資料來源。

團隊可以用不含機密的固定測試資料，依次試完成、拒答與中斷後接續。每種情況記錄使用者看到的狀態，以及最後得到的內容，這會比只收集一張成功畫面更能看出可用性。

如果外掛會產生文件，還要確認每次成果如何命名、是否保留舊版本。因為同一個研究可能反覆補問，使用者需要分辨哪份內容對應哪次條件，才不會把不同版本混著引用。

這些檢查也能幫助你決定任務大小。當小份研究已能穩定恢復，才把來源數量與範圍增加。若小任務都容易失去結果，就先改善追蹤與回傳，暫時不要再堆更多代理。

## 常用研究外掛的人，可以先驗證恢復與結果

對經常等待研究、分析或文件整理的人，這次更新值得先試。因為工作狀態與補問可以降低來回猜測，使用者有機會在必要時介入，而不用全程守著對話。

但第一個成功案例應包含完整的交付過程：任務被接受、條件被問清楚、結果可取回，而且內容符合要求。這樣才知道工具協作的改善，真的落到自己的工作上。

你可以先把一項固定研究交給已支援的外掛，記錄它如何等待、補問與回報，再決定是否擴大。也可免費訂閱 AI 郵報，持續追蹤各客戶端與外掛的實際更新。

## FAQ：Claude MCP Tasks 常見問題

### Claude MCP Tasks 會讓每個外掛自動變成背景代理嗎？

不會。客戶端與服務端都需要支援相應機制，個別外掛還要正確處理任務狀態與結果。

### 工作完成是不是代表報告已經正確？

完成表示該次工作已回傳結果，報告的事實、範圍與用途仍需要另外驗收。

### Elicitations 可以要求我在聊天輸入金鑰嗎？

規範禁止用表單補問密碼、API 金鑰等機密。涉及第三方服務授權時，應走適當的外部流程。
