Claude Code 背景子代理更新了進度回報方式，官方稱每次狀態更新所需成本降低約 99%。

這個比例指的是單次進度回報，因為代理每隔三十秒就會更新工作狀態。

過去每次回報會重新讀取整段對話，現在則由 Haiku 5.5 根據短筆記撰寫。

官方影片也估計，放到整個 Claude Code CLI 工作階段，約可少用 5% 的額度。

長時間等待背景工作的人因此較能受益，但判斷整體效率仍要把任務執行和完成驗收一起計算。

要看懂這筆節省，得先把代理做事和代理報告進度的兩段工作拆開。

## Claude Code 背景子代理省下了哪一段用量？

這次改善落在回報進度所需的閱讀工作，執行任務本身仍有自己的模型與工具成本。

子代理是 Claude Code 為特定任務啟動的另一個工作角色，它可以用自己的上下文讀資料、操作工具，再把結果交回主對話。因此，主對話能在等待期間繼續處理其他工作。

這種並行方式需要讓人知道代理目前在做什麼。官方十一月四日公告指出，執行中的子代理每三十秒會更新一行工作狀態。

以前，產生這行文字要重新閱讀該代理的整段對話。代理工作得愈久，累積的檔案內容和工具結果愈多，用來報告進度的閱讀量也跟著增加。

更新後，回報改由 Haiku 5.5 根據短筆記撰寫。狀態摘要需要的資料變少，官方因此估計每次更新約可降低 99% 的成本。

官方附圖另把影響放回整個 CLI 工作階段，估計約少用 5% 的額度。這兩個數字各有範圍，前者衡量狀態更新，後者才接近使用者完整工作期間的影響。

如果一項任務的大部分用量來自修改程式和執行工具，回報改善對總量的占比就較小。若背景工作長時間持續，規律發生的回報開銷則更值得減少。

這次公告提供了具體的背景成本來源，但官方估計仍需由個別任務紀錄檢驗。團隊可以把它當成重新觀察工作階段用量的時點。 [官方原始公告與影片](https://x.com/ClaudeDevs/status/2118063143167693011?ref=aiposthub.com)

## 短筆記如何讓進度回報避開整段歷史？

短筆記讓回報者直接取得近期工作要點，省去每次從整段歷史重建摘要的處理。

例如，程式審查代理可能已經閱讀許多檔案，現在正核對一個測試失敗。進度文字只需要交代目前階段，完整檔案和所有輸出仍是任務執行時才需要的背景。

這個例子說明兩種資訊需求的差別。執行者要能追溯問題，回報者則要用少量文字讓人理解工作狀態，兩者可以分別取得合適的資料。

Anthropic 公告指明由 Haiku 5.5 處理回報，因此這次調整同時涉及回報模型與輸入內容。公開資訊沒有拆出兩者各自貢獻多少節省，整個改善以官方提供的合併結果呈現。

對任務設計而言，進度和成果也適合分別定義。進度說明目前正在檢查哪一部分，成果則要指出實際發現、完成的修改和可供核對的產物。

如果只有一行進度，主對話仍不足以確認測試是否通過。只有在代理完成後把結果送回，主對話才有完整材料安排下一步。

這也解釋了為何回報模型調整不等於整項任務都換成同一模型。子代理的模型、工具與權限仍由它的工作設定決定，公告描述的是週期性摘要的處理方式。

當摘要產生變輕，背景工作便能用較少額度維持可見性。主工作階段接下來仍要處理需要人工決定的工具操作，以及完成後送回的結果。

## 主對話、子代理與工具權限怎麼分工？

背景子代理可與主對話同時工作，工具需要授權時，提示會出現在主工作階段。

使用者看到提示時，Claude Code 會標示是哪個子代理提出要求。核准後該代理繼續執行，若按 Esc 拒絕，則只否決當次工具呼叫，代理本身可以繼續處理其他步驟。

這讓背景工作遇到需要決策的交界時，仍有明確的接手位置。使用者能在同一個主工作階段回答，無須另找背景對話才能處理。

有些授權選擇會持續到整個工作階段，官方文件說明這類回答也會套用到主對話。因此，閱讀提示時，要留意自己核准的是一次操作，還是較長時間的允許範圍。

代理可用哪些工具，也和前景或背景執行有關。文件指出，背景子代理保留的內建工具集合較小，對話分支與恢復中的前景代理另有例外。

若任務依賴特定工具，工作能否順利完成就需要連同這個範圍判斷。進度更新本身只能告知狀態，無法補上執行環境沒有提供的能力。

前景子代理則會阻塞主對話，直到工作完成，權限問題同樣會交給使用者。背景並行和前景等待各自對應不同需求，差別主要在主對話何時能繼續。

當下一步必須先取得某項結果，可以要求 Claude 等待該代理的報告。若幾項工作彼此獨立，則可以讓背景工作繼續，同時在主對話處理其他事項。 [官方子代理文件](https://code.claude.com/docs/en/sub-agents?ref=aiposthub.com)

## 如何確認代理完成了什麼工作？

代理完成後，主對話會在後續回合收到完成通知，團隊再核對報告與實際產物。

官方文件明確區分執行中與已完成的狀態。若使用者在完成通知前詢問進度，主對話會回報該代理仍在執行，完成結果則等通知送達後再處理。

因此，背景列顯示最近動作，可以用來掌握工作方向。要確認任務交付，仍得看最終報告是否回答原本的問題，檔案或工具結果是否能支持該結論。

在終端機可以透過 /tasks 查看代理，並開啟它的對話紀錄。這份紀錄保留了工作經過，當摘要過於簡略或結果出現疑問時，便有較完整的內容可查。

若代理因用量限制或重複伺服器錯誤結束，文件也說明主對話會收到失敗資訊。部分產出可能已存在，團隊可以根據實際完成範圍決定續做方式。

這個差異會影響成本比較。一次順利完成和一次中斷後重跑，表面上可能有相近的執行時間，但重讀資料與重複工具操作會產生不同用量。

所以，同一個任務應把產物、錯誤和續做次數一起留在紀錄裡。後續才能判斷，背景摘要節省是否真的反映在完成一件事所需的總額度。

### 底部自訂狀態列和這次更新有何關係？

Claude Code 另外提供可自訂的底部狀態列，能顯示工作階段成本、上下文用量或版本分支。它由使用者設定的 Shell 腳本讀取 JSON 資料，再輸出想看的文字。

這項既有設定能幫助觀察整體工作狀況。本次新聞提到的，則是背景子代理定期產生的進度文字，兩者對應不同資訊來源。

若團隊已設置成本顯示，可以繼續用來觀察完整工作階段，再對照背景任務紀錄。如此便能把摘要機制的改善，放進自己原本使用的用量觀測方式。 [官方狀態列文件](https://code.claude.com/docs/en/statusline?ref=aiposthub.com)

### 任務交接帶哪些背景，會影響代理自己的用量？

一般子代理啟動時有獨立的上下文視窗，主對話會另外撰寫任務交付訊息。官方文件說明，它通常不會直接看到主對話所有歷史、已讀檔案或已呼叫技能，對話分支則另有繼承方式。

因此，交付任務時要說明要回答的問題、資料位置和完成條件。若必要限制只留在主對話，代理可能需要再查一次，甚至沿不同方向展開工作，這些都會影響執行成本。

自訂子代理可以預先載入指定技能，也能設定特定工具範圍。當團隊反覆派出同類工作，固定的工作定義能減少每次重述，同時讓回傳結果比較一致。

子代理本身發出的請求會計入和主對話相同的用量限制。因此，隔離大量探索資料可以維持主對話整潔，但每個執行中的角色仍各自消耗額度，並行數量也要納入觀察。

若要延續一個已完成代理的工作，文件另提供恢復機制，保留該代理先前的對話歷史。對能恢復的角色，可指定接著核對某部分，讓原本背景繼續發揮作用。

這和重新啟動另一個角色有不同的資料起點。後者需要重新取得必要背景，前者能沿先前紀錄接續，因此比較重跑成本時，也應記下實際使用哪種續做方式。

以程式審查為例，可以先交付一個模組範圍，要求列出問題位置與判斷依據。拿到結果後，再指定原角色追查其中一項，便能把後續閱讀限在已有脈絡的問題上。

這種任務設計不需要依賴某個節省比例。先讓輸入足以完成工作、回傳內容能支持結論，團隊才有穩定基準，看出進度摘要和其他用量改善各自帶來的影響。

## 團隊如何衡量這次更新的實際價值？

團隊可以用相同類型的長任務，比較更新前後的整個工作階段額度與完成結果。

適合先觀察的任務，是持續一段時間、又會累積不少背景的工作。例如閱讀大型程式庫、查找跨檔案問題或進行多項獨立檢查，都可能讓代理維持較久的執行狀態。

比較時要保留任務範圍。若更新後同時增加代理數量、擴大讀取檔案或更換主要模型，就很難判斷差異是來自回報機制，還是工作內容已改變。

總用量也要和完成品質一起看。同樣的檢查若漏掉必要範圍，雖然額度變少，團隊後續仍可能為補查和返工付出成本。

較有判斷價值的比較，是同一類工作能否以相近品質交付，背景回報的負擔是否變小，使用者是否仍能從狀態和最終報告掌握工作。

這次官方沒有為更新指定單獨的公開版本門檻，也沒有公布每種工作負載的節省分布。實際幅度因此應回到自己的工作階段紀錄，避免把單一估計套用到全部任務。

若主要消耗集中在大量工具輸出、反覆讀檔或多輪修正，後續改善也應沿那些紀錄尋找。背景摘要的節省提供一項可觀察變化，任務本身仍可能有更大的用量來源。

## 常見問題

### Claude Code 背景子代理需要重新設定才會省額度嗎？

官方公告描述的是產品內部回報方式調整，沒有要求使用者新增設定。自訂子代理的模型與工具仍應依原本任務需求安排。

### 進度顯示沒有變化，就代表代理停止了嗎？

單看一行文字不足以確認整個任務狀態。可以開啟任務清單與對話紀錄，查是否仍在執行、等待權限或已送出完成通知。

### 這次更新能直接換算成帳單折扣嗎？

官方把整個 CLI 工作階段的影響描述為額度使用估計。實際帳單仍取決於使用方案與計費方式，因此應以工作階段用量和自己的帳務紀錄分別核對。

## 把背景工作交付與進度顯示一起驗收

需要長時間並行工作的團隊，適合追蹤這次背景開銷改善。先選一項有明確完成條件的任務，記下整體用量、完成報告與需要續做的地方，才能看出更新為自己的工作省下多少額度。
