## 本書概要

這是由 SB Creative 出版的全彩書籍，共 7 章、337 頁。  
採用一邊實作一邊前進的實戰形式，透過製作名為 TaskBoard 的待辦事項管理應用程式，隨著章節推進，同一個題材也會逐步成長。

涵蓋範圍大致如下：

- 基本操作與提示詞寫法
- [CLAUDE.md](http://claude.md/) 與權限設定等控制方式
- 透過 Skill 與 MCP 擴充
- 無頭模式與 CI 等實務上的使用方式
- 安全性、成本等企業導入時的觀點

內容從個人入門一路延伸到實際現場，而且越到後半，視角就越從「一個人使用的工具」轉向「團隊使用的機制」。

## 有經驗背書的完整性

一開始讀到的第一個感想是， **很全面，但又不像字典** 。

它不是像官方文件那樣只是把功能一項一項列出來，而是連在哪裡使用、有哪些缺點、推薦怎麼用，都寫得很清楚。  
因為結合了實作與經驗，所以光是看著就會想立刻動手試試。

老實說，我原本以為自己算是相當會用 Claude Code 了。  
但即使如此，還是常常會有「原來還有這種選項啊」的發現。

## 實際跑給你看的說明

不只涵蓋範圍廣，每個功能還都附上實際運作的驗證。  
有些地方其實只要示範指令形式就夠了，但書中還會進一步把執行後的結果也放進來。  
因此更容易掌握實際行為。

像沙箱功能，我雖然有在用，卻一直沒有真正深入理解。  
這本書用圖解仔細說明後，剛好趁這個機會把知識整理了一遍。

我個人最喜歡的是安全性相關的解說。

它不是只停在「用設定就能防住」然後結束，而是像實際讓 Claude 讀取 `.env` 、直到被阻止為止的整個過程，都用日誌完整展示出來，整本書都充滿了實演感。

而且還誠實地寫出， **哪些範圍是這樣的設定也防不了的** 。  
讓人覺得它不只是說明功能，還會一起告訴你 **能信任到什麼程度的界線** ，讀起來很誠懇。

## 用得越深的人越能挖到的發現

### 內建 Skill 的廣度

我自己之前最沒注意到的是內建 Skill 的廣度。  
連設計類的功能、甚至製作圖表的功能都有，涵蓋到平常只拿來做一般開發時不太會注意到的領域。

### 無頭模式與 /loop・/goal

同樣的發現也出現在無頭模式那一章。  
把單次呼叫 Claude Code 的做法，和直到達成目標條件為止持續執行的 `/loop` 、 `/goal` 指令組合在一起，真的是讓人忍不住佩服「原來還能這樣用」。

我個人其實不太常用無頭模式，但這樣一來就能一直跑到達成目標，應用空間一下子就廣了起來。  
這種組合上的巧思，只看文件或零散知識很難注意到。

### GitHub Actions 的排程執行

與 GitHub Actions 的整合也是一樣。  
我之前只拿來做 Pull Request 自動審查或整理 Issue，所以知道排程執行能怎麼自動化，對我來說是很大的收穫。

只要排程做好，就能用最少的人力去清掉技術債，或是處理那些很容易忘記的維護工作。  
而且它還保留了相當大的客製化空間，這點也很有趣。

### 便條與專欄的零食式閱讀

這些細碎的發現，散落在備註欄與專欄裡。  
平常就很常用的人，很適合用這種「挑有興趣的地方先吃」的方式讀。  
實際上，我自己也是先這樣讀的。

把一度成為話題、後來卻沒再用的功能重新想起來，再試一次，也挺有趣的。  
建議邊讀邊做筆記、貼標籤。

## 大約從第 5 章開始改變的本書色彩

對我來說，最耐讀的是 **第 5 章以後** 。  
前半段是以 Claude Code 粉絲的角度覺得有趣，後半段則是以「想在實務上使用」的角度覺得精彩。

### 第 5 章的成本與品質

例如，如何監控並控制成本、如何讓品質穩定。  
這一段很明顯是以在團隊或企業內導入為前提來寫的，對於「這種麻煩事真的存在啊～」的痛點，回答得非常精準。

### 第 6 章的企業環境

第 6 章是企業環境相關內容。  
像是國內外導入案例、這種規模特有的安全性與合規性、以及和 GitHub Copilot 的分工方式等等，都是如果沒有特別關注很難接觸到的資訊。

我自己不是像資訊系統部門那樣的導入角色，所以有很多地方都不熟，資訊量大到有點招架不住；但 **作為讀物來看，純粹很有趣** 。

像這種設定竟然存在啊、企業環境下居然會有這種差異啊——只要先把這些點記在腦中，之後要查資料時就會多一個切入點。  
我自己第 6 章幾乎是快速翻過，但即使如此也算是建立了入口。

反過來說，光是知道這個領域，本身就可能成為 **工作上的差異化** 。  
如果你對這個方向有興趣，很值得靜下心來讀。

### 第 7 章的未來展望

第 7 章的氛圍稍微不同，談的是透過程式碼代理進行開發的未來，以及工程師的演變等主題。

它先從開發風格與 AI 模型如何演變的歷史回顧切入，再談只有一路追蹤 Claude Code 變化的人才說得出的展望。

這一章的好處是不會單純把結論導向「那就去用 Claude Code 吧」。  
它進一步談到未來需要什麼技能、在 AI agent 已經存在的前提下，工作會怎麼改變；讀著讀著就會不自覺開始思考。

前面幾乎都在講內容，這裡也想提一下書本本身的製作。

圖表與示意圖的完成度真的非常高，對於難懂的內容也用了大量視覺化的設計來幫助理解。  
全彩書籍才能做到的表現方式也不少，讓人忍不住會心一笑。

從排版送件前最後一刻還在不斷修正這點，就能看出這本書真的改到非常極限。  
甚至連前陣子才出現的 Anthropic 新模型 Fable 也被寫進去了。

畢竟 Claude Code 本身就常常在中途改變行為，而且有時還會在官方文件或變更紀錄沒寫到的情況下，偷偷在背後更新。  
以不是工具開發者的立場，要把這些細節都查得這麼清楚，應該是相當龐大的心力。

我原本就是抱著這樣的想像在讀，但後來看到 Oikon 先生在發售當天於 X 公開的寫作紀錄，就得到印證了。  
據說 Claude Code 在最近 1 年內的發佈次數高達 **310 次** 。  
他本人也寫到，正是跟著這樣的速度，一邊與責任編輯反覆修正到最後一刻。

我自己最近也才剛寫完一本關於 Claude Code 的書，所以更能感同身受。  
要把一個題材一路養到最後，還做出這樣的結構，真的非常不容易……！  
令人由衷佩服。

## 閱讀方式的建議與總結

最後，提供一些閱讀方式上的建議。

因為內容很完整，對於沒用過 Claude Code 的人來說，可能會被資訊量嚇到。  
要從哪裡開始學、先用哪些功能，取捨確實不太容易。

不過， **只要改變閱讀順序** ，應該就會好入口許多。

- 想先了解團隊使用方式的人，可以從第 5 章以後讀起
- 覺得篇幅太大而有點卻步的人，可以先讀第 7 章
- 不執著於從頭到尾通讀的人，可以挑自己有興趣的地方零食式閱讀

如果先讀第 7 章，就會先理解這本書的意義，以及學習 Claude Code 的意義。  
之後再往前回頭讀，就能順著前面的內容一路補起來。

不管用哪種讀法，都應該很值得。

另外，在「結語」中也放了像是「多和 Claude Code 對話」、「去讀資料看看」這樣的訊息。

雖然看起來像是繞遠路，但我反而覺得這才是最有效的方法，因為這是兩位作者根據自身經驗寫下的話。

無論是想從現在開始系統性整理的人，還是以團隊或公司導入為前提的人，這都是 **值得反覆讀好幾遍的一本書** 。

雖然寫了這麼多，但它確實是一本既耐讀、又能真正應用到實務上的好書！感謝！！！
