網站連結 [https://developers.openai.com/api/docs/guides/image-prompting](https://developers.openai.com/api/docs/guides/image-prompting)

OpenAI 隨著 GPT Image 2.5 推出，也更新了官方的 **Image Prompting Guide** ，詳細說明如何替新一代圖像模型撰寫 Prompt，以及如何透過參考圖片、精準編輯與多輪修改，讓生成結果更接近使用者真正想要的畫面。

這份指南值得注意的地方，在於 OpenAI 並沒有提供什麼「萬能 Prompt」或要求使用特殊語法，而是將重點放在如何清楚描述需求。官方給出的基本原則非常簡單： **先說明需要什麼圖片，再描述主體、構圖、風格與限制；如果是修改既有圖片，則要同時說清楚「什麼要改」以及「什麼不能改」。**

## GPT Image 2.5 提供 Flare 與 Sunburst 兩種模型

GPT Image 2.5 目前分成 **GPT Image 2.5 Flare** 與 **GPT Image 2.5 Sunburst** 。

Flare 是偏向速度的小型模型，圖片品質約與 GPT Image 2 相當，適合快速生成、大量圖片與需要頻繁迭代的應用；Sunburst 則更加重視圖片品質，生成品質高於 GPT Image 2，適合複雜圖片、正式素材以及對細節要求較高的工作。

兩款模型都支援圖片生成、圖片編輯與透明背景，同時改善了 GPT Image 2.5 相當重要的兩項能力： **Precision Editing（精準編輯）與 Subject Preservation（主體保持）** 。

OpenAI 建議，如果速度是主要考量，可以先從 Flare 開始；如果圖片品質要求較高，則從 Sunburst 開始。當品質已經符合需求之後，再嘗試降低品質設定或改用速度較快的模型，以尋找品質、速度與成本之間最適合的平衡。

## 好的 Prompt 不一定要很長，重點是結構清楚

在 Prompt 寫法方面，OpenAI 並沒有規定一定要使用特定格式。一般自然語言、短句、段落、標籤，甚至類似 JSON 的結構都可以使用。

真正重要的是讓模型能夠清楚理解每一項要求。

對比較複雜的圖片，可以將 Prompt 拆分成幾個部分，例如：

**Scene（場景）→ Subject（主體）→ Details（細節）→ Constraints（限制）**

如果要生成一張人物照片，就可以先描述人物所在的地方與時間，再說明人物外觀、服裝與動作，接著指定攝影角度、構圖、光線與風格，最後告訴模型哪些東西不能出現。

因此，Prompt 並不是越長越好。真正影響結果的是： **需求是否明確、各項資訊是否容易理解，以及彼此之間有沒有矛盾。**

## 與其寫「電影感」，不如描述真正看得見的畫面

AI 圖像 Prompt 很常出現「cinematic」、「moody」之類比較抽象的形容詞，但 OpenAI 建議，如果希望得到更加精準的結果，最好直接描述畫面真正應該呈現的視覺特徵。

例如想要寫實照片，可以直接使用 **photorealistic** 或 **real photograph** ；如果是夜景，則可以進一步說明光源來自霓虹燈、路燈或商店櫥窗，以及環境的明暗、色彩與空間尺度。

相機焦段、鏡頭與攝影參數也可以加入 Prompt，例如 35mm、50mm、低機位或廣角攝影。不過 OpenAI 也提醒，這些內容主要是幫助模型理解想要的「視覺效果」，並不代表模型真的在進行完整的物理攝影模擬。

## 生成人物時，動作與構圖應該寫得更具體

如果只是寫「一名女性正在看書」，模型其實還有非常大的自由發揮空間。

更精確的方式，是直接告訴模型人物如何出現在畫面中，例如「完整全身入鏡、包含雙腳」、「低頭看著打開的書」、「雙手自然拿著書本」、「人物位於畫面中央偏右」。

也就是將人物描述拆成：

**景別、身體姿勢、視線方向、手部動作，以及人物與周圍物件之間的互動。**

對人物寫真而言，這些具體資訊往往比單純加入大量「高畫質」、「電影感」、「專業攝影」之類的形容詞更加重要。

## 圖片中的文字要明確指定

GPT Image 2.5 也可以直接生成海報、資訊圖卡、廣告與其他包含文字的圖片。

如果圖片中必須出現特定文字，OpenAI 建議直接使用引號標示，例如要求：

「Yours to Create.」

並且可以進一步指定「只出現一次」、「不要加入其他文字」、「不要浮水印」等限制。

除了文字本身，也可以描述文字應該出現的位置、排版方式、字體風格以及整體設計面向的受眾。如果品牌名稱或特殊單字容易拼錯，甚至可以把字母逐一寫出來，協助模型理解。

## 圖片編輯的關鍵：不只告訴 AI 要改什麼

這份指南中特別重要的一個觀念，就是圖片編輯時應該採用：

**Change X + Preserve Y**

也就是同時告訴模型「修改什麼」與「保留什麼」。

例如使用者只想更換人物服裝，如果 Prompt 只有「把衣服換成黑色洋裝」，模型可能連人物臉孔、姿勢、背景甚至攝影構圖一起重新生成。

比較理想的方式，是明確要求：

「只更換人物服裝，保持人物身份、臉部特徵、身體比例、姿勢、表情、髮型、背景、攝影角度與構圖不變。」

這種寫法可以充分利用 GPT Image 2.5 強化後的 Precision Editing 與 Subject Preservation 能力。

## 官方甚至提供「保持人物身份，只換衣服」的案例

OpenAI 官方指南中就提供了一個非常典型的換裝範例。

範例使用一張人物照片，再搭配三張服裝參考圖片，要求模型替人物更換服裝，但必須保留原本人物的 **身份、臉部、五官、膚色、體型、姿勢、表情、髮型與身體比例** 。

同時，新服裝還必須自然配合原本人物的姿勢與人體結構，並符合原照片的光線、陰影與色溫。

背景、Camera Angle、Framing 與 Image Quality 也被列為必須保持的項目。

這也說明，在 GPT Image 2.5 中，如果需要製作固定角色、人物寫真或連續系列圖片，與其只是不斷強調「保持同一個人」，更好的方式是 **具體列出哪些人物特徵與畫面元素不能改變** 。

## 使用多張參考圖片，要告訴 AI 每張圖負責什麼

當使用兩張以上 Reference Image 時，OpenAI 建議不要只簡單地說「參考這些圖片」。

更有效的方法是直接指定：

**Image 1：人物身份參考**

**Image 2：服裝參考**

**Image 3：攝影風格參考**

**Image 4：背景參考**

然後再告訴模型要如何組合這些資訊。

例如可以要求把 Image 2 裡的狗放到 Image 1 的女性旁邊，同時保持 Image 1 原本的背景、構圖與光線。

這樣比單純寫「Combine these images」更加精確，也能降低模型誤解不同參考圖片用途的機率。

## 草圖也能變成寫實照片

Image Prompting Guide 也提供了 Sketch to Photorealistic Image 的使用方式。

如果提供一張簡單草圖，除了要求 AI 將它轉換成寫實照片之外，還可以明確要求模型保持原本的 **Layout（配置）、Proportions（比例）與 Perspective（透視）** ，再加入真實材質、光線與環境。

同時加入「不要新增其他元素或文字」之類的限制，可以避免 AI 在美化圖片的過程中自行重新設計原本的構圖。

因此，草圖不需要畫得非常精細，它更像是一種「視覺 Prompt」，用來直接告訴模型人物、物件與場景應該放在哪裡。

## 簡單修改反而不用寫很長的 Prompt

雖然複雜圖片適合使用結構化 Prompt，但如果只需要修改一個非常簡單的地方，OpenAI 反而建議保持指令簡潔。

例如要移除人物手上的花，只需要明確告訴模型：

「移除男人手上的花，其他地方不要修改。」

也就是：

**指定修改對象 + Do not change anything else**

這再次說明，圖片 Prompt 的品質並不取決於字數。當修改目標越單純，清楚而簡短的指令往往越有效。

## 多輪修改最好一次只改一件事

GPT Image 2.5 很適合進行 Multi-turn Editing，也就是產生第一張圖片後，持續透過對話進行修改。

OpenAI 建議採用：

**生成 → 查看結果 → 修改一件事情 → 再查看 → 繼續修改**

而不是每一次都重新產生整張圖片，或者一次要求模型改十幾個地方。

例如第一輪先製作黃昏時的洗髮精廣告看板；第二輪只把環境改成下雪的冬季夜晚；第三輪再將看板背景改成深藍色，同時要求產品與文字保持不變。

如果經過多輪編輯之後，某些重要特徵開始產生偏移，也不要只寫「跟之前一樣」，而應該再次明確寫出必須保持不變的條件。

## GPT Image 2.5 能處理的圖片類型更加廣泛

從 OpenAI 公布的官方範例可以看出，GPT Image 2.5 已經不只是一般的文字生成圖片工具。

官方列出的應用包含寫實攝影、資訊圖表、精準文字生成、Logo、歷史場景、四格漫畫、App UI Mockup、科學與教育圖片、簡報、圖片文字翻譯、Style Transfer、人物換裝、多圖合成、透明背景商品圖片、草圖轉寫實照片、物件移除，以及將人物放進不同場景等。

對需要連續製作插畫或固定角色的創作者而言，GPT Image 2.5 也更加重視跨圖片的角色一致性。

其中製作 App UI Mockup 時，OpenAI 還建議把目標描述成一個「真正存在、可以使用的產品」，並著重 Layout、Hierarchy、Spacing 與真正的 UI 元件，而不是使用 Concept Art 類型的描述。這樣更容易得到接近實際 App 介面的結果。

## API 支援更高解析度與透明背景

GPT Image 2.5 API 提供多項輸出控制，包括模型、圖片品質、尺寸與背景設定。

品質可以設定為 `auto` 、 `low` 、 `medium` 、 `high` 、 `xhigh` 與 `max` ；背景則支援一般不透明背景與透明背景。

圖片尺寸除了常見的 1024×1024、1536×1024 與 1024×1536，也支援更高解析度，包括 2048×2048、2048×1152、3840×2160 與 2160×3840。

OpenAI 同樣不建議所有圖片都直接使用最高品質，而是先找到能夠符合需求的設定，再測試較低品質是否仍然可以接受，藉此降低生成時間與成本。

## Prompt 的重點從「關鍵字」轉向「明確溝通」

如果把 OpenAI 這份 Image Prompting Guide 濃縮成一套方法，可以整理成：

**目標 → 場景 → 主體 → 構圖 → 動作 → 視覺風格 → 參考圖片用途 → 修改內容 → 必須保持的元素 → 禁止事項**

對於圖片編輯，則可以再進一步濃縮成一句：

**Change X, Preserve Y.**

GPT Image 2.5 的 Prompt 因此不需要追求堆疊大量華麗的攝影或藝術關鍵字。真正重要的是讓 AI 明確知道： **你要生成什麼、畫面應該如何呈現、參考圖片各自代表什麼、這次究竟要修改哪裡，以及哪些地方絕對不能動。**

從 OpenAI 這次公布的官方指南也可以看出，AI 圖像生成正在逐漸從過去偏向「抽卡」的生成方式，走向更接近實際創作流程的模式。使用者先建立初始畫面，再利用參考圖片、精準編輯與多輪對話逐步調整結果，最終得到真正符合需求的成品。

這或許也是 GPT Image 2.5 最重要的改變： **Prompt 不再只是描述一張圖片，而是成為使用者與 AI 共同完成整個視覺創作流程的溝通方式。**
