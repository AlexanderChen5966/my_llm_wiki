Gemini Computer Use 已正式開放，開發者能讓模型看畫面，再提出點擊、輸入或捲動等操作。

Google AI Studio 在十一月四日公告，從預覽版移轉沒有破壞相容性的介面變更。

這讓已有串接的團隊能沿用原本流程，但實際操作電腦的執行器仍由應用程式提供。

因此，接入工作會同時涉及模型判斷、工具執行和新畫面回傳。

我會把這次更新視為可以開始驗證正式工作流程的時點，先從結果能重現的單一任務做起。

整個流程能否穩定，取決於看圖之後的每一步有沒有接回下一次觀察。

## Gemini Computer Use 正式開放的是哪一層能力？

正式開放的是 Gemini API 的 Computer Use 工具，模型透過截圖理解介面，再產生待執行動作。

API 是應用程式呼叫模型服務的介面。開發者把使用者目標、目前畫面與工具設定一起送出，模型才有條件決定接著要點哪裡，或輸入什麼內容。

這種能力適合介面操作型工作，例如在網站填寫資料、測試網頁流程，或跨網站整理商品資訊。Google 文件列出這些情境，實際能否完成則取決於網站和執行環境。

應用程式需要接收模型提出的動作，再以自己的自動化工具執行。模型負責根據畫面做判斷，執行器則把判斷轉成滑鼠、鍵盤或其他系統操作。

因此，一個工具呼叫成功回傳，只能代表取得了模型建議。要證明工作完成，仍要看操作後的畫面、資料和使用者原先的目標是否對得上。

Google 在公告中把這次進度描述為正式開放，並強調從預覽版沒有破壞相容性的變更。已串接的團隊因而可以沿用原有介面，再核對正式流程是否仍能穩定執行。

截至二〇二六年十一月五日查詢，文件推薦以 Gemini 3.8 Flash 進行 Computer Use，另列 Gemini 4 Argon、Gemini 3.5 Flash-Lite 與 Gemini 3 Flash Preview 為支援模型。

模型選擇仍要配合延遲、工作難度與實際工具表現。工具正式開放的公告提供了可採用時點，各模型本身的狀態與特性則要依對應文件確認。 [官方正式開放公告](https://x.com/GoogleAIStudio/status/2118025709146829218?ref=aiposthub.com)

## 看圖、動作與回傳畫面如何形成循環？

應用程式把目前截圖交給模型，執行回傳動作後再截一次圖，讓下一步有最新狀態。

這個循環從目標和畫面開始。例如，測試任務要求在搜尋網站找到某個項目，第一份截圖就要能呈現目前頁面，模型才知道是先點搜尋框，還是需要處理其他畫面。

回應可能包含待執行的函式呼叫，也就是一個有名稱和參數的動作。Gemini 4 與 3.x 的動作還有 intent 欄位，用文字說明這一步想達成的目的。

執行器讀取動作和參數後，將它轉成實際操作。若是點擊，文件使用零到九百九十九的標準化座標，客戶端要依自己的視窗大小換算。

因此，螢幕截圖、視窗尺寸和換算方式必須一致。若截圖尺寸和實際操作畫面不同，模型即使選對畫面位置，換算後也可能點到另一個地方。

操作完成後，應用程式擷取新的畫面，把結果交回模型。頁面可能因捲動、跳轉或彈出視窗而改變，新的截圖就是下一步判斷的起點。

這也讓等待成為一種有用途的動作。網站正在載入時，執行器可以依模型建議等待，再觀察內容是否出現，避免把尚未完成的狀態當成錯誤結果。

若動作被阻擋或執行出錯，程式同樣需要把情況帶回循環。否則模型可能根據原本預期繼續操作，後面的每一步就會偏離實際畫面。

團隊因此可以沿每一步留下截圖、動作、執行結果與耗時。當工作失敗，這些資料能幫忙區分是模型判斷、座標轉換，還是網站當時的狀態造成差異。

## 瀏覽器、Android 與桌面有哪些操作差異？

瀏覽器、手機與桌面共用看圖操作概念，但各自提供的動作不同。

瀏覽器環境提供點擊、拖曳、輸入、捲動與鍵盤操作，也有網址導向和前後頁切換。這些動作讓模型能在網頁之間移動，再依新畫面繼續工作。

桌面環境則偏向作業系統層的滑鼠和鍵盤操作，例如移動游標、按下按鍵或拖曳項目。當任務跨越不同應用程式，執行器仍要確保目前焦點和畫面是模型以為的那個位置。

手機環境在文件中標示為針對 Android 最佳化，提供開啟應用程式、列出應用程式、長按、返回與其他觸控相關動作。

這個適用範圍會直接影響開發規畫。要做手機代理的團隊，可以先用官方列出的 Android 動作驗證，其他作業系統則需要另外確認執行器與工具支援方式。

不同環境也有不同的導覽概念。瀏覽器能直接要求開某個網址，手機可依名稱開啟應用程式，桌面則常依目前畫面和系統輸入持續操作。

因此，同一項任務搬到另一種裝置時，應重新檢查它每一步依賴什麼動作。看似相同的「打開資料」可能分別代表網頁導向、啟動程式或點選檔案。

官方還允許加入自行定義的函式，或排除部分預設動作。應用程式可以把特定工作封裝成工具，讓模型在畫面操作之外，有更直接的執行入口。

這項擴充適合搭配明確的工具語意。當自訂函式能清楚回報完成或失敗，模型便能把結果放回下一輪判斷，維持整個循環的連貫性。 [官方 Computer Use 文件](https://aistudio.google.com/docs/computer-use?ref=aiposthub.com)

### 動作參數為何也需要單獨測試？

文件中的捲動包含方向、位置與距離，拖曳則包含起點和終點。執行器若只驗證最簡單的點擊，實際碰到需要拖曳或水平捲動的介面時，仍可能缺少處理方式。

鍵盤也有一次按鍵、持續按下與放開的區別。當工作需要組合鍵或多步操作，測試就要確認按鍵能在正確時間結束，讓下一次動作從一致狀態開始。

輸入文字的動作另有是否按下 Enter 的選項，預設不送出。這個細節會影響搜尋或表單是否真的進到下一步，因此執行結果應以新畫面確認。

瀏覽器還有返回與前進，手機則有自己的返回動作。團隊可以把這些導覽納入同一個測試流程，確認代理在離開頁面後，仍能根據目前畫面找回工作位置。

這些測試和選擇模型有關，也和執行器實作有關。把動作參數先用固定畫面驗過，再讓模型自由選擇動作，較容易定位哪一層需要修正。

對要沿用預覽版程式的團隊，已有的動作測試便是可重用的基準。正式工具沒有破壞相容性的介面變更，也仍值得在自己的視窗尺寸與環境重跑這些既有案例。

## 確認提示與畫面注入偵測如何接進執行器？

當動作被標示需要確認時，應用程式要把決定交給使用者，取得同意後才繼續。

官方文件指出，動作可能帶回安全判斷，區分一般允許、需要確認或被阻擋。執行器因此要先讀這個結果，再決定是否操作，不能只把動作名稱和座標直接送到系統。

需要確認時，介面要把模型提供的說明呈現給使用者。使用者同意後，程式在動作結果中帶回確認資訊，讓接下來的模型回合知道該步驟已取得授權。

若使用者拒絕，或動作被阻擋，流程就要停在能處理中斷的位置。這能讓使用者理解任務停在哪裡，也讓應用程式保留繼續或結束的選擇。

文件列出可調整的安全類別，涵蓋交易、敏感資料修改、通訊工具、帳號建立、一般資料變更、隱私同意與法律條款等操作。

這些分類對應不同的使用者決策，因此應用程式設定要和自己的任務範圍一致。例如，研究商品和送出結帳是不同動作，工作目標應清楚到能判斷哪一步需要人接手。

即使開發者設定了部分覆寫，文件仍提醒模型可能回傳需要確認的結果。因此，執行器要保留確認處理路徑，才不會在特定網站或動作上突然中斷。

### 畫面中的指令如何避免干擾任務？

官方另提供截圖中的提示注入偵測，用來檢查畫面是否出現企圖改變代理行為的對抗性文字。例如，網站內容可能要求忽略先前命令，讓代理偏離使用者交付的工作。

這項偵測採選擇啟用，預設關閉，支援 Gemini 3.5 Flash-Lite 或更新的相關模型。若團隊要使用，需在工具設定中明確開啟，再測試被偵測時的中斷流程。

啟用後，文件描述會在偵測到截圖攻擊指令時阻擋執行。它提供一個可測試的防護環節，任務本身的帳號、工具和授權範圍仍由應用程式一起管理。

有了明確的停等和回報路徑，團隊才能重現成功與中斷的原因。這些紀錄也讓正式工作遇到彈窗或確認畫面時，有具體的接手方式。

## 從預覽版移轉，應該用什麼結果驗收？

預覽版使用者可以先沿用串接，再以相同畫面、任務與權限條件檢查結果。

先選擇一條有明確結束狀態的流程，例如在測試網站找到指定資料並留下結果。當完成條件能直接核對，就比較容易辨認模型是否在正確頁面完成目標。

同一條流程也要包含常見變化。頁面載入較慢、額外彈出視窗或搜尋結果不同，都可能改變後續畫面，因此只看一次成功還不足以描述穩定程度。

團隊可以記下每次完成比例、需要人工接手的位置、操作步數和總耗時。這些資料對應日常工作負擔，比單看某一個動作是否成功更完整。

若流程涉及修改資料，還要回到系統裡確認結果。畫面顯示送出成功，和指定欄位真的保存為正確內容，仍可分別留下驗證證據。

成本比較也需要同一個任務範圍。更多截圖、較多重試或更長模型回應都可能影響用量，因此應把成功完成一項工作所需的整體請求一起觀察。

對新接入者，Google 提供的參考實作可以作為理解循環的入口。正式使用仍要依自己的裝置、帳號與操作範圍，把執行和結果檢查接完整。

這次公告沒有公布一個能套用所有網站的任務成功率。實際導入判斷因此應由自己的流程資料累積，讓正式開放的工具能力對上具體的工作成果。

## 常見問題

### Gemini Computer Use 會直接替我控制電腦嗎？

模型會提出操作，應用程式需要提供執行環境。開發者把截圖、動作執行與結果回傳接起來後，代理才能持續進行任務。

### 手機環境支援代表所有手機系統都能用嗎？

截至查詢日，官方動作表把手機環境描述為針對 Android 最佳化。其他系統的支援與執行方式，仍需依產品及文件確認。

### 正式開放後還需要讓使用者確認嗎？

需要。當工具回傳要求確認的安全判斷，應用程式要取得使用者同意，再回傳確認結果，這是正式操作循環的一部分。

## 先讓一條可重現的操作流程穩定完成

已有執行器的團隊，適合把原本預覽版流程拿來重跑，確認動作和安全回應仍能正確處理。首次接入則先完成一條能回讀結果的任務，再依實際成功紀錄擴大工作範圍。
