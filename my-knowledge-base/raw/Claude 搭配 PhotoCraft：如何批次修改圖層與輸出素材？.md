Claude 搭配 PhotoCraft，適合先從有固定規格的圖片工作開始。例如整理同一組素材、套用相同調整，再依用途輸出檔案，可以減少重複點選。

PhotoCraft 提供命令列工具與 MCP 介面，讓 AI 代理呼叫編輯功能。這個連接方式能把文字要求轉成工具操作，但作品是否符合需求，仍要看最後的檔案。

若一句話同時要求改標題、替換圖片、重做風格和輸出所有尺寸，就會混入太多決定。先處理單一、可驗收的工作，更容易知道問題出在哪裡。

本文依 2026 年 10 月 8 日官方 README、命令列與 MCP 文件，整理從盤點到批次交付的方法。命令範例屬文件說明，沒有對應的本站成功執行紀錄。

官方下載頁的版本與主線文件可能不同，開始前應以安裝版本的說明核對可用命令和參數。新列功能不視為每個舊版本都已具備。

這套流程的起點，是先定義誰提供來源、哪些內容可以修改，以及成品要怎麼檢查。

## 先分清楚角色：Claude 規劃操作，PhotoCraft 執行編輯

Claude 是接收文字要求並安排工具使用的 AI 服務。PhotoCraft 則負責讀取文件、執行圖片命令與輸出結果，兩者的能力不能直接混為一談。

CLI 是命令列介面，使用者以文字命令呼叫程式。它適合規則清楚的工作，也方便把相同操作套到不同檔案。

MCP 是讓 AI 服務與外部工具交換功能和資料的協定。接入之後，Claude 可以根據工具提供的功能安排操作，不必每一步都由人手動點選。

但接上工具，不表示 Claude 已經理解所有圖層的用途。名為「文字 3」的圖層可能是日期，也可能是備註，仍需要先讀取文件結構與內容。

PhotoCraft 官方把介面、命令列與代理操作連到共同命令引擎。這有助於建立一致的操作方式，但功能名稱存在，不能單獨證明每種文件都能正確處理。

因此適合自動化的第一個工作，應有明確規則。例如保留背景和標誌，只對指定圖層做調整，並將成品放進獨立資料夾。

## 開始之前，建立來源、工作副本與輸出位置

可以將原始素材、練習副本與成品放在不同資料夾。這樣即使試跑不符合需求，也能知道哪些檔案仍是原始來源。

同一批素材最好先建立清單，記錄檔名、用途與預期輸出。如果來源有十張圖片，成品只有九張，就能立即查找缺少的那一張。

命名規則也要先定義。輸出檔可以包含活動、用途與尺寸，避免在同一個資料夾出現多份難以區分的「final」。

若文件包含客戶標誌或已核准文字，應在要求中寫清楚保留範圍。批次處理的便利不能變成重新改寫所有內容的理由。

對不同來源建立不同規則也很重要。同一個位置放標題的海報，可以共用一套操作。圖層結構完全不同的作品，就不適合硬套相同修改。

這一步完成後，代理得到的任務會更具體。它需要處理的是一份清楚的檔案清單，而不是在整個資料庫裡猜測哪些素材可以改。

## 安裝命令列與接入 MCP，先確認工具可以列出功能

PhotoCraft 官方提供命令列工具。macOS 發行檔包含獨立的 CLI 壓縮包。解壓後應使用實際可執行檔位置，不要把桌面 App 名稱當成命令列路徑。

本節也需要已安裝的 Claude Code。以下 `sh` 指令在電腦的終端機執行；網頁版 Claude 對話框不能直接代替這個設定流程。

`/path/to/photocraft-cli` 是可執行檔的位置示意，每段命令都要替換成實際路徑。本文不假設它已加入系統搜尋命令的位置。

先查看版本對應的使用說明，再確認可用子命令。官方將安裝工具的 `--help` 視為執行時參數的依據，適合避免把不同版本的範例混在一起。

```sh
/path/to/photocraft-cli --help
/path/to/photocraft-cli commands
/path/to/photocraft-cli batch --help
```

`commands` 用來列出命令識別碼及參數文件。命令識別碼是工具用來辨認操作的名稱，應由工具提供，不能只按中文描述自行拼出。

若要讓 Claude Code 接入本機工具，Claude 官方支援以 stdio 方式註冊 MCP。stdio 指兩個本機程式用輸入與輸出交換訊息，不是要求使用者開啟公開網站。

目前 PhotoCraft 主線 MCP 文件提供可指定讀取與寫入範圍的啟動方式。以下為路徑示意， `/work/project` 與可執行檔位置都要改成自己的工作目錄。

```sh
claude mcp add --transport stdio photocraft -- \
  /path/to/photocraft-cli mcp \
  --automation-read-root /work/project/input \
  --automation-write-root /work/project/output
```

範例將來源與輸出範圍分開，適合本次只讀取素材、另存成品的工作。實際安裝版若沒有相同參數，先查看該版本的說明，再調整啟動設定。

註冊後還要在 Claude Code 確認伺服器狀態與工具列表。註冊指令完成，只表示設定步驟成立，尚未證明文件可讀、編輯可做或結果可保存。

可在終端機執行 `claude mcp get photocraft` 查看設定，再於 Claude Code 對話中輸入 `/mcp` 檢查連線。若伺服器未連上，先確認路徑與啟動錯誤，再提交圖片任務。

## 修改圖層之前，先讀取內容與可用命令

PhotoCraft 官方命令列提供 `info` ，可輸出文件尺寸、模式、位元深度與圖層資訊。這些資料有助於建立修改前的盤點。

位元深度可理解為每個色彩通道記錄細節的精細程度。對初次批次工作，重點是確認來源和輸出規格，不必在同一輪同時改變所有影像設定。

若任務要修改標題，可以先請 Claude 找出候選文字圖層，列出目前內容、名稱與位置。只有確認目標後，才安排真正的寫入。

有些看起來像文字的內容，實際上已經變成圖片。這種來源不能假設可像一般文字圖層一樣替換，應先確認結構再選處理方式。

圖層名稱也不是唯一依據。文件可能有多個「標題」或隱藏版本，代理應結合內容與畫面確認，避免改到備用層或不會出現在成品的元素。

文字替換的命令與參數要由安裝版的命令列表查得。以下主案例先處理影像調整與曲線圖層，改日期可在這套流程確認後，再作為另一份動作清單擴充。

## 一份明確的批次提示詞，要包含修改與驗收規格

提示詞不只描述想要的風格，也要說明哪些內容保持原樣。對固定素材工作，文件範圍與驗收結果通常比形容詞更有用。

以下是本文設計的假設案例，目標是調整同組 PSD 圖片的細節與明暗，新增曲線調整圖層，再輸出 PNG。它沒有對應的本站成品，也不是官方原始提示詞。

```
只處理 input 資料夾中同一組 PSD 工作副本。
先盤點檔名、尺寸、色彩模式與圖層結構。

保留標誌、背景、主標題與已核准的內文。
查詢工具可用命令，先用一份文件示範智慧銳化，
再新增曲線調整圖層，提供 PNG 預覽和修改紀錄。

先列出銳化與曲線參數，由我確認是否適合來源。
確認單檔結果後，再依同一規則處理相同結構的文件。

PNG 成品放在 output，保留原始檔案。
回報每份文件是否成功、實際輸出名稱及未處理原因。
```

先確認一張預覽，可以看出曲線是否讓暗部過黑，或銳化是否讓邊緣不自然。參數獲得確認後，再將相同操作整理成動作清單，提示詞與批次內容才能保持一致。

若同一批文件的標題長度差異很大，可以按結構分組。固定數值的調整適合共用規則，涉及閱讀順序與構圖的修改則要保留逐張確認。

## 官方單檔命令範例，先看輸入、操作與輸出各做什麼

PhotoCraft README 提供一個單檔範例，先做智慧銳化，再建立曲線調整圖層，最後輸出 PNG。它適合認識命令組合，並非適用所有海報的推薦參數。

```sh
/path/to/photocraft-cli run ./input/wave.psd \
  --cmd filter.sharpen.smartSharpen --params '{"amount":80}' \
  --cmd layer.newAdjustmentLayer.curves \
  --params '{"points":[[0,0],[64,48],[192,212],[255,255]]}' \
  --out ./output/wave-final.png
```

`./input/wave.psd` 是輸入文件，兩個 `--cmd` 表示依序執行的操作， `--params` 提供設定， `--out` 指定成品位置。這裡沿用官方操作參數，將路徑改為本文的來源與輸出資料夾。

智慧銳化用來強調細節，曲線改變明暗分布。若照片已經處理過，重複加強可能產生不自然的邊緣，因此先看單檔結果再決定是否批次套用。

同樣地，產生 PNG 表示取得點陣成品，不能推定已保存可修改 PSD。若交付包含工作原檔，應把保存格式與回讀要求另外列明。

可修改 PSD 的交接條件，也應回到圖層、文字與效果。多張圖片成功輸出，仍不能取代工作檔的相容性測試。

## 批次處理之前，先讓一份動作清單通過試跑

官方提供 `batch` ，用動作清單處理一個輸入資料夾。動作清單把相同操作記錄下來，方便套用與回查，不必每個檔案重新口述一次。

目前主線程式接受含 `actions` 陣列的 JSON。每個動作以 `command` 指定識別碼， `params` 放入參數。以下清單與前面的兩個單檔操作相同，可保存為 `grade.json` 。

```json
{
  "actions": [
    {
      "command": "filter.sharpen.smartSharpen",
      "params": {"amount": 80}
    },
    {
      "command": "layer.newAdjustmentLayer.curves",
      "params": {
        "points": [[0, 0], [64, 48], [192, 212], [255, 255]]
      }
    }
  ]
}
```
```sh
/path/to/photocraft-cli batch --actions grade.json \
  --in ./input --out ./output --format png
```

JSON 語法正確，只表示清單能被解析。動作識別碼、參數和來源是否適用，仍要依安裝版命令列表與少量副本的試跑結果確認。

`--format png` 明確指定批次交付格式。目前主線若省略此參數，會沿用各輸入檔的副檔名，不能因為單檔範例輸出 PNG，就認定批次也會自動輸出 PNG。

這裡按官方參數整理路徑，將同組來源放在 `input` ，結果放在 `output` 。目前批次程式掃描資料夾中的檔案，不應假設還會自動走訪所有子資料夾。

官方 CLI 文件說明，批次輸出預設拒絕與輸入使用同一資料夾，以免結果取代來源。本流程保留獨立輸出位置，方便比較和重新執行。

試跑可選一份普通文件與一份最容易出問題的文件。例如較長文字、較大尺寸或不同色彩模式，能更早發現共用規則的邊界。

有錯誤時先保留訊息並縮小問題範圍。若是參數格式不正確，就修正動作清單。若是某份來源結構不同，就將它移到另一組規則。

這樣下一次重跑能針對未完成項目，而不是讓所有檔案再接受一次可能改變結果的調整。

## 完成報告要回到檔案，而不只是一句已處理

批次完成後，先對照來源與成品清單。檔案數量、名稱與格式，能揭露漏檔、重複或輸出到錯誤位置的問題。

接著查看尺寸、方向、透明背景和重要內容。文字修改要核對日期、數字與換行，圖片調整則看膚色、細節和邊緣是否符合要求。

若規則固定，也應保留一張來源與成品的對照圖。對照圖能讓下次更新時知道差異來自來源、工具版本，還是動作設定。

可修改工作檔要重新開啟，嘗試修改一段文字或關閉一個效果。這一步確認的是後續工作能否持續，與成品預覽正常不同。

| 回報項目 | 要提供的證據 |
| --- | --- |
| 工作範圍 | 實際處理的來源清單與排除項目。 |
| 編輯結果 | 修改紀錄、代表性預覽與例外原因。 |
| 交付檔案 | 真正存在的檔名、格式、尺寸及數量。 |
| 工作連續性 | 工作檔重新開啟與必要元素的修改結果。 |

當這些資料都有具體結果，代理的報告才容易被接手者理解。連線成功、命令執行與交付驗收，也就各自有清楚的完成標準。

## Claude 搭配 PhotoCraft 常見問題

### 接上 MCP 就能自動完成所有圖片工作嗎？

MCP 提供工具連接，任務仍需要來源、修改規則與驗收條件。圖層結構與複雜效果也可能限制可用範圍，適合先用單檔確認。

### 批次調整與批次改日期可以用同一套規則嗎？

固定影像調整與文字替換處理的內容不同。改日期應先確認文字層、對照表及換行，再安排相同結構的文件一起執行。

### 官方命令可以直接當成自己的修圖設定嗎？

範例用來說明語法與操作組合。銳化和曲線是否適合，仍要按來源照片與交付要求決定，不能把範例數值當成通用答案。

### 工具在本機執行，AI 使用也一定完全離線嗎？

PhotoCraft 的本機執行與 Claude 的服務使用是不同環節。是否傳送圖片或文字，應按實際代理操作確認，不能只從編輯器位置推論。

### 最值得先自動化哪一種工作？

先選來源一致、規則固定且能清楚驗收的任務。例如同組圖片調整或固定規格輸出，通常比重新設計完整作品更容易建立可重複流程。

## 讓批次結果能回查，自動化才容易持續

Claude 搭配 PhotoCraft 的實際價值，在於把明確規則轉成可重複操作。先讀取文件，再單檔確認，最後才擴大範圍，能讓錯誤更容易定位。

保留來源、動作清單與交付結果，下一次修改就有依據。當同一套流程能穩定產生可使用的檔案，再增加批次規模會更合理。
