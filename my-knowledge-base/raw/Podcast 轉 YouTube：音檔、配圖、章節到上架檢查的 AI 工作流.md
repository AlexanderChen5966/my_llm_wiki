Podcast 轉 YouTube，可以用節目封面搭配音檔，也可以加入照片與字幕，做成觀眾看得懂的影片。但音檔剪完以後，還有畫面、說明欄與上架紀錄需要處理。

如果每次都先做影片、最後才找逐字稿寫文案，常會發現標題與成片不同步。因為剪輯刪掉一段內容，章節時間與介紹文字也要一起跟著改。

比較容易維護的做法，是先確定一份音訊主檔，再讓畫面、文案與進度表沿用相同版本。這樣修改一集節目時，才知道哪些交付物也需要更新。

Claude Code 是在電腦上協助處理檔案、執行程式的 AI 工具，能整理素材與指揮影音工具。使用前需完成安裝與帳戶設定，再讓它讀取這一集的資料夾。它適合接手有明確規格的重複工作，內容取捨仍由創作者定案。

對已經固定錄音、想把節目延伸到 YouTube 的人，我會先建議完成一集簡單、可交接的版本。因為這一集會成為下次的模板，先把流程走通，比每次都增加特效更有用。

不過在準備素材前，先確認自己需要的是自動匯入現有節目，還是重新安排每集的畫面。

## Podcast 轉 YouTube，先選 RSS 匯入或自行做影片

想保留原本的音訊節目、搭配固定封面，可以先評估 RSS 匯入。RSS 是提供節目資訊與新集數的訂閱資料來源，讓平台取得你已發布的內容。

[YouTube 的 RSS 說明](https://support.google.com/youtube/answer/13525207?hl=zh-Hant&ref=aiposthub.com) 指出，支援這項功能的創作者可以匯入節目，系統會以節目封面建立靜態影像影片。能否使用仍需核對所在地區、帳戶與匯入資格。

但如果你希望照片隨內容切換，或另外製作片頭與字幕，則需要自行完成影片。因為畫面跟音檔有了對應關係，後製也必須保留時間資訊。

以下把兩條路線放在一起，方便先選擇適合自己的工作量。

| 路線 | 適合的需求 | 需要管理的內容 |
| --- | --- | --- |
| RSS 匯入 | 新集數自動匯入，畫面以封面為主 | 節目資料、匯入狀態與平台設定 |
| 自行製作影片 | 照片、圖卡與字幕配合內容變化 | 音訊版本、畫面時間表、影片與文案 |
| 已有真人錄影 | 以錄影畫面作為節目主體 | 影像與音訊同步、剪點、字幕與輸出 |

這張表的差別是你要管理多少畫面。本文採自行製作影片的路線，從一份完成初剪的音檔開始，準備能交給上架者使用的整套資料。

透過工作室手動建立 Podcast 時，也要分清影片與播放清單。 [YouTube 官方說明](https://support.google.com/youtube/answer/12751636?hl=zh-Hant&ref=aiposthub.com) 將 Podcast 視為播放清單，各集則是影片，不能直接把 MP3 當成影片上傳。

因此，手動上架前需要準備影片檔；RSS 匯入則是另一條由平台處理的路徑。先選好方式，才不會為只需要固定封面的節目增加多餘剪輯。

## 音檔、逐字稿與封面怎麼整理

先選定一份完成初剪的音檔，並把它當成這一版影片的聲音來源。因為畫面與章節都會跟著它的長度安排，後面換音檔時，也要重新核對時間。

### 讓逐字稿對應到實際使用的音訊

逐字稿是把錄音轉成文字的文件，最好保留時間碼，讓每段文字能回到音檔中確認。辨識工具仍可能聽錯人名，所以專有名詞要人工核對。

如果手上的逐字稿來自未剪輯錄音，就不能直接拿它當成品時間表。因為初剪刪掉了段落，後面的時間也會改變，應重做對應或重新轉錄成品音檔。

延伸閱讀： [AI Podcast 剪輯教學：Claude Code 如何找贅字、重錄與離題片段？](https://www.aiposthub.com/claude-code-ai-podcast-editing-tutorial/)

### 給照片留下內容與來源

照片不必只用流水號管理。可以加上內容、可使用範圍與建議段落，例如「店面外觀，品牌自有照片，可用於開場」，讓 AI 安排畫面時有依據。

但照片跟談話主題接近，仍不代表它能證明談話中的事件。若節目說的是另一家店，就不能用手邊照片讓觀眾誤認拍攝地點。

檔案整理也要能看出版本。以下是一份可自行採用的專案結構，名稱是示例，並非已完成的節目成品。

```
episode-001/
  source/       原始音檔與照片
  approved/     本次確認的音訊主檔
  transcript/   對應主檔的逐字稿
  project/      畫面時間表與可修改專案
  export/       影片、字幕與文案
  review/       檢查結果與上架紀錄
```

原始檔與確認版分開後，回頭修改就有依據。如果 AI 做出的版本不合適，也能從主檔重新製作，不必找回被覆蓋的素材。

## 如何讓 Claude Code 協助做出第一版影片

先請 Claude Code 盤點素材與提出方案，再讓它建立影片。Claude Code 負責讀取專案、整理規則與執行指令，影音處理則需搭配實際安裝的工具。

例如 FFmpeg 可以處理影音轉檔，HyperFrames 可以用網頁程式描述影片畫面與時間。但你需要先確認環境能執行，再決定這一集使用哪條製作路線。

延伸閱讀： [HyperFrames x Codex 快速上手：安裝、工作流、案例分享](https://www.aiposthub.com/hyperframes-codex-quickstart-guide/)

### 第一輪只做素材盤點與畫面表

先讓 AI 列出音檔長度、照片內容與缺少的素材，能減少做到一半才發現資料不足的情況。以下是任務提示範例，可依自己的資料夾修改。

> 請先盤點本專案的確認版音檔、逐字稿與照片，不修改原始檔。依逐字稿提出畫面時間表，列出每段的開始、結束、照片與選用理由。缺少合適照片的地方可以保留簡單標題畫面，不新增未提供的事實。先給我方案，確認後再製作影片。

這一輪的交付物是時間表。你可以先檢查照片是否對題、畫面是否需要停留較久，再決定哪些安排交給工具執行。

### 第二輪先完成能播放的版本

方案確認後，再要求 AI 以固定畫面、少量照片和完整音軌完成第一版。因為這時要驗證的是同步與內容完整，過早加入大量動畫會增加排錯範圍。

第一版至少要能完整播放，也要記錄使用哪份音檔。輸出影片後，可抽查開頭、畫面切換處與結尾，再完整看過一次，確認沒有截斷句子。

若準備一般 MP4 檔案，可參考 [YouTube 建議的上傳編碼設定](https://support.google.com/youtube/answer/1722171?hl=zh-Hant&ref=aiposthub.com) 選擇輸出方式。編碼是儲存影像與聲音的方法，選擇合適格式只是其中一步，不能取代播放檢查。

等這個版本確認後，再加入字幕或更細的畫面變化，因為後續問題才容易回到某一輪修改。

## 標題、說明與影片章節怎麼準備

文案應從確認版內容整理，讓觀眾點進來後能找到標題承諾的答案。可以請 AI 提供幾種切角，但每個標題都要附上對應段落，方便核對。

### 標題說清楚這集談了什麼

假設一集內容討論咖啡店第一次經營外送，標題可以聚焦菜單選擇或出餐流程。若節目沒有揭露營收，就不能因為想吸引點擊而寫「營收翻倍」。

這樣做會限制標題的誇張空間，但能讓內容與承諾一致。說明欄也可沿用相同規則，把重點、來賓與來源連結整理成可核對的文字。

可以這樣要求 AI：「依本版逐字稿提出標題與說明草稿，每個主要說法附對應時間。沒有出現在內容裡的成果、數字與人物關係，不要補寫。」

### 章節時間以最終影片為準

章節是讓觀眾跳到特定段落的時間標記。 [YouTube 手動章節規則](https://support.google.com/youtube/answer/9884579?hl=zh-Hant&ref=aiposthub.com) 要求第一筆從 00:00 開始，至少有三個時間標記，依時間先後排列，每個章節至少十秒。

但符合格式後，仍要核對標記是否對準內容。下面是假設一集十二分鐘節目的示例，時間不能直接套用到自己的影片。

```
00:00 這集的問題：咖啡店第一次做外送
01:10 哪些品項適合先測試
04:30 出餐與包裝要怎麼安排
08:40 試營運後怎麼調整
```

如果影片前面後來加了片頭，這些時間也要跟著移動。因此應在影片內容定版後，再輸出章節文件，並點選每個時間確認位置。

上架時，把時間標記與章節標題貼進影片說明欄，儲存後再從影片頁逐一點選檢查。這樣才知道文件裡的時間，有沒有正確接到平台上的內容。

## 上架前要檢查什麼，進度如何追蹤

把成片、文案與檢查結果放在一起，上架者才知道手上的版本能不能使用。建議先用私人影片檢查平台處理後的畫面與聲音，確認後再決定公開或排程。

以下清單可以直接作為一集節目的交接欄位。

| 檢查對象 | 要確認的結果 | 建議留下的紀錄 |
| --- | --- | --- |
| 影片與音訊 | 開頭、段落與結尾完整，沒有錯配音軌 | 成片檔名與音訊版本 |
| 畫面與字幕 | 照片對題、手機能讀、名稱沒有辨識錯誤 | 問題時間與修正結果 |
| 文案與章節 | 標題沒有超出內容，時間標記正確 | 最終標題、說明與章節檔 |
| 素材來源 | 圖片、音樂與來賓使用範圍已確認 | 來源或授權紀錄 |
| 平台設定 | 頻道、播放清單與瀏覽權限正確 | 影片連結與發布狀態 |

清單的用途是保留已確認的結果。若影片版本改變，對應的檢查就需要重做，避免舊紀錄讓人誤以為新版也已經看過。

進度表可以先用一列管理一集，欄位包含集數、音訊版本、成片版本、文案確認人、待修項目、影片連結與狀態。因為完成輸出和完成公開是不同階段，狀態要分開寫。

若要讓 AI 更新 Google 試算表，先確認連接方式與寫入範圍，再指定唯一的集數欄位。沒有設定連線時，也可以先輸出表格供人工貼入，不必為了第一集就串接全部工具。

## Podcast 轉 YouTube 常見問題

### Podcast 轉 YouTube 一定要拍攝真人嗎？

可以採用封面或照片搭配音訊，不一定需要真人錄影。但畫面仍要與節目內容一致，也要確認素材的使用權利。

### 已有 RSS，還需要自行剪一支影片嗎？

若帳戶與所在地區支援 RSS 匯入，固定封面形式可能已經足夠。想讓照片、字幕與內容一起變化時，再評估自行製作影片。

### Claude Code 可以直接幫我公開節目嗎？

能否操作取決於連接的工具與權限，但建立影片不代表已授權公開。先讓 AI 交付成片與文案，人工確認頻道、設定與內容後，再執行發布。

### 整集影片與 Shorts 可以放在同一個 Podcast 播放清單嗎？

官方建議 Podcast 播放清單收錄完整集數，宣傳片段另行整理。短片可以協助觀眾認識節目，但不能把片段當成完整集數的替代品。

## 先完成一集能交接的上架包

有固定音檔來源的人，可以先以少量畫面完成一集，並留下成片、文案、章節與檢查紀錄。因為下一次需要重複的工作已經明確，AI 才比較容易接手。

還沒有固定節目流程時，先把錄音與初剪做好，再擴充到影片。想持續取得這類 AI 內容工作流，可以免費訂閱 AI 郵報；需要跟做完整操作時，再查看對應課程。
