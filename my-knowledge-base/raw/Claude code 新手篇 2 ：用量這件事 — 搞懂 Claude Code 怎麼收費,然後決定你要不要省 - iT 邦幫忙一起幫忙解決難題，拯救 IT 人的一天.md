## Claude code 新手篇 2 ：用量這件事 — 搞懂 Claude Code 怎麼收費,然後決定你要不要省

- 分享至

## 1\. 新手裝完工具後,最大的恐懼

上一篇 G1 我帶你裝好了 Claude Code,也提到一個重點:**它沒有免費試用,要訂閱或 API key 才能用** 。

那一講完,很多人的下一個念頭就是 ——

> 「那我會不會一不小心,被收一大筆錢?」

這個焦慮我理解。我自己剛開始也會擔心,就怕對話跑長就燒出一張嚇人的帳單,結果反而 **綁手綁腳、有使用上的焦慮** 。

這篇就是來解決這個焦慮的。讀完你會知道:費用到底怎麼算、上限在哪、怎麼隨時查、以及該選哪個方案。

> 💡 **先直接給一個大結論**:只要你走「訂閱」(Pro / Max)這條路,你這個月 **最多就是付那個固定月費,不會有額外的費用** 。用超過了,它只會擋你、叫你等額度重置,**不會再額外的扣錢** 。真正會「用多少扣多少、可能噴錢」的只有 API key 那條路 —— 而新手不會走那條(第 2 節會講兩條路的差別)。

> 📖 **先講一個會一直出現的字:token** 。可以把他大概想成 Claude 在讀和回答時,把文字切成的「小積木」 —— 大約 1 個 token ≈ 半個到一個中文字。你貼給它的字、它回你的字、甚至它在背景讀的設定檔,全部都換算成 token 來算錢、算額度。之後看到「燒 token」,就是「積木用得多」的意思。

那個「不敢用」,才是新手真正的成本。所以這篇就一個目標:**讓你不再怕被亂收錢,然後了解自己的用量。**

## 2\. 你是怎麼被收費的?(訂閱 vs API key)

Claude Code 的收費有兩條完全不同的路,先搞懂你走的是哪一條。

### 關鍵觀念:Claude Code 不用另外買

有些人以為 Claude Code 是一個要單獨付費的產品。 **不是。**

只要你有付費的 **Claude 訂閱(Pro / Max / Team / Enterprise)**,Claude Code 就 **內含在裡面** —— 它跟你用的網頁版、桌面版、手機版 Claude **共用同一個訂閱、同一份額度** 。

> 可以想成:你訂閱了 Claude 之後,終端機裡的 Claude Code 是「同一張會員卡也能刷」的東西,不用再多付一次錢。

(但反過來提醒:因為是 **共用** 額度,你在 Claude Desktop 聊太多,Claude Code 能用的量就會相對變少。)

### 兩條計費路線

**路線 A — 訂閱(月費,大多數人走這條)**

- **Pro** — 每月 $20(年繳約 $17/月)。偶爾寫程式、日常用,夠了。
- **Max 5x** — 每月 $100,每段(session)用量約是 Pro 的 5 倍。
- **Max 20x** — 每月 $200,每段用量約是 Pro 的 20 倍。
- Team / Enterprise — 給團隊/公司用,新手用不到,跳過。

> 那個「5 倍 / 20 倍」是官方對方案的 **相對說法**,給你一個量級感;但實際換算成「能用幾則訊息」官方一樣不公布(原因第 3 節講),所以還是以 `/usage` 查到的為準。

**路線 B — API key(沒月費,用多少付多少)**

到 Claude 的開發者平台([platform.claude.com](https://platform.claude.com/))申請 API key,純粹按 token 用量計費,要先預存 credits(先儲值的金額,用 token 一點一點扣)。

**這兩個是分開的產品、分開計費。** 新手請走路線 A(訂閱),只有當你要做自動化、大量批次跑、或把 Claude 接進自己的程式時,才需要考慮 API key。

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796PeUAm9SYjP.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796PeUAm9SYjP.png)

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796nlU5CtwHLH.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796nlU5CtwHLH.png)

### ⚠️ 一個很多人中招的地雷

有人明明訂了 Max,卻發現自己 **被按 token 收費** —— 因為他電腦的 **環境變數** (你電腦裡一個全域的設定值,常常是之前裝別的工具、跟著某個教學設的,你可能早就忘了它在)設了 `ANTHROPIC_API_KEY`,而這個變數會「蓋過」你的訂閱登入,Claude Code 就改用 API key 計費了。

檢查方法很簡單,在 Claude Code 裡打 `/status`,它會告訴你現在是「訂閱」還是「API」在計費。如果你訂了方案卻顯示 API,就是中招了 —— 在 **電腦的終端機** (不是 Claude Code 裡面)打 `unset ANTHROPIC_API_KEY` 清掉就好。不確定怎麼弄?直接問 Claude「怎麼清除 ANTHROPIC\_API\_KEY」。

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796MLLlfcMFUE.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796MLLlfcMFUE.png)

> 圖說:`/status` 結果 — `Login method: Claude Max account` 就代表「訂閱計費」;如果這裡顯示 API,就是被環境變數蓋過了

## 3\. 看懂花費:/usage

有兩個地方可以看用量,挑你順手的:

- **方法一(terminal)**:在 Claude Code 裡打 `/usage`,會打開用量主畫面。
- **方法二(圖形介面)**:打開 **Claude Desktop**,按 `Cmd + ,`(逗號)開設定,裡面有一個 **Usage** 分頁。如果你還不習慣 terminal,用這個點一點更安心。

**對訂閱用戶,你只要看一個東西:「方案用量條」** —— 它告訴你這段時間用掉多少、還剩多少。就這樣。

> ⚠️ 畫面上會有一個美元金額(Session cost)。 **訂閱用戶請忽略它** —— 那是 Claude Code 在你本機用 token 數「估算」出來的,給 API 用戶參考用,跟你的訂閱帳單沒關係。看到那個 $ 不要嚇到,它不是你要付的錢。

(進階一點:`/usage` 還能按 `d` / `w` 切換看過去 24 小時 / 7 天,也會列出最近哪些操作吃掉最多額度 —— 新手現在大概沒裝什麼額外工具,看到一片乾淨是正常的,不用緊張。它只統計 **這台電腦** 的紀錄,手機、網頁版的用量不算在內。)

**你現在只要記住一件事:想知道「還剩多少」,就打 `/usage`,看用量條。**

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796qE9yU0PNik.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796qE9yU0PNik.png)

> 圖說:`/usage` 真實畫面 — 看到「每段 39% / 每週 8% / Sonnet 專屬 2%」三條用量條了嗎?這就是文章說的雙層上限

### 不是「吃到飽」:額度怎麼算

順便說一個與 ChatGPT 不同的地方。(雖然我沒用過幾次 GPT 但我聽說好像幾乎不會撞到上限):**Claude 的訂閱方案不是無限吃到飽**,連 Max 也不是。 **記住一件事:它的用量額度同時有「兩層」碼表在跑 —— 一個每 5 小時、一個每週,兩個都要還沒滿才用得了。**

1. **每 5 小時的量** —— 短期額度,防你一口氣爆量;用完等幾小時就回血
2. **每週的量** —— 大池子,從你開始用那一刻起算 7 天才重置

所以就算你每 5 小時的量還沒用完,**只要週的量見底,一樣會被擋** 。這兩層在下面這張 Claude Desktop 的 Usage 畫面看得最清楚:

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796w7tI7qNLG3.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796w7tI7qNLG3.png)

> 圖說:Claude Desktop 的 Usage 分頁 — 上面 Current session 是「每 5 小時的量」(4hr 32min 後重置),下面 Weekly limits 是「每週的量」(All models + Sonnet only,週四 6am 重置)。兩層分得清清楚楚

**但確切的 token / 訊息數字,官方就是沒公布,而且常常改** (2026 年 5 月才剛把「每 5 小時」的額度加倍)。所以:

> 你在網路上看到的「Max 每 5 小時能用 900 則」這類數字,**都是猜的,別信** 。自己打 `/usage` 查最準。

那你會不會撞到?**這要分兩種人看:**

- **如果你是剛學、偶爾寫一點** —— 多數時候碰不到上限,安心用。
- **如果你開始天天重度用** (跨多個專案、跑很長的對話、讓它連續做大任務) —— **那撞到上限其實滿常見的** 。我身邊就不少人撞到 Pro、甚至 Max 的每週額度,單純就是用得多而已。

但別慌:**撞到上限不會斷線、更不會偷扣錢** 。它會跳出來問你要「等額度重置」、「升級方案」、還是「(自己選擇)加錢用 API 續用」。新手選「等」就好;如果你發現自己一天到晚在等重置,那就是 `/usage` 在告訴你「該升級方案了」(第 7 節有決策表)。

## 4\. 看懂記憶體:/context 與「白板」

這是新手最不直覺、但最關鍵的觀念。搞懂它,後面所有省用量的動作你才知道 **為什麼** 要那樣做。

`/context` 顯示的不是錢,是\*\*「這一輪對話的記憶體用了多少」\*\*。打下去,它會列出:系統設定、你連的工具、 `CLAUDE.md` 、對話歷史 …… 各佔多少空間,還剩多少。長這樣:

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796xW1nzpglGq.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796xW1nzpglGq.png)

> 圖說:`/context` 的畫面 — 最上面 `opus-4-8[1m] · 489.2k / 1.0M (49%)` 就是「白板用了一半」;下面分項列出各類別各吃多少 token、還剩 Free space 50.4%。順帶一提:Claude Code 也會在輸入框旁邊的狀態列用橘色小圓圈提示 context 用量,到 50% 以上才會出現,就是在提醒你「白板有點滿了」

那個「記憶體」是什麼?用一個比喻:

> **把它想成 Claude 跟你共用的一塊白板。** Claude 其實沒有真正的記憶 —— 它每次要回你之前,都得把白板上「目前寫著的所有東西」整個重看一遍,才知道前情提要。白板上字越多,它每次要看的就越多,也就越花 token。

所以對話拖越長,白板越滿,**每一句就越燒 token、越貴** 。這就是為什麼「 **一個任務開一個新對話** 」會省錢又省腦 —— 下一節會講怎麼做。

**白板有多大?** 現在比較新的模型更大:Opus 4.8 和 Sonnet 4.6 可以到 **100 萬 token**,而且如果你是 **Max 方案、用 Opus,還會升級到 100 萬、不用多付錢** 。(所以像我用 Max + Opus,白板其實是百萬級的,聽起來很多但也不是完全用不完喔。)

> 白板真的快寫滿時,Claude 不會當機 —— 它會自動把前面對話「濃縮成摘要」清出空間繼續,你會看到一行 `Conversation compacted` 。好消息是:系統設定、 `CLAUDE.md` 這些常駐的東西會自動重新載入,不會消失;但 **被濃縮掉的中間細節會變模糊** 。所以重要的結論,養成習慣自己另外記下來,或寫進 `CLAUDE.md` (G3 會講)。

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796ru4lLg8rzn.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796ru4lLg8rzn.png)

> 圖說:Context 就像一塊白板 — 對話越長、白板越滿,每次回話都要重看一遍,所以越燒 token

## 5\. 我的真實選擇:為什麼我直接上 Max 5x

講完機制,講點真實的。

我用 **Max 5x($100/月)**,而且我 **不太省 token** 。不是因為我不懂省,是因為我算的是 **另一筆帳** 。

對我來說,**時間成本遠比 token 成本貴。** 如果我每次對話都要在心裡盤算「這句會不會太燒」、「要不要先 `/clear` 」、「這個任務該降到 Sonnet 嗎」 —— 那個分心、那個猶豫,拖慢的是我整個工作節奏。我寧可付固定月費,換一個「 **不用想、放開用** 」的狀態。

第二個理由是 **開發與模型需求** 。我在工作中與論文上做的東西常常需要比較重的推理 —— 複雜的架構決策、RAG 系統設計、模型開發等等的邏輯。這些我會用最強的 Opus 模型,而 Opus 跑起來比較吃量。Max 5x 對我是那個「 **用得起最強模型、又碰不到上限** 」的甜蜜點。Pro 對我的用量太緊,Max 20x 又超過我需要。

我不是要你也去買 Max。我想說的是:

> **先想清楚你算的是哪一筆帳。** 是 token 的錢?還是你的時間?還是你需要的模型?答案不一樣,選的方案就不一樣。不然也可以跟我一樣,先使用 Pro 方案,真的不夠用了再升級到 Max 5x。

這也帶到下一節:如果你算下來 **確實需要省**,該怎麼省。

## 6\. 如果你想省:最有效的幾個動作

不是每個人都像我一樣吃 Max。如果你是 Pro、或走 API key 計費,以下是官方建議裡 **最有感** 的幾招。

### 省「對話」本身

- **切換新任務就 `/clear`** —— 這是最有效的一招。前面說過,對話越長、白板越滿、每句越貴。做完一件事、要開始不相關的新任務,就 `/clear` 開乾淨的白板。
- **`/compact`** —— `/clear` 是全清,`/compact` 是濃縮:想保留一點脈絡、又想清空間時用它。前面提過系統在白板太滿時會 **自動** 做一次(那行 `Conversation compacted`);`/compact` 就是你 **主動** 提早做。(小提醒:壓縮本身也會花一點 token 去產生摘要,但之後省更多。)
- **簡單任務用便宜模型** —— 改 typo、調文字,不需要動用最貴的 Opus。用 `/model` 切到 Sonnet 甚至 Haiku。

### 省「每個 prompt 的效率」

這塊我點到為止,因為它牽涉到後面兩篇的主題:

- **一次把話講清楚** —— prompt 越精準,來回越少、燒的量越少。(但別誤會,G1 講過 Claude Code 是「對話」不是「一次查詢」,該補充還是要補充。)
- **餵結構化文件** —— 給它整齊的 Markdown,比貼一坨雜亂文字省、也更準。
- **用 `CLAUDE.md` 避免重複交代** —— 把專案的固定資訊寫進去,就不用每次對話從頭講一遍。 **這個威力很大,完整講法留到 G3。**
- **記憶系統** —— 讓 Claude 跨對話記得你,也能少講很多重複的話。 **這是 G4 的主題。**

所以要省 prompt,最有用的其實是 G3 的 `CLAUDE.md` 跟 G4 的記憶系統。這篇先讓你知道它們跟用量有關,後面再拆開講。

## 7\. 該選哪個方案?(一張決策表)

把第 2 節收個尾。你是哪種人,大概就對應哪個訂閱:

![https://ithelp.ithome.com.tw/upload/images/20260602/20182796ONhELkST3G.png](https://ithelp.ithome.com.tw/upload/images/20260602/20182796ONhELkST3G.png)

> 圖說:你是哪種人,就選哪個方案 — Pro / Max 5x / Max 20x 的用量量級與適用對象

| 你是這種人 | 建議 |
| --- | --- |
| 偶爾寫一點、學習階段、預算敏感 | **Pro($20)** —— 先從這開始,不夠再升 |
| 幾乎每天寫、會用 Opus 跑重任務 | **Max 5x($100)** (我就是這個) |
| 重度、整天掛著、大量平行任務 | **Max 20x($200)** |

選方案的心法很簡單:**從低的開始,撞到上限再升。** 不要一開始就買最貴的 —— 你大概率用不到,而且 Pro 升 Max 隨時可以。

> **表格沒列 API key** —— 因為對新手它幾乎都不是答案。只有當你要做自動化、批次大量跑、或把 Claude 接進自己寫的程式時才需要,而且那是唯一會「用多少扣多少」的路。如果你真的走這條,務必到 [platform.claude.com](https://platform.claude.com/) 設一個 **monthly spending limit** (預設沒有上限)。
> 
> 其實 G1 結尾我提過「第一週燒掉 $30 才學乖去設上限」 —— 那正是走 API key 才會發生的事。 **如果你走訂閱,根本不是這樣算的**:封頂、不會有第二筆。所以新手走訂閱,連這個焦慮都省了。

## 8\. 本課單字:看懂用量的指令

延續 G1 的「本課單字」,這篇收四個跟「用量」有關的指令,看完就可以打進 terminal 試試:

### /usage

你的用量儀表板。訂閱用戶看「方案用量條」(那個 $ 金額忽略),按 `d` / `w` 切換 24 小時 / 7 天。 **對成本有感的第一步。**

### /context

看「這一輪對話的記憶體白板」被什麼佔用、還剩多少,並給優化建議。對話覺得變慢、變貴時,先打這個看看是不是塞太滿。

### /status

看你現在是「訂閱」還是「API」在計費、目前用哪個模型。 **懷疑自己被亂收錢時,先打這個。**

### /compact

把目前對話濃縮成摘要、清出白板空間。相對於 G1 教過的 `/clear` (全清),`/compact` 是「溫柔版」 —— 想保留脈絡又想省空間時用。對話跑很長、又還不想全部清掉時最好用。

## 9\. 給新手的三個提醒

### a. 先求「敢用」,再求「省」

新手最大的成本不是 token,是 **因為怕花錢而不敢用、學得慢** 。先用 `/usage` 確認花費在掌控中,然後放開用。省 token 是熟了之後的事。

### b. 不要相信網路上的「確切額度數字」

官方刻意不公布、而且常調整。看到「每 5 小時幾則」這種數字,一律當參考、別當保證。你自己的 `/usage` 才是真相。

### c. 從便宜方案開始,撞牆再升

Pro → Max 5x → Max 20x 隨時能升。一開始就買最貴的,通常是浪費。先用低的,讓 `/usage` 告訴你需不需要升。

## 結語

搞懂用量這件事,重點其實不在省錢,而在於 **你不再怕它** 。

當你知道自己是怎麼被收費的、額度怎麼算、花費去哪查,那個「會不會被亂收錢」的焦慮就消失了。然後你才會開始 **放開用** —— 而放開用,才是你真正開始學會 Claude Code 的時候。

我自己是 Max 5x、不太省,因為我算的是時間。你的帳大概不一樣,**重點是這筆帳你自己算過、自己決定的。**
