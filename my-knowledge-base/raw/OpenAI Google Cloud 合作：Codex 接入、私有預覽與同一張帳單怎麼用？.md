企業想把另一家的 AI 放進工作流程，常常得先過採購、帳號權限與資料管理，模型分數只是其中一關。

OpenAI Google Cloud 合作在 2026 年 10 月 21 日公布，把前沿模型與 Codex 工作流程帶進 Google Cloud 的 Model Garden。

Model Garden 是 Google Cloud 的模型目錄，這次合作讓原本就在這個雲端環境工作的團隊，多一個選擇模型的入口。

Google 隨後說明，Astra、Sol 與 Luna 正對選定企業客戶做私有預覽。OpenAI 把全面開放放在未來幾週，這是兩個階段，並非所有帳號今天都能直接啟用。

企業可透過 Marketplace 採購，抵扣既有雲端支出承諾，但不代表個人 ChatGPT 訂閱變便宜，也不代表所有資料保護選項都已就緒。

我會建議已有 Google Cloud 治理與採購需求的企業申請小型驗證。只想換個入口免費用 Codex 的人，這次合作不解決那個問題。

先把模型入口、執行位置與採購方式分清楚，才能判斷合作對自己的團隊有沒有差別。

## OpenAI Google Cloud 合作帶來什麼？模型入口與 Codex 工作流程

合作把模型推論帶進 Google Cloud 環境，Codex 則是利用模型完成開發工作的入口之一。

推論是模型讀取資料、產生回答或工具指令的計算。使用者看到的桌面程式、終端機與聊天介面，和背後執行模型的位置，不一定在同一個地方。

依 [OpenAI 官方公告](https://openai.com/index/openai-models-google-cloud/?ref=aiposthub.com) ，這次整合希望讓企業在原本使用的雲端環境裡，取得模型與代理工作流程，不必為每個新模型重新安排一套採購和資料治理。

代理工作流程是讓 AI 依任務分步驟執行、使用工具，再根據結果繼續處理。例如修改程式之後讀取測試結果，和只產生一段答案需要不同的系統配合。

因此，這次消息對企業開發者的意義，不只是多一個模型名稱。若模型可使用既有雲端身分、稽核與帳單，導入時能沿用的制度也可能增加。

但沿用平台不代表不用改任何程式。現有工具呼叫、回傳格式、錯誤處理與權限設定，仍要確認接入後是否照預期運作，不能從「同一個模型目錄」推成「一鍵替換所有工作」。

模型、操作工具和雲端平台也各有責任。模型負責判斷下一步，工具執行讀寫，平台控制誰能呼叫哪些資源，三者的設定不應混成一個開關。

對一般讀者，可以把這次合作理解成企業原本熟悉的採購與管理入口，多了新的模型供應選項。它沒有把 Google 自家的模型移除，也不是宣布某一家的能力全面取代另一家。

要接進現有工具之前，還得先核對自己能取得的是預覽，還是已全面開放的服務。

## Astra、Sol、Luna 誰能先用？私有預覽與未來幾週

選定企業的私有預覽已開始，全面開放仍是未來計畫，兩份官方說明可以放在同一條時間線理解。

[Google Cloud 的合作文章](https://cloud.google.com/blog/products/ai-machine-learning/google-cloud-brings-openai-models-to-customers?ref=aiposthub.com) 列出三個模型，並表示正在向選定企業客戶逐步提供。

私有預覽代表先讓部分客戶測試，不等於一般帳號都能取得。OpenAI 另一份公告則說，全面可用預計在未來幾週，並提供申請入口。

因此，公司已有 Google Cloud 合約，不代表員工打開控制台就一定看得到這些選項。還要看組織是否獲邀、管理員是否啟用，以及實際提供哪些模型。

Google 對三個 OpenAI 型號的定位如下，這些是產品描述，不能當成本站做過的性能排名。

| 模型 | Google 公告中的定位 | 評估時要問的問題 |
| --- | --- | --- |
| GPT-6 Astra | 較困難的寫碼、電腦操作、專業工作與研究 | 是否在自己的困難任務上減少失敗或返工 |
| GPT-6.1 Sol | 以較低成本提供接近 Astra 的能力 | 品質差距是否影響實際交付 |
| GPT-6 Luna | 大量日常工作需要的速度與成本效率 | 簡單工作是否能用更少資源完成 |

表格的選法是先看工作，再看型號。大量格式固定的整理工作，和跨檔案修正複雜程式，不必預設使用同一個模型。

但官方沒有在這次合作公告列出完整區域、每個型號的單價與全部配額。還沒取得這些資料前，不能只根據「較低成本」就替企業算出節省比例。

同樣地，私有預覽中的結果，也不能直接當成未來全面服務的長期條件。測試報告應保留使用日期、模型和當時設定，後續更容易對照變動。

取得資格後，才輪到企業真正要安排的採購與帳單，這也是合作最具體的一部分。

## Marketplace 與雲端承諾額度：同一張帳單不等於免費

雲端承諾抵扣改變的是採購通路，不會自動消除模型的使用成本。

Marketplace 是企業購買雲端產品的市場。這次模型會透過 Google Cloud Marketplace 交易，所以用量可放進同一張雲端帳單。

企業的雲端支出承諾，則是合約中答應在一定期間使用的金額。官方表示，這類採購可扣抵既有 Google Cloud 承諾支出，並納入跨模型供應商的 Flexible Savings Plans。

這對已有承諾的企業有實際意義，因為原本分散到外部模型平台的採購，有機會改走同一份雲端合約。但是否適用、如何抵扣，仍要對照自己實際的合約與服務條件。

不能因此認為「反正本來就有預算，呼叫模型不花錢」。那筆用量仍然消耗企業承諾支出，若把它分配給模型，就不能同時當成已用在別處的同一筆資源。

也不能拿 ChatGPT 個人訂閱做直接比較。ChatGPT、Codex 帳號方案與雲端模型推論，是不同採購層次，公告沒有說個人月費自動包含 Google Cloud 模型用量。

估算時應把模型請求量、工具往返和完成任務的成功率放在同一批工作裡看。單次模型較便宜，但若需要更多回合才能完成，總成本仍可能不同。

反過來，單次較昂貴的模型若減少大量返工，也可能適合某些工作。不過這是需用自家任務驗證的成本關係，不能從合作發布就推定哪個型號一定划算。

企業可以先選一種已知工作量，例如固定的程式審查或文件整理，計算相同輸入下的總消耗，再比較原通路與新通路。這樣才能分辨採購便利和模型效果各貢獻了什麼。

採購整合之後，資料保護功能也要按「已說明提供」與「即將推出」分開，不能把未來選項當成目前承諾。

## 資料治理與 ZDR：哪些保護已說明、哪些還在路上？

Google 列出資料邊界與稽核控制，但零資料保留和機密運算仍標示為即將推出。

資料治理是企業規定哪些資料可以交給誰、用在什麼工作，以及如何記錄和追查。當代理能讀文件、寫程式或操作工具，這些條件會和模型能力一起影響導入。

Google 表示，提示、上下文與輸出會留在指定資料邊界內，也不會用來訓練基礎模型。上下文是模型這次處理時一起讀取的資料，可能包含文件、程式片段與工具結果。

但「不用來訓練」和「完全不保留」是不同承諾。前者說明資料不進入模型訓練，後者還涉及服務端記錄與保存方式，不能把兩者當成同義詞。

ZDR 是零資料保留的縮寫，Google 在這篇公告把該選項列為即將推出。如果組織要求必須有 ZDR，現在就不能只憑合作消息判定條件已符合。

另一項未來功能是 Confidential Compute，也就是保護資料使用中狀態的機密運算。公告說模型會在專用 Google Cloud 基礎設施上運作，但專用設施不等於該功能今天已啟用。

官方另列出身分識別、統一稽核記錄與 VPC Service Controls。這些用來限制存取範圍和追查互動，但實際專案如何配置，仍是企業部署的一部分。

對團隊最有用的確認方式，是把必要條件逐一對到可取得的服務。如果工作只需要已提供的身分和稽核控制，可以在預覽中驗證；若必須依靠未推出選項，就先等待或改選符合要求的工作。

同一平台提供這些能力，也不代表任何地區、產業或資料類型都自動合規。公告能說明產品方向，實際使用仍要對照自己的資料處理條件，不能用一段合作新聞取代完整服務條款。

這些條件會影響哪些任務適合放進預覽，也讓「本機 Codex」四個字更需要分清楚。

## 本機 Codex 接雲端推論：介面位置與資料位置別混淆

本機命令列或桌面程式可以當操作入口，模型計算仍使用雲端服務，所以不是把模型下載到自己的電腦。

Google 表示，取得預覽的企業客戶能透過 API 建立工作，也能把本機 Codex CLI 和 Desktop 工作流程接到平台做推論。API 是讓程式呼叫服務的介面，CLI 則是終端機裡的操作工具。

這種安排讓開發者可能保留熟悉的操作方式，但後端改由企業選定的雲端模型服務處理。介面看起來相近，不代表資料流向和帳單來源沒有改變。

例如原本透過某個帳號方案工作的團隊，若改用雲端推論，應核對憑證、專案歸屬與用量紀錄，確認請求真的走向預期環境，而不是以為選了新模型就完成切換。

這不是要求每位一般讀者手動改設定，而是說明企業測試必須驗證的結果。合作公告沒有提供完整配置步驟，不能憑新聞自行拼出一組確定可用的服務網址。

工作驗收也應保持相同任務。若切換前用小型錯字修正，切換後測大型重構，就無法知道差距來自模型、平台，還是題目變難。

除了最後答案，也要看工具能否正常讀檔、修改與取得測試結果。代理任務靠多個環節串起來，單次文字回答正常，不表示整段開發流程都相容。

Google 與 OpenAI 也預告，未來還會把模型帶進 Antigravity 等產品。這和現在讓既有 Codex 入口連到預覽推論不同，不能把未來整合寫成今天每個使用者都能選。

能否保留原本操作方式，又不改壞既有工作，應用相同一批任務驗證，才有足夠依據決定是否擴大。

## 什麼企業值得試？從採購與治理問題倒推試點

已有 Google Cloud 合約、權限制度和資料管理需求的團隊，比追求消費者優惠的人，更可能直接受益。

如果原本引進一個新模型要另外簽約、建立帳號、整理帳單，改走既有平台可能縮短採購協調。但這項便利應和模型本身的品質分開記錄，才知道合作解決了哪個問題。

另一類值得評估的團隊，是希望同一份應用能依任務選模型。先把簡單整理、複雜分析與程式修改分開，會比所有工作預設都用最高階型號，更容易看出成本和能力的取捨。

但不適合為了多雲的名義，立刻把已運作的流程全部搬家。若新通路沒有改善採購、資料條件或任務效果，額外遷移反而會增加要維護的設定。

首次試點可以保留原通路，用同一批非正式工作比較新環境的結果與用量。當帳單、權限和任務品質都能對上，再安排更大範圍的遷移，比只看單次示範穩妥。

還要等實際區域和單價清楚後，才有辦法完成長期成本估算。官方的未來幾週是計畫時程，不能替組織保證某一天一定可正式上線。

OpenAI 同時明示，Microsoft 仍是主要雲端合作夥伴。因此，這次增加 Google Cloud 通路，應理解為取得方式擴大，不能寫成已經結束與既有夥伴的合作。

真正的採用判斷，是這個新入口是否讓自己的工作更容易管理、交付和結算，而不是合作名單變長就必須跟進。

## OpenAI Google Cloud 合作常見問題

### OpenAI Google Cloud 模型已經全面開放嗎？

尚未。Google 說選定企業私有預覽已開始，OpenAI 把全面可用列為未來幾週的計畫，仍要看帳戶實際資格。

### ChatGPT 訂閱會包含 Google Cloud 模型用量嗎？

合作公告沒有這項承諾。雲端模型透過 Marketplace 交易，與個人 ChatGPT 訂閱是不同採購與計費安排。

### 使用本機 Codex 就代表資料不會離開電腦嗎？

不代表。這次本機工具是操作入口，後端推論透過 Google Cloud 服務執行，應依實際連線與資料治理條件判斷。

### ZDR 和 Confidential Compute 已經可以用嗎？

Google 在合作公告中把兩項都標為即將推出。需要依賴這些能力的企業，不能先當成預覽已提供的條件。

## 先確認取得資格與帳單條件，再安排模型比較

這次合作最直接的變化，是企業可在既有 Google Cloud 採購與治理環境裡評估更多模型。它不保證價格更低，也不代表消費者方案得到新額度。

已有相關需求的企業，可以先申請預覽、核對必要資料條件，再用同一批工作比較品質與總成本。需要未推出功能的團隊，則等條件到位後再安排正式採用。

想持續追蹤模型平台、Codex 與企業 AI 採購變化，可以免費訂閱 AI 郵報，並在測試前重新核對官方開放狀態。
