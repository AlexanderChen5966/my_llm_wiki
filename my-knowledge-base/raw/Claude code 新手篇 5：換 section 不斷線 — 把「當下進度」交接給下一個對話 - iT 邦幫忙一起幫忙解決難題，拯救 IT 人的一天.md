## Claude code 新手篇 5：換 section 不斷線 — 把「當下進度」交接給下一個對話

- 分享至

> 這是「Claude Code 實戰手冊」系列的第五篇(G5)。G3 講了 `CLAUDE.md` (你寫的專案規矩)、G4 講了自動記憶(它自己記的筆記)，但那兩篇都放不了「這次做到哪、剛剛決定了什麼」。這篇補上最後一塊 —— 對話跑太長要換一塊乾淨白板時，怎麼讓進度不斷線。

## 1\. 記憶管得住規矩，管不住「做到哪」

G3 跟 G4，我們花了兩篇把「跨對話記得」這件事講完:你手寫的 `CLAUDE.md` (專案的規矩)，還有 Claude 自己記的筆記本(自動記憶)。

但那兩篇的結尾，我都留了同一句話:**它們都不適合放「這次做到哪、剛剛決定了什麼」。**

為什麼不適合？因為那種東西 **會過期** 。你今天做到第三步，明天就第五步了;你今天決定「先用 A 方案」，下週可能整個換掉。這種當下的、一次性的進度，寫進「每次對話都自動載入」的常駐檔，只會讓 Claude 每次都讀一份過時的資訊。

可是問題就來了。你一定遇過這個情況:

> 一個任務做到一半，對話越來越長 —— 開始變慢、你也隱約感覺它「有點忘了前面」。你想開一個乾淨的新對話重新來過，但一開新的， **剛剛那一大攤進度就斷片了**:做到哪、剛剛為什麼選這個方案、哪個檔不能動……全都要重講一遍。

這就是這篇要解決的事。而且要先講清楚一件事:

> 🎯 **這篇講的不是「記憶」，是「交接」。** 記憶(G3/G4)管的是 **長期穩定** 的東西;交接管的是 **當下這一攤** 。兩件事，兩種工具。

---

## 2\. 先分清楚:三種「換」，別搞混

新手最容易把接下來的東西混成一團，所以先花一分鐘把三件事排開。你手上目前有三種「換」:

| 你想做的事 | 用什麼 | 這是哪一篇教的 |
| --- | --- | --- |
| 換一個 **全新對話** ，舊的不要了 | `/clear` —— 直接擦掉白板 | G1 |
| 讓它記住 **長期的規矩 / 偏好** | `CLAUDE.md` 、自動記憶 | G3、G4 |
| 把 **當下這攤進度** 搬到下一塊白板 | **交接** ← 這篇 | G5 |

一句話定調:

> **記憶管「長期穩定」，交接管「當下這一攤」。**

搞混的下場很具體:把「這次做到哪」寫進 `CLAUDE.md` ，它就變成一份每次對話都被讀一遍的過期筆記(G3 講過的「規矩不是日記」);反過來，把「這個專案一律用 yarn」只留在交接檔裡，下次開新任務又得重講一遍。

---

## 3\. 先講內建的三招:壓縮、倒帶、挑回舊對話

在說明做法之前，我想要先提到:**Claude Code 本身就有處理這件事的內建工具。** 我們應該先了解它們，也該知道它們的極限在哪。

### /compact —— 把白板上的字壓縮成摘要

在對話裡打 `/compact` ，它會 **把目前整段對話換成一份結構化的摘要**:你的需求和意圖、關鍵的技術概念、看過或改過哪些檔、遇到什麼錯誤怎麼修的、還有哪些待辦、現在做到哪 —— 這些它會留著。

換來的好處是白板騰出空間，你可以在 **同一個對話** 繼續做下去。

但它 **丟掉** 的東西也很實在:逐字的工具輸出、中間的推理過程、它先前讀過的原始程式碼細節。壓縮完它還記得「我改過那個檔」，但不會再有那個檔的完整內容在手上。

> 💡 **一件你可能已經遇到、但不知道原因的事:** 白板快滿的時候，Claude Code 會 **自己** 做這件壓縮(auto-compaction)，不是只有你手動打 `/compact` 才會發生。所以有時你會覺得「它怎麼好像忘了前面講的細節」—— 很可能就是剛剛自動壓縮過了。

### /rewind —— 倒帶回剛剛那個時間點

按兩下 `Esc` (或打 `/rewind`)，可以回到之前某個時間點的 **對話與程式碼狀態** ，也可以從你選的某一則訊息重新開始摘要。做壞了、想退回去重來的時候用這個。

### /resume —— 挑回之前的對話

開 Claude Code 時用 `/resume` ，可以從清單裡挑一個之前的 session 接著做。

### 那為什麼還需要「交接檔」？

上面這些都很好用，但它們有三個共同的限制:

- **壓縮留什麼，是「它」決定的。** `/compact` 幫你摘要，但你沒辦法精準指定「我要 A、B、C 這三件事一定留下來」。
- **它們跨不出這台機器、這個專案。** `/resume` 挑得回你自己的舊對話，自動記憶也只在這台電腦(G4 講過)。但你沒辦法把它「傳給同事」「餵給另一個 agent」。
- **有時你就是想要一塊乾淨的白板。** 不想帶著舊對話那一堆雜訊，只想帶「結論」過去 —— 壓縮做不到這件事，它是把舊的濃縮，不是重新開始。

這三個限制，正好就是下一節那招的用武之地。

---

## 4\. 主角登場:讓 Claude 產生一份「交接檔」

這是我自己工作流裡天天在用的一招，講穿了非常簡單:

> **在換對話之前，叫 Claude 把「現在做到哪、決定了什麼、下一步要做什麼」寫成一份交接檔。**

就這樣。一個檔案，交給下一棒。

你可以把它想成 **下班前留給接班同事的交接單** 。你不會把整天的對話錄音丟給他，你會寫一張紙條:進度到哪、剛剛為什麼這樣決定、他接手第一件事該做什麼、哪裡有雷。

比起 `/compact` ，它多了三個關鍵好處:

- **你控制內容。** 你點名要寫哪幾件事，不用賭它幫你摘要時會不會留下來。
- **它是一個檔案。** 檔案可以貼給下一個對話、可以傳給同事、可以丟給另一個 agent，甚至可以存進 git。它跨得出這台機器。
- **人也讀得懂。** 你自己打開來就看得到「上一棒做到哪」，不用去翻對話記錄。

> 💡 **那這個檔要用什麼格式？** 最直覺的是 `.md` ，先用它就好。 **不過我自己後來改用 `.html` 了** —— 為什麼、差在哪，結尾會講。

### 實際上怎麼下這道指令

新手最需要的是「我到底要打什麼」，所以直接給你一句可以複製的:

```markdown
我們等一下要換一個新對話繼續。
幫我產生一份交接檔 handoff.md，寫清楚:
1. 這個任務的目標
2. 目前已經完成什麼、改了哪些檔
3. 剛剛做的關鍵決定，以及為什麼這樣決定
4. 還沒做的下一步
5. 有哪些地方不要碰、有什麼雷
```

然後在 **新的對話** 開場，只要一句:

```markdown
先讀 handoff.md，然後接著上一棒繼續做。
```

新白板一開場就拿到了上一攤的重點，你不用重講。

> 圖說:換對話前先產一份交接檔，新對話讀它接手 —— 白板換了，進度沒斷

## 5\. 交接檔裡該寫什麼(一個可以直接抄的骨架)

跟 G3 教 `CLAUDE.md` 一樣，重點不是「有這個檔」，而是 **裡面寫什麼** 。給你一個骨架:

- **① 目標** —— 這個任務要達成什麼，一兩句話就好。
- **② 已完成** —— 做到哪一步、動過哪些檔。
- **③ 關鍵決定 + 為什麼** —— 這是 **最重要、也最容易斷片** 的一項。「我們選了 A 方案，因為 B 方案在這個情境會卡住」—— 這句話沒留下來，下一棒很可能又繞回去試 B。
- **④ 下一步** —— 接手的第一件事該做什麼。
- **⑤ 別碰 / 注意** —— 哪些檔不要動、踩過什麼雷。

判斷標準只有一條:

> **想像你明天失憶了坐回這台電腦，你會希望桌上那張紙寫什麼？** 寫那個就對了。

還有一個提醒，跟 G3 那條分界同一個道理:

> 🎯 **交接檔是一次性的快照，不是 `CLAUDE.md` 。** 任務做完它就可以丟掉。別把它變成常駐檔 —— 過期的進度天天被讀進白板，只是浪費。

---

## 6.(進階，先知道就好)同一招也能交接給「另一個 agent」

這一節你現在不用急著用，但值得知道這條路存在。

交接檔的下一棒，不一定是「你的下一個對話」，也可以是 **另一個 agent** 。

舉個例子:你讓一個 agent 專心做調研，調研完它產出一份交接檔;接著另一個 agent 讀那份檔，接手去做實作。兩個 agent 之間沒有共用的記憶、也沒有共用的白板 —— **那份交接檔就是它們唯一的接口** 。

這就是多 agent 協作最樸素的雛形:不是什麼玄妙的架構，就是「上一棒寫一張紙條，下一棒讀它接手」。

> 💡 **但現在別急。** 對現在的你， **先把「換對話用交接檔」練熟就夠了** 。等你哪天真的需要拆成多個 agent 分工，你會發現用的還是同一招。

## 7\. 本課單字:接住當下進度

延續系列慣例，這篇收三個 —— 兩個內建指令、一個動作:

### /compact

把目前對話壓縮成結構化摘要，騰出白板空間繼續做。 **同一個對話想接著跑、但覺得變慢變鈍時用它。** 記得它會丟掉逐字細節。

### /rewind(或按兩下 Esc)

回到之前某個時間點的對話與程式碼狀態，也可以從某則訊息重新摘要。 **做壞了想倒帶時用。**

### 「幫我產生一份交接檔」(這個也不是斜線指令，是一句話)

本篇的主角動作。 **要換乾淨白板、要精準控制帶什麼過去、要傳給別人或別的 agent 時，用它。** 一份檔案，交給下一棒。

---

## 8\. 給新手的三個提醒

### a. 先分清楚「記憶」和「交接」

穩定的規矩 → `CLAUDE.md` / 自動記憶(G3、G4)。當下的進度 → 交接檔(這篇)。 **搞混了，就會把會過期的東西塞進每次都要讀的常駐檔。**

### b. 交接檔的價值在「為什麼」和「下一步」

只寫「我做了什麼」的交接檔用處有限。真正救命的是\*\*「剛剛為什麼這樣決定」 **(免得下一棒繞回頭走冤枉路)和** 「接手第一件事做什麼」\*\*(免得它從頭猜)。

### c. 內建的先用，不夠再手動

同一個對話想繼續 → `/compact` 就好，不用大費周章。 **想要乾淨白板 + 只帶結論、或要傳給別人 → 才用交接檔。** 別一開始就把流程搞複雜。

## 結語

到這裡，「 **讓資訊跨對話傳下去** 」這件事，你手上湊齊三種工具了:

- **你寫的規矩** —— `CLAUDE.md` ，專案的長期慣例(G3)。
- **它記的筆記** —— 自動記憶，它自己累積的經驗(G4)。
- **你交接的快照** —— 交接檔，當下這一攤的進度(G5)。

三個各管一段，不要互相取代:規矩要常駐、筆記讓它自己長、進度用完就丟。

不過交接這件事，我自己後來還多做了一個調整 —— **把交接檔的格式，從 `.md` 換成了 `.html`** 。

理由很單純:純文字的 `.md` 打開來一片黑白，重點跟雜訊長得一樣，我常常要讀第二遍才抓得到。換成 `.html` 之後，重點可以放大、可以標色、可以排成表格 —— 我掃一眼就知道現在在哪。做網頁的時候更明顯:我可以直接叫它畫一個簡單的 wireframe，用畫面跟它對需求，比我打一百字描述精準得多。

這招不只用在交接檔，而是改變了我平常「怎麼跟 Claude 來回」的方式。下一篇就講這個。

---

下一篇 **G6 — 別再只丟純文字:用 HTML 跟 Claude 溝通** 。同樣的內容，`.md` 打開是一片黑白，`.html` 可以放大重點、標色、排表格，甚至直接生一張 wireframe 跟它對需求。這篇講我怎麼用、什麼時候用 —— 以及什麼時候 `.md` 就夠了。
