> **本期要点**
> 
> 装好 Claude Code 就吃灰，不是工具不行，是顺序错了。大多数人先装工具再找问题，我反过来：先看每天做内容的六个步骤，每一步配一个 Skill。从早上七点自动跑同行数据选题，到三个 AI 交叉审稿、五轮迭代封面、字幕一键转文章，再到一条命令推送四个平台。六个工位串成一条流水线，AI 出方案，判断永远在自己手里。

## 你可能早就把它装好了，然后呢？

你可能早就把 Claude Code 装好了，跑过几个任务，甚至自己做过一些 Skills。那一刻你觉得它挺厉害的。但回到日常，你还是把它当成一个终端里的 ChatGPT，问一句答一句，复制粘贴。

这个问题不在于安装，也不在于第一个 demo。是因为它压根没被你安排进真正的工作流里。

先给你看一组数字。Claude Code 官方有一个使用洞察报告，给我算过一笔账：我用得最猛的那个月，有五万五千多条消息，六千多个会话，三百多万行的代码改动。报告给我的评语是「工业级规模」，还有一句我特别认同的话：你设置的大量自动化，才是真正在发挥 Claude 的杠杆，而不是拿它做一次性任务。

背后真正干活的，是我自己写的七十多个 Skills。而每天真正离不开的，就这六个。

## 为什么多数人装完就吃灰

大部分人装完 Claude Code、装完 Codex 就吃灰，不是工具不行，是顺序错了。大部分人是先装工具，再找问题：装了十几个看起来很厉害的 Skills，每个都试一下，每个都觉得还不错，然后再也没打开过。

我的做法是反过来的。先看我每天的活是什么，再给每一步配一个 Skill。我的活是做内容，从选题到发布一共六步。所以接下来你看到的六个 Skills，不是六个孤立的工具，而是一条流水线上的六个工位。

这个思路你可以直接照搬：把你的工作拆成几步，每一步找一个 Skill 来做。

![左边是一堆散落吃灰的灰色工具，一个人迷茫地站在旁边；右边同样的工具被一条焦橙色的线串成一条有序的路径，一个人沿着路径自信前行](https://img.axtonliu.com/newsletters/2026/06/2026-06-19-six-skills-claude-code-content-pipeline-02.png)

## 工位一：选题

这是我所有 Skills 里最值钱的一个。它每天早上七点，自动监控三十一个同行的频道、一千四百多条视频，然后告诉我什么选题在涨，什么在跌。

给你看它具体怎么干活。我手里同时有几个选题想法，自己也拿不准，就让它把这几个方向到同行频道里跑一遍数据。拉回来的结果经常让我意外：我自己最看好的那个方向，同行做出来普遍只有几千播放；另一些我没太在意的方向，同类视频却有人能做到几万、几十万。

我不会盲信自己的直觉，也不会盲信它给的数据。但它给了我决策时该有的参考：真实的数据，而不是一个人拍脑袋。最后到底做什么，还是我定，但我是有依据地定。这就是 Skill 和「问一句 AI」的区别。

> 你问 ChatGPT「我该做什么选题」，它会凭训练数据给你猜一个。而这个 Skill 给我的，是 31 个频道此时此刻的真实播放量。

这个 Skill 是我自己写的，暂时还没开源。我正在把它和另外几个工具整合成一套，之后如果开源，会第一时间通知你。

在那之前，思路我直接告诉你，很简单：让 Claude Code 帮你写一个。你只要说清楚三件事：

- 监控谁
- 看什么数据
- 每天什么时候运行

这正是 Claude Code 的正确用法：没有的工具，就让它给你造。

## 工位二：审稿

选题定了，稿子写完了，第二个工位是审稿。写东西的人都知道，自己看自己的稿子很难看出问题。我的做法是让三个 AI 互相挑刺：Claude 负责写，Codex 和 Gemini 负责评审。

一个真实的例子。我之前写过一篇 Newsletter，自己读了几遍都觉得没问题，丢给这个 Skill 之后，Codex 直接指出了全文最大的逻辑漏洞：我用来支撑观点的一个类比，仔细推敲反而是我观点的反面证据。这种细微之处，Codex 很擅长揪出来。

跟人一样，一个 AI 写东西也会自嗨；两个不同公司的 AI 互相挑刺，就可靠多了。这个 Skill 叫 ai-pair，已经开源，链接放在文末。

## 工位三：封面与配图

第三个工位是封面和配图。这个 Skill 叫 smart-illustrator，是我开源项目里用得最多的一个。一句话描述：它给你出概念方案，连图带封面文字一起给。

给你看一次真实的迭代。这是我之前一条视频的封面，第一版是保险库的大门，风格不对，否决；第二版太吓人，删掉；来回五轮，最后定了一个抽象隐喻，封面文字就两个字。那条视频的点击率也很好。

重点不是 AI 一次出图有多惊艳，是它把「我有个模糊的感觉」到「五个可选方案」之间的时间，从原来的很长，压缩到了几分钟。

## 工位四：图解与动画

第四个工位，视频里的图解和动画。你在我视频里看到的那些手绘风格的思维导图、一步步展开的流程动画，不是我手工拖鼠标画的，是用一个叫 Excalidraw Diagram 的 Skill，把文字直接变成图，还能生成动画。我有一条视频，光思维导图动画就一万多帧，全是它生成的。

更划算的是，这些图做完，不只视频能用，文章配图也能直接用，一图两用。这个在我 GitHub 开源的 Obsidian 可视化 Skill（axton-obsidian-visual-skills，已获 3000+ Star）里就有，链接放在文末。

## 工位五：字幕校对

第五个工位，发布前最枯燥的活：字幕。视频录完，自动转录的字幕很可能是一堆错别字。这个 Skill 帮我校对，我有一条视频将近 700 块字幕，它能挑出几十个错的地方。

### 一份工作，两份产出

但真正值钱的是下一步。校对好的字幕，另一个 Skill 可以直接把它变成一篇能发布、能存档的文章。700 多块字幕变成 45 个段落，还附上 30 多条编辑建议：哪里要删口语，哪里该补背景，都给你标好。一条视频的内容，就这样自动变成一篇文章。一份工作，两份产出。

## 工位六：发布

最后一个工位是发布。文章写完，要发到我的网站、发到 Newsletter、发到微信公众号，还可以发到 X。四个平台，四种格式，手工干一遍，得一两个小时。

这个 Skill，一条命令：自动配图，图片传到我自己的图床，替换成图床链接，生成微信能用的格式直接推送到草稿箱，再打包成 X 支持的文章格式。我只需要坐在那儿看着它跑，点几下确认就行。

（你现在读到的这篇 Newsletter，就是这条命令的产物。）

## 六个工位串起来看

![从选题到发布的六个工位排成一条横向流水线，一条焦橙色的主线把它们串起来，末端站着一个手持对勾的人负责验收](https://img.axtonliu.com/newsletters/2026/06/2026-06-19-six-skills-claude-code-content-pipeline-01.png)

这才是今天真正想交给你的东西。我三月份有一条视频，整个生产过程是这样的：

1. 选题：用数据锁定方向
2. 审稿：三个 AI 交叉评审，揪出两个问题
3. 封面：五轮迭代定稿
4. 图解动画：一万多帧自动生成
5. 字幕：自动校对 + 自动转文章
6. 发布：一条命令推送四个平台

> 从选题到全网发布，过去这是一个小团队一周的活。现在我一个人，加上一台装了这些 Skills 的 Claude Code，就能搞定。

注意，每个环节最后拍板的，还是我，还是人。封面我迭代了五版才定稿，审稿意见也是我决定改不改。 **AI 出方案，判断永远在自己手里。**

这就是这套东西真正能跑起来的原因。

## 你的活不一定是做内容，思路一样

你的工作可能不是做内容，但思路一模一样：把你的活拆成一个个工位，每个工位找一个 Skill 来做，最后你来验收。复杂的工位，可以让几个 Skills 组队，用 Agent 给它配上更多 Skills、更多工具和能力。今天我们先从单个 Skill 入门，跑通了再加。

Claude Code 装完会吃灰，不是因为它不强，而是因为你还没把它放进你的工作里。今天这六个工位，开源的我都把链接放在文末了，装上就能用；没开源的，思路也都给你了，让 Claude Code 帮你做一个，这本身就是你练习用 Claude Code 最好的方式。

工具我可以给你，但有一件事是工具给不了的：

- 怎么把任务说清楚
- 怎么画边界
- 怎么验收结果

这三件事，是「工具堆」和「工作系统」的差别。
