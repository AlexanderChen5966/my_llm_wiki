## Claude Code 雲端實戰篇0：拿送的美金 250 額度做一個每天自動跑收集股票相關資訊的工具(總覽)

- 分享至

## 為什麼想測

9 月底，Claude Code 的雲端 session 正式推出，Pro 和 Max 訂閱者可以領一筆只能用在雲端的額度，我的 Max 方案領到美金 $250，11/5 到期。領取期限已經過了，不過沒領到也沒關係：每天自動跑的排程本來就不扣這筆額度，扣的是訂閱用量（第 4 節坑 7）。

介紹文章很多，大多是在講「關上電腦它還會繼續跑」「手機也能下指令」。但我比較想知道的是：

- 實際丟一個真的專案上去，它能做到什麼程度？
- 那筆額度到底怎麼扣？用得完嗎？
- 雲端跟本機差在哪，會不會有本機遇不到的問題？

所以我不看介紹， **直接拿它從零做一個每天要跑的東西** ：每個交易日早上 8 點多，自動收集前一天的大盤、法人、類股、ETF 和新聞，整理好送到我的 Telegram。

選這個題目，是因為它剛好用得到雲端的兩個功能：「寫程式」用雲端 session，「每天自動跑」用排程（Routines）。而且收集盤前資訊是很多人每天都要花時間做的事。

先說清楚：

- **這是我自己好奇做的測試，沒有業配。**
- **報告只整理公開資訊，不構成投資建議。** 觀察清單只放大盤和 ETF，不碰個股。
- 開發和測試是 2026-10-07～10-09，之後排程每個交易日都還在跑；我用的是 Max 方案。

## 先講結論

1. **開發 3 個版本，總共花了美金 $22，都從雲端額度扣。** 每天的排程跑一次約美金 $0.34～0.50（Claude Code 估算的 API 價格）， **但排程不扣雲端額度，扣的是訂閱用量。**
2. **最大的坑不在 AI，在「雲端主機的位置」。** 同一支程式，在台灣跑全部正常，搬到雲端就被證交所擋。而且擋頁回的是 HTTP 200，只看狀態碼會以為成功。
3. **雲端 session 是「做東西的地方」，不是「放東西的地方」。** 適合有頭有尾、材料在 GitHub 上、你不用在電腦前的工作。要每天跑，要靠排程。
4. **AI 寫的程式和報告，數字很準。** 這幾天的報告都用另外寫的程式核對，AI 寫出來的數字全部正確。關鍵在設計：數字由程式算好，AI 只負責照抄和寫文字。
5. **對投資人來說** ：每天早上一則訊息，看完前一天的大盤、法人、ETF 和新聞重點。但它只整理資訊，不推薦、不預測。

下面照順序講。

每個交易日 08:07，排程會自動跑，大約 2 分鐘後，我的 Telegram 就會收到一則「盤前整理」：

最上面是 AI 寫的「今日重點」。這是 10/8 早上那份（資料日 10/7）：

> 2. 三大法人合計 -241.6 億、外資 -130.4 億；鉅亨網內文列出的外資賣超前 10 名裡，有觀察清單的 0050（內文寫 2.41萬張，JSON 外資 -24,147 張）。
> 3. 今天的行事曆有行政院會、內政部公布 9 月人口統計、財政部公布 9 月進出口統計，以及多家公司法人說明會；觀察清單 ETF 今天沒有除息。

下面是數字和新聞：

- **大盤** ：加權指數、成交金額、上漲和下跌各幾家
- **法人** ：外資、投信、自營商的買賣超（這三類機構投資人合稱「三大法人」）
- **融資融券** ：投資人借錢買股（融資）、借股票來賣（融券）的餘額變化
- **類股** ：漲最多、跌最多的前三個產業
- **ETF** ：觀察清單 5 檔的收盤、漲跌、外資和投信的買賣超

## 給股民：它幫你省了什麼、有什麼限制

**省了什麼** ：以前開盤前，我要自己開證交所看法人、翻好幾個新聞網站，再看一下自己的 ETF。現在早上一則訊息就看完，新聞也先幫我挑過、寫好摘要。

**準不準** ：報告裡的數字是程式從證交所抓下來算好的，AI 只負責照抄和寫文字。我另外寫了一支程式，把每份報告上的 42 個數字跟證交所再對一次，到 10/15 為止，寫出來的數字都正確；證交所擋掉、抓不到的資料，報告會寫「無資料」，不會自己填（第 5 節）。

**限制** ：

- 只有大盤和 5 檔 ETF，沒有個股。
- **只整理資訊，不推薦、不預測。** 新聞裡分析師的看法、目標價，刻意不寫進報告。
- 新聞只看 Yahoo 股市、經濟日報、鉅亨網三家。
- 證交所偶爾會擋雲端的主機，那天某些資料會寫「無資料」。

**不會寫程式能用嗎？** 老實說有門檻，但不用自己寫程式：

- 要有 Claude 的 Pro 或 Max 訂閱、一個 GitHub 帳號、Telegram。
- 把我放在 GitHub 的專案複製一份到自己的帳號，照 README 建一個 Telegram 機器人、一個雲端環境、一個排程。我第一次弄，設定的部分大約花了 40 分鐘。
- 每天跑一次，大約用掉美金 $0.5 等值的訂閱用量（Claude Code 的估算）。Pro 的用量上限比 Max 低，每天跑會佔掉一部分。
- 觀察清單在 `config.toml` ，可以換成你自己關心的 ETF。

> 深入篇：#2（10/30）給股民的設定教學，從複製專案到收到第一則訊息，一步一步附截圖。

下面開始是技術細節，想知道雲端 session 怎麼用、踩了哪些坑的人再往下看。

## 1\. 雲端 session 和排程，到底是什麼

### 雲端 session

一句話： **把 Claude Code 搬到 Anthropic 的主機上跑。** 你丟一個任務就可以關電腦，它會繼續做，做完把改動推到 GitHub 的分支，你看過再合併。

|  | 本機 | 雲端 session | Remote Control |
| --- | --- | --- | --- |
| 跑在哪 | 你的電腦 | Anthropic 的雲端主機（Ubuntu、4 核、16 GB） | 你的電腦 |
| 電腦關掉 | 停 | 繼續跑 | 停 |
| 碰得到什麼 | 你電腦上的檔案 | 只有 GitHub 上的 repo | 你電腦上的檔案 |
| 網路 | 都能連 | 預設只能連套件庫、GitHub 這類白名單 | 都能連 |
| 從哪裡開 | 終端機 | 網頁、手機 App、桌面版、 `claude --cloud` | 用手機遙控本機的 session |

一開始我以為「放在雲端」就代表它可以一直開著，後來才搞清楚： **它是做東西的地方，不是放東西的地方。** 主機是臨時借的，閒置幾分鐘就暫停，之後可能被回收。做完的東西要推回 GitHub 才留得下來。

### 排程（Routines）

要「每天自動跑」，要用另一個功能：排程。設定一段指示、一個 repo、一個觸發條件（排程、API、GitHub 事件），時間到了它就 **開一個新的雲端 session** 照著做。最短間隔是一小時，目前還是 research preview。

### 什麼任務適合丟給它

我整理出四個特徵：

1. **材料都在 GitHub 上** ，不需要你電腦裡的東西。
2. **是一件有開始、有結束的工作** ，不是要一直開著的服務。
3. **你不用在電腦前** ：丟了就走，用手機看結果。
4. **成品有地方放** ：GitHub 的分支、PR，或像這次送到 Telegram。

> 深入篇：#1（10/23）雲端 session 該不該用、本機／雲端／Remote Control 怎麼選、第一個任務怎麼下。

## 2\. 實驗怎麼設計

### 分工

```markdown
本機（我 + Claude Code）：寫規格、審 PR
        │
        ▼
雲端 session：照規格從零寫程式，開 PR          ← 扣雲端額度
        │  合併
        ▼
排程：每個交易日 08:07 開一個雲端 session      ← 扣訂閱用量
   程式抓資料、算好數字 → AI 讀新聞、寫報告 → 送 Telegram → 存回 GitHub
```

程式碼全部讓雲端 session 從零寫，我不自己寫。我在本機用 Claude Code 做兩件事：先把規格寫清楚（要抓哪些資料、怎麼算、報告長怎樣），PR 開出來後在本機審過再合併。這也是官方建議的用法：本機規劃、雲端執行。

### 數字由程式算，AI 只照抄

盤前資訊最怕數字錯。所以我刻意把工作切開：

- **程式** 負責抓證交所的資料，把每個數字算好、格式化成要顯示的樣子（例如「-66.6 億」）。
- **AI** 負責挑新聞、讀內文、寫整理， **數字一律照抄程式給的** ，不能自己換算，也不能上網另外查。

### 量什麼

| 項目 | 怎麼量 |
| --- | --- |
| 花費 | 每個階段前後看雲端額度餘額；排程那次執行裡輸入 `/usage` |
| 時間 | 從開始到開出 PR |
| 準確度 | 另外寫一支核對程式，自己再向證交所抓一次，比對報告上的 42 個數字 |
| 踩坑 | 每遇到一件意外就記一列，雲端那邊也被要求記 |

## 3\. 開發過程：三個版本、一個排程

| 版本 | 做什麼 | 模型 | 時間 | 花費 | 結果 |
| --- | --- | --- | --- | --- | --- |
| v1 | 從零寫：抓資料、算數字、送 Telegram | Opus 5.5 | 約 40 分鐘 | 美金 $11 | 118 個測試；Telegram 收到測試訊息 |
| v1.1 | 減少對證交所的請求、修正法人算法 | Opus 5.5 | 約 20 分鐘 | 美金 $5 | 請求 12 次 → 6 次，不再被擋 |
| 排程 | 每個平日 08:07 跑一次 | Sonnet 5.5 | 每次 1～2 分鐘 | 不扣額度 | 第一次就送出報告 |
| v2 | 讀新聞內文，寫「今日重點」和新聞摘要 | Opus 5.5 | 約 40 分鐘 | 美金 $6 | 181 個測試 |

雲端額度從 $250 → $239 → $234 → $228。

![https://ithelp.ithome.com.tw/upload/images/20261015/20182796hhudGYIjLU.png](https://ithelp.ithome.com.tw/upload/images/20261015/20182796hhudGYIjLU.png)

幾個讓我意外的地方：

- **它會回頭指出規格的錯。** 我在規格寫「外資 = 外資及陸資 + 外資自營商」，它實作時讀到證交所的備註：「外資自營商買賣金額已計入自營商買賣金額」，提醒我這樣會重複計算。那天外資自營商剛好是 0，我自己根本看不出來。
- **它會派一個子代理審自己的程式。** v1 做完後，它另外開一個 agent 對照規格審查，修了 3 個 bug（例如某檔 ETF 沒有成交時，整個流程會中止）。
- **它會在 PR 說明列出「規格沒寫清楚的地方」** ，v1 列了 27 個，每個都附上它的暫時做法。這比它自己亂決定好太多。

> 深入篇：#6（11/27）v1 → v2 → v3 怎麼演進，以及怎麼設計才讓 AI 整理資訊又不亂寫。

## 4\. 踩坑實錄

這是這次最有價值的部分。照類型分，每個坑這裡只講重點，細節分在後面幾篇：

- 網路（坑 1、2）→ #3（11/6）
- 額度與費用（坑 7、8）→ #4（11/13）
- 排程、金鑰、介面、外部依賴（坑 3～6、9～11）→ #5（11/20）

### 雲端主機的網路

**坑 1：證交所擋雲端主機，而且擋頁回 200。**  
同一支程式，在我台灣的電腦上跑，12 個資料來源全通；搬到雲端，證交所開始回「因為安全性考量，您所執行的頁面無法呈現」。更麻煩的是：openapi 的擋頁回 **HTTP 200** ，www 的回 **307** ，而且沒有轉址目標。第一次連線檢查只看狀態碼，結果回報「全部連得到」，其實是錯的。後來改成檢查內容是不是擋頁。

被擋的情況還會越來越嚴：一開始只擋幾個網址，反覆測試之後，原本正常的也開始被擋，冷卻 15 分鐘才恢復。

![https://ithelp.ithome.com.tw/upload/images/20261015/201827963VmkcXXb9k.png](https://ithelp.ithome.com.tw/upload/images/20261015/201827963VmkcXXb9k.png)

解法是 **減少請求** ：我在本機找到一個網址就能拿到大盤、類股、成交統計和全部 ETF 的收盤價，v1.1 把每次的請求從 12 次降到 6 次，之後只剩 ETF 法人那一支偶爾被擋：到 10/15 為止，10/7 第一次手動執行和 10/14 的排程各被擋一次，其他天都正常。

這件事讓我體會到雲端 session 的一個好處： **開發和正式跑都在同一種雲端環境。** 如果在本機開發、本機測試，這個問題要等上線才會發現。

**坑 2：預設網路連 pypi 都不行；執行中改設定不會生效。**  
我把網路設成「自訂」，只開需要的網域，結果 `pip install` 被擋。我在 session 跑到一半時把 pypi 加進允許清單，官方文件說「執行中的 session 約一分鐘內會套用」，但實際上還是被擋，要新開的 session 才生效。好在主機上已經裝好 requests 和 pytest。

![https://ithelp.ithome.com.tw/upload/images/20261015/20182796sBjmjRRPUR.png](https://ithelp.ithome.com.tw/upload/images/20261015/20182796sBjmjRRPUR.png)

![https://ithelp.ithome.com.tw/upload/images/20261015/20182796kzWcDaJD1n.png](https://ithelp.ithome.com.tw/upload/images/20261015/20182796kzWcDaJD1n.png)

**坑 3：排程主機的 `python3` 是 3.11，沒有 requests。**  
開發用的 session 一直用 Python 3.13 跑得好好的，第一次排程卻找不到 requests。原因是排程主機上的 `python3` 指到 3.11。它自己發現了，改用 `/usr/bin/python3.13` 跑完。之後我在指示裡寫死用 3.13。

### 金鑰

**坑 4：Telegram 的 token 放不進官方的金鑰保護。**  
雲端環境有一個「API 憑證」功能：金鑰存在 Anthropic 那邊，送出請求時才代為加上，Claude 本身看不到。很好，但 Telegram 的 token 是放在網址裡的（ `/bot<token>/sendMessage` ）。我把憑證類型的選單整個看過一遍：Bearer、Basic、Body parameter、AWS、GCP、OAuth……全都是放在標頭或內容裡，沒有一個能放進網址。最後只能放環境變數，而設定畫面上就寫著「任何使用此環境的人都能看到這些內容」。我的做法是開一個專用的新 bot，外洩就撤銷。

![https://ithelp.ithome.com.tw/upload/images/20261015/20182796ckbbg45qwo.png](https://ithelp.ithome.com.tw/upload/images/20261015/20182796ckbbg45qwo.png)

**坑 5：截圖時把 token 一起拍進去了。**  
建 bot 的時候，我截圖給 Claude 看設定步驟，token 完整入鏡。更有趣的是，我叫它直接從截圖讀 token 去查 chat id， **被 Claude Code 的安全檢查擋下來** ，最後是我自己用瀏覽器查的。

**坑 6：GitGuardian 把 AI 造的假 token 當真。**  
測試裡要驗證「token 不會被印出來」，它自己造了一個 `123456789:AAFa…` 的假 token，格式太像真的，PR 被 GitGuardian 標成紅燈。下一版改成 `fake-bot-token-for-tests-only` 就過了。

### 額度與費用

**坑 7：送的額度不能用在排程。**  
手動開的雲端 session 都是馬上扣額度（$11、$5、$6）。但排程從 10/7 到 10/9 跑了 4 次，額度只在我手動開 session 時減少，排程前後都沒動：10/7 兩次跑完還是 $234，10/8、10/9 跑完還是 $228。在排程那次執行裡輸入 `/usage` ，畫面上的雲端點數也是同一個數字。官方文件寫的是：「Routines draw down subscription usage the same way interactive sessions do」。也就是說， **那筆額度適合拿來開發，每天的排程照樣吃你的訂閱用量。**

**坑 8：想看一次花多少，要在那次執行裡輸入 `/usage` 。**  
訂閱制沒有「這次花多少錢」的帳單。後來發現 `/usage` 在雲端 session 裡也能用，一個畫面就看得到：這次的估算費用、用了哪個模型、雲端點數還剩多少。

| --- | --- | --- | --- |
| v1（10/7） | 美金 $0.34 | 1 分 20 秒 | 輸出 394、快取讀取 472.3k、快取寫入 52.6k |
| v2（10/8，多讀新聞內文） | 美金 $0.50 | 2 分 10 秒 | 輸出 490、快取讀取 739.6k、快取寫入 69.2k |

費用大部分花在「讀」：每做一步，就要把規格、資料重新帶進去一次。真正寫報告的輸出反而很少。照 v2 的 $0.50 算，一個月 21 個交易日大約美金 $10（API 價格換算，訂閱制不另外收）。

### 介面和文件

**坑 9：排程表單會帶入預設值，要一個一個改。**  
建排程時，環境預設帶到我以前建的「遊戲開發」，連接器預設帶了 3 個（Claude Docs、Gamma 等）。官方文件也提醒：排程執行時，連接器可以不經詢問就寫入。這兩個沒改，就會用錯環境、多開不需要的權限。

## 5\. 結果：報告長怎樣、準不準

### 從「抓資料」到「整理」

v1 的報告，數字都對，但比較像「昨天的盤後回顧」：AI 只能照抄數字、只看新聞標題。10/7 那份的開頭只有一句：

> 前一交易日加權指數收 49,822.55（+110.51，+0.22%），三大法人合計 -192.0 億。

就是把下面的數字重講一遍。v2 開始讓它讀新聞內文，前面「先看成果」的今日重點就是 v2 寫的。其中第 2 點是我最想要的：把法人的數字和新聞內文連起來，還指出我的觀察清單也在裡面。新聞摘要只寫事實，文中分析師的看法、目標價都沒寫進去。

它還會自己處理新聞之間的矛盾：兩篇新聞對同一件事的百分比寫法不同（88.3% 和 99%），它查證不了，就兩個都不寫，並記進踩坑紀錄。

![https://ithelp.ithome.com.tw/upload/images/20261015/20182796eziWyRWrDA.png](https://ithelp.ithome.com.tw/upload/images/20261015/20182796eziWyRWrDA.png)

### 準不準

每份報告都用另外寫的核對程式比對 42 個數字（大盤、法人、融資融券、類股前三、5 檔 ETF 的收盤、漲跌幅、外資、投信），另外檢查有沒有「看好」「目標價」這類用語、有沒有免責聲明。

| 報告 | 結果 |
| --- | --- |
| 10/7 04:03（第一次手動執行） | 32/42：ETF 的法人資料那次被證交所擋，報告寫「無資料」並註明缺少。AI 寫出來的 32 個數字全對 |
| 10/7 08:07（第一次排程） | 42/42 |
| 10/8 08:07（第一份 v2） | 42/42 |
| 10/9（國慶補假） | 只送一行「今天休市，不發盤前整理。」，休市判斷正確 |
| 10/12 08:07（連假後第一份，資料日 10/8） | 42/42 |
| 10/13 08:07 | 42/42 |
| 10/14 08:07 | 32/42：ETF 的法人資料又被證交所擋，報告寫「無資料」，並在「今日缺少」註明原因。AI 寫出來的 32 個數字全對 |

到 10/15 為止，7 份有數字的報告，寫出來的數字沒有一個錯；被證交所擋的兩次，報告都寫「無資料」並註明缺少，沒有自己填數字。

## 7\. 想自己架的話，先知道這些

- **要有 GitHub** ：雲端 session 和排程都靠 GitHub 拿程式、存結果。私人 repo 要讓 Claude 的 GitHub App 看得到。
- **網路先想清楚** ：預設只能連白名單。要連一般網站，就把網域加進「自訂」， **在開 session 之前** 加。台灣的網站可能會擋國外的主機，先用一支小程式在雲端測一次連線。
- **金鑰** ：放在標頭的 API，用「API 憑證」保護；像 Telegram 這種放在網址裡的，只能用環境變數，記得用可以隨時撤銷的金鑰。
- **額度** ：送的額度拿來開發最划算；排程扣的是訂閱用量。
- **量花費** ：在那次執行裡輸入 `/usage` 。
- **本機規劃、雲端執行** ：先在本機把規格寫清楚，雲端照著做，PR 回來在本機審。這次三個版本都是這樣做的。
