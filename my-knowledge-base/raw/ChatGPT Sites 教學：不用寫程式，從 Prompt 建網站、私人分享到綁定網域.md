ChatGPT Sites 是 OpenAI 放在 ChatGPT 裡的 AI 建站工具。你只要用文字說明網站要給誰用、要解決什麼問題，以及需要哪些功能，ChatGPT 就能建立可互動的網站或小型 Web App，連主機、儲存與分享權限也一起處理。

2026 年 9 月 12 日，OpenAI 在 [@ChatGPT 官方貼文](https://x.com/ChatGPT/status/2098457920291946894?ref=aiposthub.com) 表示，Sites 推出三個月後，使用者已建立超過 500 萬個網站。這次更新又加入共同編輯、私人分享、資料庫檢查與自訂網域，從 Prompt 到部署所需時間也縮短一半。

這不代表所有網站都能交給 AI 一鍵完成。Sites 最適合需求明確的活動頁、作品集、Dashboard、內部入口網站與小工具。如果要做大型電商、醫療系統或需要複雜後端的正式產品，仍要投入工程、資安、法務與長期維護。

這篇 ChatGPT Sites 教學會帶你完成第一個網站，也會說清楚「儲存版本」和「正式部署」的差別、共同編輯者能看到哪些資料，以及什麼情況不適合使用。

## ChatGPT Sites 是什麼？和一般 AI 建站工具有何不同？

![ChatGPT 官方 Sites 文件藍色主視覺，左下顯示 Sites 字樣](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/2026/09/chatgpt-sites-docs-overview.png)

ChatGPT Sites 能建立、代管、修改與分享網站、Web App 和遊戲。 圖片來源： ChatGPT Learn 官方文件 。

ChatGPT Sites 可以把自然語言需求轉成一個由 OpenAI 代管的網站、Web App 或遊戲。Web App 是能讓訪客輸入資料、按按鈕並取得結果的網頁應用程式，例如計算機、專案追蹤器或互動測驗。

它不只產生一張漂亮頁面，還把建立、預覽、修改、儲存版本、部署與分享放在同一段 ChatGPT 對話裡。你不必先申請另一個虛擬主機，也不必自己設定部署流程。

| 工具類型 | 最適合做什麼 | 使用者要負責什麼 |
| --- | --- | --- |
| 文件或簡報 | 閱讀、提案、一次性分享 | 內容是否清楚 |
| 傳統拖拉式架站 | 品牌官網、部落格、電商 | 模板、外掛、主機與維護 |
| ChatGPT Sites | Dashboard、作品集、活動頁、內部 Portal、互動小工具 | 說清楚需求、檢查結果、設定權限 |
| 客製化軟體 | 複雜流程、高流量或特殊整合 | 工程、資安、測試與維運 |

我的判斷是，ChatGPT Sites 現在已經不只是「AI 幫你做網頁」的展示功能，更像一個輕量的協作開發平台。但它的優勢是把小型專案快速做成可用版本，不是取代所有網站開發。

## 這次 ChatGPT Sites 更新了什麼？

OpenAI 這次公布的五項更新，真正改變的是網站做好之後如何交付與維護。

### 1\. Build together：邀請團隊共同編輯

Site 擁有者可以把同一個 ChatGPT 工作區裡的成員設為「Can edit」。編輯者能修改網站、儲存版本，也能在擁有者完成第一次發布後，將後續版本發布到同一個網址。

這讓行銷、設計與營運人員可以直接在同一個 Site 上工作，不必把每一個改字需求都交回原建立者。不過第一次發布、權限管理、網域、Secrets 與擁有權仍由 Site 擁有者控制。

### 2\. 私人分享：指定人看，不必全站公開

新 Site 預設只開放給擁有者與工作區管理員。你可以邀請特定成員、群組或外部人士檢視，也可以依方案與管理員設定，開放給整個工作區或網際網路上的所有人。

外部受邀者只有檢視權，不會因此加入你的工作區，也不能修改或發布 Site。這很適合先把提案、Prototype 或客戶頁面交給少數人驗收。

### 3\. 從 Prompt 到部署的時間減半

官方說法是「從 Prompt 到 deployment 所需時間減半」。Deployment 是把已完成的版本部署到正式網址，不是指訪客開啟網站的速度快一倍。

對經常修改文案、欄位與流程的人來說，縮短的是每一輪建立和上線的等待時間。這項改善對反覆修改的工作流程，比對一次生成更有價值。

### 4\. ChatGPT 可以檢查 Site 資料庫

你可以直接請 ChatGPT 查看 Site 儲存的資料，找出欄位、記錄或流程上的問題。共同編輯者也能讀取網站的即時資料庫內容，因此「Can edit」同時是程式碼與資料的存取權，不能只當成改文案的權限。

### 5\. 綁定自己的網域

符合資格的帳號可以把已擁有的主網域或子網域連到 Site。DNS 是網域名稱系統，作用像網路上的地址簿。你需要在網域商後台加入 Sites 提供的 DNS 記錄，才能讓自己的網址指向網站。

官方文件目前註明，Enterprise 工作區在自訂網域功能上線初期不支援這項功能。實際可用性仍要以你的方案、地區與 Site 設定頁為準。

## 使用 ChatGPT Sites 前，先確認帳號與入口

ChatGPT Sites 仍在公開 Beta 測試。OpenAI 文件列出的適用方案包括 Plus、Pro、Business、Enterprise 與 Edu，但功能會依地區、方案、工作區權限與分批開放進度而不同。如果你看不到 Sites，不一定是操作錯誤，也可能是尚未開放到該帳號，或被工作區管理員關閉。

網頁版可以進入 ChatGPT 的 Work，或從 More 選擇 Sites。桌面版則可以從 ChatGPT 的 Work 或 Codex 開始。最簡單的觸發方式，是在提示詞裡明確寫出「建立一個 website」，或直接使用 `@Sites` 。

## ChatGPT Sites 教學：從一句 Prompt 到第一個網站

### 步驟一：先選一個範圍小、結果清楚的用途

第一個 Site 不要從「幫我做一個厲害的公司官網」開始。這種需求沒有對象、內容與完成標準，AI 只能猜。

更好的做法是先回答四件事：誰會使用、要完成什麼工作、要顯示哪些資料、使用者做完後應看到什麼結果。

你可以直接套用這個 Prompt 骨架：

> 請用 ChatGPT Sites 建立一個【網站類型】，給【目標使用者】使用。核心任務是【要完成的工作】。請包含【必要區塊與功能】，使用【視覺風格】。資料需要【是否長期保存】，訪客權限是【私人／工作區／公開】。先建立可預覽版本，不要部署，並列出你做了哪些假設。

### 步驟二：用一個完整 Prompt 建立第一版

假設你要做新人 Onboarding Hub，可以這樣下指令：

> 請用 ChatGPT Sites 建立一個新人 Onboarding Hub，給剛加入行銷團隊的同事使用。首頁要有團隊任務、成員介紹、第一週待辦、常用文件、FAQ 與求助窗口。版面要簡潔、適合手機閱讀。先使用範例資料，所有外部連結以新分頁開啟。先產生可預覽版本，不要部署，並標示哪些內容之後要換成公司資料。

這段 Prompt 把對象、目的、欄位、行動版與部署界線都說清楚，第一版通常會比只寫「做一個新人網站」更接近可用狀態。

### 步驟三：先檢查流程，再改顏色與字體

第一輪預覽先測三件事：導覽能不能走完、按鈕有沒有反應、資料會不會出現在錯誤的位置。流程正確後，再處理字體、配色與動畫。

修改時一次只交代一個目標，例如：「保留目前欄位與順序，把首頁改成手機優先的單欄版面，主按鈕在 390px 寬度下仍要完整顯示。」這比「再高級一點」更容易驗收。

### 步驟四：需要保存資料時，明確要求 D1 或 R2

D1 是用來保存表格型結構化資料的關聯式資料庫，例如專案名稱、負責人、狀態與日期。R2 是保存圖片、PDF、音訊或其他檔案的物件儲存空間。

如果網站需要記住訪客的進度，可以寫：「請使用持久資料庫保存每位登入使用者的完成狀態。」如果需要上傳作品，則寫：「請保存上傳檔案，並在資料庫記錄檔名、擁有者與上傳時間。」暫時性的深色模式或關閉提示，不需要為了炫技放進資料庫。

### 步驟五：先 Save a version，確認後再 Deploy

這是整篇最重要的操作觀念。Save a version 是建立一個可部署的版本，讓你先檢查。Deploy 才會把該版本放到正式環境並產生 production URL，也就是實際可供指定對象使用的網址。

OpenAI 文件明確提醒，每一個 deployment URL 都是正式部署。若只是要給自己驗收，請先要求 ChatGPT 儲存版本，不要把「預覽」當成「已部署但沒人知道」。

部署前至少測試桌面版與手機版、所有按鈕和表單、錯誤訊息、存取權限，以及登出狀態下看得到什麼。

### 步驟六：選擇公開、私人或團隊協作

在 Share 設定裡，依帳號可用選項選擇擁有者與管理員、特定使用者或群組、整個工作區，或網際網路上的所有人。若是客戶驗收或內部資料，優先選最窄的權限，再用受邀者帳號實際開啟一次。

要共同編輯，擁有者需在 Share 裡加入同一工作區成員，再把權限從「Can view」改成「Can edit」。外部客戶可以受邀檢視，但不能因此成為共同編輯者。

### 步驟七：需要品牌網址時再連接自訂網域

先確認你已擁有網域，而且能修改 DNS。接著到 Site 的 Settings 選擇 Add domain，輸入主網域或子網域，將系統顯示的 DNS 記錄貼到網域商後台，等待幾分鐘後回來重新整理狀態。

自訂網域只是換成自己的網址，不會自動改變誰能觀看。連接後仍要重新檢查 Site 的 audience、登入流程與公開狀態。

## 3 個可以直接複製的 ChatGPT Sites Prompt

### 個人作品集

> 建立一個給自由工作者使用的個人作品集網站。首頁要有一句定位、三個精選案例、服務項目、合作流程與聯絡按鈕。案例卡片要能篩選類型，手機版優先。先使用假資料並建立私人預覽，不要部署。

### 專案 Dashboard

> 建立一個給 10 人產品團隊使用的專案 Dashboard。顯示里程碑、負責人、狀態、風險與下次更新時間，支援依負責人和狀態篩選。使用持久資料庫保存變更，只有工作區成員能開啟。先建立版本並說明資料欄位。

### 活動報名頁

> 建立一個 80 人實體講座的活動頁。包含議程、講者、地點、FAQ、剩餘名額與報名表單。表單只收姓名與 Email，提交後顯示確認畫面。請說明資料保存方式與刪除流程，先做私人測試版本，不要公開部署。

這些 Prompt 都把「誰用、做什麼、資料是否保存、誰能看、先不部署」寫進去。這五件事比指定十種動畫更能決定網站是否真的可用。

## ChatGPT Sites 適合拿來接案開工作室嗎？

拿 ChatGPT Sites 做小型網站工作室是可行的，但適合的商品不是「任何網站都能一鍵完成」，而是範圍清楚、交付快速的方案，例如活動頁、作品集、內部 Portal、互動提案與簡單 Dashboard。

真正的商業門檻會落在需求釐清、內容整理、驗收、權限與後續維護。OpenAI 的 [ChatGPT Sites Terms](https://openai.com/policies/chatgpt-sites-terms/?ref=aiposthub.com) 也寫明，建立者仍要對網站內容、功能、終端使用者、授權與法律遵循負責。若網站收款，要使用第三方支付，交易、退款、稅務與客服也不會因為使用 Sites 就轉由 OpenAI 負責。

所以我會把 Sites 定位成「快速完成第一個可用版本與小型交付」的工具，而不是把它賣成免維護的萬用網站。客戶若需要複雜會員制度、敏感資料、高流量保證或多系統整合，應改用完整開發流程。

## ChatGPT Sites 的資料與隱私要注意什麼？

共同編輯者可以讀取 Site 的即時資料庫，因此只應邀請可信任、確實需要存取程式碼與資料的人。API 是讓不同服務交換資料的介面，而 API 金鑰則像系統通行證。這類 Secrets，也就是不該公開的機密值，必須放在 Site 設定的環境變數中，不能貼進 Prompt、附加檔案或網站內容。

官方也限制 Sites 不得處理付款卡資料，除非付款完全由第三方支付處理。受保護醫療資訊等敏感資料也不適合放進 Sites。若表單會收集姓名、Email 或其他個人資料，網站建立者仍需說明用途、保存方式與刪除流程，並遵守適用的隱私法規。

## ChatGPT Sites 常見問題

### ChatGPT Sites 免費版可以用嗎？

官方文件目前把 Sites 列為公開 Beta，適用於 Plus、Pro、Business、Enterprise 與 Edu。功能仍在分批推出，方案限額與地區也可能不同，最準確的判斷方式是查看帳號裡是否出現 Sites，以及當下顯示的用量限制。

### 不會寫程式也能使用 ChatGPT Sites 嗎？

可以。新手可以直接用自然語言描述網站，但仍要負責檢查內容、按鈕、表單、手機版與權限。會不會寫程式影響客製化深度，不影響你做出第一個範圍明確的小工具。

### ChatGPT Sites 可以做電商嗎？

可以展示商品或服務，也能串接第三方支付處理收款，但建立者仍要負責商品履約、退款、客服、稅務與法規。若需要完整庫存、物流、會員與訂單系統，專業電商平台通常更合適。

### 私人 Site 可以分享給公司外的人嗎？

可以在功能開放且權限允許時，邀請指定外部人士以 viewer 身分檢視。對方要使用收到邀請的帳號登入，且不能編輯或發布。這和把網站公開給所有人是兩種不同設定。

### 自訂網域會讓私人 Site 變公開嗎？

不會。網域只改變網址，Site 的 audience 設定才決定誰能觀看。連接網域後，仍要用預定訪客的帳號或登出狀態重新測試。

### ChatGPT Sites 能連接即時公司資料嗎？

Sites 能使用自己的持久資料庫與檔案儲存，也能讓 ChatGPT 檢查 Site 資料。至於外部即時資料源、私人網路或特殊後端是否支援，會依執行環境與帳號功能而異。複雜整合應先做相容性測試，不要把展示成功直接當成正式系統驗收。

## 結論：先把一個明確工作做成可用網站

ChatGPT Sites 最有價值的地方，是讓沒有完整工程團隊的人，也能把資料、流程與互動需求快速變成一個可分享的網站。超過 500 萬個 Sites 說明使用者願意嘗試，但共同編輯、私人分享與自訂網域，才真正讓它開始具備交付與維護的條件。

第一個專案建議從作品集、Onboarding Hub、活動頁或簡單 Dashboard 開始。把對象、任務、資料、權限與完成標準寫進 Prompt，先儲存版本、完整驗收，再決定是否部署。這套流程比追求「一句話上線」更接近真正可靠的 AI 建站。
