Cinetic 把產品動畫製作拆成企劃、視覺、節奏、聲音與檢查，讓程式代理依照同一套流程完成短片。

它最有價值的地方，是把這些決定留在可修改的專案中：標題變了、功能流程調整了，團隊有機會回到原始內容修正，再重新輸出影片。

Skill 是讓 AI 代理重複使用的工作指引，通常包含說明文件、素材和腳本。

Cinetic 是開發者 Leonxlnx 發布的第三方 Skill，可搭配 Claude Code、Codex 等能執行程式的代理使用，並非 Anthropic 官方內建的動畫功能。

Claude Code 在這裡負責理解企劃及操作專案，Cinetic 提供製片規則，最後由動畫引擎產生畫面。 [工具定位與示範見作者儲存庫](https://github.com/Leonxlnx/cinetic?ref=aiposthub.com) 。

本文以 2026 年 10 月 8 日查閱的作者文件為基準，從四款官方示範作品，說明 Cinetic 適合哪些影片、如何準備環境，以及怎麼用中文企劃和逐輪審片改善成果。

文中的影片是原作者提供的作品，中文企劃則是本文的示例，沒有把作者作品描述為本站生成的結果。

## Cinetic 的工作方式：先決定觀眾要理解什麼

產品短片最容易失焦的地方，是每個畫面都在動，觀眾卻說不出產品解決了什麼。Cinetic 的作者文件因此把概念放在寫程式之前：代理先提出三個不同方向，再選定一個能貫穿影片的故事。

這讓動作有服務對象，例如加速的方塊可以呈現等待時間縮短，而不是只用來填滿畫面。

作者也把品牌、畫面與聲音放在同一個製作流程中。品牌可以由提供的規範決定，包括顏色、字型與視覺語氣。若沒有提供，代理會依企劃建立方向。

對已有品牌的公司，最重要的準備是提供可用的字型和正式素材，避免影片做好後才發現名稱、標誌或風格不符合公司的對外形象。

動畫引擎預設使用 Remotion，也能採 HyperFrames。Remotion 透過 React 這種建立介面的程式工具，將畫面按時間轉成影片。HyperFrames 則採用 HTML 等網頁技術組織動畫。

對不熟悉程式的讀者，可以把它們理解為讓每一刻的畫面都能依規則重新產生的工具，因此文字與尺寸的修改有機會沿用原專案。

這種方式尤其適合介面、數字、圖表與文字組成的影片。若需求主要是人物訪談、現場實拍或大量既有影片的剪接，仍需要相應的拍攝與剪輯安排。

Cinetic 的作品能說明程式動畫的方向，不能因此推論所有影片類型都能用同一個方法完成。

作者的示範包含產品發布、直式社群短片、網站循環動畫與標誌開場。這些作品適合用來認識格式和敘事的差別，不宜只看哪個動作最漂亮。相同產品如果換到另一個展示環境，畫面密度、停留時間和聲音需求都會變。

Kiln 用大量建置項目的變化呈現快取概念。重點不在於方塊數量，而是觀眾能先看見等待和重複工作的問題，再看見快取帶來的改變，最後把視覺元素收回品牌。

這是一個能套用到其他產品的分析方向，但換產品時仍要重新決定物件，不能只把名稱改掉就視為完成企劃。

把完整桌面介面縮小塞進直式畫布，通常會讓觀眾看不清字與操作，企劃時就應決定要放大的關鍵內容。

讀者更應觀察作品如何把產品意義轉成畫面，再建立自己的驗收標準。

## 安裝 Cinetic 前，先確認代理能找到必要工具

作者提供的基本安裝指令如下，透過 Skills CLI 將 Skill 加入選定代理。CLI 是用文字指令操作工具的介面， `npx` 則是 Node.js 生態中執行套件工具的方式。

這段指令是作者的使用說明，安裝前仍應閱讀來源與當時選項。

```bash
npx skills add Leonxlnx/cinetic
```

這個流程會讓使用者選擇代理與安裝範圍。專案內安裝適合先在單一影片專案嘗試，全域安裝則供同一使用者的不同專案使用。

作者另外提供 Claude Code 外掛方式，但第一次使用選一條路徑即可，避免同時安裝 Skill 和外掛，讓代理載入兩份相同工具。

安裝 Skill 只是把製作規則放好，真正輸出影片還需要其他工具。作者的環境需求列出 Node.js 22 以上、Python 3.11 以上、FFmpeg 6 以上與 Chromium。

Node.js 用於執行相關程式，Python 腳本處理聲音與檢查，FFmpeg 負責影音編碼等工作，Chromium 則將畫面轉成可輸出的影格。

Python 所需套件建議放在獨立的虛擬環境中，讓這個專案的依賴和其他工作分開。更關鍵的是，代理開始工作時必須找得到這個環境。電腦上有套件，和代理執行的 `python3` 能讀到套件，是不同的情況。

如果出現缺少套件的錯誤，應先核對代理使用的執行環境，而不是一再重複安裝 Skill。

作者文件說明以 Linux 測試為主，macOS 的測試較少，Windows 的 WSL2 路徑尚未測試。WSL2 是在 Windows 上提供 Linux 環境的方法。

需要可靠交期的團隊，應先依 [作者 setup 文件](https://github.com/Leonxlnx/cinetic/blob/main/docs/setup.md?ref=aiposthub.com) 完成小型測試輸出，確認環境可以產生影片，再開始正式企劃。

## 第一份中文企劃，先寫功能和觀眾，再決定動作

一份容易執行的企劃需要影片目的、核心功能、觀看環境、品牌素材和交付規格。可以先問自己：觀眾看完後，應理解哪一件事情？如果答案是三四個不同功能，第一支短片可能應先縮小範圍。

短時間內資訊過多，即使每個功能都出現在畫面上，也不代表觀眾能記住。

以下是本文設計的假設案例，用來示範怎麼描述一個學習產品的新功能。它不是作者原始提示詞，也沒有對應的本站實測影片。

```
請用 Cinetic 為一款假設的閱讀筆記 App 製作 15 秒直式功能短片。
觀眾是會用手機記錄讀書心得的人，影片將放在社群貼文。

這支影片只說明「把零散筆記整理成一張主題卡片」這個功能。
先呈現三段零散筆記，再讓它們集中成一張能回顧的卡片。
使用深灰文字、米白背景與單一藍色重點，字型依我提供的素材。
字幕使用繁體中文，每個主要畫面保留足夠閱讀時間。

請先提出三個概念及各自的畫面摘要，我確認方向後再製作。
交付 1080×1920 的 MP4、可修改專案及主要畫面預覽。
```

這份企劃給代理的限制，都和交付有關。指定直式是因為觀看環境，限定一項功能是為了讓觀眾理解，要求先看概念則是讓製作者能在投入完整渲染前調整方向。

渲染是把專案計算成影片畫面的過程，越晚修改整體故事，越可能需要重做大量工作。

如果公司已有正式介面，還應明確區分「產品真實畫面」與「為了說明概念重新設計的示意圖」。功能動畫可以放大操作重點，但不應讓尚未提供的能力看起來像已經上線。

影片企劃與產品現況一致，才有辦法交給業務、行銷或客戶觀看。

## 審片順序：先故事，再畫面，最後完整輸出

Cinetic 作者的流程包含風格畫面、時間安排、預覽與品質檢查。對使用者來說，可以先確認靜態畫面中的產品名稱、文字、顏色和素材，再檢查動態節奏。

若第一輪連核心功能都表達錯誤，就不必先花時間要求音效更精緻，因為後續聲音和轉場可能會跟著故事一起重做。

故事方向確認後，檢查每個動作是否讓資訊更容易理解。例如筆記集中成卡片時，觀眾要看得出內容來自哪些筆記，也要有時間閱讀最後的卡片。若動作太快，應調整停留與移動時間，而不只是加上更多特效。

文字的閱讀時間應以實際字數和播放大小判斷，尤其繁體中文的小字不能直接照搬英文示範的密度。

聲音檢查則關注音量與畫面事件是否同步。功能完成的一刻可以有提示音，但提示音不應壓過重要語音或讓整段影片過於擁擠。若影片預計自動靜音播放，關鍵資訊必須留在畫面，不能只靠音效或旁白傳達。

這也是作者分別提供有聲社群作品與無聲網站作品的原因。

給代理的修改意見最好包含位置、問題和預期結果。例如「第六秒卡片合併後立刻離開，請讓最後內容停留到第九秒」，比「再有質感一點」更容易執行。

若需要整支影片更安靜，可以同時指出動作數量、速度和音效密度，讓修改有具體方向。

## 交付可修改專案，才能承接下一輪產品更新

影片完成後，除了 MP4，也應保留企劃、素材、字型資訊和動畫專案。MP4 適合發布，但不能提供同等程度的文字與時間修改能力。若公司下個月更改功能名稱，只留下影片的團隊可能需要重做畫面。

保留原專案則能從原始內容修改，再驗收新的輸出。

對跨人員交接，還應留下執行版本和重新輸出的方式。接手者需要知道哪些文字可以改、素材放在哪裡、這支影片採用哪個引擎，以及如何核對輸出尺寸。

這些資訊屬於製作交接，無需塞進對外影片，但會直接影響團隊下次修改的成本。

透明標誌動畫也要有不同的驗收方式。透明表示沒有固定背景，可以疊在其他影片上，但不是所有影音格式都能保留透明通道。作者 Halden 作品另外提供透明版本，正是因為一般觀看版和剪輯用素材的需求不同。

需要這種交付物時，應先詢問接收者使用的格式與剪輯工具，再決定輸出。

Halden 作品把產品意象延伸為短標誌動畫，作者另提供剪輯用透明版本。圖片來源： Cinetic 作者官方儲存庫 。

## Cinetic 免費嗎？Skill、引擎和模型成本要分開

Cinetic 本身採 MIT 授權，但使用它製作影片仍可能有模型使用、運算和素材成本。MIT 是開源授權的一種，允許依條款使用與修改程式，並要求保留相關授權與著作權聲明。

它不會自動讓外部模型、商用字型或提供的品牌素材都免付費。

預設引擎 Remotion 也有自己的授權。依 2026 年 10 月 8 日查閱的 Remotion 官方條款，個人、最多三名員工的營利組織等符合免費條件的使用者，可以在允許範圍內使用。

不符合免費資格的組織需取得公司授權。團隊評估 Cinetic 時，應同時看引擎的條件，不能只看到 Skill 是 MIT 就推定整條製作流程適用相同授權。 [Remotion 授權條款](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md?ref=aiposthub.com) 提供完整規定。

輸出時間則受影片長度、解析度、硬體和效果影響。作者說明動態模糊會增加多次影格計算，因而增加渲染工作量。對第一支影片，先用較輕量的預覽確認內容，再做完整品質輸出，比每次小改字都重新計算所有效果更合理。

這也能避免將過多等待時間花在尚未確認的企劃上。

## Cinetic 常見問題

### 不會寫 React，也能使用嗎？

代理可以協助建立和修改專案，但使用者仍需要能準備環境、提供素材及檢查輸出。完全不理解檔案與錯誤訊息的人，開始時可能需要工程協助。判斷門檻應看能否維護這個製作流程，而不只是能否輸入一句需求。

### 一次提示就能得到作者展示的影片嗎？

作者作品經過開發和評估流程，並未保證任意提示都能達到相同結果。可以借用作品的敘事分析方式，再用自己的產品資料逐輪確認。第一版的功能表達與後續修改能力，比是否一次完成更有實際價值。

### 可以用它批次做很多尺寸嗎？

程式專案能提供修改版面與規格的基礎，但不同尺寸仍需要重新檢查構圖。橫式影片改成直式時，小字、留白和主要動作可能需要重排。應把不同尺寸視為各自要驗收的版本，避免只改寬高就直接交付。

### 這是 Claude 官方推出的動畫功能嗎？

Cinetic 是原作者公開的第三方專案，Claude Code 是其中可使用的代理。Anthropic 官方文件說明 Skill 的機制，但工具的作品、依賴與維護狀態由專案作者說明。

使用時應把代理產品與第三方工具的角色分清楚。

## 適合先做一支短片，再決定是否導入

Cinetic 適合有明確產品功能、願意保存程式專案並逐輪審片的團隊。先用一個能在十多秒說清楚的功能，完成環境確認、企劃、預覽和交付，就能判斷它是否有助於自己的行銷工作。

作者四款作品最有用的啟發，是各自只有清楚的觀看環境和核心故事。

團隊若能在下一次產品更新時沿用原專案、修改功能內容並再次輸出，這套流程的價值才會變得具體。把 Cinetic 當成可維護的製作方法，會比只收藏漂亮的 AI 動畫案例更接近可持續的工作成果。
