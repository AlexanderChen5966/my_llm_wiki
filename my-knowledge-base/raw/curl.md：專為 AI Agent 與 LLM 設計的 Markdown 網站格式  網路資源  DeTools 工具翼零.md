curl.md 是一個專門為 AI agent 與大型語言模型（LLM）設計的 Markdown 網站格式標準，核心概念可以理解為：「讓網站內容能被 AI 更有效率地讀取與使用」。它並不是傳統 Markdown 編輯器，也不是一般文件網站，而是一種偏向 AI-first 的內容格式與傳輸方式，目標是降低 AI 在讀取網站時的複雜度與 token 成本。

這個概念出現的背景，與 AI agent 正逐漸成為網路流量的一部分有關。過去網站主要是設計給人類瀏覽器與搜尋引擎閱讀，但 AI agent 在解析網站時，其實不需要完整 HTML、CSS 與 JavaScript。對 LLM 而言，這些內容往往只是額外噪音，不但增加 token 消耗，也降低理解效率。

curl.md 的核心目標，就是把網站內容轉換成「LLM 友善格式」。透過 Markdown 作為主要輸出形式，AI 可以更快抓到文章結構、標題、連結與重點內容，而不必處理大量前端渲染與樣式資訊。

從定位來看，curl.md 更像是一種「AI-ready content layer」，試圖成為未來 AI agent 與網站互動的輕量協議之一。它的思路與近年興起的：

- `llms.txt`
- Markdown negotiation
- Agent-ready websites
- AEO（Answer Engine Optimization）

等概念高度相關。

其核心特色可以整理如下：

- Markdown-first：以 Markdown 作為 AI 讀取的主要格式
- 降低 token 消耗：避免 AI 處理大量 HTML 與前端內容
- 提升 AI 可讀性：讓 LLM 更容易理解網站結構
- 適合 agent workflow：便於 AI agent 擷取與整理資訊
- AI-native 網站概念：網站不只服務人類，也服務 AI

實際上，這種設計反映一個很重要的趨勢：網站未來可能需要同時面向兩種使用者：

- 人類（Human UI）
- AI agents（Machine UI）

而 curl.md 所做的，就是提供一種更偏向 Machine UI 的內容層。

從使用情境來看，這類格式特別適合：

- 技術文件網站
- API 文件
- 部落格與知識庫
- AI 工具平台
- 希望被 AI agent 更有效索引的網站

尤其在 AI 搜尋與 agent workflow 興起後，網站若能直接提供 Markdown 內容，往往比只提供 HTML 更容易被 AI 使用。
