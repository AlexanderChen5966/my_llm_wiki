AI 食譜動畫最有用的地方，是讓觀眾看到材料何時加入、分量多少，以及完成後的樣子。Rory Flynn 的公開示範，就是把這幾件事寫進同一份動畫需求。

他要求 Opus 5.5 以 HTML 或 JavaScript 製作解說，讓空杯逐步變成完成的飲品。HTML 負責網頁結構，JavaScript 可以控制物件隨時間改變，因此畫面能跟著配方的順序播放。

如果你有自己的配方與完成照，可以借用這種寫法。照片看不出來的分量和步驟仍要自己提供，才能讓動畫傳達正確內容。

## AI 食譜動畫原始 prompt 包含哪些重點？

[Rory Flynn 的原貼](https://x.com/Ror_Fly/status/2102853258582880547?ref=aiposthub.com) 直接寫出使用方向，包含空杯到完成飲品、解說風格、逐步顯示材料與分量，以及約 30 秒的片長。

這份需求把「成品看起來如何」和「製作過程怎麼發生」一起交代，讓代理有機會安排順序。若只給一張飲品照並要求做動畫，它可能只做出旋轉的杯子。

若使用瀏覽器繪圖，像 [Canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API?ref=aiposthub.com) 這類畫布功能，可以讓程式安排液面、標籤與材料圖形。不過原貼沒有要求讀者必須使用某一套固定框架。

## 先把配方寫成會依序發生的動作

先做一張流程表，再把它和照片交給代理。以無酒精飲品為例，可以明確區分倒入液體、加入冰塊與最後裝飾，讓每個畫面都有可核對的內容。

| 欄位 | 需要提供的資訊 |
| --- | --- |
| 容器 | 杯型、容量與是否需要刻度 |
| 材料 | 名稱、分量與單位 |
| 順序 | 每一步加入什麼、是否攪拌 |
| 成品 | 完成照與要保留的外觀特徵 |

這張表的目的，是阻止模型替照片補出不存在的配方。某項分量不知道時，先完成配方確認，再製作動畫。

## 可複製的食譜動畫需求單

把完成照與配方表放進同一專案，再讓能產生及保存檔案的程式代理處理。若使用一般聊天介面，先確認它能交付可下載的網頁與影片。

以下是本站依公開方向改寫的範本，並非原貼逐字翻譯，尚未做成片實測。

```
根據我附上的完成照與配方表，做一支 30 秒飲品解說動畫。
使用 HTML／JavaScript，保留可修改的原始檔。
從空杯開始，完全依配方表的順序加入材料。
每種材料進入杯中時，同時出現名稱、分量與單位。
液面變化要符合加入量，標籤不可遮住倒入位置。
每一步留出閱讀時間，最後展示完成飲品與完整材料表。
不要根據照片猜測材料、分量或額外的健康效果。
先給分鏡與一個倒入動作的預覽，再製作完整版本。
交付可修改的 HTML／JavaScript 與 MP4，輸出方式依本次工具確認。
```

## 檢查分量與順序，才算完成食譜解說

先對照流程表，逐步停格檢查材料名稱、數字與單位。如果動畫很順，但分量少了一個零，觀眾照做就會得到不同結果。

再關掉聲音看一次。材料標籤應足以讓人理解步驟，因為社群上的觀看情境未必會開啟聲音。手機上也要確認文字不會和杯子重疊。

最後檢查完成照和動畫成品是否一致。液體顏色與裝飾可以簡化，但不能把原本沒有的材料畫進去，再當成配方的一部分。

### 只有完成照，也能做 AI 食譜動畫嗎？

可以先做外觀示意；要做讓人照著操作的解說，仍需補上可靠的材料表與步驟。

### 網頁動畫就是可上傳的 MP4 嗎？

網頁檔和影片檔是不同成果。需求裡應分別指定可修改原始檔與影片輸出，並檢查輸出後的字體、節奏和聲音。

拿一份自己熟悉的配方，先驗一個倒入鏡頭，再做完整流程，會比第一次就做一整套食譜系列容易掌握。
