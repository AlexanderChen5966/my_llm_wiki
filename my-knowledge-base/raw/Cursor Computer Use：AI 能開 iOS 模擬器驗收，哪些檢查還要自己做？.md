Cursor Computer Use 讓 AI 改完程式後，能進一步操作應用程式檢查結果。因為程式測試通過，仍可能遇到按鈕點不到或畫面遮住欄位，這些問題需要實際互動才容易發現。

Cursor 在 2026 年 10 月 23 日透過官方 X 帳號宣布，代理可以控制電腦，並以 iOS Simulator 等桌面應用測試它建立的功能。

iOS Simulator 是在 Mac 上模擬 iPhone 或 iPad 軟體環境的工具，能幫開發者觀察畫面與互動。但它與實體手機的硬體、效能及所有系統行為仍有差別。

這次更新適合用在重現介面錯誤與基本操作檢查，例如打開頁面、輸入資料、確認結果，再把操作證據交回開發者。

不過能操作桌面，並不表示每台機器都已自動啟用。官方自架文件列出作業系統、桌面環境與權限要求，實際能力要連同執行位置一起看。

要開始試用，先釐清代理在哪一台電腦操作，才能知道它看得到什麼，也才能安排可信的驗收。

## Cursor Computer Use 會在哪裡操作應用程式？

依 [Cursor 自架機器官方文件](https://cursor.com/docs/cloud-agent/self-hosted/computer-use?ref=aiposthub.com) ，Computer Use 讓執行節點上的代理點擊、輸入、截圖並操作有介面的應用程式。若節點安裝 Chrome 或 Chromium，也能操作瀏覽器。

執行節點就是替代理跑工作的電腦。它可能是自己指定的機器，也可能是團隊機器池中的節點，因此聊天視窗在哪裡打開，與代理實際在哪裡按按鈕，不一定相同。

### 為什麼要先確認執行位置？

如果要測 iOS 應用，節點需要有合適的 Mac 開發環境與模擬器。若任務被安排到其他系統，即使代理能寫程式，也不能直接推定它具備相同的測試工具。

同樣地，瀏覽器裡登入的是哪個測試帳號，也會影響畫面。如果代理用了另一個權限不同的帳號，看到的功能可能不同，所以驗收紀錄要保留帳號角色與資料條件。

自架文件說明，Computer Use 可用於 macOS 與 Linux，包含個人機器與團隊機器池。但桌面分享是另一項功能，且目前這份文件列為 Linux 專用，不能把兩者混為一談。

因為操作與觀看可以分開，團隊先要決定是否只讓代理做事，或還要讓授權的人觀看及接手。這會影響節點的桌面配置，也會影響需要留下哪些紀錄。

### 官方展示與自架文件怎麼一起看？

X 公告顯示產品方向與 iOS 模擬器案例，自架文件則提供特定執行模式的條件。兩者可以互相補充，但不能拿自架設定直接推定所有受管理雲端代理都有完全相同的行為。

因此本文的環境說明以官方自架機器指南為範圍。使用其他執行模式時，應查對應能力頁與實際帳號介面，避免把不適用的安裝步驟搬到另一種產品上。

對一般開發者而言，第一個確認方式很具體：讓代理打開指定應用、到達一個已知畫面並回傳截圖。這比只看到工具被列為可用，更能知道桌面連接是否真的運作。

## macOS 與 Linux 分別需要哪些準備？

官方把 Computer Use 與桌面分享設計成明確啟用的功能，伺服器不會自行替你打開。開始前也要求更新 Cursor CLI，也就是在命令列中管理代理的工具，確保使用支援這些能力的版本。

這個前提很重要，因為沒有桌面權限或必要套件時，代理即使接到任務，也可能點不了、截不到圖。把環境準備好，再處理應用錯誤，才不會把兩種問題混在一起。

### Mac 要把權限給哪個程式？

在 macOS 上，官方使用名為 Cursor Computer Use 的輔助程式，操作已登入的桌面工作階段。它需要輔助使用與螢幕錄製權限，分別用來輸入點擊與取得畫面。

權限必須授給這個輔助程式，不能只授給終端機或主 Cursor 應用。因為 macOS 依程式身分管理權限，其他程式已經被允許，不代表這個輔助程式也能操作。

官方另提醒，安裝後的檢查指令能確認輔助程式存在，卻不能直接證明兩項權限都已生效。因此還需要跑一次截圖與點擊任務，才能驗證完整流程。

Mac 也需要保持對應使用者已登入桌面。因為這種模式操作的是登入中的圖形環境，不能把沒有桌面的背景程序，直接當作已準備好進行介面測試的機器。

若系統更新或輔助程式身分改變，原有允許狀態可能需要重新檢查。實際做法應沿用官方安裝流程與系統設定，避免為了省一個步驟去改動作業系統的保護機制。

### Linux 的桌面與分享有何差別？

Linux 的 Computer Use 使用 X11 桌面，可以沿用已存在的顯示環境，或在無桌面機器上建立受管理的桌面。官方文件列出需要安裝的桌面與操作套件，節點本身要先具備這些條件。

桌面分享則是獨立選項，讓授權的人觀看或操作代理桌面。依文件，它使用隔離的代理桌面，而不是直接分享機器原本的使用者工作階段，也會限制剪貼簿傳送。

資料傳送走節點已有的對外連線，官方說明不另外打開對內連接埠。但這並不表示所有桌面內容都適合交給任何觀看者，團隊仍應確認誰有權參與這個測試。

以下把目前官方自架文件中的差異放在一起。

| 項目 | macOS 自架節點 | Linux 自架節點 |
| --- | --- | --- |
| 電腦操作 | 支援，使用輔助程式 | 支援，使用 X11 桌面 |
| 桌面條件 | 已登入的圖形工作階段 | 既有或受管理的桌面 |
| 需要準備 | 輔助程式與系統權限 | 操作及桌面相關套件 |
| 文件中的桌面分享 | 不能套用 Linux 專用選項 | 可依設定觀看或接手隔離桌面 |

所以第一次測試最好只選一種環境，把截圖與點擊驗證完成。等工作順利後再安排機器池，會比較容易找到問題出在哪一台節點。

## iOS 模擬器該怎麼安排驗收情境？

模擬器適合驗證一段具體的互動，例如使用者從首頁按下按鈕，填完資料後看見成功畫面。因為每個步驟都有可觀察結果，代理比較容易知道何時需要停下來修正。

與其要求「測完整個 App」，不如先列出使用者要完成的工作，再指定起始畫面與預期結果。這讓測試與產品需求接得起來，也方便人重新檢查。

### 正常流程以外，還要測哪些狀態？

如果代理新增一個表單，除了成功送出，也應看空欄位與錯誤資料的提示。因為只用一組正確輸入，很可能看不到欄位驗證與錯誤訊息的問題。

畫面狀態也會影響互動。例如鍵盤彈出後，按鈕可能被遮住。資料載入較慢時，使用者可能重複點擊。這些都是介面操作能幫忙觀察的情況，應依本次功能選擇相關測試。

如果測試需要登入，就先準備專用帳號與可辨識的測試資料。因為介面操作可能真的寫入資料，測試結束時應清楚知道新增了什麼，避免把驗收紀錄混到正式客戶內容。

對只改文案的工作，不必因此擴大成整個產品測試。可以檢查受影響畫面與窄螢幕排列。若改動涉及送出流程，才把資料寫入與結果回讀納入，讓檢查範圍與變更一致。

### 操作成功要怎麼證明？

代理按到送出按鈕，只證明它觸發了動作。要知道功能成功，還得看結果，例如成功訊息、資料列表中的新增紀錄，或重新載入後仍存在的內容。

這也是截圖要保留時間與情境的原因。一張成功畫面如果沒有說明從哪裡開始、用什麼資料到達，就很難重現，日後遇到同樣問題也難以比較。

較完整的回報可以包含測試步驟、實際結果與受影響檔案，再附對應畫面。這樣開發者能看出程式修改與使用者行為的關係，也比較容易判斷是否需要補測。

如果代理遇到錯誤，應把最後成功到達的位置與錯誤畫面留下。因為「無法完成」有很多原因，保留重現路徑能幫人接手，而不必再從頭猜一次。

## 怎麼讓操作證據能被團隊重新檢查？

先把測試環境寫清楚，包括執行主機、作業系統、應用版本與模擬裝置。因為同一功能在不同尺寸或系統設定下可能呈現不同結果，這些條件會影響他人是否能重現。

接著記錄被測試的程式版本。若代理改完後又繼續修改，前一張通過畫面可能已經不代表最後狀態，所以交付時應讓程式與證據對應到同一版本。

### 錄影與截圖各有什麼用途？

錄影能看見操作順序，適合重現點擊與等待的過程。截圖則能把錯誤或結果停在一個明確畫面，讓審閱者仔細檢查文案、對齊與提示內容。

兩者都需要避免把無關帳號或資料錄進去。因為代理操作的是桌面，其他應用或通知也可能出現在畫面上，使用專門測試環境會比較容易控制證據範圍。

對團隊而言，還要區分「已看見」與「已驗證」。例如代理看見列表多了一行，若工作要求資料永久保存，就應重新載入或再開一次頁面確認，才能支持持久化的結論。

若涉及外部服務，也要說明驗證到哪裡。測試環境能成功呼叫測試接口，不代表正式環境的權限、流量與網路條件都相同，回報應保留這個範圍。

### 為什麼模擬器通過後還要真機？

模擬器可以縮短反覆修改的時間，但真機仍可能有不同的觸控、效能與硬體行為。相機、定位、藍牙或其他裝置能力，也需要依功能安排實體驗證。

因此這次能力最適合放在開發中的反覆檢查，先把可重現的畫面問題修掉，再讓人集中處理真機與正式發布相關的項目。這樣比較容易把代理的價值落在具體流程。

本文整理的是官方公告與文件，沒有把官方展示當作自行操作通過的結果。若團隊準備導入，應從自己的應用建立一份小型驗收紀錄，再衡量是否增加使用範圍。

### 環境更新後，要重查的是操作能力

官方自架指南提醒，更新系統或替換輔助程式後，應重新做截圖與點擊測試。因為安裝狀態看起來正常，仍可能因權限未套用而操作失敗，這時應先修好環境，再判斷應用功能。

若團隊準備複製節點環境，也應保存一份已實際驗證的設定紀錄。每次增加機器後先跑相同小任務，確認能打開應用並取得結果，才把較大的測試交給它，會比較容易追查問題來源。

## 開發者可以先讓代理重現一個已知問題

如果你常遇到 AI 改完程式後，仍要親自打開 App 才發現介面問題，這次更新值得先試。因為它能把寫程式與實際互動接在一起，讓錯誤更早被看見。

第一個任務可以挑一個已知、容易重現的問題，要求代理先截圖記錄，再修改並跑相同路徑。當前後差異能被清楚檢查，再擴大到更多情境，也可免費訂閱 AI 郵報追蹤後續功能。

## FAQ：Cursor Computer Use 常見問題

### Cursor Computer Use 會自動接管所有電腦嗎？

官方自架文件把它列為明確啟用的功能，節點仍需具備桌面環境與相應權限。

### Mac 也能使用文件中的桌面分享選項嗎？

目前這份官方自架指南將桌面分享列為 Linux 專用。macOS 的電腦操作與 Linux 的分享功能應分開理解。

### iOS 模擬器測試成功，就可以直接發布嗎？

模擬器只是驗收的一部分。真機行為、正式環境與發布條件，仍要依產品要求確認。
