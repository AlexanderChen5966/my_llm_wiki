Open WebUI0.13.1 想接住的工作，是讓聊天介面能接著處理專案。模型需要拿得到檔案、執行工具，並把進度留在同一處，否則對話與電腦裡的改動仍得靠人搬運。

Open WebUI 在2026年11月8日釋出這個版本，讓提供代理的 Open Terminal 把 Claude Code、Codex 與 Pi 等工具放進模型選單，也推出桌面伴隨程式 Tether。

Open Terminal 是執行命令與處理檔案的工作層，Tether 則把自己的電腦接到 Open WebUI。兩者配合後，使用者能從瀏覽器和手機接續檢查同一個工作環境。

新版也改變工具對話的資料安排，讓重複請求較容易使用模型供應商的提示快取。但是否省錢，還得看供應商、對話內容與實際用量。

這次更新同時改動檔案預載與資料庫結構，既有部署需要對齊版本。Tether 的個人非商用例外與組織正式使用授權，也和 Open WebUI 主程式分開。

我認為這版適合已自架 Open WebUI、想把對話接進實際工作檔案的團隊研究。選擇前要先看執行位置、代理可用條件與升級路徑，不能只看到選單裡多了模型名稱。

先分清聊天伺服器、執行終端與桌面伴隨程式的角色，才能理解工作會在哪裡進行。

## Open WebUI0.13.1 如何把程式代理放進聊天？

提供代理的 Open Terminal 把代理列成可選模型，但每個對話只使用一個代理。因此，這個選單可以選到會執行工作的程式，不只是替同一個聊天請求換模型。

依 [完整發行說明](https://github.com/open-webui/open-webui/releases/tag/v0.13.1?ref=aiposthub.com) ，使用者可以和代理聊天或用語音呼叫，選擇推理強度與服務層級，也能在對話中批准工具要求。

推理強度用來調整代理或模型投入多少推理，服務層級則連到所選服務的供應方式。選單提供這些控制，不表示所有代理都有完全相同的選項與費率。

因為代理依附在提供它的終端，終端不見時，既有對話與新對話會回到預設模型。之前的回覆仍保留原代理名稱，所以回看標籤不代表原執行環境仍在線。

### 對話能延續，不代表每個舊按鈕都適用

代理對話不支援重新生成、接續生成，以及編輯舊訊息後重送。這些是回覆操作的限制，不能解讀成使用者做完一輪後，就不能再提出後續問題。

代理對話中的自動補全使用另外的任務模型，沒有這個模型時便略過。因為補全和執行工作分工不同，選到程式代理也不會自動補齊所有背景服務。

對使用者而言，最直接的變化是工作進度與工具核准可以留在聊天裡。但真正能讀取哪些檔案，仍由選到的終端提供，而不是由模型選單自行決定。

## Tether 怎麼把自己的電腦接到工作區？

Tether 由電腦主動連出，把檔案與終端帶進 Open WebUI，而不要求另開對外連接埠。這讓原本只存在這台電腦的專案，可以成為遠端聊天介面的工作位置。

官方提供 macOS、Windows 與 Linux 版本。登入後，電腦會出現在終端選單的 Your devices，使用者再選擇要讓這場對話接到哪個環境。

因為工作位置仍是那台電腦，從手機打開介面，不代表專案已搬進手機。手機提供的是存取入口，檔案與工具仍在原本連線的執行環境。

Tether 會在短暫斷線後接續終端輸出，也能在沒有開啟 Open WebUI 網頁時，送出桌面通知。這兩項能力改善的是進度可見性，沒有宣稱所有執行中的工作都不受斷線影響。

### 登入期限與工作位置要一起看

Tether 使用可以續期的會話，預設連續90天未使用才到期，期限可由伺服器設定。這是登入狀態的預設，不是一份工作保證能連續執行90天。

工作區也能替每個對話記住分頁、分割配置與選定終端，重新開啟時恢復。因為配置按使用者保存，換裝置後仍可看見自己的工作安排。

但恢復配置與讓電腦保持可用，是兩個不同條件。Tether 的角色是連接工作環境，並未在公告中附帶一台保證永遠在線的雲端電腦。

### 同一份專案如何接著編輯？

工作目錄選單可以搜尋資料夾，聊天資料夾也能指定預設終端和工作位置。因為同一台電腦可能放著多個專案，這項選擇會影響接下來的工具在哪裡找檔案。

新版加入快速開檔搜尋，也讓 Markdown 預覽可以直接編輯並存回檔案。這讓人能在模型處理前後接手修正，而不必只把檔案當成聊天附件。

檔案瀏覽器另可複製 Git 程式庫，並標示哪些檔案新增或變動。Git 是保存程式版本的工具，這些標示能把聊天裡的工作對回尚未提交的實際差異。

因為文字編輯會存回終端中的檔案，使用者需要把它和只改聊天訊息分清楚。前者會影響專案內容，後者則是對話紀錄，兩個入口不應靠外觀相似就混為一談。

環境接上之後，每個工具呼叫如何取得許可，也會影響使用方式。新版因此同時提供另一項工具權限改動。

## 自動工具審查如何決定是否詢問人？

新增的 Auto 模式把工具請求交給另一個模型判斷，無法完成審查時會回到人手核准。它是工具權限的新選項，預設關閉，需要管理員先啟用。

既有選項包含完整存取與要求核准，Auto 放在兩者旁邊。審查模型判斷這一次是否需要確認，認為可以直接執行時，工具才會繼續。

為了做判斷，系統會把工具名稱、參數與最近幾則訊息送到設定的評分 API。API 是讓不同程式交換請求與結果的入口，這裡接的是審查服務。

所以，即使主要聊天模型在本機，啟用另一個評分服務仍可能產生不同資料路徑。自架介面不能單獨證明每一項審查都在電腦裡完成。

### 沒有審出結果時，流程如何繼續？

審查若發生錯誤、逾時或內容太多，系統會要求人批准。因為缺少可用判斷就回到確認，它沒有把「審查失敗」直接當成「允許執行」。

這和把程式代理放進模型選單是不同的改動。官方分別描述代理對話中的核准與 Auto 工具模式，不能據此推定 Auto 已接管每個代理內部的全部權限機制。

工具迴圈也新增停止條件。同樣參數連續失敗兩次後，模型會結束工具迴圈並寫最後答覆，避免一直重做沒有改變的請求。

若回覆因 token 上限被截斷，未完成的工具呼叫不會繼續執行。Token 是模型處理文字的單位，這項處理避免把不完整參數當成完整動作。

核准方式處理行動，對話內容如何送給模型，則關係到成本與模型能看見的資料。

## 提示快取與檔案預載，為何一起改變？

新版減少每輪重寫固定提示，並讓原生工具呼叫的模型自行讀取附檔。因此，資料何時進入對話，成為理解費用和讀檔行為的關鍵。

提示快取是供應商重用先前已處理內容的機制。若每輪請求前面都相同，就比較容易沿用快取，反之，每輪都改寫開頭便可能失去這個條件。

0.13.1 把記憶回想、技能列表與附加知識清單，改成使用者訊息之後的隱藏工具結果。隱藏描述的是介面呈現，內容仍會送給模型，並非不會外傳的私密筆記。

這項安排讓對話開頭較穩定，但官方沒有提供適用所有供應商的省費比例。是否支援快取、命中多少內容與費率，仍決定最後帳單。

### 附件不再一律先塞進模型

使用原生工具呼叫時，附檔預載預設關閉，由模型透過檔案工具讀取。模型若沒有工具能力，或沒有啟用 Files 工具，就要另外開啟預載，才能看見附檔內容。

舊式工具呼叫，以及並非來自網頁聊天的 API 請求，則保留原行為。所以，相同檔案在不同呼叫方式下，不能只靠一個畫面推定內容已送進模型。

擷取文字少於預設50,000字元的檔案，會改用完整文字，而不只取檢索片段。字元是擷取後的文字量，和原始檔案大小或模型 token 數不同。

檢索預設也從前三段增加到前十段，切塊大小由1000改為1024。自己儲存過的設定不會被這項預設取代，舊知識內容則要重新建立索引才會改切法。

因為自訂處理程式可能看到最後一則訊息變成工具結果，沿用舊訊息排列的擴充也要調整。資料安排改了，既有部署自然不能只換前端畫面。

## 既有部署升級時有哪些不相容條件？

0.13.1 包含資料庫變更，多伺服器不能逐台滾動更新，同日0.13.2另修正 HTTP 聊天問題。兩個版本的變更應按先後閱讀。

官方要求升級前備份資料庫與相關資料。若有多個工作程序、多台伺服器或負載平衡，全部實例需要一起更新，否則不同版本讀取同一份結構會造成應用失敗。

滾動更新指的是服務不停機、逐批替換版本。這次明列不支援，表示維運安排必須考慮一致版本，不能把一般容器換版方式直接套上去。

同日的0.13.2修正區域網路或 Docker 位址經一般 HTTP 開啟時，聊天卡在載入中的問題，也修正部分留言與 Markdown 編輯操作。

因此，本次新聞主體仍是0.13.1的新工作模式，0.13.2則是緊接著的修補。它沒有把前述資料庫升級條件改成可以混用版本。

0.13.1另包含安全修正，但公告表示細節要等 CVE 編號分配後公布。現有資料不足以把它寫成某種特定攻擊，或推算受影響使用者比例。

升級能完成之後，使用成本仍要把桌面授權與模型費用分開計算，因為幾個元件採用的條件不同。

## 自架主程式與 Tether 授權有何差別？

Tether 允許個人非商用免費使用，代表組織的正式使用則需要適用的企業授權。這是 [實際授權文件](https://github.com/open-webui/tether/blob/main/LICENSE?ref=aiposthub.com) 列出的條件。

個人例外還要求不是代表雇主或其他組織使用。開發與測試另有不需訂閱的條款，但不能據此把組織正式部署也納入個人免費範圍。

Open WebUI 主程式採另一份授權，重點之一是保留品牌識別。30天內使用者不超過50人的部署，另有品牌修改例外，這並不是主程式只能供50人使用。

所以，能下載原始碼、能自架聊天平台，以及能免費在公司正式使用 Tether，是不同問題。模型供應商、伺服器與企業授權也沒有被合成一個統一價格。

已有自架環境的人，可以先選一個專案和終端，確認工作位置與核准方式是否合適。組織要正式採用時，再把各元件用途對到適用條款與實際報價。

## Open WebUI0.13.1 常見問題 FAQ

### 模型選單出現代理，就代表可以讀取全部電腦嗎？

代理由所連的 Open Terminal 提供，檔案與工具依該終端環境決定。選單名稱本身沒有替它建立所有電腦的存取權。

### Auto 模式預設開啟嗎？

它預設關閉，由管理員決定是否啟用。審查服務無法判斷時，工具會要求人批准，並非把錯誤視為自動同意。

### Tether 和 Open WebUI 都能在公司免費正式使用嗎？

兩者授權不同。Tether 的免費例外限個人非商用，代表組織的正式用途需要相應企業授權，不能只看主程式可自架便下結論。

## 結論

這次更新把聊天、程式代理與自己的電腦接得更近，也改變工具呼叫和附件進入模型的方式。這些機制要一起運作，才會形成可接續的工作環境。

如果已在自架 Open WebUI，可以先固定一個專案與代理，對照工作位置、核准和讀檔結果。升級版本及授權都對齊後，再決定是否把它擴到日常團隊流程。
