Bencho 在 X 被原作者 Lorenzo Cabra 以「讓 Claude 更有 UI 品味」介紹，吸引不少開發者注意。UI 指使用者介面，也就是人實際看到並操作的按鈕、選單與畫面。

這句話打中的問題很直接：請 AI 做一個好看的網站並不難，但想說清楚按鈕怎麼回應、選單如何展開，往往比描述配色更費力。

因為互動包含時間與狀態，截一張圖只能看到其中一刻。助理即使重現外觀，也可能做出完全不同的操作感受。

這個工具用能即時操作的 React 積木，讓人先試過互動，再把程式與設定帶進自己的專案。React 是用可重複使用的元件組成網頁的程式工具。

它適合有能力調整 React 專案、希望給 AI 更具體參考的團隊。展示裡看起來流暢的互動，仍要放進實際內容後，檢查觸控、鍵盤與資料行為。

要理解它能補上哪一塊，先看可操作的參考，怎麼變成可以交給助理的工作規格。

## Bencho 是什麼？把「我想要這種感覺」變成能看懂的互動

Bencho 是互動元件與微互動的資源庫。微互動指單一操作前後的小回應，例如複製完成的狀態、拖曳中的位移，或選項切換時的回饋。

在 [官方元件首頁](https://bencho.dev/?ref=aiposthub.com) 可以看到按壓、拖曳、滑動、輸入與載入等不同互動。分類的用途，是讓人先從要完成的動作找參考，而不只按視覺風格搜尋。

例如想改善檔案上傳，應先看拖放區與處理狀態，確認使用者怎麼知道檔案已接收。若只是找一個漂亮的發光按鈕，可能無法處理上傳過程真正的疑問。

這種選擇方法能讓設計討論更具體。團隊可以說「希望成功後保留檔名，失敗時仍可重試」，而不是只丟一句「做得更高級」給助理猜。

不過現成互動也有自己的使用情境。為音樂播放器設計的拖曳操作，套到課程報名表單可能過於複雜，因此選擇前仍要回到使用者要完成的任務。

如果一個效果需要很長的說明才能讓人知道怎麼按，就應先考慮是否有更直接的呈現方式。互動資源庫能提供選擇，不能替產品決定哪個效果最適合。

選定方向後，還需要辨認手上的內容是可以帶入專案的程式積木，還是只供觀察的設計參考。

## Blocks、Finds 與 Bench 有什麼不同？收藏靈感和取得程式要分清楚

在同一個網站看到的內容，不一定都具有相同交付方式。理解分類能減少一個常見誤會，就是把看到的每個案例都當成已提供原始碼的元件。

Blocks 是可以操作的元件積木，使用者能調整其設定並查看程式。對要讓 AI 直接整合功能的人，這部分比較接近可採用的起點。

Finds 偏向互動參考，會連結到原作者的作品或貼文。這些案例有助理解動態表現，但看得到示範，不代表能取得或重新散布原作品的程式。

Bench 則提供整理手上元件的工作空間。團隊可以先把要比較的互動放在一起，觀察不同效果是否會在同一個頁面互相搶注意力。

例如選單、提示訊息與提交按鈕各自看都很吸引人，放在同一頁卻可能同時移動。把它們並排看，才能討論應把注意力留給哪個操作。

因此，參考收集和專案整合最好保留不同紀錄。前者記下想學的行為，後者記下實際採用的積木與版本，後續修改才找得到來源。

當團隊決定使用某個積木，MCP 就能把這份參考變成助理可讀取的程式材料。

## MCP 怎麼把元件交給 Claude？程式、樣式與依賴要一起取得

MCP 是 AI 助理連接外部工具的共同方式。這個工具的 MCP 讓助理搜尋積木並取得相關內容，減少只憑截圖猜測實作的情況。

依 [官方 MCP 說明](https://bencho.dev/mcp?ref=aiposthub.com) ，服務提供 `search_blocks` 、 `get_block` 與 `list_categories` ，分別用來找積木、取完整內容與列出分類。

其中完整內容包含 React 元件、CSS、所需套件與設定。CSS 負責網頁樣式，因此只拿元件程式卻漏掉樣式，畫面可能和展示差很多。

相依套件同樣重要。相依是元件執行時還需要的其他程式，如果專案尚未安裝，助理即使把程式貼進正確檔案，也可能無法正常編譯或顯示。

所以整合要求應明確指定「保留來源元件的互動，列出新增套件與修改檔案」。這樣團隊能看見採用成本，也能避免為了一個小效果帶進不需要的整組工具。

官方提供 Claude、Cursor、Claude Code 與 Codex 的連接方式，並透過 Pro 帳戶產生金鑰。金鑰相當於使用該帳戶資源的通行資訊，需要個別管理。

金鑰在建立時只顯示一次，也能從帳戶選單撤銷重建。設定完成後應存放在助理對應的私人設定裡，避免把含有金鑰的連線字串放進公開程式庫或教學截圖。

連上服務後，先請助理列出分類或搜尋一個積木，再取得完整內容。因為能連線和能正確整合是兩個步驟，這樣比較容易找到問題發生的位置。

如果團隊想把現成元件接進日常製作，可以先參考以元件完成表單的工作分工，再決定哪些互動值得加入。

## 用一個報名表單試做，提示詞要交代哪些行為？

試做時先描述操作的起點、結果與失敗狀態，AI 才能判斷要接哪個互動。只說「加一個好看的按鈕」，通常還缺少真正影響使用者的條件。

### 先指定結果，才選互動形式

例如報名表單的目標是讓使用者知道資料正在送出，並避免重複點擊。可以先要求保留既有欄位與送出邏輯，再加入清楚的處理中狀態。

這是一個整合示例，不是本篇的實測成果。團隊可以指定「送出時顯示進度，成功後顯示確認文字，失敗時保留輸入並提供重試」。

如果選用彩紙或彈跳效果，還應說明它何時觸發。只有伺服器確認成功後才慶祝，和點下去就顯示成功，傳達的是完全不同的訊息。

伺服器是實際接收並處理資料的服務，因此介面應反映它的結果。視覺效果可以補充狀態，但不能取代資料是否真正保存的判斷。

### 保留原有內容，讓改動能被核對

請助理修改前先列出會碰到的檔案，並說明是否更動資料送出方式。如果任務只有改善回饋，就不需要順便改會員登入或整頁版型。

完成後檢查程式差異，再用一筆測試資料跑完整流程。成功時要確認資料有進入預期位置，失敗時也要確認畫面沒有錯誤地清空內容。

如果表單會等待較長時間，也要讓狀態能持續被理解。短促的成功動畫只能說明一刻的回應，長時間處理則需要明確文字，讓使用者知道是否還應等待。

Bencho 的積木可以作為起點，團隊仍應依真實等待時間調整。這樣視覺參考才會融入產品的實際行為，避免把展示中的快速結果套到不同流程。

這樣驗收的價值，在於把好看和能用接在一起。當結果正確後，才有依據微調節奏與視覺，而不必為了展示效果反覆推倒整段流程。

## 免費與 Pro 怎麼用？程式授權和展示照片有不同條件

採用 Bencho 元件前，應依目前的官方授權區分免費與 Pro 內容。舊資源清單可能把整站描述為免費 MIT，但在 2026 年 10 月 19 日查詢時，官方已分開列出條件。

[官方授權頁](https://bencho.dev/licence?ref=aiposthub.com) 對免費開放的積木與聲音採 MIT 條件，允許修改與商業使用，並要求在大量複製原始碼時保留著作權與授權聲明。

Pro 積木則使用另一份授權，允許放進自己或客戶的應用與網站，但不能把積木本身再當成元件庫、範本、主題或素材包分發。

這個差別對接案者很實際。把互動放進客戶網站，和把同一份程式整理成付費 UI 工具包販售，屬於不同用途，不能把前者的允許延伸成後者也允許。

官方也說明 Pro 是個人授權，每位取得 Pro 積木來工作的人都需要自己的方案。因此團隊採購時，要看實際使用方式，不能只共用一組登入與金鑰。

展示中的照片也不隨程式一併授權。若元件包含人物或商品影像，應換成自己有權使用的素材，避免把程式可以採用誤解成畫面裡所有內容都能照搬。

官方另保留 2026 年 10 月 12 日前取得的 MIT 內容條件。這表示取得時間與來源紀錄有意義，日後要確認權利時，能回到當時保存的版本。

程式、照片與服務帳戶分清楚後，接著才是體驗是否適合實際讀者的檢查。

## 觸控、鍵盤與低動態偏好怎麼驗收？不要只重現展示影片

完整驗收應讓不同操作方式都能完成同一件事。滑鼠懸停能看到的提示，手機使用者未必能觸發，因此主要資訊不能只藏在滑入效果裡。

鍵盤操作則要看焦點是否清楚、選項能否切換、按下確認後是否到預期位置。焦點就是目前接收鍵盤操作的元件，若看不出位置，操作會變得困難。

有拖曳效果的元件，也應確認是否需要提供其他操作方式。例如調整順序可以有上下移動按鈕，讓不方便拖曳的人仍能完成工作。

減少動態效果的偏好同樣值得測試。當動畫減少時，選取狀態、成功提示與錯誤資訊仍要清楚，否則把動畫關掉之後，資訊也可能一起消失。

最後放進實際長度的文字與資料。展示裡很短的按鈕名稱，換成中文課程名稱後可能溢出，因此字長、手機寬度與錯誤訊息都應一起看。

也可以替同一個任務保留一份原版，讓兩位同事分別操作，再問他們是否知道目前狀態與下一步。這比只請人投票哪一版漂亮，更能發現效果有沒有幫上忙。

若新版需要多等一段動畫才能繼續填表，就應把等待納入比較。動態可以讓狀態切換更清楚，但使用者只是想完成報名時，不一定願意反覆看同一個效果。

記錄最常造成停頓的地方，再只調整那個互動。因為產品問題已縮小到具體一步，助理也比較能保留其他已經正常的內容，避免每次修改都重新設計整頁。

當這些條件都能成立，互動積木才有機會從靈感變成可維護的專案內容。

## Bencho 常見問題

### 這是替 AI 換一個更懂設計的模型嗎？

它提供具體互動與程式參考，讓助理有材料可以整合。模型並沒有因為連接資源庫，就自動保證所有設計決策都適合產品。

### MCP 可以免費連接全部積木嗎？

官方 MCP 以 Pro 帳戶金鑰提供服務。瀏覽公開內容、取得免費積木與使用 Pro 服務，應分別看對應條件。

### 可以直接把展示照片帶進客戶網站嗎？

官方授權說明將照片另外處理，因此應換成自己有權使用的素材。程式的授權不會自動涵蓋其他影像資產。

## 結語：先把一個互動講清楚，再讓 AI 幫忙整合

Bencho 的用途，是把抽象的介面喜好變成可操作、可查看程式的參考。對已有 React 專案的團隊，這能讓設計與開發討論有更明確的對象。

建議先挑一個表單回饋或選單互動，說清楚成功、失敗與操作方式，再請助理整合。確認功能與授權都符合用途之後，才把方法擴大到其他頁面。

也可以免費訂閱 AI 郵報，持續追蹤介面工具與 AI 開發流程，並把每次通過驗收的互動留下來，形成團隊自己的工作參考。
