過去 Codex 在處理長時間任務時，會不斷將先前的對話與操作紀錄壓縮成摘要，隨著任務越跑越久，摘要也會被反覆壓縮，這就可能產生一個問題： **越前面的細節，越有可能在多次壓縮的過程中遺失。**

例如：

- 前面已經嘗試過哪些解法
- 為什麼當時要修改某一段程式碼
- 某個工具當時回傳了什麼結果
- 哪些方法已經測試過但失敗了

當這些資訊逐漸從摘要中消失後，Codex 後續就只能依靠壓縮過的內容繼續推理。

現在 Codex 新增了一項實驗性功能，改變了原本的上下文管理方式：

**從「反覆壓縮摘要」改成「筆記 + 可搜尋的歷史紀錄」。**

啟用之後，Astra 可以跨越不同的上下文視窗保留筆記；當需要先前的細節時，也能直接回頭搜尋同一個任務中的歷史訊息與工具執行結果。

換句話說，Codex 不再需要完全依賴一份被反覆壓縮的摘要。

當它需要知道「之前到底做過什麼」時，就有機會直接把相關紀錄重新找回來。

這對大型專案或長時間執行的 Coding Agent 任務尤其有幫助，不但能降低重要資訊在上下文壓縮過程中遺失的機率，也有機會減少 GPT-6 的 Token／額度消耗。

### 如何開啟？

編輯 Codex 的設定檔：

`~/.codex/config.toml`

加入以下設定：

```
[features.context_management]
experimental_mode = true
```

儲存設定後， **重新建立一個新的 Codex 任務** 即可。

需要注意的是，目前這仍屬於 **實驗性功能** ，需要使用支援此功能的 Codex 客戶端，並透過符合資格的 ChatGPT 訂閱帳號登入。

**目前使用 API Key 的方式暫不支援。**
