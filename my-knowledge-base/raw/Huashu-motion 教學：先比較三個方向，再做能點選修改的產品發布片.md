想替產品做一支短片，最容易卡住的往往是第一版風格不對，後面又不知道從哪裡改。Huashu-motion 的做法是先看產品、提出視覺方向，再把成片留在可修改的專案裡。

它是一套讓程式代理照著工作的 Skill，也就是裝進 Claude Code 或 Codex 的任務說明與工具。因為品牌、節奏和修稿方法一起留下，下支影片也能接續同一套做法。

這套流程適合手上已有產品頁、Logo 與明確賣點的人。第一次先做一支短片，確認能在畫面上指出要改的位置，再決定是否拿來製作系列內容。

## Huashu-motion 公開了哪些可以直接利用的內容？

花叔在 X 發布專案時，示範了從產品資訊到宣傳片的流程。 [原作者文章](https://x.com/AlchainHust/status/2111811721471897618?ref=aiposthub.com) 與 [開源專案](https://github.com/alchaincyf/huashu-motion?ref=aiposthub.com) 都可查看，包含安裝方式、樣片與實際修改意見。

先提供三個方向的關鍵影格，是這個流程值得借用的地方。關鍵影格就是足以代表畫面風格的一張圖，先選定字體、色彩與構圖，能避免整支影片做好才發現方向不合。

專案也示範按 C 點選畫面、留言修改。留言會帶著時間點與場景資訊交給代理，因此「開頭標題太擠」能變成有位置的修改任務。

## 第一次使用，先準備一個產品資料夾

把官網網址、透明底 Logo、品牌色與要呈現的畫面放在同一處，再寫下觀眾看完應該記住的一件事。如果網站還沒有的功能也放進需求，代理就可能替你演出不存在的操作。

建議按這個順序處理第一支片：

1. **確認素材** ：列出可使用的圖片、介面與文案，缺少的先提出來。
2. **選定方向** ：請代理給三張不同構圖的關鍵影格，選一個繼續。
3. **先驗最難鏡頭** ：例如介面縮放或產品拆解，先確認做得到。
4. **完成後局部修改** ：用時間點、元素與預期變化描述意見。

官方列出的本機需求包含 Node 22 以上、Chrome 類瀏覽器與 FFmpeg。FFmpeg 是合成和輸出影片的工具，配好環境後仍要實際播放成片，確認聲音與畫面一起正常。

## 可複製的產品發布片需求單

先從上方原始專案依安裝說明載入 Skill，再在開啟產品資料夾的 Claude Code 或 Codex 專案中送出需求。以下文字不會替你完成環境安裝。

以下是本站依公開做法改寫的範本，非原作者逐字 prompt，也未以此範本完成成片實測。替換中括號後再交給代理。

```
用 huashu-motion 替［產品名稱／官網］製作 24 秒橫式發布片。
觀眾是［對象］，看完只需記住［一項價值］。
可用素材在［資料夾］，產品功能只採用我提供的說明。
先提出三個視覺方向，各給一張實際渲染的關鍵影格。
選定後先寫場景節奏表，標出文字出現與可閱讀的時間。
先做最困難的鏡頭給我看，再完成其他場景。
完成後保留可點選留言修改的專案，以及 MP4 成片。
若使用外部素材，附上來源；不要把示意介面當成真實功能。
```

## 檢查能否修改，比只看成片更有用

驗收時先改一個標題、一個數字與一段停留時間。如果只能重做整支影片，這個專案還沒有發揮可編輯的價值。

再聽一次配樂跨場景的位置，尤其是片尾。原作者的公開紀錄就有針對音樂突然中斷的修改，代表畫面順利輸出後，聲音仍是需要單獨確認的部分。

### Huashu-motion 能直接生成真人拍攝畫面嗎？

這套專案以程式畫面與素材合成為主。需要真人或實拍時，先提供自己的素材，再讓工具安排鏡頭與包裝。

### 開源是否代表示範片裡所有內容都能拿來用？

程式碼授權與角色、品牌、音樂是不同的權利。製作自己的片時，保留方法並替換成可使用的素材，會比直接沿用整支示範片容易管理。

先用自己的產品完成一次「選方向、改一處、重新輸出」，就能判斷這套工作流是否適合你的製作節奏。
