電視還能播放影片，卻得等桌面廣告和推薦列載完，才找得到想看的 App。這也是 X 上 Claude Code 改造 Android TV 貼文會引起共鳴的原因。

原作者表示，他用一個下午停用 25 個預載 App，並把記憶體占用 192 MB 的原廠桌面換成 83 MB 的自製桌面。這是作者那台電視的紀錄，不代表所有型號都會出現同樣差距。

這類改造能成立，是因為 Android TV 原本就有 ADB 偵錯工具，電腦取得電視授權後，可以查看套件、調整設定並安裝自己的桌面。AI 幫忙整理工作，真正執行的仍是 Android 工具。

但電視上的預載服務不全是廣告，有些也負責遙控器、投放或系統更新。因此，操作前先保留現況和還原方法，比一次停用多少套件更影響結果。

對願意備份、逐項驗證的人，這是一個讓舊電視更順手的方向。若希望完全不用理解設定，則先整理現有桌面，通常比較符合期待。

## Claude Code 改造 Android TV，能改善的是哪些地方？

這個案例來自 [Mihir Gupta 在 X 的分享](https://x.com/0900mihir/status/2111746030228455883?ref=aiposthub.com) ，文中的裝置數字均為原作者說法。

AI 可以協助換掉操作入口，但不能改變舊電視處理器的能力。這個差別會決定你該期待什麼：首頁變得簡單、常用 App 更容易找，和影片解碼能力變強，是不同的結果。

X 原作者提到的 192 MB 與 83 MB，是兩個桌面的記憶體用量比較。因為用量和型號、版本、背景程式都有關，不能直接換算成開機快幾倍，或推論串流畫質會提高。

桌面在 Android 上常稱為 Launcher，也就是按下首頁鍵後看到的入口。它負責排列應用程式、顯示推薦內容和接收遙控器操作，所以換一個較簡單的入口，可以改變每天使用的感受。

這類工作也有公開專案可參考。 [tv-vibehack 的專案說明](https://github.com/Gathin23/tv-vibehack?ref=aiposthub.com) 把流程分成備份、停用不需要的套件，以及安裝自製桌面。這是另一個作者公開的實作，不能把它與熱傳貼文中的電視視為同一次測試。

所謂停用，是讓套件暫時不運作，資料與程式仍可能留在裝置中。這和直接刪除有差別，因此專案才能設計還原路徑。讀者採用時也應保留這個前提。

AI 在這裡的角色，是把型號資料、套件清單和使用需求整理成可執行的工作。知道哪些設定可以改之後，還得確認這台電視是否開放電腦連線。

## 怎麼確認電視支援 ADB 與第三方桌面？

第一個門檻是作業系統。Android TV 與 Google TV 可以沿著 Android 的工具路徑研究，但三星 Tizen、LG webOS 等系統不能直接套用同一份做法。

ADB 是 Android Debug Bridge，白話說就是電腦與 Android 裝置之間的偵錯通道。 [Android 官方文件](https://developer.android.com/tools/adb?ref=aiposthub.com) 說明它可以執行裝置指令、安裝應用程式與協助檢查狀態，因此代理能透過它完成部分操作。

不過，電腦上裝了工具，不代表已取得電視的控制權。使用者仍要在電視啟用對應設定，並確認電視上出現的連線授權提示，才有辦法繼續。

實際選單會因品牌與系統版本不同，所以請先確認型號、Android 版本和韌體版本，再讓助理查相符的步驟。若助理只根據品牌猜位置，就可能叫你找不存在的選項。

連線後可以先做讀取工作，例如確認裝置名稱、列出套件與擷取首頁畫面。因為這些結果能證明助理連到正確電視，也能留下後續比較所需的基準。

同一個網路裡若有多台 Android 裝置，還要核對裝置識別與畫面。不要只因為指令成功就往下做，否則一份正確的指令，也可能被送到錯誤的裝置。

連得上之後，先留下原本狀態，才有條件判斷哪些服務可以停。

## 先做備份，哪些預載套件應該保留？

備份應記錄停用前狀態，避免把日後仍要用的服務一併關掉。只存一張首頁截圖還不夠，因為截圖看不出套件名稱、原本是否啟用，以及目前的預設桌面。

比較實用的紀錄，是把型號與系統版本、套件清單、預設入口和變更清單放在同一個資料夾。每一項改動都能對回原本狀態，還原時才不必靠記憶猜測。

使用需求也要先說清楚。有些家庭只用兩個串流 App，有些還會投放手機畫面、用語音搜尋或切到數位電視。因為需求不同，同一份精簡清單未必適合兩台電視。

下面這張表，可以用來和助理確認哪些功能要保留。

| 日常功能 | 停用前要確認的事情 | 完成後的測試 |
| --- | --- | --- |
| 串流播放 | 常用 App 與登入是否正常 | 播放、暫停、字幕與重新開啟 |
| 遙控器 | 首頁、返回、方向鍵的行為 | 在首頁與 App 之間來回操作 |
| 手機投放 | 家人是否仍需要投放 | 用原本手機實際連線 |
| 系統維護 | 韌體更新與設定入口 | 能否打開更新與網路設定 |

表格裡的功能是保留目標，不是建議一律停用哪些服務。因為品牌常把功能分散在不同套件，不能只看到名稱像廣告或分析，就直接做出刪除決定。

一個適合交給助理的要求，是「先列出每個建議停用項目的用途與依據，保留語音、投放和更新，先改一組，再回報結果」。這樣工作就能分段檢查。

如果查不到某個套件的用途，可以先留著。讓桌面清楚一點，通常不需要把所有背景服務都處理到最乾淨，因此可以把不確定項目排除在第一輪之外。

確認要保留的服務後，測試就能對準家人每天會用的功能。

## 換好桌面後，如何確認遙控器與串流正常？

首頁能打開，只完成一半，還要用平常的遙控器和 App 逐項測試。因為安裝畫面看起來正常，仍可能在重開機、切換輸入源或叫醒電視時出現問題。

先按首頁鍵回到新桌面，再進入常用串流 App。播放一段影片後返回首頁，確認焦點還在合理位置，方向鍵不會跳到看不到的按鈕，家人也找得到原本入口。

接著測試待機與重新開機。兩者會走不同的系統路徑，所以只做一次關螢幕測試，不能證明完整開機後仍會使用新桌面。

如果平常有接遊戲機或機上盒，也要切換 HDMI 輸入，再回到串流畫面。這一步能確認新的操作入口仍接得回原本的觀看習慣，沒有為了漂亮桌面增加額外障礙。

效能比較最好使用固定流程，例如同樣從開機到打開某個 App，再開始播放。每次都用相同起點，才比較看得出桌面整理帶來的差別，避免把網路波動當成改善成果。

記憶體資料也要在相近狀態讀取。如果一邊剛開機，另一邊已經播放一小時，差距裡就混入了其他程式的影響，因此不能只挑一個最漂亮的數字做結論。

測試時請把「正常」「失敗」和「沒有測」分開記錄。例如手機投放沒有實際使用過，就不能因為設定頁還在，便把它算成通過。

如果日常使用出現問題，原本的設定紀錄就是還原依據。

## 怎麼給 AI 一份不會改過頭的電視整理任務？

把「幫我加速電視」改成具體使用需求，代理才比較容易提出合理方案。像是「首頁只保留常用四個 App，方向鍵操作要和原本一樣，投放與更新要保留」，就比追求最快更容易檢查。

任務裡可以先限定第一輪只讀取。請助理回報裝置身分、目前桌面與套件清單，再指出每個建議變更會影響的功能，因為你要先知道它理解的是不是同一台電視。

確認清單之後，再把執行範圍縮到一組設定。若畫面和使用方式沒有變壞，就保留這份紀錄，再安排第二組。這樣出問題時，需要回頭檢查的項目會少很多。

備份也應要求助理提供可辨識的檔案位置，以及讀取備份後看到的內容。只回報「已備份」並不足以讓使用者判斷日後能不能還原，因此要確認檔案實際存在而且可以讀取。

安裝自製桌面時，可以請助理保留原廠桌面的切回方法。因為第三方桌面可能缺少特定系統入口，保留兩個入口的選擇，會比立即把原廠元件停得一乾二淨更方便比較。

每次工作結束，要求助理整理本輪改了什麼、測了什麼、哪些功能還沒測。這份紀錄可以很短，但要能對上具體套件或設定，避免下一次對話只剩下「上次已經處理過」的模糊印象。

如果家人不參與設定，也可以把他們的日常操作當作最後一道測試。請他們不用你的提示，從首頁找到節目、調字幕再返回，這會比自己熟悉新介面後的操作更貼近實際情況。

當助理提出更新韌體、恢復出廠或更改帳戶等額外工作，先回到原本目標確認是否必要。桌面整理可以獨立完成的話，就不必把每一種可能改善都放進同一次改造。

## 不滿意時怎麼還原，哪些人適合動手？

還原靠的是原本套件與設定仍被保留，所以一開始就不能把停用誤作刪除。專案中的還原腳本也應先讀懂它要恢復哪些項目，不能把任何「restore」檔名都當成完整保證。

最小的還原可以從恢復原廠桌面開始，再逐項重新啟用停用服務。每恢復一項就重測原本失敗的功能，因為這樣比較容易找出造成影響的變更。

如果新桌面和原本服務的關係不明，先停止新增改動。把目前套件狀態、錯誤訊息與已執行指令整理給助理，比反覆嘗試網路上不同型號的修復指令更容易縮小問題。

完成操作後，也要依官方工具說明檢查偵錯連線設定。偵錯通道原本是維護用途，日常不需要時，應回到自己能掌握的連線狀態，避免之後忘記還開著哪些入口。

這項改造比較適合願意花時間測試、能找到型號資訊，也願意保留原廠入口的人。如果家中只有一台主要電視，而且沒有時間處理異常，先減少推薦列或整理常用 App，負擔通常比較小。

AI 讓特定裝置的整理工作更容易開始，但生活設備的成功標準很簡單：家人拿起原本遙控器，就能完成每天的事情。是否值得保留新桌面，應由這個結果決定。

## Claude Code 改造 Android TV 常見問題

### 這樣會把舊電視變成 Apple TV 嗎？

不會。類似 tvOS 的桌面只是外觀和操作入口，原本的硬體、作業系統和應用程式相容性仍然不變。

### Claude Code 可以直接控制任何智慧電視嗎？

不能。這條路需要裝置支援對應偵錯工具，也需要電視端授權。不同作業系統不能直接共用 Android TV 的做法。

### 停用 25 個套件是必須完成的目標嗎？

不是。那是原作者案例的數量，自己的目標應是保留需要的功能，再移除確定不需要的干擾。

### 有公開專案就能直接照做嗎？

仍要讀支援範圍與操作內容。開源提供檢查的機會，但不能代替型號確認、備份與實際測試。

### 第一個動作應該做什麼？

先記下型號、系統版本與每天會用的功能，再做只讀的套件與狀態紀錄。等這份基準完整，再考慮讓助理提出最小變更。
