AI 修圖的下一步，未必只是再生成一張新圖片。有時使用者想要的是把已有作品的標題放大、調整某一層顏色、替一批圖輸出不同尺寸，並保留所有可編輯的結構。這些工作看起來普通，卻正是設計師每天花時間完成、也最需要結果能回頭修改的環節。

開源影像編輯器 PhotoCraft 近期受到關注。臺灣時間二〇二六年十月八日凌晨查閱官方 GitHub 儲存庫時，專案已有一萬五千四百五十九個星號收藏。這是當時的開發者關注快照，不能換算成付費用戶或實際工作人數。儲存庫九月三十日建立，本文關注近期進展，不將十月的討論日期寫成首次發布日期。

PhotoCraft 的特色，是以 Rust 程式語言重建影像編輯工作環境，讓同一個引擎可由使用者介面、命令列與 AI 代理操作。它值得關注的方向，是可編輯文件逐步成為代理能理解與執行的工作對象。專案仍明確標示早期測試版，現階段較適合探索與限定任務，還不能據此宣告專業工作已可全面搬離 Photoshop。

## 代理能操作圖層，與模型直接生成圖片不同

一般生成式修圖，是模型根據描述產生新的影像結果。PhotoCraft 的代理介面則讓外部程式呼叫既有編輯命令，例如調整圖層、使用濾鏡、管理選取範圍與輸出檔案。它把熟悉的影像編輯工作變成可呼叫的操作，而不是只把一段提示詞送進生成模型。

官方說明，每個選單、工具與對話框都經過共同的命令登錄系統。使用者點選與代理呼叫共享同一個執行引擎，因此自動化工作較容易對應到具體操作。這個設計的價值，是當結果不如預期時，可以檢查用了什麼命令、哪些參數，以及文件在哪一步被改變。

這也能降低不同操作路徑之間的差異。若人工調色與批次程式各用一套處理邏輯，難免出現同一參數卻輸出不同結果。共享引擎提供一致性的基礎，但不自動保證每個功能都正確。命令有接起來、能收到成功回覆，仍要與畫面和輸出結果分開核對。

專案提供 MCP 伺服器與命令列工具。MCP 可以理解為讓 AI 應用連接外部工具的共同介面，命令列則讓程式透過文字指令執行工作。這使不同代理有機會使用相同編輯能力，但代理本身用哪個模型、能讀到哪些檔案，仍由使用者的外部工作環境決定。

因此，看到「為代理打造」不應推定已具備完整的生成式填色或 AI 圖像能力。官方路線圖將生成式功能列為重要缺口，機器學習後端尚未啟動。現階段的新聞價值，是編輯工具的自動化入口，而非宣稱它已提供另一套能取代成熟生成式修圖服務的模型。

## 保留圖層，讓自動化結果還能繼續修改

PhotoCraft 提供圖層、遮罩、調整圖層、文字與向量等工作結構。圖層像分開疊放的透明紙，遮罩則控制某個效果在哪些區域顯示。調整圖層將色彩變化獨立保存，便於改動強度、調整順序或暫時關閉，而不必每次都重新修改原始像素。

官方畫面展示《神奈川沖浪裏》上的文字卡片、陰影，以及色彩和曲線調整。這些截圖由專案透過自身控制通道產生，是官方應用畫面，並非本文作者完成的實測。它們可用來理解操作對象，卻不能單靠一張畫面證明長時間編輯、大型文件與所有工具都已穩定。

對代理而言，保留結構比一次得到好看圖片更有長期價值。假設活動日期改了，代理可以修改日期文字層，保留背景與版面。若品牌要求降低飽和度，可以調整指定圖層，而不必重畫整張作品。這是設計上的假設情境，實際可用性仍需用自己的文件測試。

遮罩也讓任務範圍更清楚。官方《戴珍珠耳環的少女》示例使用橢圓遮罩，讓臉部保留顏色、外圍變灰。它呈現的是可明確指定區域的編輯。若代理要修改背景卻改到人物，就應檢查選取範圍與遮罩，而不是只要求模型「再做一次」，期待結果碰巧正確。

這些結構也有助於交接。工程式的自動化工作若只留下最終 JPEG，下一位設計師可能看不到如何得到結果。若保留可編輯文件、必要圖層與操作紀錄，人工就有機會接續調整。是否能真正節省時間，取決於文件是否仍可使用，而不只是第一張輸出是否吸引人。

## 同一套命令，讓一批圖片的規格更容易一致

官方命令列示例包含開啟文件、套用濾鏡、建立曲線調整與輸出，也能把一份動作清單套用到整個資料夾。動作清單是明確的操作序列，適合需要重複處理的工作。它可以讓每張圖片依同一套參數執行，減少人工反覆點選時產生的差異。

但批次一致不等於視覺上都合適。相同裁切範圍對橫式與直式照片可能產生不同結果，相同亮度調整也可能使少數圖片失去細節。代理應先理解哪些步驟可以固定、哪些需要逐張判斷。若任務要求人物完整保留，就不能僅靠尺寸符合規格來宣告成功。

適合的起點，是輸入條件清楚、輸出可直接核對的工作。例如同一款版面換標題、既定尺寸輸出，或對已確認的圖層套用相同效果。這不是官方提供的成功案例，而是根據命令架構提出的試用方向。先從小批量開始，較容易發現例外文件與輸出差異。

輸出也應有獨立的驗收條件。格式、尺寸、透明度與檔名正確，只回答了交付規格的一部分。文字是否截斷、主體是否保留、色彩是否合理，仍要檢查。官方輸出對話框提供預覽與檔案大小估計，讓使用者能理解工作結果，但估計數字不能取代實際輸出檔案。

對團隊而言，自動化最有用的地方，是把重複操作與需要判斷的例外分開。完成規格化工作後，人工集中檢查不符合條件的作品。若每張圖片都要從頭修正，批次指令即使執行很快，也只是把工作換了一個階段，沒有真正降低總負擔。

## PSD 可以重存，仍要看清楚測試證明了什麼

PSD 是 Photoshop 常見的分層文件格式，可能包含文字、效果、遮罩與其他結構。PhotoCraft 能開啟、編輯並儲存 PSD，是它受到關注的重要原因。但相容性不是只有「檔案能打開」一種標準，還包括畫面是否一致、物件能否繼續編輯，以及重存後是否保留必要資訊。

專案 README 表示，在 psd-tools 的三百零九份測試文件中，三百零七份開啟後重存能保留渲染結果。另一份混合測試集為一百七十份中的一百六十九份。這些是專案自己的測試成果，本文沒有重新執行。它們支持特定測試集的重存能力，不等於所有商業文件都能無損往返。

渲染結果是把圖層合成後看見的影像，與檔案每個位元組完全相同是不同條件。PhotoCraft 明確指出，應用重存會改寫影像資源、圖層記錄與合成內容，因此重存文件不會逐位元組一致。若讀者把高測試通過數理解為文件完全沒有任何改變，就會高估證據支持的範圍。

專案另有獨立的 PSD 解析與寫入程式庫，在不經應用文件模型的往返測試中重現可解析文件的原始位元組。這是另一條測試路徑，不能套用到使用者在介面裡開檔、修改再存的整個流程。理解兩者差別，才能知道哪些檔案屬性仍需要實際檢查。

如果團隊準備試用，應以工作副本測試代表性文件，包含文字、智慧物件、遮罩、色彩模式與特殊效果。先比較開啟時的畫面，再修改、重存並回到原本軟體核對。這個順序能區分讀取、編輯與輸出的差異，也能判斷某個問題是個別格式功能，還是整體流程不適合。

## 本機編輯與雲端代理，要分開看資料流

PhotoCraft 的桌面編輯工具可以離線運作，官方說智慧選取也在本機執行，不需要雲端帳戶。這有利於希望自己保管素材、避免每個編輯動作都依賴外部服務的使用者。但當外部 AI 代理加入工作時，模型是否在本機執行，就是另一個需要確認的條件。

假設代理透過雲端模型分析圖片，它可能需要把畫面或文件資訊送往該模型服務，即使最後的調色命令在本機執行。離線編輯器與離線模型並非同一件事。團隊應確認代理如何取得必要資訊，再判斷哪些作品適合用這條自動化流程，避免只看編輯器宣傳就推定所有資料都留在電腦上。

官方桌面控制通道限制在本機迴送位址，並要求連線先驗證。迴送位址是同一臺電腦內部連接的入口，不是直接對整個網路提供控制。這些是控制介面的具體設計，但不能代替使用者對外部代理的檔案範圍管理。能呼叫哪些命令與能讀寫哪些資料，仍應與任務相符。

代理也需要判斷工作是否真正完成。控制通道可以讀取介面與文件狀態，有些命令則可能在背景執行。收到開始工作的回覆，不一定代表最終影像已輸出。自動化流程應等到需要的結果存在，再核對文件與圖片，而不是把每個命令都有回應當成整份交付完成。

這種可檢查的操作流程，是代理編輯的實用方向。比起一直描述「更漂亮一點」，明確說明修改哪一層、使用哪種效果、輸出哪些檔案，往往更容易驗收。模型仍可協助理解需求，但最後需要回到文件、畫面和輸出，讓人能判斷它是否照要求完成。

## Rust 與 GPU 是架構優勢，不能直接當效能保證

PhotoCraft 使用 Rust，並透過 wgpu 將畫面合成接到不同圖形後端，包含 Metal、Vulkan、DX12 與 WebGPU。GPU 是擅長平行運算的圖形處理器，圖形後端則是軟體使用硬體能力的途徑。這種設計有助於跨平台共用引擎，但實際表現仍受到硬體與文件內容影響。

官方也使用寫入時複製的圖像區塊。意思是資料可以先共享，真正修改時再建立必要副本，減少每次操作都複製整張大型影像的負擔。這是支援復原與大畫布的合理架構，但不能僅從技術名稱推導每次編輯都比既有軟體更快，更不能忽略特定操作的例外。

專案表示有超過一千七百項測試，並將 CPU 與 GPU 的合成結果互相比較。測試數量提供開發品質的線索，測試覆蓋哪些功能才決定它能證明什麼。官方路線圖也坦承，早期使用者發現過原測試沒有涵蓋的基本操作問題，因此實際工作仍需要自己的驗收。

這份坦承比單純宣稱功能齊全更有參考價值。它提醒使用者，選單接到命令、測試通過、操作感受成熟，是不同層次的成果。若特定環境下筆壓、排版或外掛流程還不完整，就可能影響專業工作。團隊應看自己最常用的功能深度，而非累加選單項目來決定是否切換。

## 現階段值得試用的，是有邊界的工作流程

官方將 PhotoCraft 定位為早期測試版，明確表示尚不能作日常專業工作的 Photoshop 替代。主要缺口包括生成式功能、部分工具、文字排版深度、專業流程與外掛相容性。這些會直接影響使用者能否接續原本工作，也說明開源和免費本身不會自動消除切換成本。

適合現在評估的使用者，是願意測試圖層工作、自動化命令與開放文件流程的人。若某個限定任務表現可靠，就可以保留那一段用途，逐步擴大範圍。對有交付期限、既定外掛與複雜 PSD 的團隊，則應先證明自己的關鍵流程可用，再考慮更大規模搬遷。

專案程式碼可選 MIT 或 Apache 2.0 授權，附帶素材則保留各自來源與權利條件。官方截圖使用公開領域藝術作品，並列出來源。品牌名稱與標誌另有規範，不能由程式碼開放推定品牌也可任意改用。這些區分對準備修改、分發或商業導入的團隊都有意義。

PhotoCraft 值得關注的地方，是讓可編輯影像文件與代理操作接得更直接。現階段可以從一個具體問題開始：「哪一段真實工作已能穩定完成，並保留人工接手的條件？」如果這個問題能用實際文件回答，早期工具也能找到有價值的位置。

## 常見問題

### 現在已經能全面取代 Photoshop 嗎？

官方明確表示尚不能作日常專業替代，並列出功能與流程缺口。較合理的方式是先挑選有限的編輯任務，用自己的副本驗證開啟、修改、重存與輸出。可用的部分可以先採用，尚未可靠的部分則保留原有工具處理。

### 有 MCP，就代表內建 AI 生成圖片嗎？

MCP 提供外部代理呼叫工具的介面，讓模型操作既有編輯命令。它與內建生成模型是不同能力。專案仍把生成式與機器學習功能列為缺口，因此應以目前已提供的命令與編輯結果理解代理支援，而不是期待所有生成式修圖功能都已完成。

### 星號收藏多，代表品質已經成熟嗎？

星號反映使用者當時願意關注儲存庫，無法直接證明穩定度或專業採用量。它可以說明話題受到注意，但採用仍要看具體文件、必要功能、錯誤恢復與交付結果。這些實際條件，比關注數能更直接決定工具是否適合自己的工作。
