Graphify 是近期很受關注的 GitHub Skill，2026 年 11 月初約有 14 萬顆 Stars。這次我用 Chrome 小恐龍做了一個簡單測試，但如果只單看我的測試「把程式碼畫成圖」，其實會錯過它不少功能。以下整理官方提供的能力，以及可以怎麼用在實際工作上。

## 01｜Graphify 是什麼？可以做哪些事？

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/2026/11/data-src-image-1d46624a-158f-4da8-a1c6-d08fb1c465cc.png)

01｜Graphify 是什麼？可以做哪些事？

[Graphify](https://github.com/Graphify-Labs/graphify?ref=aiposthub.com) 是一款可以搭配 Claude Code、Codex、Cursor 等 AI 工具使用的 Skill。它可以分析程式碼、文件、PDF、資料庫結構，甚至圖片及影音內容，將資料中的資訊與關係整理成一張可以查詢的知識關聯圖。

你可以把它想成一個幫忙梳理資訊的工具。當一個專案裡有大量檔案、功能、規格和流程時，Graphify 可以協助找出這些內容之間的關係，方便後續搜尋、分析與整理。

例如，你可以拿它分析網站的功能架構，也可以將需求文件、技術規格及資料庫結構納入分析，了解不同資訊之間有哪些關聯。

目前最成熟的應用仍然是程式碼分析；文件、圖片和影音則需要依格式設定額外的解析工具或 AI 模型。

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/size/w2400/2026/11/-------2026-11-04-------4.20.56.png)

### 1\. 自動整理專案架構與功能關係

Graphify 可以解析專案中的檔案、模組、函式及相互關係，找出核心節點，並將關聯密切的內容分成不同群組。

除了技術架構，也可以用來輔助理解產品的功能組成。例如分析一個購物網站時，可以從會員、商品、購物車、訂單等功能出發，查看它們在程式中如何互相連接。

如果同時提供需求文件及相關資料，也可以進一步探索文件概念與程式實作之間的關係。

適合用在： 產品功能盤點、既有專案交接、系統架構理解、功能模組整理。

### 2.直接提問，查詢不同功能或資料之間的關係

Graphify 支援 `query` 、 `path` 、 `explain` 三種查詢方式，不需要每次都手動在關聯圖上尋找節點。

例如想知道會員登入與訂單功能之間有哪些關係，可以直接提出問題，讓 Graphify 找出符合問題的節點及連線。

也可以指定兩個節點，追蹤它們之間的路徑，或查看某個節點的詳細資訊。

常見查詢方式：

```
graphify query "what connects auth to the database?"
```
```
graphify path "UserService" "DatabasePool"
```
```
graphify explain "RateLimiter"
```

其中， `query` 適合從問題找相關資訊； `path` 適合查看兩個節點如何連接； `explain` 則可以查看指定節點及其關係。

適合用在： 功能關聯查詢、跨模組分析、需求釐清、尋找資料來源。

### 3\. 分析修改需求可能影響哪些功能

假設你是 PM，今天要調整會員登入流程，新增一道驗證步驟。

除了登入畫面，可能還要考慮登入狀態、驗證逾時、API 串接，以及登入成功後的頁面導向。

這時可以利用 Graphify 查詢登入功能涉及的模組、函式及上下游依賴，先找出程式中有哪些直接關聯。

同樣的方式，也可以套用到訂單狀態調整、付款流程修改、會員權限變更等需求。

Graphify 提供的是依據現有資料找出的關係與影響線索。像是沒有記錄在程式或文件裡的業務規則、人工流程，仍需要另外確認。

適合用在： 需求變更影響評估、PRD 前期盤點、功能調整、測試範圍討論。

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/size/w2400/2026/11/-------2026-11-04-------4.25.42.png)

可以選取你只想觀看的內容

### 4\. 自動產生 Wiki、架構圖與流程圖

Graphify 可以將分析結果整理成 Markdown Wiki，也能輸出架構圖及函式呼叫流程圖。

例如接手一個已經開發多年的網站，過去沒有完整的系統文件，就可以先讓 Graphify 分析現有專案，整理主要模組、相互關係及核心功能。

若分析資料包含需求文件，也能將這些資訊作為後續撰寫產品或功能說明的參考，但不代表能直接產生完整且正確的 PRD。

操作指令：

```
/graphify . --wiki
```
```
graphify export callflow-html
```

產出的文件可以提供團隊閱讀，再根據實際的業務規則和系統運作方式補充內容。

適合用在： 技術文件整理、系統交接、功能文件初稿、團隊知識庫建立。

### 5\. 協助 GitHub Pull Request 審查

如果團隊使用 GitHub 管理程式碼，Graphify 也能協助分析 Pull Request（PR）。

例如當兩位工程師同時開發不同功能，可以先查看他們修改的內容是否涉及相同模組，或某個 PR 可能影響哪些程式關聯。

它也能整理 PR 的審查狀態及相關檢查結果，協助團隊安排審查工作。

操作指令：

```
graphify prs
```
```
graphify prs 42
```
```
graphify prs --conflicts
```

需要注意，Graphify 提示的潛在衝突不代表 Git 一定會發生合併衝突，仍需要工程師確認。

適合用在： 程式碼審查、多人協作、版本整合、修改影響分析。

### 6\. 讓知識圖譜隨著專案持續更新

專案不會永遠維持同一個版本。當程式碼或功能持續調整，原本建立的關聯圖也需要更新。

Graphify 支援增量更新，也可以透過 Git Hook，在程式提交等情境中自動更新分析資料。

操作指令：

```
/graphify . --update
```
```
graphify hook install
```

例如一個網站持續新增會員、訂單或行銷活動功能，就可以在程式變更後更新圖譜，減少反覆從頭分析的工作。

適合用在： 長期專案維護、功能迭代、交接資料更新、持續追蹤系統變更。

### 7\. 整合不同類型的資料，建立跨文件關聯

Graphify 能處理的資料不限於程式碼，也包含 Markdown 文件、PDF、SQL Schema、圖片，以及影音逐字稿等內容。

例如一個產品專案可能有需求文件、API 規格、資料庫結構和程式碼。如果這些資料都能被正確解析，便可以放在同一套圖譜中探索關係。

你可以進一步研究某項需求涉及哪些技術元件、某張資料表與哪些程式有關，或文件中提到的概念是否能找到對應的實作。

這類應用需要留意資料格式、模型設定與來源品質。Graphify 能協助建立關聯，但不會自動驗證文件中的所有需求是否已經實作。

適合用在： 需求文件研究、跨文件分析、知識庫整理、產品與技術資訊整合。

### 8\. 讓 AI 重複使用既有的專案知識

Graphify 產生的 `graph.json` 可以保存分析結果，讓 AI 後續透過查詢圖譜取得相關資訊。

例如前一天已經分析完會員系統，隔天又要研究訂單流程，就可以沿用既有圖譜，不必每次都重新搜尋所有原始檔案。

Graphify 也提供整合設定，讓 Claude Code 等工具在處理專案問題時，優先參考既有圖譜。

這對長期維護的專案很方便，尤其是經常需要回頭查看不同功能、追查相依關係的工作。

適合用在： AI 輔助開發、長期專案研究、重複查詢、團隊知識累積。

## 02｜這些功能怎麼用在工作中？

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/2026/11/data-src-image-c9ff5132-4a2b-473d-b6e5-b43aa31dcf1e.png)

### 情境 A｜接手舊專案：快速整理要先讀哪些程式

新進團隊或接手別人的系統時，常常遇到文件不完整、資料夾很多、不知道從哪個檔案開始看的問題。可以先跑一次 Graphify，再用功能群組和核心節點整理閱讀順序。

例如先找應用程式入口、登入模組、資料處理與主要 API，再讓 Claude 列出五個優先閱讀的檔案。和工程師交接時，能直接帶著檔案及函式名稱討論。

請用 Graphify 分析這個專案。列出主要入口、核心功能群組、依賴最多的模組，以及我應該先讀的五個檔案。每一項請附上原始碼位置與判斷依據。

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/size/w2400/2026/11/-------2026-11-04-------4.24.52.png)

請用 Graphify 分析這個專案

### 情境 B｜PM 修改需求：盤點影響，再找工程師確認

假設產品要新增登入後的二次驗證。使用者只看到多一個步驟，但程式端可能牽涉登入狀態、逾時、API、錯誤處理與回跳。這時可以用 Graphify 先定位登入模組，查相關函式的呼叫路徑。

整理時，建議分成「圖譜已確認的程式關聯」和「需要向工程師確認的影響」。像外部銀行介面、法遵規定、人工核對流程，如果沒有完整反映在原始碼裡，Graphify 不會知道全部答案。

我們想在登入流程加一道驗證。請查詢 Graphify，列出相關函式、API、狀態處理與上下游路徑，附來源位置。再列出可能涉及的逾時、失敗重試及登入後回跳情境，把已確認關聯與推測分開。不要直接修改程式。

### 情境 C｜工程師改程式：先查依賴，再安排測試

工程師準備修改一個共用函式時，可以先看哪些地方會呼叫它，是否會牽動其他模組。遇到異常，也可以從功能對應的函式一路往上、往下追。這能縮小搜尋範圍，錯誤根因還是需要靠執行紀錄、重現和測試確認。

請找出［函式名稱］所有可解析到的呼叫者、相依模組與相關路徑，並標出來源。建議我修改前應該檢查的測試情境。

### 情境 D｜把舊系統整理成文件，交接或開會可以直接用

很多系統做了好幾年，文件早已跟不上程式。可以先產生 Wiki、架構圖和函式呼叫圖，再讓工程師補上業務背景、外部介面及例外流程。對 PM 來說，這些資料也能拿來對照 PRD、UX Flow 或 API 規格，確認需求討論時有沒有漏掉重要的處理環節。

例如登入流程的 Wiki 可以說明主要函式與模組，呼叫圖可以輔助找出流程經過哪些地方。要做正式交接文件，仍需核對內容並維持版本更新。

### 情境 E｜多人開發：幫工程團隊排 PR 審查順序

當很多功能同時開發，光看 PR 標題不容易判斷哪些改動互相接近。Graphify 的 PR 儀表板和圖譜影響資訊，可以協助找出碰到相近模組的 PR，再請負責工程師優先檢查整合風險。

這項功能主要適合有 GitHub 開發流程的工程團隊；需要對應 Repository、PR 權限與執行環境，並不是一般 PM 安裝後就能直接看到公司的所有 PR。

### 影片實測：Chrome 小恐龍只是其中一個例子

這次我挑的是公開 GitHub 專案 wayou/t-rex-runner，問題很簡單：「如果要讓小恐龍跳得更高，需要查看哪些程式？」

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/size/w2400/2026/11/-------2026-11-04-------4.24.15.png)

我挑一個公開的專案去實測

小恐龍主要的遊戲邏輯在 index.js，適合拿來練習查跳躍速度、重力和跳躍控制函式。流程就是下載專案、建立圖譜、向 Claude 提問，再回到程式碼確認。它示範的是 Graphify 的查詢和關聯分析能力，並沒有涵蓋上面所有功能。

如果想跟著試，先準備 Python 3.10 以上及 uv，再執行：

```
v tool install graphifyy
graphify install
git clone https://github.com/wayou/t-rex-runner.git
cd t-rex-runner
```

接著在 Claude Code 的專案資料夾執行：

> /graphify.  
> 請用 Graphify 查出小恐龍跳躍速度、重力和跳躍控制相關的設定及函式，附上檔案位置與關聯路徑。先不要修改程式。

完成後可以打開 graphify-out/graph.html 查看互動圖、閱讀 GRAPH\_REPORT.md 分析摘要，或保留 graph.json 繼續查詢。不要預期所有功能都能被自動辨識；這個小專案也不一定會生成非常複雜的跨檔案圖。

## 03｜其他玩法：讓專案分析資料持續累積

![](https://storage.ghost.io/c/5e/61/5e6189f0-c5e0-49a0-97b4-5eddd3f43c77/content/images/2026/11/data-src-image-6aba42e0-85ac-4b15-8927-35d9255b8ed1.png)

03｜其他玩法：讓專案分析資料持續累積

除了逐一分析專案，還能合併多份圖譜、整合文件與影片逐字稿，或把圖譜提供給其他工具使用。例如用 graphify merge-graphs 整合兩份資料；需要更長期的跨 Repository 分析、Jira／Sentry 整合與持續更新，則可評估 Graphify Cloud。Cloud 是另外的服務，不能當作免費本機 Skill 全部內建。

如果使用公司程式或文件，請先確認資安政策和資料流向。原始碼的本機解析不需把程式碼送給外部模型；但文件、圖片和影片的語意分析可能使用額外服務。

從一個問題慢慢來去嘗試

第一次接觸 Graphify，可以先拿小型公開專案試查函式關係；熟悉後，再試著產生 Wiki、查修改影響或分析 PR。工作上最適合它的時機，是你手上已有一份程式專案，卻還沒弄清楚功能怎麼串、哪些地方會受改動影響。

分析結果可以拿來準備問題、對齊需求、整理交接文件。正式修改前，仍然要找工程師核對原始碼與測試結果。
