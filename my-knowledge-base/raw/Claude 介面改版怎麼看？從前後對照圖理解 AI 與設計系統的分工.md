Claude 介面改版值得看的，是參與設計者同時公開了修改前後的畫面，並說明團隊使用 Claude 與既有設計系統完成工作。

10 月 24 日，Chase McCoy 在 X 分享 Claude Code 桌面版與 Artifacts 的對照圖，表示從草圖到推出不到三週。Artifacts 是對話旁顯示並持續修改文件、程式或互動內容的工作區。

這個時間是團隊對單次專案的描述，背後還有設計師與既有元件。它不能直接換算成每個網站都能三週改完。

對想讓 AI 協助設計的人，較有參考價值的是先給模型一致的規則，讓人可以比較和修改同一份成果。

把新聞中的展示與自己的設計任務分開，才知道哪些做法能帶回工作裡。

## 前後圖可以拿來觀察哪些設計問題

靜態圖適合比較資訊排列、視覺層級與元件一致性，不能完整說明操作過程。看圖時先選一個問題，會比直接評「好看很多」更有用。

### Claude Code 桌面版：入口與對話內容的關係

原貼的 Code 桌面版對照使用相同的匯出按鈕任務。修改前，搜尋以左側一條輸入框呈現；修改後，搜尋放進左側的操作清單，與 New、Customize 等入口排列在一起。

這種改動可以讓團隊討論「哪些操作要一直顯示」「哪些內容應留給工作紀錄」。但僅憑截圖，無法判定使用者找搜尋的時間是否縮短。

對話中的程式碼與修改摘要也有視覺處理差異。因為使用者需要分辨說明文字、程式片段與已修改的檔案，所以可以觀察它們的層級，而非只比較哪種底色比較漂亮。

### Artifacts：卡片如何區分內容

Artifacts 的修改前畫面，作品預覽與名稱放在相同的卡片中。修改後的圖加入不同背景色、較明顯的類型圖示，以及把名稱與更新時間集中在下方的資訊區。

這些變化可以用來討論「還沒讀標題時，能不能先認出內容類型」。例如文件、程式與互動頁是否有可辨認的線索，名稱又是否仍然比裝飾更容易找到。

不過，顏色與圖示只能作為輔助。若要確認新卡片真的更容易找資料，可以請使用者用同一組項目尋找指定文件，再記錄是否找得到、花了多久，以及是否點錯。

UX 是使用者完成一件事時的整體體驗。因為它包含尋找、理解、操作與得到回饋，所以靜態的 UI 外觀只是其中一部分。

## 設計系統怎麼幫 AI 少猜一點

設計系統是一套可重複使用的視覺與元件規則，讓每個畫面有共同的依據。因為字體、間距、按鈕與錯誤訊息都有規則，所以 AI 不必每一頁重新猜。

元件就是可重複使用的介面部件，例如一個帶載入狀態的按鈕。沿用元件時，連同它的行為一起保留，才不會只得到外觀相似的新版本。

例如團隊已有一個主要按鈕，明確定義文字、顏色、大小與載入狀態。請模型製作新表單時，就可以直接沿用，而不是再生成一個外觀相似、行為卻不同的新版本。

因為大家沿用相同的規則，修改也有了共同語言。你可以要求「沿用既有的主按鈕，只調整這一頁的資訊順序」，而不必每次描述圓角、色碼與字重。

[Anthropic 的 Claude Design 使用指南](https://support.claude.com/en/articles/14604416-get-started-with-claude-design?ref=aiposthub.com) 說明，設計工作可以結合對話、畫布與團隊的設計系統，從產生第一版到持續調整。這是官方提供的協作方法背景，不代表本次介面改版使用了文件列出的全部功能。

### 規則要包含行為，不能只放色票

如果設計文件只有品牌色，AI 仍不知道表單送出失敗時該做什麼。較完整的資料應包含欄位提示、錯誤狀態、內容排列，以及不同螢幕下怎麼變化。

還要留下可以保留的決策。例如一個流程已經讓使用者熟悉，若改版時沒有明確說「保持操作順序」，模型可能為了視覺變化重排整件事。

官方的 [Artifacts 說明](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them?ref=aiposthub.com) 則介紹如何把內容放到對話旁持續查看與修改。對團隊來說，能看同一份內容、指出同一個位置，會比只用文字轉述畫面更方便討論。

有了規則，再給清楚的任務與限制，生成結果才容易比較。

## 把改版案例變成自己的協作需求

開始一個小型改版時，先保留現有內容與操作，再請 AI 提出可比較的排列方案。一次只處理一個畫面，才容易知道改動與結果的關係。

例如作品列表找不到需要的文件，可以先固定相同的九個項目，比較卡片資訊順序、類型標示與篩選入口，而不是換一組更漂亮的展示資料。

同一份測試內容也要包含長標題、沒有縮圖、剛新增與很久以前更新的項目。因為整齊的示範資料容易掩蓋問題，所以比較時應放入實際會遇到的例外。

以下是本站整理的設計協作需求，可按自己的頁面改寫。

```
請協助改版既有作品列表，只處理這個畫面。

使用者任務：從列表找到上週建立的課程大綱，並打開閱讀。
請先閱讀現有設計系統、元件與頁面，不新增品牌風格。

保留：資料內容、作品網址、搜尋功能與主要導覽順序。
比較：標題、內容類型與更新時間的排列方式。
請提出兩個方案，兩版使用相同九個作品與同一套字體。
其中包含長標題、沒有縮圖與不同內容類型。

先解釋每個方案如何支持尋找任務，再建立可操作的預覽。
不要因為樣式改變，就宣稱操作速度或使用者滿意度提升。
把需要實際觀察使用者才能知道的問題另列出來。
```

這份需求讓 AI 提案，也保留了人的判斷。你可以挑一版進行實際操作，再根據找錯、回頭與看不懂的位置修正，而不是只看哪張圖更吸睛。

## Claude 介面改版常見問題

### 這次是 AI 自動完成整個改版嗎？

參與者明確提到產品設計師、Claude 與設計系統一起工作。原貼沒有提供可以把所有設計與決策歸給 AI 的證據。

### 三週可以當成我們的專案工期嗎？

不能直接套用。已有元件、內容複雜度、團隊人數與審查方式都會影響時間，應先用自己的小型任務估計。

### 為什麼我的畫面還沒變？

這篇依參與者公開素材整理，沒有逐一驗證所有平台、版本與帳號。實際使用時以你的應用程式與官方更新說明為準。

### 沒有完整設計系統可以開始嗎？

可以先整理目前在用的字體、顏色、按鈕與狀態。從同一個畫面保留一致規則，比直接要求模型重設整個產品更容易管理。

## 先建立共同規則，再請 AI 畫新版本

對有既有產品的團隊，設計系統與任務說明比一句重新設計更能保留已經有效的決策。對還在探索的新產品，也可以先用少量規則比較不同方向。

這次案例值得帶走的是協作方法：固定內容、提供既有規則、比較同一任務，再由人選擇和驗證。工期與使用成果，仍應由自己的專案記錄回答。
