Unusual Whales Claude 連接器讓使用者能用自然語言查詢市場資料，再在同一個對話裡追問。這對原本就會看資料的人，有機會減少切換網站與整理表格的時間。

官方在 2026 年 10 月 17 日分享 Claude 整合示範，到 10 月 19 日查詢時約有 12.8 萬次瀏覽。它的焦點是把期權資金流帶進聊天視窗，並非發布一套新的股價預測方法。

期權買方取得在一定條件下買進或賣出資產的權利，但沒有必須履約的義務，資金流則記錄相關成交情況。但看到成交，不代表 AI 同時知道交易者的完整部位與目的。

因為同一筆成交可能只是整套策略的一部分，資料還需要時間、合約條件與平台分類方式才能解讀。把資料接上 Claude，只處理了取得資訊的一步。

這種整合能節省整理時間，前提是使用者保留查詢條件與原始結果。我會把它用在範圍清楚的市場研究，無法核對日期與定義的摘要，不適合直接變成買賣決定。

而開始研究前，還有一個很實際的問題，帳號登入與程式金鑰是兩條不同連線路徑，選錯入口便可能連不上，或誤解自己取得的資料權限。

## Unusual Whales Claude 整合能帶進哪些資料？

整合提供市場查詢工具，涵蓋期權、暗池與基本面等類別。暗池是部分交易在公開交易所報價簿之外完成的市場機制，相關紀錄仍需要看資料定義。

[官方 AI 應用說明](https://unusualwhales.com/ai-apps?ref=aiposthub.com) 列出 Claude、ChatGPT 與 Grok 的接入方式。這讓相同資料服務可以在不同 AI 介面使用，但各平台的查詢呈現形式與授權要求並不完全相同。

依 2026 年 10 月 19 日查詢的文件，Claude 與 Grok 以文字和表格回答，互動小工具則是 ChatGPT 的功能。因此看過其他平台示範後，不能推定 Claude 會出現完全相同的圖表介面。

官方也明寫，這條 AI 應用連接路徑提供唯讀工具，不能替使用者下單、建立警示或修改帳號。唯讀就是只取得資訊，這與讓代理操作券商是不同工作。

開發者的 [MCP 官方頁面](https://unusualwhales.com/public-api/mcp?ref=aiposthub.com) 則列有期權、暗池、機構持股、財報與其他查詢工具。MCP 是讓 AI 透過統一方式使用外部工具的連接規則，可以先把它理解成資料服務與助理之間的介面。

不過，工具清單長不代表帳號能使用每個項目。因為資料方案、權限與更新條件仍會影響結果，所以研究者應先確認自己的查詢類別，而非只看總數。

這次官方 X 查詢影片證明品牌正在推廣這種查詢方式，但本文沒有使用付費帳號測試即時行情。功能說明與自己的實際可用狀態，仍要在登入後分開確認。

## 登入與 API key 兩條設定路徑怎麼選？

一般使用者可先看帳號登入路徑，開發者則依 API 文件配置。API 是讓程式取得服務資料的介面，而 API key 是用來辨認與授權請求的金鑰，應像密碼一樣保管。

帳號登入方式的優點，是不必自行把金鑰貼進對話。依官方 AI 應用頁面，Claude 的支援方案包括 Pro、Max、Team 與 Enterprise，組織方案還涉及管理者設定。

個人方案可從連接器設定加入自訂連接，組織方案則由擁有者在組織設定處理。這個差異會影響誰有權開啟工具，因此團隊成員不一定能自行完成所有步驟。

官方為 Claude 帳號登入提供專用連線位址，再引導使用者到 Unusual Whales 網站登入並同意存取。設定時應從官方頁複製當次欄位，避免把產品介紹頁當成伺服器網址。

API key 路徑則需要另外確認 API 方案與配額。它使用不同端點，可能透過標頭或客戶端支援的方式提供授權，因此不能把帳號登入網址與 API 設定混在一起。

以下把兩種需求放在同一個比較表。

| 使用需求 | 較適合先看的入口 | 需要確認 |
| --- | --- | --- |
| 在 Claude 對話查資料 | 官方 AI 應用登入說明 | Claude 方案與資料帳號權限 |
| 在自製程式取得資料 | 官方 API 文件 | 金鑰、配額與資料範圍 |
| 在其他 MCP 工具研究 | 官方 MCP 設定頁 | 客戶端支援方式與授權 |

表格裡的入口對應不同身分與方案，因此有 Unusual Whales 網站帳號，不代表所有 API 服務都已包含。反過來說，拿到 API key 也不會自動替 Claude 的訂閱或組織權限解鎖。

如果連線失敗，先核對入口、授權與錯誤訊息，再重新嘗試。不要把金鑰貼到公開討論串求助，錯誤紀錄若含有授權欄位，也應先移除敏感內容。

## 如何問出可以核對的市場摘要？

問題應指定標的、日期、交易時段與資料類型，結果才有可比性。因為「今天市場怎麼樣」可以同時指價格、成交量或期權，助理必須替你選擇範圍。

比較具體的研究請求可以是「整理指定交易日某檔股票的期權警示，列出到期日、成交時間與篩選條件」。這種問法先要求資料，還沒有預設一定存在某種方向的訊號。

日期要寫出時區或交易日。台灣早上查詢時，美國當日可能還沒開盤，因此「今天」容易指向不同日期，明確寫出年月日能減少這種誤解。

也要確認資料延遲。官方 AI 應用說明寫明，付費方案提供即時資料，免費帳號延遲兩個交易時段，部分工具需要升級，因此不能把免費結果寫成當下市場。

連線成功後，可以先請 Claude 說明資料時間與所用工具，再呈現摘要。因為這兩項能幫助使用者理解答案是如何取得，之後比較結果也有共同基準。

[官方資料慣例](https://api.unusualwhales.com/docs/conventions.md?ref=aiposthub.com) 指出，交易發生、報告與可取得的時間可能不同。這代表查詢時間只是你拿到資料的時間，不能直接代替資料本身對應的時間。

同一份文件也建議從回傳內容的時間欄位確認新鮮度，而不是看兩次回覆是否相同。因此看到相同數字，不一定表示快取失效，也可能只是底層資料尚未更新。

若查詢沒有結果，應先確認條件。官方把成功回應中的空資料，與請求錯誤分開說明，沒有資料可能與日期、標的或篩選範圍有關，不能立即翻成「市場沒有活動」。

這些差異會影響研究結論，所以可以要求摘要旁保留查詢範圍。當別人想核對時，就能從相同日期和條件出發，而不必猜助理當時用了什麼資料。

## 期權資金流為什麼不能直接預測股價？

成交紀錄呈現交易的一部分，通常不會同時交代完整部位與目的。因此從一筆紀錄跳到「有人知道股價要漲」，中間還缺少證據。

Unusual Whales 在 [官方資金流警示文件](https://api.unusualwhales.com/docs/api/option-trade/flow-alerts.md?ref=aiposthub.com) 中，把警示描述為依規則彙整期權成交。也就是說，警示首先是資料經過篩選與組合的結果。

文件對重複成交的說明尤其有用。同樣是多次成交，可能是一個訂單分別與其他訂單配對，也可能是多位買賣方同時交易，所以不能直接當成多個獨立看法一致的投資人。

這會改變摘要的寫法。「出現多筆符合規則的成交」是資料描述，「大戶集體進場」則增加了交易者身分與意圖，後者需要更多支持。

若 AI 把平台標籤改寫成確定因果，讀起來會很順，但研究價值反而下降。因為使用者看不出哪些是原始資料，哪些只是模型補出的解釋。

因此可以把報告分成資料、可能解釋與尚缺資訊。這不是要把每個結論都模糊化，而是讓讀者知道某個判斷建立在哪些條件上。

例如想解讀一個合約，就應先看期限、成交條件與是否涉及多腿交易。多腿指同時組合數個合約的策略，單看其中一腿，可能無法代表整組部位的方向。

研究者也不應只挑符合原本看法的警示。如果看見其他期限或相反方向的成交，應放進同一個分析範圍，才不會讓自然語言摘要變成選擇性蒐證。

這些做法仍不會把工具變成預測保證，但能讓研究過程比較容易被質疑、核對與修正。對需要和同事討論的人來說，能回到原始條件，比一句肯定的市場判斷更有用。

## 誰適合先接入，使用前要確認什麼？

熟悉資料定義且願意核對來源的人，較能從自然語言查詢受益。若連基本成交與合約概念都還不清楚，先學資料如何閱讀，會比直接要求 AI 給買賣答案更實際。

對固定整理市場報告的研究者而言，可以先挑一種反覆使用的查詢。因為需求越具體，越容易比較整合前後節省了哪些工作，也更容易找到錯誤。

如果只是偶爾看新聞，不一定需要立刻購買進階資料服務。先確認公開資料是否已經足以回答問題，才能避免為了工具清單付費，最後卻沒有穩定用途。

費用也不只是一個網站訂閱。Claude 方案、Unusual Whales 資料權限與 API 配額可能分開計算，因此付費前應確認自己走的是哪條路徑。

團隊還要注意對外使用。官方 API 慣例把個人或內部用途與再散布授權分開，因此能查到資料，不代表可以直接放進公開付費報告或提供其他客戶使用。

這裡最適合的起點，是用少數標的做一份可回頭核對的摘要。等資料時間、查詢條件與輸出格式都穩定，再考慮定期報告，避免把錯誤流程反覆自動化。

## Unusual Whales Claude 常見問題

### Claude 可以透過整合替我下單嗎？

官方 AI 應用說明將這組工具列為唯讀，不能下單或修改帳號。資料查詢和券商交易是不同範圍，不應因為能對話就把兩者混在一起。

### 免費帳號看到的是即時資料嗎？

依 2026 年 10 月 19 日查詢的官方說明，免費帳號延遲兩個交易時段。付費方案提供即時資料，但個別查詢工具與資料權限仍應看方案條件。

### 一定要把 API key 貼給 Claude 嗎？

不一定，官方也提供用 Unusual Whales 帳號登入的方式。若採 API 路徑，金鑰應透過支援的授權設定提供，不要當成普通聊天內容公開分享。

### AI 摘要和原網站數字不同時怎麼查？

先核對交易日、時間、資料類型與篩選條件，再確認帳號延遲及回傳欄位。若比較範圍不同，即使兩邊各自正確，也可能得到不同數字。

## 把對話變成研究入口，保留回到資料的路

這次整合讓市場研究多了一個較方便的入口，使用者可以用自然語言取得資料，再追問定義與比較。它最有幫助的地方，是減少整理工作，而非替投資判斷加上保證。

願意核對時間、條件與分類的人，適合先用一份小型摘要試試。若希望直接得到不需驗證的買賣答案，這個工具無法補上所缺的研究過程。

開始前可以先讀官方 AI 應用與 MCP 文件，選好連線路徑，再設定一個能自行核對的查詢。訂閱 AI 郵報，也能持續追蹤 AI 與金融資料整合的功能及限制。
