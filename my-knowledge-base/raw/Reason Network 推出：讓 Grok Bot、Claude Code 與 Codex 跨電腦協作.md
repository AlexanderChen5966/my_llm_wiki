Reason Network 想處理的是不同 AI 代理各做各的問題。當同事分別用 Claude Code、Codex 或 Grok Bot 工作，代理若能知道彼此的位置與任務，就有機會先詢問，再決定如何分工。

[官方產品頁](https://reasonmachines.com/network?ref=aiposthub.com) 介紹，Reason Network 可連接同一台電腦與團隊成員電腦上的代理，區域網路條件允許時直接通訊。

區域網路是辦公室或家中設備共用的近端網路。點對點連線讓訊息可以在設備間直接傳遞，但不代表每個模型都在本機執行，也不代表不會產生雲端模型費用。

這項工具比較適合已經同時使用多種程式代理的團隊。若任務只需要單一助理完成，增加通訊層未必會讓工作更簡單。

先理解代理如何相互找到，再看免費與開源的範圍，會比較容易判斷用途。

## Reason Network 如何連接不同代理？

官方以「成員／代理」的方式指定對象，例如把問題交給另一位成員電腦上的 Claude。代理收到工作後回覆，團隊也可以查看誰在哪台電腦、哪個專案工作。

`reason network setup` 負責設定連接， `reason network` 提供互動入口，而 `reason network serve claude` 可以啟動等待工作並回覆的代理。

### 這對團隊分工有什麼用？

如果一個代理正在處理登入功能，另一個代理需要同一段程式的資訊，可以先詢問現有工作者，而不是直接另改一份。這能減少重複探索，也讓分工更容易被看見。

不過，「能看見」和「一定不衝突」仍是兩件事。代理可以知道別人在做什麼，但誰有權修改檔案、誰負責最後合併，還需要明確安排。

官方也說明，原本使用 `reason ask` 的腳本仍可沿用，因為它與新入口相容。既有使用者因此有機會逐步遷移，不必一次重寫所有呼叫。

## 免費與開源各包含哪一部分？

Reason Network 官方把網路通訊引擎列為 Apache 2.0 開源，但負責設定的 Reason CLI 並沒有開源。CLI 是透過文字指令操作工具的介面，不能因為引擎開放就推論整個產品都採同一授權。

官方表示點對點網路免費，雲端 Reason 工作階段仍照常計費。模型、外部工具與主機資源也可能另有成本，所以免費通訊不等於免費完成所有工作。

關於速度，產品頁以已啟動、等待工作的代理處理短問題為例，列出約 1.5 至 2 秒的回覆。這個條件不能直接延伸到完整改程式、測試或跨網路的大型任務。

對採購或導入者來說，應先拆開通訊、代理執行與模型呼叫三段費用。知道費用發生在哪裡，才不會把某一層免費當成整體預算。

## 跨電腦協作，怎麼避免改壞同一份工作？

可以先讓網路只用於詢問與回報，再逐步增加修改能力。例如要求另一個代理整理呼叫關係，主代理收到結果後，仍在自己的分支完成修改。

等團隊確認訊息、身分與任務對應正確，再安排不同代理各自負責清楚的檔案或功能。跨電腦分工尤其要保留版本資訊，避免甲在舊程式上回答，乙卻把答案套到新版本。

以下是開始前值得寫清楚的規則：

| 協作問題 | 建議的明確安排 |
| --- | --- |
| 代理可以接誰的工作 | 限定團隊成員與用途 |
| 同一檔案由誰修改 | 指定單一負責者或分支 |
| 結果如何被採用 | 附版本、證據與檢查結果 |
| 成員離開團隊 | 驗證身分與連接權限撤銷 |

官方表示僅已登入的工作區成員可加入、設備間流量有端對端加密。團隊仍應實際測試成員移除與錯誤路由，確定控制符合自己的需求。

## Reason Network 常見問題

### 一定要使用同一種模型嗎？

官方列出多種代理與入口，目的就是讓不同工具彼此協作。各工具原本的帳戶與使用限制仍然存在。

### 整個 Reason 都是開源嗎？

不是。官方明確區分開源網路引擎與未開源的設定 CLI。

### 點對點免費，就沒有模型費嗎？

模型與雲端工作階段可能另計費。通訊費和完成工作的費用需要分開看。

## 結語：先讓代理交換有證據的答案

Reason Network 適合先從跨代理詢問開始試點。用同一個真實任務，檢查回覆是否包含正確版本與來源，再決定要不要擴大到跨電腦執行工作，會比一開始就全面放權更容易管理。
