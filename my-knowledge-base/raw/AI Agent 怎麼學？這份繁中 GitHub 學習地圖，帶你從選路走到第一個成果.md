AI Agent 怎麼學，常讓人卡在第一步。已經會用聊天工具的人，打開教學卻同時看到框架、記憶、工具與多代理，很難知道現在該先做什麼。

因為這些名詞對應不同問題，直接照熱門清單安裝，很可能花了一晚設定環境，仍說不出工具能替自己完成哪件事。

WenyuChiou 維護的 awesome-agentic-ai-zh，把學習入口分成使用現成代理、自建代理，以及日常使用者指南。讀者可以先依目標選路，再沿著章節的練習前進。 [專案原始說明](https://github.com/WenyuChiou/awesome-agentic-ai-zh?ref=aiposthub.com)

對想把 AI 接進工作的人，這種安排的價值在於每一步都有用途。你可以先學會交辦與檢查成果，需要自己寫系統時，再增加程式與執行控制的知識。

先決定自己想完成哪種工作，才知道眼前需要的是工具使用能力，還是打造工具的能力。

## AI Agent 怎麼學，先選哪一條路？

AI Agent 可以依目標選擇下一步、使用工具，再根據結果繼續或停止。學習時最先要理解的，就是它如何從「得到回答」走到「完成工作」。

例如，你希望它整理公開公告，它可能需要找頁面、讀日期、擷取重點，再產生有來源的摘要。每一步的結果都可能影響下一步，因此交辦方式與完成條件也要一起設計。

這份地圖把需求分成幾種入口，選擇時可以先對照自己的目標。

| 現在想完成的事 | 適合的入口 | 先累積哪種能力 |
| --- | --- | --- |
| 在日常工作中使用 AI | 日常使用者或角色指南 | 整理需求、提供材料、檢查結果 |
| 用現成代理處理檔案與專案 | Track A | 設定規則、重複交辦、接入工作流程 |
| 自己開發代理與服務 | Track B | 程式呼叫、工具執行、狀態與驗收 |

Track 是學習路線，Stage 則是路線上的章節。若只是想改善寫作或資料整理，可以先走角色指南，有了實際需求後再補技術章節。 [地圖的選路說明](https://github.com/WenyuChiou/awesome-agentic-ai-zh?ref=aiposthub.com#-%E7%8F%BE%E5%9C%A8%E5%B0%B1%E9%96%8B%E5%A7%8B)

走 Track A 或 Track B 前，先確認 Stage 0–2 的共用基礎。已有 Python 程式、Git 版本管理與 API 呼叫經驗的人，可以略過 Stage 0，從模型基礎開始。

選路也可以隨目標調整。先用現成工具整理資料，之後想把相同流程提供給同事使用，就有理由進一步學習系統開發。

## 基礎要學到什麼程度，才能開始做？

基礎是否足夠，可以從你能不能說清楚資料如何進入、工作如何執行，以及結果如何回來判斷。這比先背完所有縮寫，更容易接上第一個練習。

大型語言模型是能讀寫語言、依輸入產生內容的模型。API 是讓程式呼叫服務的介面，程式可以把問題送進模型，再接回輸出，繼續處理後續步驟。

工具呼叫則讓模型提出具體操作，例如要求讀取一份檔案。實際讀檔的程式執行後，把結果交回模型，它才有新的資料可用來判斷。 [Anthropic 工具使用說明](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview?ref=aiposthub.com)

因此，入門練習可以先只做一件可檢查的工作。你若能指出提供了哪些資料、工具讀到了什麼，以及輸出哪裡有錯，就已經有能力繼續改善流程。

### 用一份摘要，檢查自己是否理解流程

以下是本文設計的練習示範。選一份公開公告，要求工具保留標題、發布日期與來源網址，再用幾句話整理它對讀者的影響。

完成後，自己打開來源比對。如果摘要把活動日期當成發布日期，就能知道問題出在欄位理解，而不需要同時更換模型、提示與整套工具。

接著只修改其中一個條件，例如把「日期」改成「頁面標示的發布日期」。再次執行後比較差異，才能看出這次修改有沒有解決原本的錯誤。

這種練法會留下清楚的因果。每次只處理一個缺口，後面的學習也就有明確方向。

## Track A 與 Track B，實作順序怎麼走？

Track A 著重把現成代理用進工作。CLI 是透過文字指令操作工具的方式，這條路線會帶讀者選工具、保存規則，再處理真實工作中的整合需求。

依 2026 年 11 月 5 日查詢的專案說明，Track A 先走 A1、A2，再接 Stage 5 與 A3。Stage 8 建議接著學，但完成 A3 後就能開始畢業專題。 [Track A 正式順序](https://github.com/WenyuChiou/awesome-agentic-ai-zh?ref=aiposthub.com#track-a%E4%BD%BF%E7%94%A8-cli-agent-%E6%8A%8A%E5%B7%A5%E4%BD%9C%E5%81%9A%E5%AE%8C)

這樣安排的理由很實際。第一次能完成工作後，還需要把規則留下來，否則下一次仍要重新解釋資料位置、輸出格式與修改範圍。

例如，固定要求文章附來源、資料表保留原始欄位，以及修改前先讀專案規則，都可以成為可重複使用的交辦條件。

延伸閱讀 [CLAUDE.md 怎麼寫？2026 記憶、Rules、Skills 與 5 種任務模板教學](https://www.aiposthub.com/claude-md-guide-templates-rules-stop-conditions/)

Track B 則把重點放在自己組出執行流程，主線依序為 Stage 3、4、5、6、7、7.5、8。先做工具迴圈，再學多步驟安排、工具規則、資料取回與上線驗收，最後接進階閱讀與操作介面。 [Track B 正式順序](https://github.com/WenyuChiou/awesome-agentic-ai-zh?ref=aiposthub.com#track-b%E5%BE%9E%E9%9B%B6%E6%89%93%E9%80%A0-agent)

工具迴圈就是反覆進行「模型提出下一步、程式執行、結果回給模型」的過程。因為模型可能繼續要求操作，所以開發者也需要安排輪數、停止條件與失敗處理。

兩條路都會遇到相同的工作問題，但負責的範圍不同。使用者要知道如何交辦與查驗，開發者還要讓這些規則在程式裡確實執行。

## 第一個專案，如何留下學習證據？

第一個專案可以小到只整理一組公開資料，只要完成後能說明結果如何產生、哪裡需要改進，就有繼續練習的價值。

以每週公告摘要為原創示範，可以先固定幾個來源，交付一張包含標題、日期、摘要與網址的表格。這個練習可以先用少量資料完成，讓每個欄位都能回查。

開始前先寫清楚範圍，例如只處理指定日期內的公告，遇到找不到發布日期的頁面就列出缺口。這樣檢查結果時，才知道哪些資料應該出現。

接著把第一次成果留下來。來源少一筆、網址重複，或日期格式不一致，都可以成為下一次重跑的檢查項目。

| 要留下的紀錄 | 為什麼需要 |
| --- | --- |
| 輸入與來源範圍 | 下次能用相同條件比較 |
| 實際交付檔案 | 可以重新開啟與核對 |
| 錯誤與修改 | 看出問題是否反覆出現 |
| 執行時間與費用 | 了解工具是否適合持續使用 |

這些紀錄能讓進步具體可見。當輸出格式已經穩定，卻仍漏掉頁面資料，就應先檢查讀取方式，再決定是否調整後續整理步驟。

### 練習通過後，還要確認用了哪些能力

有些練習會先用固定資料測試規則，讓讀者確認程式流程。真正連接模型或外部服務時，還會多出回應變動、連線失敗與計費條件，應依該題的執行說明確認。 [專案範例入口](https://github.com/WenyuChiou/awesome-agentic-ai-zh/blob/main/examples/README.md?ref=aiposthub.com)

因此，進度紀錄可以寫成「規則測試通過，已能讀懂輸出」，接著再記錄是否完成模型連接與結果核對。這樣比較容易知道自己還缺哪一段。

若材料會長期累積，也可以把來源、規則與已確認的內容分開保存。新的工作有相同背景時，就能取用同一份資料，減少版本混用。

## 資源怎麼挑，才不會一直換工具？

挑資源時，先帶著一個已經遇到的問題。知道自己卡在讀檔、工具執行或結果檢查，才容易從地圖裡找到下一個需要的章節。

例如，工具明明讀到資料，摘要卻常忽略限制，可以先回看需求與規則。若整個流程需要在幾個固定步驟之間切換，再研究多步驟安排會更有用途。

這份專案提供進度表，方便把章節與完成條件放在一起記錄。學習時可以補上自己的案例與問題，讓下一次閱讀接著上次的缺口走。 [專案學習進度表](https://github.com/WenyuChiou/awesome-agentic-ai-zh/blob/main/PROGRESS.md?ref=aiposthub.com)

模型、工具版本與價格則需要回到供應商文件。地圖協助安排學習順序，實際安裝或串接時，仍要依所用工具的當期要求處理。

時間安排也應回到可投入的時段。一次完成一個小成果，再依錯誤調整下一次練習，比同時開很多課程，更容易知道自己是否正在前進。

## AI Agent 怎麼學常見問題

### 完全不會寫程式，可以開始嗎？

可以先走日常使用者指南，練習交辦、提供資料與核對結果。想進一步操作 CLI 或自己開發時，再補上對應的基礎準備。

### 閱讀教材與執行練習都免費嗎？

專案公開提供教材，採 MIT 授權。實際練習若連接付費模型或雲端服務，費用則依你選用的供應商與方案計算。 [專案授權](https://github.com/WenyuChiou/awesome-agentic-ai-zh/blob/main/LICENSE?ref=aiposthub.com)

### 走完會取得官方認證嗎？

這份專案是社群作者維護的學習地圖，核心是章節、資源與實作成果。若需要某家供應商的證書，應另外查該機構的課程與認證條件。

### 一開始就需要學多代理嗎？

先讓一個範圍清楚的任務能穩定完成。等工作出現可獨立分工的部分，再比較多代理是否改善交付，會更容易理解新增架構的用途。

## 從一個能驗收的小成果開始

這份學習地圖適合已經想做事、卻不知道如何安排順序的人。先選符合目標的入口，完成一次小任務，再把錯誤與修正留下來，章節才會逐步變成自己的能力。

下一次打開地圖時，可以只決定一件要交付的成果。完成後更新進度，依卡點繼續閱讀，讓每一站都接得上實際工作。
