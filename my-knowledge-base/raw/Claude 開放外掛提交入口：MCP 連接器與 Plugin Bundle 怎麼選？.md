Anthropic 新開放 Claude 外掛目錄提交入口，讓付費 Claude 方案的開發者能自行提交作品、查看審核狀態，通過後決定何時上架。這對已有遠端服務的團隊，是把工具送進 Claude 目錄的正式路徑；對想把操作方法也一起交付的團隊，則提供了 Plugin Bundle。

## 先決定要提交哪一種形式

單一 MCP 連接器適合已經運作的遠端 MCP 伺服器。MCP 是讓 AI 與外部工具、資料來源互動的協定；若功能重點是讓 Claude 呼叫 API、查資料或執行受控操作，提交連接器即可。Plugin Bundle 則能把 MCP 伺服器與 Agent Skills 一起封裝，託管於 GitHub 儲存庫。Skills 提供任務做法與使用邊界，能讓工具被更有脈絡地使用。

Claude Code 的外掛還能包含指令、Hooks、Agents 與 LSP 等元件，但不代表這些元件在所有 Claude 介面都有相同功能。提交前先確認目標使用場景和支援的產品介面，避免把桌面端或終端功能誤寫成網頁版普遍可用。

## 審核後能看到什麼？

Anthropic 說明，提交時系統會自動驗證並進行安全掃描；開發者能查看審核狀態、回饋與建議修正。外掛上線後，分析資料可顯示不同產品介面的安裝情況、版本分布、目錄頁瀏覽與搜尋詞。這些數據可用來判斷使用者找到了什麼、在哪個步驟離開，不能直接當作活躍使用量或商業收入。

## 從現有工具到目錄上架，可以怎麼走？

第一步是把使用者要完成的任務寫清楚。例如「讀取工單狀態」和「替使用者關閉工單」需要不同權限，也該在介面上有不同的確認方式。若已有遠端 MCP 伺服器，就先檢查端點可用性、登入流程、錯誤回覆與最小權限。若還需要教 Claude 何時、如何使用工具，再把操作指引加入 Plugin Bundle。

第二步是用一個乾淨帳戶測試安裝。開發者自己的帳戶常已登入所有服務，容易忽略第一次使用時的授權阻力。應確認使用者看到的名稱、說明、範例任務和錯誤提示，足以讓他完成第一個成功操作。第三步才是依照入口提交，處理自動驗證與安全掃描回饋。通過後再決定上架時間，並留意版本更新是否會改變既有使用者的權限。

## 安全掃描通過，還需要自己檢查什麼？

目錄審核可以幫助找出部分問題，但開發者仍要理解連接器接觸的資料。先列出每個工具能讀寫的範圍、授權何時到期、失敗後是否會重試，以及重試會不會造成重複寫入。若外掛會寄送訊息、刪除資料或修改付款設定，應清楚區分「提出建議」與「實際執行」，並讓使用者能在關鍵步驟確認。

Bundle 中的 Skills 也要當成產品的一部分維護。指引如果描述了已改版的 API 或不存在的按鈕，使用者即使成功安裝工具，任務仍可能失敗。上架後要把回報的錯誤與新版本更新連在一起，避免目錄頁看起來很完整，實際流程卻無法走完。

## FAQ：分析看板可以告訴我什麼？

安裝量與版本分布能顯示外掛被找到、被採用到哪個階段；目錄頁瀏覽與搜尋詞則幫你檢查名稱及說明是否符合使用者需求。但安裝不等於成功完成任務，搜尋曝光也不等於收入。若要改善留存，還要把第一個成功任務、錯誤率和支援回報與這些資料一起看。

## 兩種提交路徑，用實際例子比較

如果你經營一套專案管理服務，只想讓 Claude 搜尋專案和新增任務，遠端 MCP 連接器通常是更簡單的起點。它的工作是提供工具與授權入口。若你希望 Claude 在讀取會議紀錄後，依團隊規範整理待辦、標示負責人並提醒使用者確認，再送入專案系統，就可能需要把操作規則與連接器一起包成 Plugin Bundle。

選 Bundle 不代表必須塞滿所有元件。Skills、MCP 連接器、指令與 Hooks 各有作用，過多元件會增加維護與審核負擔。先完成最常見的一條工作流，確認使用者能理解其授權範圍，再考慮擴充。Anthropic 也說明，兩種提交方式最後都要經過驗證與審核。

## 目錄頁要回答使用者的三個問題

第一，這個外掛能幫我完成什麼具體任務？第二，它會接觸哪些帳戶與資料？第三，安裝後第一個動作該怎麼做？如果說明只寫「提升生產力」，使用者很難判斷是否值得授權。相反地，明確寫出「搜尋本週客服工單並整理待回覆案件」，就能讓搜尋詞、產品能力和使用者期待對齊。

版本更新時也要維持這份清楚。若新版本增加寫入能力或改變登入方式，目錄頁、範例任務與權限說明應同步更新。分析看板可以幫你看到哪個版本被安裝，但要理解使用者為何留下，仍需要觀察第一個任務是否順利完成。

## 上架前的實作檢查

先用最小權限測試連接器，把需要登入與授權的動作寫清楚；再讓第一次接觸的使用者試裝，確認說明能讓人完成第一個任務。若做 Bundle，儲存庫中應清楚交代依賴、版本、可存取的資料與失敗時的回復方式。通過審核只是進入目錄的門檻，真正影響留存的是工具能否安全、穩定地完成使用者要做的事。
