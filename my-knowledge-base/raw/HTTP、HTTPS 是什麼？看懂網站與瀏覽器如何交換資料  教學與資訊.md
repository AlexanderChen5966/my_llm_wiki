每天打開網站、送出登入表單，或在網頁上搜尋資料，背後都有瀏覽器與網站彼此「對話」的過程。這種對話最常使用的規則，就是 HTTP。

前一篇〈 [從輸入網址到網頁呈現：揭開瀏覽器運作的黑魔法](https://tools.wingzero.tw/articles/3711) 〉介紹了 DNS、連線與瀏覽器呈現頁面的流程。這篇則把焦點放在其中負責交換資料的 HTTP，以及網址列常見的 HTTPS。

## HTTP 是什麼？

HTTP 是 Hypertext Transfer Protocol（超文字傳輸協定）的縮寫，是一套讓用戶端與伺服器交換資料的通訊規則。用戶端通常是瀏覽器或 App，伺服器則是提供網站或 API 的服務。

HTTP 採用「請求（request）—回應（response）」的模式：用戶端提出請求，伺服器處理後回傳回應。瀏覽器取得的內容不只有 HTML，也可能是圖片、CSS、JavaScript、JSON 或其他檔案；載入一個頁面時，往往會發出多筆 HTTP 請求。

HTTP 本身不負責決定網站的商業規則，也不等於資料庫。它規範訊息如何表達、方法與狀態碼代表什麼；伺服器收到請求後要查哪些資料、是否允許操作，則由網站程式決定。

## 一筆 HTTP 請求包含什麼？

以 HTTP/1.1 為例，請求通常可從幾個部分理解：

- **方法（method）** ：說明想對資源做什麼，例如讀取或送出資料。
- **路徑與查詢參數** ：指出要存取的資源，例如 `/articles?page=2` 。
- **標頭（headers）** ：附帶格式、語言、驗證資訊等中繼資料。
- **本文（body）** ：可選，用來放表單或 API 要處理的資料。
```
GET /articles?page=2 HTTP/1.1
Host: tools.wingzero.tw
Accept: text/html
```

上例表示瀏覽器想讀取文章列表，並告訴伺服器它偏好收到 HTML。這是方便閱讀的 HTTP/1.1 格式示意；HTTP/2 與 HTTP/3 在網路上會用不同的二進位框架傳送，但請求與回應的核心概念仍相同。

標頭也常見 `Content-Type` （本文資料格式）、 `Authorization` （驗證資訊）與 `Cookie` （瀏覽器保存的狀態資料）。例如 API 可能用 `Content-Type: application/json` 表示本文是 JSON。

## 伺服器如何回應？

伺服器的回應會帶有 **狀態碼** 、標頭，以及視情況附上的本文。瀏覽器會根據回應決定接下來怎麼做：顯示內容、前往新網址、使用快取，或提示錯誤。

```
HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
Cache-Control: max-age=60
```

這裡的 `200` 表示請求成功， `Content-Type` 說明回應本文是 HTML， `Cache-Control` 則提供快取相關指示。

## 常見 HTTP 方法

- **GET** ：讀取資源，例如開啟文章頁。依照 HTTP 語意，GET 應是「安全」的讀取操作，不應以改變資料為目的。
- **POST** ：提交資料或要求伺服器處理某項操作，例如送出表單。是否建立新資料要看 API 的設計。
- **PUT** ：以提供的表示內容建立或取代目標資源；相同請求重送時，預期效果應一致。
- **PATCH** ：部分修改資源；是否可安全重送，取決於具體操作的設計。
- **DELETE** ：要求刪除目標資源。重複送出不代表回應文字一定相同，但預期的最終狀態應一致。

「冪等（idempotent）」指的是同一個請求執行一次或多次，對伺服器資源造成的預期效果相同；不代表每次回應都一模一樣。這對網路中斷後要不要重試請求很重要。方法的正式語意可參考 [RFC 9110：HTTP 方法](https://www.rfc-editor.org/rfc/rfc9110#section-9) 。

## 狀態碼怎麼看？

HTTP 狀態碼是三位數，第一位大致表示結果類別：

- **2xx：成功** 。例如 `200` （成功）、 `201` （已建立）、 `204` （成功但沒有回應本文）。
- **3xx：重新導向或快取** 。例如 `301` 表示永久重新導向， `302` 常用於暫時重新導向， `304` 表示可使用未變更的快取內容。
- **4xx：請求端需要處理的問題** 。例如 `400` （請求格式或內容有問題）、 `401` （缺少或無效的驗證資訊）、 `403` （不允許存取）、 `404` （找不到資源）、 `429` （請求過多）。
- **5xx：伺服器端處理失敗** 。例如 `500` （伺服器發生未預期錯誤）、 `502` （閘道收到無效回應）、 `503` （服務暫時無法使用）。

狀態碼是排查問題的線索，不一定能單靠數字判斷根因。例如 `404` 可能是網址打錯，也可能是資源已移除；遇到 `5xx` 時，通常需要檢查伺服器或上游服務的紀錄。

## HTTPS 和 HTTP 有什麼不同？

HTTPS 可以理解為透過 TLS 保護的 HTTP。建立 HTTPS 連線時，瀏覽器會驗證網站憑證是否有效並與網址的網域相符，之後在用戶端與該連線端點之間加密資料，並檢查傳輸內容是否遭到竄改。

這能降低別人在網路傳輸途中讀取或修改資料的風險，也讓瀏覽器可以確認自己連到的是憑證所對應的網站。不過，HTTPS **不等於網站一定可信** ：它不能保證網站內容正確、網站沒有惡意程式，也不能保證伺服器收到資料後如何保存或使用資料。

瀏覽器網址列的 `https://` 表示連線使用 HTTPS。HTTP/1.1 與 HTTP/2 通常透過 TCP 傳輸；HTTP/3 則以 QUIC 為基礎。這些版本的傳輸方式不同，但對一般網站開發者而言，仍可先從 request、response、標頭與狀態碼理解 HTTP。

## 瀏覽器載入網頁時發生什麼事？

1. 瀏覽器解析網址，並視情況檢查快取與網域資訊。
2. 瀏覽器與網站建立連線；HTTPS 會進行 TLS 相關協商。
3. 瀏覽器送出 HTTP 請求，伺服器或前方的 Web Server、反向代理接收請求。
4. 網站程式處理請求，回傳狀態碼、標頭與內容。
5. 瀏覽器讀取 HTML，並可能再送出請求取得 CSS、JavaScript、圖片等資源，最後呈現頁面。

因此，打開一個網頁不是只有「下載一份 HTML」；瀏覽器與網站可能會往返多次。若想看每筆請求的網址、狀態碼、載入時間與回應標頭，可以開啟瀏覽器開發者工具的 Network（網路）面板。

## 遇到問題時可以先看什麼？

- 頁面跳到其他網址：查看是否有 `301` 或 `302` 重新導向。
- 找不到文章或圖片：確認請求網址與 `404` 回應。
- 登入後仍無法使用功能：檢查登入狀態與 `401` 、 `403` 回應的差異。
- 網站暫時打不開：若看到 `5xx` ，問題可能在網站伺服器或它依賴的服務。
- 頁面顯示舊內容：檢查瀏覽器或 CDN 快取是否仍在有效期間。

## 簡單總結

HTTP 是瀏覽器、App 與網站服務交換資料的共同語言：用戶端提出請求，伺服器回傳狀態碼、標頭與內容。理解方法、標頭與狀態碼，就能更容易看懂網站如何載入資料、API 如何溝通，以及錯誤該從哪裡查起。HTTPS 則在 HTTP 傳輸外加上 TLS 保護，但它不代表網站本身一定可信或資料儲存方式一定安全。
