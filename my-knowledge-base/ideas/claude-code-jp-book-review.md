日文書《Claude Code 実践入門［生成式 AI 深挖指南］》（SB Creative，2026-08-14 發售，**全彩 7 章 337 頁**）的當日讀後感。⚠️ **日文書，繁中讀者需自行評估**，故列 ideas 而非 wiki。

## 🔑 本篇最值得記的一個數據

> **Claude Code 在最近 1 年內的發佈次數高達 310 次**（作者 Oikon 於發售當天在 X 公開的寫作紀錄）。

書評者的觀察是：Claude Code **常常在中途改變行為，而且有時會在官方文件或變更紀錄沒寫到的情況下偷偷在背後更新**——所以「以非工具開發者的立場把細節查到這麼清楚」是龐大心力（甚至趕上把剛出現的 Fable 模型寫進去）。

⚠️ 這個數字對本知識庫的實務意義：**任何 Claude Code 的功能細節條目都有快速折舊風險**，引用版本號與日期是必要的（本庫既有判例已如此處理）。

## 內容涵蓋與章節色彩

以製作 TaskBoard 待辦應用為主線的實戰形式，涵蓋基本操作與提示詞 → CLAUDE.md 與權限設定 → Skill 與 MCP 擴充 → 無頭模式與 CI → 安全性與成本。**越到後半，視角越從「一個人使用的工具」轉向「團隊使用的機制」。**

書評者認為第 5 章之後最耐讀：**第 5 章**成本監控與品質穩定（以團隊／企業導入為前提）／**第 6 章**企業環境（國內外導入案例、規模特有的安全與合規、與 GitHub Copilot 的分工）／**第 7 章**未來展望（開發風格與模型演變的歷史回顧 ＋ 展望，且**不會把結論導向「那就去用 Claude Code 吧」**）。

## 🔑 閱讀順序建議（本篇最實用的部分）

- 想先了解**團隊使用方式** → 從第 5 章讀起
- 覺得篇幅太大而**卻步** → 先讀第 7 章（先理解「學 Claude Code 的意義」，再往前回頭補）
- 不執著通讀 → **挑有興趣的地方零食式閱讀**（書中的便條與專欄很適合）

## 書評者自己挖到的四個發現

1. **內建 Skill 的廣度**——連設計類、製作圖表的功能都有
2. **無頭模式 ＋ `/loop`／`/goal` 組合**——從「單次呼叫」變成「跑到達成目標條件為止」
3. **GitHub Actions 排程執行**——不只做 PR 自動審查或整理 Issue，**排程可用最少人力清技術債或處理容易忘記的維護工作**
4. **安全性解說最受推崇**：不停在「用設定就能防住」，而是**實際讓 Claude 讀取 `.env` 直到被阻止的整個過程都用日誌展示**，並誠實寫出**哪些範圍是這樣的設定也防不了的**
