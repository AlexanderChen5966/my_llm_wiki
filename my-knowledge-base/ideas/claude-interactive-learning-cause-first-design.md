## 設計骨架：預測 → 操作 → 解釋

1. **先定要讓學生理解的因果**，再挑要保留的操作（例：「為什麼要先加水再清洗」vs「脫水與烘乾有何不同」需要不同畫面，不要一開始就做全功能）
2. **一次只改一個條件**：同時改水量、轉速、時間，學生無法判斷哪個造成結果
3. **先預測再操作**：結果先藏起來，請學生預測，再執行，才能對比自己的想法與畫面
4. **預測錯了讓學生回看剛改的條件**，用自己的話修正解釋（不只跳「答錯了」）
5. 給 Claude 的描述要有可檢查任務與對象：學生年齡、已知概念、學習目標，再談畫面（「讓學生比較兩種操作後的結果並解釋差異」優於「做漂亮的洗衣機」）

## 教師要驗證的清單

- 簡化是否誤導（安全鎖、感測器被省略；「脫水」與「乾燥」不能混為一談）
- 字幕與物件狀態同步（走完每條操作路徑）
- 重設是否可靠（下一組回到相同起點）
- 平板可用性（小圖示難點、狀態文字看不清）
- 顏色不單獨承載資訊（搭配文字或形狀）
- 可記一張課程表：學習目標、允許的操作、預期反應、刻意省略之處

## 評估：看解釋與遷移，不看點擊數

- 活動前後用相近問題各請學生一句話回答，**比較理由而非答案**
- 放一個**陌生例子**，看學生能否沿用解釋
- 小規模課堂觀察能找到介面問題，但不足以宣稱普遍提升成績
- 與原教材比較時，兩組要回答相同問題；有老師帶領 vs 完全自學不能全歸因互動效果
- 製作時間（含原理查核與修正）也要記，才知道下次是否做得起
- 互動教材不能取代真實設備操作（觸感、安全、環境條件）
